# Self-update on the check tick

- The Bun global self-update runs `bun add -g tokenmaxxing@<version>` with no preceding `bun remove -g`. The `DependencyLoop` error recorded in `AGENTS.md` belongs to installing a local `.tgz` over an existing global, not to a registry version.
- The global root is detected from the running entry: the first of `BUN_INSTALL_GLOBAL_DIR`, `BUN_INSTALL/install/global`, `dirname(dirname(process.execPath))/install/global`, and `~/.bun/install/global` whose `node_modules/tokenmaxxing/src/main.ts` is the real path of `Bun.main`. Each candidate is `resolve`d against the check's own working directory before use, because a relative `BUN_INSTALL_GLOBAL_DIR` would otherwise re-resolve against the child's `cwd` (the state directory) and install into the wrong tree. The executable-derived candidate is what makes a timer unit without `BUN_INSTALL` in its environment still find a custom Bun root; `process.execPath` is the real binary path, never the invoked symlink. A `bunfig.toml` `install.globalDir` is not read, and a root set only through `BUN_INSTALL_GLOBAL_DIR` is invisible to a timer that does not carry it, so both read as unmanaged and never self-update. A package directory that is a symlink is unmanaged as well: `bun link` registers a checkout exactly that way, and a registry install is always a real directory.
- The version read and the install share one registry, the public one, with `--registry` passed to `bun add` because that flag overrides `.npmrc`, `bunfig.toml`, and the environment; `TOKENMAXXING_NPM_REGISTRY` overrides both for hermetic runs against a local stub. The `latest` document's `engines.bun` is checked with `Bun.semver.satisfies` against `Bun.version` before the install, because `bun add -g` installs a package whose engine floor the running Bun fails and exits zero. The registry URL is built inside the update path, not at module load, so a malformed `TOKENMAXXING_NPM_REGISTRY` fails only the update attempt and never breaks the module import that every command shares; the metadata error strips any userinfo from the URL, so an authenticated registry override never prints its credentials.
- The self-update runs after the evaluation and the parked sampler, outside the pool lock and the Claude refresh lock, so a stalled registry request never delays a swap.
- The install child runs with `cwd` at the state directory and `BUN_INSTALL_GLOBAL_DIR` set to the detected root, because `bun add` reads `bunfig.toml` from its working directory and the environment variable wins over that file, and it is killed after 60 seconds (`Bun.spawn` `timeout` with `SIGKILL`), because launchd and systemd skip a firing while the previous check runs and an unbounded child would block every later tick. The child's stderr is inherited, not piped: a piped read stays pending after the direct child is killed while a descendant holds the pipe, and a race on that read leaves the read outstanding, whereas an inherited descriptor gives the check nothing to drain, so the deadline is the whole bound.
- Only the Claude `init` installs the check timer. A Codex-only install has no tick and no self-update; that ceiling is documented, not engineered around.
