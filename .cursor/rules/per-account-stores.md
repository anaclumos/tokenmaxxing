# Per-account credential stores

Invariants of the Claude seat model (issue #79) and what its hermetic verification taught.

- One store per pooled account, `stores/<uuid8>/`, set on a session as `CLAUDE_SECURESTORAGE_CONFIG_DIR` at spawn. Claude Code hashes that variable's NFC-normalized value into the macOS keychain item name whenever it is set, even with `CLAUDE_CONFIG_DIR` also set, and roots its refresh lock at the same directory; `isolatedTarget(storeDir)` names the same item.
- tokenmaxxing writes a store once, at onboarding, after the token's owner is verified through the profile endpoint. Claude Code's refresh is the only writer afterwards. A credential is never copied between stores, hosts, or Claude Code's default store: a refresh rotation revokes the previous access token of that grant and the other copy dies at its next refresh. Separate logins are separate grants and coexist.
- The seat is fixed for the life of a process. Hooks, the statusline, and the CLI read it from the inherited store variable; a respawn is a new process under another store. Nothing needs a swap clock, an adoption grace, or a cooldown on the Claude pool.
- A Claude move is a respawn marker written by the session's own hook at a turn boundary. The check tick has no seat and moves nothing; an unsupervised session gets enforced-limit stamps and nothing else.
- A session id is not fixed for the life of a process: `/clear` gives the same process a new one and fires SessionStart with `source: "clear"` and that id, while `--resume` keeps the id unless `--fork-session` is passed (2.1.278 binary). A guard that compares the hook's stdin id with the launch id alone drops every hook of the process after a `/clear`, and a seat-watch move then resumes the pre-clear conversation. The live id lives in `sessions/<sid>.json` as `current`, read by the hooks and the seat watch. The event `source` cannot prove which process changed the id, because `/clear` is `supportsNonInteractive` and a nested `claude -p /clear` reports `source: "clear"`; the proof is the process tree. A hook runs as `hook <- sh -c <- claude` (observed under dash; a shell that execs its last command drops the middle hop), so the hook adopts a new id only when the walk up from its parent, through shell processes alone, reaches the presence record's pid.
- A hermetic run of the live-id rule needs the stub `claude` to spawn the hooks as its own children (`sh -c` with a file redirect, not a pipe: a forked bash subshell keeps the script's `comm`, which is not a shell name), and a nested variant spawned under a non-shell process such as `bun -e`.
- Placement and moves rank usable accounts by session-window headroom per session after placement, `(bar - used) / (sessions + 1)`, then pace pressure. The pick and the presence write share the pool lock, so concurrent launches see each other.
- A tee is ordered against the stored record by the sample time it carries, never by file mtime: Linux stamps mtime from the coarse clock, which can lag `Date.now()` by a tick, so a tee written right after its timestamp can read older than itself.
- `auth --all` selects by the store, not by the `needsReauth` flag alone (2026-09-13). A missing store never stamps the flag (it is `StoreUnusableError`, skipped for the evaluation only), so a host that self-updated across the store layout change had every account failing `sample.failed ... no credential in this account's store` and `doctor` red on every store while `auth --all` reported nothing to do. The selection now asks the provider whether each account's store holds a usable credential (`storeUsable`: present, parseable, not dead; the codex side reads its store `auth.json`), so `doctor`, the sampler, and `auth --all` name the same accounts.
- A hermetic run of this model needs a stub `claude` that records its environment and sleeps for interactive launches, and a stub usage endpoint named by `TOKENMAXXING_OAUTH_USAGE_URL`, because usage comes from that read and never from `/usage` output; the supervisor, hooks, `check`, and `status` then run end to end under a throwaway `HOME` and `TOKENMAXXING_HOME` with a synthetic version 2 pool, and store hashes before and after prove the credentials never moved. Seed stored tokens that the usage GET accepts; there is no `/usage` spawn.
