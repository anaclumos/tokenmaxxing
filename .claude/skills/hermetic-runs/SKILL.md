# Hermetic runs

Run-recipe traps are in `.memory/hermetic_runs.md`.

- `TOKENMAXXING_HOME` isolates state files only. `init`, `uninstall`, and the codex hook install write settings.json, codex `hooks.json`, the shell rc, and the timer unit under `HOME` regardless, so a throwaway root does not make them hermetic: a run of a mutating command (`init`, `add`, `auth`, `uninstall`, the codex hook install) builds a full isolated `HOME` with `TOKENMAXXING_SKIP_TIMER=1` set, or runs in a container; a single app variable is never the isolation. `HOME` alone does not cover the timer: `systemctl --user` and `launchctl` address the login user's instance under any `HOME`. `uninstall` guards this in code (`onLoginHome` in `install.ts`): it prints its targets first, refuses without `--yes` when `HOME` is the login home, and under an isolated `HOME` removes only the unit files under that `HOME` without addressing the instance. `init` has no such guard, so a hermetic `init` needs `TOKENMAXXING_SKIP_TIMER=1`.
- A hermetic run of the store model needs a stub `claude` that records its environment and sleeps for interactive launches, and a stub usage endpoint named by `TOKENMAXXING_OAUTH_USAGE_URL` that answers per access token (`TOKENMAXXING_OAUTH_PROFILE_URL` for identity), because usage comes from that read and never from `/usage` output; the supervisor, hooks, `check`, and `status` then run end to end under a throwaway `HOME` and `TOKENMAXXING_HOME` with a synthetic version 2 pool, and store hashes before and after prove the credentials never moved. Seed stored tokens that the usage GET accepts. A run of the live-id rule needs the stub to spawn the hooks as its own children (`sh -c` with a file redirect, not a pipe: a forked bash subshell keeps the script's `comm`, which is not a shell name), and a nested variant spawned under a non-shell process such as `bun -e`. The stub server runs as a separate process (an in-process server stalls behind `Bun.spawnSync`), stays reachable until every child exits, and external network access is denied throughout. The harness stays in the session scratchpad, never in the repo.
- macOS has no `/bin/true`. Use `/usr/bin/true` in hermetic runs.
- A hermetic reproduction that claims to prove a fix also runs the same scenario against the pre-fix tree, and a case that passes on both trees proves nothing: build that tree with `git archive <ref> src package.json tsconfig.json | tar -x -C <scratch>/<name>` plus a `node_modules` symlink, never `git checkout`, `git worktree`, or `git stash`, because another session can move the shared checkout's HEAD while the run executes.
- A stub proves a code path, not a contract: a parser for an external body is verified against one real response before it ships.
- A race finding on a hook or the decision is answered with a hermetic reproduction, never with a timing argument: a helper process holds the pool lock and moves the seat inside it while the hook or the decision runs against it.
- A measurement report timestamp-filters the request corpus, deduplicates messages, and separates temporal association from causation before quoting cache overhead; API price weights do not establish subscription quota accounting.
