# Codex

Source-verified against rust-v0.144.5 and re-checked on later binaries; codex changes monthly, so re-verify before trusting any line here. Detail: `docs/content/docs/codex.mdx` and the Supermemory documents in the two namespaces `AGENTS.md` names.

- No hot-swap: restart IS the switch (`codex resume <sid>`).
- A Codex pool account id is the sha256 hex of `<chatgpt_user_id>__<chatgpt_account_id>` from the token's `https://api.openai.com/auth` claim (`codexSeatIdOf`, `codexIdentityOf`), never `chatgpt_account_id` alone: that claim is the workspace, so every member of one team workspace shares it and an id keyed by it collapses them onto one account. The usage GET still sends the workspace id as `ChatGPT-Account-Id`.
- Refresh-token reuse is punished, and a superseded token kills the whole grant family. Harvest by true owner and persist every rotation into the account's own store the instant it returns; never refresh an account running in another session from outside.
- An idle codex still touches tokens: the Apps surface builds throwaway auth managers that fresh-read the session's own store home `auth.json` mid-run. Sample from the store file at the last moment.
- An account running in another supervised session is never a session placement or move target and never gets its store refreshed from outside; a `seat --codex` borrow still shares a codex session's account. Unmeasured does not imply not running.
- A codex child that runs on a pooled store gets `CODEX_ACCESS_TOKEN` and `CODEX_API_KEY` dropped from its environment (`CODEX_CRED_ENV`): codex resolves `CODEX_ACCESS_TOKEN` ahead of `$CODEX_HOME/auth.json`, so an inherited one would run the session on another account than its seat. A seatless launch keeps the caller's environment, because it runs on the ambient login.
- Classify windows by DURATION, never by position. Current plans may have no 5h window at all.
- Codex silently skips untrusted hooks until the user runs `/hooks`, so auto-switching never engages until they do. Never clobber the user's `notify` key in `config.toml`; nothing in code guards it.
- `~/.codex/hooks.json` is not the only hook config source: a plugin manifest can point at its own via a `hooks` path key. tokenmaxxing only ever writes hooks.json, so check for other sources before assuming precedence.
- `borrowCodexSeat` is the one supported borrow for unattended consumers. The shim runs it keyed to its own pid for `exec`, `e`, `review`, and a bare `app-server` when `CODEX_HOME` is unset (no help or version flag before `--`, no `TOKENMAXXING_UNMANAGED` or `TOKENMAXXING_PROBE`), forwards SIGTERM to the codex child the way the Claude and pi passthroughs do, rewrites the record's `pid` field with the child's pid once it spawns (`recordPresenceOrStop`; the record keeps its `seat-<shim pid>` name), so no signal to the shim alone unreserves a running child, and passes through with no supervisor and no respawn, because a move cannot resume an `exec` turn or an `app-server`; with no usable account it passes through on the ambient login. An `app-server` with any further positional stays on the ambient login, because `app-server daemon start` detaches and outlives the child pid its presence is keyed to, which would leave the store unreserved while the daemon runs on it. `tokenmaxxing seat --codex <pid>` exposes it to consumers that spawn their own codex (the SDK's bundled binary): it refreshes every candidate older than `usagePollTtlMs` through `observeCodex` with `refresh: false` outside the lock (a borrower drains quota with no Stop hook and no `status`, so the cached figure is the only thing that would otherwise screen; the read never rotates a token, because two borrows run concurrently from parallel hooks and a double refresh kills the grant family, so an expiring token keeps its cached figure), then under the pool lock it picks, among the usable accounts whose store holds a readable credential (`codexStoreUsable`, the one predicate for that, shared with `pickCodexSeat` and `validWanted`), the one with the fewest living presence records, sessions and borrowers alike, with `pickBest` breaking a tie, writes `codex-live/seat-<pid>`, and prints the store for the consumer to pass as `CODEX_HOME`. Presence keyed to the consumer's pid self-reaps when it exits. An account that a codex session or another borrower holds stays a candidate; one that a pi session holds (a `PI_PRESENCE_PREFIX` record) does not, because no codex process runs on its store and the pi supervisor, its only refresher, refreshes only while no other record names the account. Sharing goes against OpenAI's CI/CD auth guide (https://learn.chatgpt.com/docs/auth/ci-cd-auth), which forbids one `auth.json` across concurrent jobs: codex takes no cross-process lock around its refresh, so two processes on one store can send the same refresh token, and the loser's `refresh_token_reused` can sign the account out until `tokenmaxxing auth --codex` runs again. Sharing accepts that risk, with no cap on processes per account; the spread keeps the processes per `auth.json` as few as the pool allows. Pointing a consumer at `codex-stores/` directly skips the lock and presence and can kill a grant family; never do it and never recommend it.
- `borrowClaudeSeat` (`tokenmaxxing seat <pid>`) is the Claude sibling and a shared-seat borrow: under the pool lock it folds the tees, picks with `pickBest` on cached figures with every `switchModels` family gating, over accounts that are not `needsReauth` and pass `storeUsable`, writes `live/seat-<pid>`, and prints `storeDirFor(id)`; no usage read and no `pickEarliestReset` fallback, because a borrower cannot wait. The record counts as one session in `presence()`, so the account stays a placement and move target for host sessions and a candidate for other borrowers, and `seatHeadroom` spreads a burst of borrows the way it spreads launches. The Claude grant stays safe only through Claude Code's refresh lock rooted at the store, so the consumer must run Claude Code with that directory itself as `CLAUDE_SECURESTORAGE_CONFIG_DIR`, as the store's host owner (a read-write directory bind mount into a container that maps to that uid works); a copied `.credentials.json` or a single-file bind mount leaves the lock behind, and a container process that maps to another uid, root under a rootful runtime included, takes the file over on its first refresh, because the refresh writes a new 0600 file and renames it, and the host sessions lose read access. On macOS the store is a keychain item, so only a same-host process can use it. `seat <pid> --store <id>` skips `pickBest` and grants the named store after the same `needsReauth` and `storeUsable` checks and nothing else, because a consumer with stricter rules (its own bars, no credits seat, a per-store cap) cannot get a usable store from a ranking that ignores them; a live record for the pid on another store is exit 2, an unusable named store exit 1.
- The Codex Stop hook moves nothing unless the presence record of its supervisor id exists and names the seat in its `CODEX_HOME` (`codexstop.foreign_seat`): a borrowed child spawned inside a supervised session inherits `TOKENMAXXING_CODEX_SUPERVISOR_ID`, and without the guard its move writes a marker that restarts the parent on the child's thread. The guard holds only while the child's seat differs from the parent's, so `borrowCodexSeat` never lends the account of the supervised session that the caller's `TOKENMAXXING_CODEX_SUPERVISOR_ID` names; the record is absent between the supervisor's `clearPresence` and its rewrite during a respawn, when only such a child can be running. A seatless supervised session has no record and no move to lose (`evaluateAndMaybeSwap` returns before the lock with no seat). The Claude hooks guard the same case by session id.
- Codex Stop stdin carries `session_id`, `turn_id`, `transcript_path`, `stop_hook_active`, and `last_assistant_message`, but no error signal, so the reverted text-sniffing failsafe (`code.md`, "Do not reintroduce") applies here too. `CodexStopStdinSchema` is a loose object declaring only `session_id` and `hook_event_name`, so it silently swallows the rest.
