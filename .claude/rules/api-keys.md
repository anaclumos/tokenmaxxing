# API keys

An Anthropic or OpenRouter API key (`key add`, `api-keys.json` plus `api-keys/<id>`) is a paid fallback for Claude sessions while no pooled account is usable; the policy is in `docs/content/docs/switching.mdx`. Codex, pi, and `seat` borrows never use one (`piMover` clears the `apiKeys` capability).

- The key reaches the child only through a socket at descriptor 3 named by `CLAUDE_CODE_API_KEY_FILE_DESCRIPTOR` (an extra `"pipe"` in the `Bun.spawn` `stdio` array, which Bun makes a `socketpair` on every POSIX platform and exposes to the parent as the number in `stdio[3]`, owned by the caller), never argv or env. The supervisor writes the key plus a newline and closes its end (`sendApiKey`) for the launch and the compaction spawn. Keep it a socket: the binary (`nre()` in 2.1.294) reads a socket descriptor directly until the newline, closes it, and deletes the variable, while any other descriptor kind is reread through `/proc/self/fd/<n>`, which macOS lacks, and stays open for descendants. `ANTHROPIC_API_KEY` is ignored by an interactive session until the key is approved in `~/.claude.json`, which tokenmaxxing never writes.
- A key session returns to a subscription account only at the Stop and SessionStart hooks; the seat watch moves it only when its key is spent or refused, so no turn on a key is cut to save money.
- The supervisor is the only writer of `spentUsd`. It folds the growth of the session's cumulative client-side cost (`cost/<sid>/<live id>.json`, one file per live session id of the launch so a `/clear` never replaces the previous id's unfolded reading, written by the statusline and by the stream-json tee only while `api-keys.json` exists, checked on every cost line, never once per launch, so a key added mid-session still records the baseline; the fold bills every file in the launch's directory and then deletes all but the newest, so a historical file never rereads against a baseline that another supervisor's resume moved or the retention pruned; a reading at or below its baseline changes nothing, because a cumulative cost only grows and a lower write would bill the difference again) under the pool lock, against the baseline in `api-keys.json` `baselines`, keyed by the live session id inside the cost observation (never the launch sid, which a `/clear` leaves behind) and written in the same atomic save as `spentUsd`, so a failed write and a retry cannot bill twice. It records the baseline while the session runs on an account too, so pre-key cost is never billed. A live id with no baseline bills its reading minus the total Claude Code restores for it: the supervisor snapshots the last `cost-state` row of the id's transcript (0 when the transcript has none or the id is new) when it launches the resume, before any paid turn, and keeps the first snapshot per id. A live id the supervisor never launched (an in-session `/resume` adopts an older conversation) takes the same snapshot the first time the fold meets it, only when its transcript was created before the supervisor started (`birthtimeMs`), so the restored total is never billed. A fresh launch id is recorded as 0, and so is a `/clear` id, whose transcript the session created after the supervisor started, so its first turn bills in full. The snapshot of an adopted id is taken after the adopting turn can have run, so it can omit that turn's cost, never bill the restored total. The supervisor also deletes the launch sid's cost file at that launch, because a file that an earlier crashed supervisor left behind can read above the transcript's total. A stream-json session's first reading is the `result` line after its first turn, so the first turn bills as that reading minus the snapshot, never as zero. The pre-move `/compact` child writes no cost file: `compactClaudeSession` reads the last `cost-state` transcript row it appended, and the supervisor writes it to the cost file and folds it under the source seat's key (no key for an account seat) before the relaunch, so the destination's first reading carries no compaction cost; a session with no baseline takes that total as its baseline and bills nothing, because the restored history is not spend.
- A key session never moves to an account in its `refused` list (`TOKENMAXXING_REFUSED`), on every path: the engine applies `opts.refused` whenever `keyId` is set, and the Stop, SessionStart, StopFailure, and seat-watch callers pass it. The account seat watch passes `apiKeys: true`, so a seat crossing a bar mid-turn moves to a key rather than a wait.
- An OpenRouter key is a secret that starts with `sk-or-`, and `isOpenRouterKey` reads the secret file to say so: routing, the cost fold, `key credit`, and the credit refresh never test a stored field. A supervisor or hook from an older release saves `api-keys.json` through its own schema and drops the `ApiKey.openrouter` it does not know, so a launch that routed on that field would send the key to Anthropic (`Invalid API key · Fix external API key`). `ApiKey.openrouter` is only the cached credit read, and the refresh restores it. The key rides the same descriptor: `apiKeyEnv` adds `ANTHROPIC_BASE_URL` after the scrub, and OpenRouter's `/api/v1/messages` accepts `x-api-key` (verified live: a valid key gets 400 for an empty body, an invalid one 401) and maps bare Claude Code model ids. Its credit left is `limit_remaining` from `GET /api/v1/key`, read at `key add` and on the check tick (`refreshOpenRouterCredit`), and the cost fold never adds to its `spentUsd`, because Claude Code prices `anthropic/...` response ids against the wrong model. Claude Code classifies the hook `error` as `billing_error` only from the text "credit balance is too low" and maps 402 to `unknown` and 403 to `authentication_failed`, so a spent OpenRouter limit leaves the key unrefused and the seat watch moves the session once the tick reads the limit at or below 0. OpenRouter ignores `max_tokens: 0` and runs the request, so it is no free probe. A supervisor keeps the release it started on, so a session that started on a release without OpenRouter routing cannot launch an OpenRouter key until it restarts; restart such sessions after an install.
- `billing_error` is the only refusal signal for a key (it is in `ENFORCED_ERRORS`, so the matcher changed). A workspace spend limit arrives as `unknown` and a 429 spend cap as `rate_limit`; do not classify those, and never match message text. On an account session `billing_error` returns before any decision.
- A key marker adds `apiKeyId` and keeps `accountId` as the empty string. A hook writes one only when the supervisor set `TOKENMAXXING_API_KEY_ID` on its child (empty on an account seat), because a supervisor from an older release would read the empty `accountId` and relaunch on a fresh pick of an exhausted account in a loop.
- A key session's presence record lives in `live/` (so the live-id adoption and the session prune see it) with `apiKeyId` and `accountId: ""`; `presence()` and `seatCounts` skip it, so account counts are unaffected.
