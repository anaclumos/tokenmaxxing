# Usage hub

`serve` (`src/cli/serve.ts`) answers the CLIProxyAPI management subset a dashboard reads, `GET /v0/management/auth-files` and `POST /v0/management/api-call`, on the hostname `localhost` at `hub.port` (the loopback address the host's own resolver names, so a same-host consumer's `http://localhost:<port>` lands on it), with the key in `hub-key` (0600, minted on the first run, never printed; an existing key file readable by others is refused at boot). The contract is verified against router-for-me/CLIProxyAPI v7.3.11 and against what T3 Code's server decodes; user page in `docs/content/docs/hub.mdx`. The hub is a view over the cached figures and never a proxy: `api-call` matches the Claude and Codex usage URLs only, ignores the client's `header`, and never forwards a request. A Claude account is never read live from the hub, because the usage endpoint rate limits each Claude account on its own and the check tick already samples each account once its sample interval passes, up to three per tick: `auth-files` and `api-call` both answer from the index with the tee folded in memory (`foldTee`, never saved), so `unavailable` and the served windows agree. A Codex account goes through `observeCodex` with `probe: true` and `refresh: false`, because no tick samples that pool: a cached figure older than `policy.usagePollTtlMs` costs one usage GET with the stored access token, stored under the pool lock the way a `status` sample is, and never a token refresh. The two-hour cutoff is per window, on each window's own `sampledAt` (a fresh tee advances the aggregate windows while `mergeWindows` keeps the per-model rows at the time of the last direct read): a window older than that is left out, and an account whose session and weekly windows are both that old is a 502, because the protocol carries no sample age and a passed reset would otherwise read as 0. The Codex body places the cached windows in `primary_window` and `secondary_window` by ascending duration (a weekly-only plan keeps the primary slot) and carries the named limits as `additional_rate_limits`. `reset-quota`, the Codex credit reads, and every other route are 404 or 400; keep it that way until a consumer needs one. The Claude `init` runs the hub as a background service beside the check timer (`com.tokenmaxxing.hub` launchd agent on macOS, `tokenmaxxing-hub.service` systemd user service on Linux, both running `serve`; `TOKENMAXXING_SKIP_HUB=1` skips the imperative unit the way `TOKENMAXXING_SKIP_TIMER=1` skips the timer, `doctor` checks it, and `uninstall` removes it).
