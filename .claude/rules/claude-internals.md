# Claude internals

Verified auth and quota mechanics are Supermemory documents with `project` `tokenmaxxing`; the credential store and swap sequence are in `DESIGN.md` §2-3.

- Quota comes from the direct `GET /api/oauth/usage?at_wall=1&skip_spend=1` with the account's stored access token, from every sampler (the check tick, `status`, the seat's in-decision read, and onboarding); `skip_spend=1` is the no-spend read Claude Code itself uses, so it opens no window and spends nothing. The body is top-level `five_hour` and `seven_day` (`utilization` already a percent, `resets_at` validated as ISO 8601 with an offset) plus `limits[]`, whose `kind: weekly_scoped` rows carry the per-model caps keyed by `scope.model.display_name`, the same rows `/usage` renders. The read answers 200 for a seat with live sessions, so there is no live-seat gate. Nothing parses `/usage` text, and there is no second usage source: a failed read yields no figure for that attempt. The endpoint rate limits per account, not per host: a limited account answers 429 with `retry-after` in seconds (over 50 minutes observed) while other accounts answer 200 from the same host in the same second, and a read during the penalty fails too. `fetchUsageDirect` returns that deadline, every sampler stores it as `usageRetryAt` (onboarding through `Harvest.usageRetryAt`), and `usageBlockedUntil` in `sample.ts` is the one gate: `sampleOldest` still checks a blocked account's store on its turn and sends it no read, `observeLive` skips the probe without counting a failure, and `sampleAccountUsage` answers `status` with the wait. A new sampler goes through `sampleAccountUsage` or checks the gate itself. No sampler sends a read with an expired stored access token (the `expiresAt` that `prepareSample` returns): the endpoint answers such a read 401, and a few of them earn the account the hour-long 429, which then outlasts the refresh. tokenmaxxing holds no refresh grant, so a due sample that finds the token expired has Claude Code refresh it first (`refreshStore` in `sample.ts`: `claude -p /usage --no-session-persistence --safe-mode` with the store set and a throwaway `CLAUDE_CONFIG_DIR`, its output never read) and reads with the token Claude Code wrote; a store the refresh dead-clears stamps `needsReauth`. The child runs outside the pool lock and `rm` refuses only an account with a live presence record, so after the child exits `refreshStore` takes the lock and deletes the store and its keychain item when the account left the pool meanwhile. Without that spawn an idle account's figure freezes from its token's expiry until a session lands on it. Codex reads its own usage GET, not this endpoint.
- The per-account tee (`usage/<uuid8>.json`, written by a terminal session's statusLine and by the supervisor of a stream-json session) stays the primary source for an account with sessions. The decision engine samples the seat with the direct read when the seat's tee is older than `usagePollTtlMs` or its active model is a gated family (one attempt at most once per sample interval, doubling the interval per consecutive failure up to 30 minutes, reset on success), and `status` samples an account only when its tee is missing or older than the stored sample and its sample interval has passed; for an account whose tee is missing or older, it reports a rate limit or an unusable store by its reason before the interval gate (`readyToSample`, no network). A failed sample is unmeasured, never zero, and a sample never overwrites a newer one (`status` and the decision engine both keep the newest of tee and stored record). The tee carries no per-model rows, so a seat's Fable cap comes from that in-decision sample; the StopFailure hook is the backstop.
- StopFailure fires INSTEAD of Stop when a turn ends on an API error, for subagents too (`agent_id` set), with `error` (`rate_limit`, ...) and `last_assistant_message` on stdin. `quotaLimits` (rateLimitType, resetsAt in epoch seconds) lives only on the transcript row. The Fable credits refusal is the row whose typed `apiError` is `model_requires_usage_credits`: no quotaLimits, no reset, and a text that follows the cause (`You've reached your Fable limit.`, `You're out of usage credits.`, `You've hit your monthly spend limit.`). The usage read cannot tell which accounts will refuse it: the refusing account's Fable row can read far under its bar while another account serves the same session. It classifies as `kind: credits` whatever `policy.switchModels` holds, stamps no wall, and moves the session with the Fable windows screening candidates. The session carries the accounts that refused it in `TOKENMAXXING_REFUSED`, which the StopFailure hook extends and the marker's `refused` relays to the supervisor for the next child; a credits move excludes them, so it never returns to one of them and the session stays put once every candidate has refused. A move off a credits seat that still serves reads it; a move for a bar or a wall does not read the list, because a `/model` change inside the session can make those accounts usable again; such a move can land on a refusing account once, and the next refusal moves the session on. A subagent's credits refusal moves nothing. An organization refusal is the row whose `error` is `oauth_org_not_allowed` (no `quotaLimits`, no reset): it walls the account for five hours and moves the session, because the usage read is no signal for it (reads for refusing accounts answered 403 and 429). `ENFORCED_ERRORS` in `usage.ts` is both the hook's gate and its installed matcher, and the self-update never rewrites settings.json, so a new kind reaches a host only after `init` re-runs there; `doctor` reports the stale matcher. The statusline payload no longer carries `organizationUuid`.
- The StopFailure hook waits up to three seconds for the transcript's error row before classifying (`awaitEnforcedRow`): Claude Code can fire the hook before the row is flushed, and an unclassified failure stamps nothing. `stopfailure.unclassified` logs `subagent`.
- `claude setup-token` is abandoned for the local pool: it is inference-only scoped and returns no rate-limit percentages, which breaks monitoring. Do not revisit without solving usage.
- Every new spawn of a real product binary (claude, codex, grok) goes through `resolveRealBin()`, and every `init` pin through `verifyRealBin()`, with the product's name, config key, and version predicate as the only per-product input. Preset the depth cap for subtrees that must never re-enter the wrapper; set `TOKENMAXXING_UNMANAGED` where nested invocations are legitimate. The layered guards live in `src/lib/claudebin.ts` (`TOKENMAXXING_WRAP_DEPTH` sentinel, realpath rejection of the wrapper's own bin dir, `verifyRealBin` gating the `init` pin, the on-disk record of recent wrapper entries); read them there before adding a spawn. Past 60 entries in 30 seconds the record refuses an entry only when five of those entries are its process ancestors, because a burst of concurrent sessions exceeds any fixed host-wide limit; a shim that strips the sentinel and detaches its re-entry escapes it. A spawn that must read a pooled account sets `CLAUDE_SECURESTORAGE_CONFIG_DIR` to that store after `scrubCredEnv` in `usage.ts` (the supervised launch, its compaction, and the refresh spawn); a spawn that must not (the onboarding login) leaves it scrubbed. The scrub also drops `ANTHROPIC_BASE_URL` when the shell set any other override key, because the binary sends the store's bearer to that URL, and a URL set up for a gateway token must not receive a seat's token.
- Subagents cannot run on another pooled account: the Agent tool, forks, background agents, and in-process teammates all use the parent process's one OAuth token (verified in the 2.1.274 binary); only pane-mode teammates spawn a second process, and they forward the parent's store. An API proxy is a non-goal, so the answer to "can subagents use different accounts" is no.
