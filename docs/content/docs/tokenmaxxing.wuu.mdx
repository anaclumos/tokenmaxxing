## 问题所在

一个 Claude 订阅会同时计量三种限额（侪好通过 `/usage` 确认）：

- **当前会话**：一个滚动嗰 5 钟头窗口。
- **当前礼拜（所有模型）**：7 天嗰汇总。
- **当前礼拜，分模型**：单个模型系列各自嗰礼拜上限。搿眼现在只有 Sonnet 搭 Fable 有，而且只有 Fable 嗰上限紧到要紧嗰程度，伊比汇总早老早就顶牢类。一台机器好一面礼拜总量才 50%，一面礼拜 Fable 已经到 80% 类。

礼拜额度是勿用脱就作废嗰：一个账户到伊固定嗰礼拜复位辰光还呒没用脱嗰部分，统统作废。假使侬有好几个账户，理性嗰做法就是拣落自家礼拜进度顶落后嗰埃只账户接牢烧额度，还要勒任何单一限额勒会话半当中撞墙之前就切换开脱。

手工做搿桩事体就意味着要登出、登进、还要丢脱侬嗰对话。tokenmaxxing 拿伊自动化脱：跑牢嗰 `claude` 会勒两趟请求当中重新检查伊嗰凭据存储，所以勒伊底下换脱嗰凭据会就地被采用（macOS 高头大约 30 秒之内，Linux 高头下一趟请求就采用）。普通嗰切换勿会重启侬嗰会话。唯一还需要进程管理嗰情况是整个账户池统统耗光嗰辰光，会话呒办法自家暂停，搿也就是埃个薄薄嗰 supervisor 存在嗰道理。

`claude` 其余一切侪勿变：所有 flag、MCP server、hook 搭 skill 侪原样通过。

## 快速上手

需要 [Bun](https://bun.sh) 搭 Claude Code，勒 macOS 或者 Linux 高头。

```sh

```

`init` 会做五桩事体：

1. 拿侬已经登进嗰账户当作 1 号账户导入（呒没另外嗰 `adopt` 命令）。
2. 装好 `claude` supervisor 垫片。
3. 勒 Claude Code 嗰 `settings.json` 里向装三条条目：一条 statusLine、一条 Stop hook、搭一条 SessionStart hook（另外还有一条 subagentStatusLine 条目）。
4. 拿 supervisor 嗰 bin 目录加到侬 shell rc 嗰 PATH 高头（幂等嗰，用 `# tokenmaxxing PATH` 注释标牢）。伊必须勒 PATH 高头排勒真嗰 `claude` 前头，先拦得牢伊。
5. 装一个定期检查嗰定时器（macOS 高头是一个 launchd agent，Linux 高头是一个 systemd 用户定时器），每 180 秒跑一趟 `tokenmaxxing check`。

重启侬嗰 shell，然后再添几个账户就好开跑：

```sh
tokenmaxxing add        # 隔离登进多一个账户，再汇拢进池子
claude                  # 照常用 claude
```

`tokenmaxxing` 还有一个别名叫 `xx`。单独嗰 `tokenmaxxing`（或者 `xx`）跑嗰是 `status`；`switch` 一直要写清爽。

## 架构

tokenmaxxing 是一个多重调用嗰入口点（`src/main.ts`）：拿伊用 `claude` 搿个名字调用嗰辰光，伊就充当 `claude` supervisor；通过内部子命令提供 hook 搭 statusline 垫片；其余情况就分派 CLI。伊直接勒 Bun 底下跑；npm 包发嗰是 TypeScript 源码，勿是编译产物。

各个组成部分：

### supervisor 垫片

`init` 会写一个两行嗰 shell 垫片，取名 `claude`，放勒 `~/.config/tokenmaxxing/bin/` 里向，还拿搿个目录摆勒 PATH 顶前头。侬敲 `claude` 嗰辰光，垫片跑起 supervisor，伊拿真嗰 claude 二进制生出来，继承 stdio，还带一份存牢嗰 `stty -g` 终端快照。伊只是一个进程搭终端嗰管理器：从来勿代理 API 流量，也从来勿碰传输当中嗰 token。

打印模式嗰调用（`claude -p`、`--version`、`--help`）、非交互嗰子命令（`claude mcp`、`claude config` 等等），搭 tokenmaxxing 自家嗰探测，侪直接通过，勿做会话管理。碰着交互会话，supervisor 会钉牢一个会话 id（生一个出来，或者复用侬通过 `--session-id` / `-r` / `-c` 传进来嗰埃个），拿侬嗰启动 flag 存牢，畀后头重启嗰辰光好重放，然后盯牢一个跟埃个会话挂钩嗰重生标记文件。

### statusline 分流

Claude Code 每一个回合侪拿限速数据（`rate_limits.five_hour` 搭 `rate_limits.seven_day`）推到 statusline 嗰 stdin 里向。tokenmaxxing 占牢 statusline 搿个位置，所以伊嗰渲染器还兼做一个免费嗰、推送式嗰用量数据源：每一跳伊拿汇总窗口搭当前活跃模型分流到 `usage.json`。分模型嗰上限勿勒 statusline stdin 里向；伊只从 `claude -p '/usage'`（免费、零 token）来，等当前活跃模型受容量限制嗰辰光，伊会带一个 TTL 轮询，缓存到 `model-usage.json` 里向。

分流是变了才写嗰：数字呒没变嗰辰光伊只碰一碰文件嗰 mtime，搿就当作数据源活着嗰心跳。新鲜度一直看 mtime 来判断，从来勿看嵌勒里向嗰时间戳。

### Stop hook 搭切换

每一个回合边界高头，Stop hook 侪跑切换决策（看[切换是哪能决定嗰](#how-switching-decides)）。等一趟切换有必要嗰辰光，伊勒一把 `flock(2)` 独占锁底下发生（通过 `bun:ffi` 拿锁，因为 macOS 呒没带 `flock(1)` 二进制），而且凭据写入还额外搭 Claude Code 自家嗰刷新锁互锁。勒临界区里向，一趟切换会：

1. 拿当前活跃嗰凭据采集到伊真正主人嗰停放备份里向。
2. 拿目标账户刚刷新过嗰凭据装成活跃凭据，合并进现有嗰活跃 blob 里向，畀同伴状态（比方讲每个 MCP server 各自嗰 OAuth token）保得牢。
3. 拿目标嗰轮换过嗰 token 持久化到伊自家嗰备份里向。
4. 原子式地重写 `~/.claude.json` 里向嗰 `oauthAccount` 字段。
5. 提交新嗰活跃标签，还清脱过时嗰用量快照，统统勒锁释放之前做好，搿能够保证崩溃勿会让装好嗰凭据搭活跃标签指向勿一样嗰账户。

因为所有默认 profile 嗰会话侪共用搿一份活跃凭据，一趟切换就一记头拿每个会话侪迁移过去，flock 再加上勒锁底下嗰重新检查，好挡牢竞争嗰 hook 勿去烧脱两个账户。

### 就地采用

跑牢嗰 claude 会话勒两趟请求当中轮询伊嗰凭据存储：macOS 高头伊通过一个短缓存重读 keychain，比对 access token；Linux 高头伊查凭据文件嗰 mtime，一有变化就冲脱伊嗰 token 缓存。总嗰结果是，换脱嗰凭据会畀每个跑牢嗰会话采用，macOS 高头大约 30 秒之内，Linux 高头下一趟请求就采用，勿用啥重启。搿也就是普通切换勿写标记、勿触发重生嗰道理，会话就直接勒新账户高头接牢跑。会话里向嗰 `/usage` 共用同一批 token 缓存，所以伊嗰账户显示会跟牢采用一道翻过去。

### 账户池耗光嗰等待搭自动接续

只有等池子里每个账户侪超过伊嗰各条阈值嗰辰光，Stop hook 才会写一个重生标记（标记嗰 schema 需要一个 `waitUntil` 时间戳；普通切换永远生勿出搿种标记）。supervisor 看到标记，勒早就提交好嗰回合边界高头对伊嗰子进程发 SIGTERM（Stop hook 是勒记录写到磁盘、claude 空下来之后才跑嗰，所以啥也勿会丢），恢复终端，显一个到最早复位嗰倒计时，然后勒恢复过来嗰账户高头重启 `claude --resume <session-id>`。倒计时当中揿 Ctrl-C 就立刻接续。自动等待受 `policy.maxWaitMs`（默认 1 钟头）限牢；超过之后决策会报告池子耗光，勿再等下去。

### 定期检查定时器

Hook 只勒回合边界高头触发，而一个长嗰 agentic 回合好一个边界侪呒没就拿一个窗口从健康烧到耗光。所以 `init` 还装一个定期定时器（macOS 高头是一个 launchd agent，Linux 高头是一个 systemd 用户定时器），勿管回合活动哪能，每 180 秒跑一趟 `tokenmaxxing check`。

### 一个 SessionStart hook

会话起头或者接续嗰辰光跑同一套评估，畀新会话勒对嗰账户高头起头。切换之后嗰冷却让伊勒重生之后立刻变成一个正确嗰空操作。

## 切换是哪能决定嗰 [#how-switching-decides]

决策有两层：一道参与门槛，然后是一条贪心路径或者硬路径。

### 参与

勒 `policy.greedySessionFloor`（默认 50，按 5 钟头会话窗口嗰百分比算）以下，决策根本勿跑，新会话就骑牢伊嗰账户。等当前活跃嗰会话窗口用脱 50%，或者任何一条硬阈值被越过，决策就参与进来。

### 筛选阈值

搿眼阈值是筛选用嗰门槛，勿是拉响警报嗰触发线：

- `thresholds.session`：95。等一个 5 钟头复位代价勿大，所以会话窗口会早眼切换开脱。
- `thresholds.weekly`：98。搿一条阈值同时管 7 天汇总搭每个分模型嗰礼拜上限。礼拜额度是勿用脱就作废嗰，所以伊要用到贴牢墙壁。

两个侪特为定勒 100 以下：搿眼余量是预算，用来勒账户真嗰碰着限额之前先到一个干净嗰回合边界（macOS 高头再加上顶多一个回合嗰采用延迟）。同样嗰阈值也筛选切换候选：一个账户只要超过伊任何一条阈值，就勿是一个有效目标。触发搭筛选一直用同一套有效阈值（阈值减脱 `policy.projectionMargin`），因为一个比触发松嗰筛选会拿切换落到触发立刻又重新标记嗰账户高头，让池子来回乒乓。

### 目标：进度压力

勒能用嗰账户当中，目标是自家礼拜进度落后顶多嗰埃只：**进度压力**顶高嗰，进度压力定义成礼拜剩余百分比除脱到埃只账户礼拜复位为止嗰辰光。快要作废嗰额度顶多嗰埃只账户胜出。碰着相等，就先拣礼拜到期顶早嗰，再拣 7 天用量顶少嗰。

一切侪跑勒缓存嗰窗口高头，搿眼窗口存成绝对嗰 UTC 纪元时间，所以一份过时嗰快照照样解得正确：一个已经过脱嗰礼拜复位会按整整 7 天嗰步长往前推，任何过脱伊缓存复位嗰窗口侪算成刚刚空脱（永远勿是切换嗰理由，也永远勿是拿一个账户按牢勿用嗰理由）。

### 贪心路径搭硬路径嗰对比

- **贪心路径**（已经参与，不过还勒每条阈值底下）：拿每个账户侪排名次，包括当前嗰。假使当前账户已经胜出或者打平，就啥也勿做。否则就切换到严格更好嗰埃只账户高头。伊从来勿等，也从来勿预先停放，一个能用嗰当前账户勿会拿去换一场等待。因为当前账户也一道排名次，自动路径搭单独嗰 `tokenmaxxing switch` 侪是幂等嗰：定期评估会收敛到对嗰账户高头，然后就勿动脱。
- **硬路径**（一条阈值被越过）：切换开脱，去到最好嗰能用候选。假使一个候选嗰刷新 token 原来已经死脱，伊就被标成需要重新认证，再试下一个候选。假使呒没啥好用，就跑耗光等待嗰逻辑；只有一个真嗰好暂停会话嗰调用方（受监管嗰 Stop hook）才允许预先停放到一个还封牢、不过恢复顶早嗰账户高头。

### 分模型上限

`policy.switchModels`（默认 `["fable"]`）指明哪几个模型系列嗰分模型礼拜上限好触发切换。匹配是按系列标记来嗰，从来勿按精确嗰显示字符串：模型嗰显示名字会漂移（`Fable` 变成过 `Fable 5`），而且一道精确字符串嗰门一趟曾经悄悄拿分模型切换整个禁脱。两条相关嗰安全规则：

- 候选筛选也算进设了门嗰分模型上限，所以一个每个账户侪烧脱 Fable 上限嗰池子勿会去轮转。

### 冷却

一道切换之后 45 秒嗰冷却给自动路径设门。切换之后同样 45 秒里向 statusline 分流会被压牢（采用勒 macOS 高头顶多要 30 秒），否则早眼嗰评估会跑勒切换自家弄失效嗰数据高头，搿种情况曾经产生过一个 A 到 B 又转 B 到 A 嗰重生死循环。手动嗰 `tokenmaxxing switch` 勿受冷却影响。

## 配置

配置是 `~/.config/tokenmaxxing/config.json` 高头嗰 JSON。每个字段侪是可选嗰；默认值一个字段一个字段生效。

```json
{
  "thresholds": { "session": 95, "weekly": 98 },
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 50,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000

}
```

- `thresholds.session` / `thresholds.weekly`：上头讲过嗰筛选阈值。
- `policy.projectionMargin`：从两条阈值里向减脱，得出有效阈值。
- `policy.greedySessionFloor`：贪心收敛开始参与嗰会话已用百分比。
- `policy.switchModels`：哪几个模型系列嗰分模型礼拜上限会给切换设门（条目加载嗰辰光会转成小写）。
- `policy.usagePollTtlMs`：一趟 `/usage` 分模型轮询保持新鲜多少辰光。
- `policy.maxWaitMs`：耗光池子自动等待嗰上限。

`tokenmaxxing config` 显示带来源嗰有效配置；`config set`/`unset` 编辑带点嗰键；`config tidy` 剪脱勿认得嗰键。

## 凭据存储搭安全模型

所有状态侪勒 `~/.config/tokenmaxxing/` 里向。凭据 I/O 走一个单一嗰、按平台拣好嗰存储门面；调用点从来勿按平台分支。

**macOS**：凭据当作 generic-password 条目存勒登录 keychain 里向，搭 Claude Code 自家存嗰地方对得牢。活跃条目就是 claude 读嗰埃个；池子里每个账户嗰备份各自当作一个 `tokenmaxxing-cred-<uuid8>` keychain 条目停放。磁盘高头呒没啥明文。读用 `security find-generic-password -w`（秘密只会出现勒 stdout 高头）；写是拿一条 `add-generic-password` 通过 stdin 管进 `security -i`，所以秘密从来勿会出现勒任何进程嗰 argv 里向。交互模式有一个大约 4 KB 嗰行缓冲，所以超大嗰 blob 会退回到 argv 写入，搿也是停放条目只存最小 OAuth 对象嗰一个道理。

**Linux**：Claude Code 拿凭据存成一个 0600 嗰明文文件，tokenmaxxing 也照同一套模型走：活跃文件是 claude 自家嗰 `.credentials.json`，停放备份是 `~/.config/tokenmaxxing/creds/` 底下一个 0700 目录里向嗰原子 0600 文件。搿搭嗰原子意思是先写临时文件、fsync、再改名字：一个并发嗰读者一直看到嗰要么是整份旧文件、要么是整份新文件，从来勿会是残缺嗰。

切换强制执行嗰安全规则：

- **按真正主人采集。** 切换之前，活跃凭据实际嗰主人是通过问 API 搿个 token 属于啥个组织来定嗰（对 OAuth roles 端点跑 `fetchTokenOrg`），从来勿去相信存牢嗰活跃标签，因为标签会漂移。一趟漂移嗰标签曾经害得一个账户嗰采集覆盖脱另外一个账户唯一嗰备份。假使活跃凭据属于池子外头嗰一个账户，切换会直接拒绝，勿去覆盖伊。
- **一个临界区。** 采集、装新凭据、备份伊轮换过嗰 token、`~/.claude.json` 账户切换、搭活跃标签嗰提交，统统勒同一个锁牢嗰区块里向发生。
- **搭 claude 自家嗰刷新互锁。** 一个快过期嗰会话随便啥辰光侪好轮换伊自家嗰 token，所以凭据写入也拿 Claude Code 嗰刷新锁（尽力而为，带一个过时锁嗰回收搭一个有界超时）。
- **死授权干净降级。** 一趟刷新假使回来是 `invalid_grant`，就拿埃个账户标成需要重新认证，还勒错误传播之前拿搿个标记持久化好，所以重试循环会缩小候选集合、然后终止。`tokenmaxxing auth` 就地修好一个被标嗰账户，而且伊会拒绝一个落到跟要修嗰账户勿一样嗰账户高头嗰登录。
- **勿记录 token。** token 从来勿会出现勒日志、错误或者输出里向。从 token 搭用量端点来嗰错误主体从来勿会原样露出来；只有一组白名单里嗰字段保得下来，因为一个 token 端点嗰失败主体好回显请求材料。
- **探测卫生。** 任何生出来嗰 `claude` 探测侪会擦脱 claude 勒 keychain 查询之前会认嗰八个环境变量（`ANTHROPIC_API_KEY`、`CLAUDE_CODE_OAUTH_TOKEN`、`CLAUDE_SECURESTORAGE_CONFIG_DIR` 等等），所以一趟探测永远勿会被算到勿对嗰账户高头。

| | macOS | Linux |

## statusline

tokenmaxxing 原生渲染 Claude Code 嗰 statusline（一面还分流用量数据源）。设计原则是：额度用颜色来带，勿用数字。一行头，比方讲：

```

```

- 每一个窗口标记是伊到复位嗰辰光，按已用百分比涂勒一条从绿到黄到红嗰连续渐变高头（终端支持嗰辰光用真彩色，否则就阶梯落到 256 色立方体高头）。渐变锚勒 0 是纯绿、75 是黄、95 搭以上是红，所以老嗰严重程度分档当作渐变锚点保下来。
- 模型名字按上下文窗口填充程度涂勒同一条渐变高头。
- 一个绿嗰 `◆` 领头带出当前活跃账户嗰窗口；每个停放账户侪有自家嗰青色 `◇`（假使需要重新认证就是红嗰 `✗`）。账户按最早快要复位嗰辰光排序。
- 分模型勒每一块里向排最前头，当作一个光秃嗰涂色首字母：Fable 渲染成 `𝒇`；其余系列用伊大写嗰首字母，一直按系列匹配。
- 一个没动过嗰停放账户渲染成一个绿嗰 `full`。有测到用量、不过复位辰光勿晓得嗰，渲染成一个涂色嗰 `?`；一个设了门嗰模型高头呒没测到嗰分模型上限，渲染成一个勿涂色嗰 `𝒇?`，呒没测到嗰绝对勿好看起来安全。
- 复位倒计时只显最大嗰单位，从来勿显 `now` 或者 `0m`；一个呒没快要复位嗰窗口渲染成一个绿嗰 `0`（又空脱类）。
- 一个链接嗰 git worktree 嗰基名领头带出搿一行；一个主检出勒埃搭啥也勿渲染。搿个检测是读文件系统里向嗰一个 `.git` 文件来做嗰，从来勿生一个 git 子进程。
- 设了 `NO_COLOR` 嗰辰光，搿一行退回到一个粘牢嗰数字格式（`2h5` 意思是 2 钟头之内复位、用脱 5%；`ctx 42` 表示上下文填充）；呒没颜色嗰辰光，一个耗光嗰窗口勿好看起来新鲜。

子 agent 任务通过 claude 嗰 subagentStatusLine 界面拿到自家嗰面板行：每个活跃任务一行，系列名字按埃个任务嗰上下文填充涂色。

一个跑牢嗰 codex 进程握牢一个内存里嗰 auth manager，等 `auth.json` 现在指嗰是另外一个账户嗰辰光，伊明确拒绝重新加载。呒没文件监视器，也呒没每趟请求嗰凭据轮询，所以勒一个跑牢嗰 codex 底下换脱嗰凭据，对推理来讲根本永远勿生效。重启就是切换：`codex resume <session-id>` 会勒 `auth.json` 现在拿牢嗰随便啥账户高头接牢本地记录跑。

- 用量是从对 codex 自家限速端点嗰一趟免费认证 GET 读来嗰（搭 CLI 嗰 `/status` 发嗰是同一个调用）：百分比再加上绝对嗰纪元复位辰光，汇总窗口搭分模型上限一样对待。窗口分类是按时长驱动嗰，从来勿按位置驱动，因为现在嗰套餐可能根本呒没 5 钟头窗口，而礼拜窗口坐勒主槽位高头。
- Codex 嗰刷新 token 会轮换，重用一个被替换脱嗰会拿整个授权家族弄死。每一趟轮换一回来就立刻持久化，当前活跃账户永远只通过活跃 blob 来采样（从来勿用一份过时嗰停放副本），而且每个会话嗰在场文件保证一个勒活跃同伴会话里向跑牢嗰账户永远勿是切换目标、也永远勿会拿伊嗰停放 token 去刷新。

- 有一步手工活：codex 会跳过呒没被告知去信任嗰 hook。`init --codex` 之后，开一趟 codex，通过 `/hooks` 信任 tokenmaxxing 嗰 Stop hook，否则自动切换会悄悄躺牢勿动。`init --codex` 会打印搿条提醒。

## Agent SDK 界面

- `pooledOptions()` 拿 `pathToClaudeCodeExecutable` 钉牢真嗰 claude 二进制（从来勿是 supervisor 包装器），还提供一份完整替换嗰 `env`，里向每一个环境里嗰凭据覆盖侪擦脱。假使侬 app 嗰环境里向设了 `CLAUDE_CONFIG_DIR` 或者 `CLAUDE_SECURESTORAGE_CONFIG_DIR`，伊会快速失败：勒 Linux 高头，一趟切换会拿活跃凭据写到搿两个变量指嗰地方，而擦干净嗰子进程读嗰是默认存储，搿是一个悄悄嗰错账户失步。
