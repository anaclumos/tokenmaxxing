tokenmaxxing 原生渲染 Claude Code 嗰 statusline（一面还分流用量数据源）。设计原则是：额度用颜色带，勿用数字。一行头，比方讲：

```
tm-wt-demo Fable 5 (high) +156/-23  ◆ 𝒇 2h 1d  ◇ 19h  ◇ 𝒇 2d  ◇ full  ✗ ?
```

- 每个窗口标记就是伊到复位嗰辰光，按已用百分比涂勒一条从绿到黄到红嗰连续渐变高头（终端支持嗰辰光用真彩色，否则就阶梯落到 256 色立方体高头）。渐变锚勒 0 是纯绿、75 是黄、95 搭以上是红，所以老嗰严重程度分档当作渐变锚点保下来。
- 模型名字按上下文窗口填充程度涂勒同一条渐变高头。
- 绿嗰 `◆` 领头带出当前活跃账户嗰窗口；每个停放账户侪有自家嗰青色 `◇`（假使需要重新认证就是红嗰 `✗`）。账户按最早快要复位嗰辰光排序。
- 分模型勒每块里向排最前头，当作光秃嗰涂色首字母：Fable 渲染成 `𝒇`；其余系列用大写嗰首字母，总归按系列匹配。
- 呒没动过嗰停放账户渲染成绿嗰 `full`。有测到用量、不过复位辰光勿晓得嗰，渲染成涂色嗰 `?`；设了门嗰模型高头呒没测到嗰分模型上限，渲染成勿涂色嗰 `𝒇?`，呒没测到嗰绝对勿好看上去安全。
- 复位倒计时只显最大嗰单位，从来勿显 `now` 或者 `0m`；呒没快要复位嗰窗口渲染成绿嗰 `0`（又空脱类）。
- 链接嗰 git worktree 嗰基名领头带出搿一行；主检出勒埃搭啥也勿渲染。搿个检测读文件系统里向嗰 `.git` 文件，从来勿开 git 子进程。
- 设了 `NO_COLOR` 嗰辰光，搿一行退回到粘牢嗰数字格式（`2h5` 意思是 2 钟头之内复位、用脱 5%；`ctx 42` 表示上下文填充）；呒没颜色嗰辰光，耗光嗰窗口勿好看上去新鲜。

子 agent 任务从 claude 嗰 subagentStatusLine 界面拿到自家嗰面板行：每个活跃任务一行，系列名字按埃个任务嗰上下文填充涂色。
