---
title: "Замечания по платформам: macOS против Linux"
description: "Чем macOS и Linux различаются в хранении, принятии и таймерах"
---

| | macOS | Linux |
|---|---|---|
| Активные учётные данные | Элемент generic-password в login keychain | Файл `.credentials.json` с правами 0600 |
| Припаркованные учётные данные | Элементы keychain для каждого аккаунта | Файлы 0600 в каталоге 0700 |
| Принятие после переключения | В течение ~30 секунд (кэш чтения keychain) | Следующий запрос (опрос mtime файла) |
| Периодическая проверка | Агент launchd, базовый такт 60с, свой темп от 60с до 300с | Пользовательский таймер systemd, базовый такт 60с, свой темп от 60с до 300с |
| Хранилище изолированного входа | Служба keychain с хешированным пространством имён для каждого каталога конфигурации | Файл внутри изолированного каталога конфигурации |

Две специфичные для Linux детали, которые стоит знать: claude определяет свой каталог учётных данных сначала из `CLAUDE_SECURESTORAGE_CONFIG_DIR` (затем `CLAUDE_CONFIG_DIR`, затем `~/.claude`), и tokenmaxxing в точности повторяет это разрешение, чтобы они никогда не рассинхронизировались. И две сборки одной и той же версии claude под разные ОС форматируют время сброса в `/usage` по-разному (одна использует связку " at ", другая - запятую); парсер tokenmaxxing принимает ровно эти две формы и логирует, а не угадывает, при любой третьей.

На macOS есть одно честное ограничение: `init` и `add` намеренно обращаются к keychain интерактивно, чтобы первый доступ `security` не был холодным внутри безголового хука.
