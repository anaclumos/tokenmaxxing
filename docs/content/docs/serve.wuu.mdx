`tokenmaxxing serve` 用 Socket Mode 跑只本地 Slack 守护进程，勿需要公开 URL。设置：

```sh
tokenmaxxing serve setup                    # 打印 app manifest，提示输入两个 token
tokenmaxxing serve link <channel-id> <repo> # 拿一个频道绑到一个仓库检出高头
tokenmaxxing serve                          # 跑守护进程
```

勒链接过嗰频道里向 @ 一记 bot，伊就畀搿条 thread 勒链接嗰仓库检出里向开只 Claude Code 会话。每一条 thread 消息照旧跑一趟带 `resume` 嗰 Agent SDK `query()`，所以 `ensureBestAccount()` 勒每一个回合侪会重新评估池子，守护进程也好重启，勿会丢脱 thread（thread 记录是持久嗰；守护进程勒启动嗰辰光重新订阅伊拉），不过每一趟 query 侪收流式输入，搿就是一条回复好牵引牢正勒跑嗰回合嗰原因。

值得一讲嗰行为：

- **引导**：一条回复要是勒搿条 thread 嗰回合还勒跑嗰辰光到脱，就会折进搿个回合里向，搭 Claude Code 交互嗰辰光用嗰回合中途插入是一样嗰道理，所以模型会勒伊下一趟工具边界高头看到伊，然后调整方向，勿会先把错嗰事体做完。一条回复要是勒回合最后一趟工具调用之后到，就会紧接牢当一个自家嗰回合跑；两样情形侪勿会丢脱啥。被引导嗰消息会带牢沙漏回应，搭回合一道收场，伊拉嗰文字也搭牢回合嗰持久标记走，所以重启搭用量限额自动恢复侪会重放伊。只有排勒别嗰等候消息后头嗰消息才会跳过折进（顺序还是保牢嗰），排空中嗰守护进程照旧大声丢脱，勿会去引导。
- **流式**：回复原生流进 Slack，带思考搭工具运行嗰任务卡片，围栏代码带高亮渲染，收尾嗰 `Turn` 卡片带成本搭时长；一个回合嗰卡片侪会折叠成一只好展开嗰计划块，所以一个回合平常读起来是一条消息：回复搭一只伊嗰活动下拉框（回合中途嗰重试或者被拒脱嗰追加会开一条后续消息）。TodoWrite 调用会就地更新一张稳定嗰清单卡片。
- **权限**：每条链接嗰 `permissionMode` 默认是 `acceptEdits`；`--yolo`（别名 `--dangerous`）畀一条链接选进 `bypassPermissions`。交互对话框勒转发嗰回合里向勿允许，因为呒没人好勒 Slack 高头回答伊，所以模型用文字问，侬勒 thread 里嗰回复就是下一个回合。一个捆牢嗰插件 skill 教伊勒要做决定嗰辰光 @ 请求嗰人，然后结束回合。
- **状态回应**：触发一个回合嗰搿条消息会用 emoji 回应带牢伊嗰状态：回合跑嗰辰光是只沙漏，然后是勾（做好类）、叉（失败类）或者问号（模型要侬做决定）。需要当前 manifest 里嗰 `reactions:write` 权限；已经装好嗰 app 要重新贴一趟 manifest 再重新安装。
- **提醒搭催一记**：模型要问侬讨决定嗰辰光，伊会调用一个进程内嗰 `need_attention` 工具，搿能守护进程就晓得搿条 thread 正勒等侬。侬要是 10 分钟呒没声音，伊就勒 thread 里向 @ 侬一趟。thread 正勒等嗰辰光，对搿个问题加回应就当作侬嗰回答转发过去（点个赞就是选推荐嗰选项）；侬勒跟踪嗰 thread 里加嗰别嗰回应侪会折进下一个回合当作上下文。需要 `reactions:read` 搭 `reaction_added` 事件。
- **斜杠命令**：一条 thread 消息，剥脱之后嗰文字要是用 `/` 开头，就当作 claude 斜杠命令跑。Slack 嗰输入框会吃脱用 `/` 开头嗰消息，所以要用 @ 在前头嗰形式（`@bot /usage`）或者前头加个空格。
- **用量限额自动恢复**：等池子里向嗰账户侪到限额嗰辰光，短辰光嗰中断会把消息搁牢，原地重试；长辰光嗰中断会发一条等候通知，等池子恢复过来之后自动接牢回合，守护进程重启也保得牢。只有寻勿着恢复辰光嗰限额才会问侬重新发一趟。
- **优雅关闭**：SIGTERM/SIGINT 会排空，新嗰回合会大声丢脱，正勒跑嗰回合最多给 5 分钟，而 claude 子进程勒伊自家嗰进程组里向脱离运行，畀终端嗰 Ctrl-C 勿好勒排空保住回合之前先拿伊杀脱。
- **Thread 清理**：等侬告诉伊活干好类，模型会调用一个进程内嗰 `finish_thread` 工具；等回合完全结束之后，守护进程拿 thread 记录删脱、取消订阅、还发一条确认。一趟新嗰 @ 会起头一个新会话。
- **错误卫生**：回合错误发嗰是修剪过嗰、只有消息嗰文字，从来勿是原始嗰错误主体。
