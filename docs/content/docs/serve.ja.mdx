---
title: "Slack ブリッジ: xx serve"
description: "xx serve は Socket Mode 上で Slack のスレッドから Claude Code セッションを実行する"
---

`tokenmaxxing serve` は Socket Mode 上でローカルの Slack デーモンを実行します。公開 URL は不要です。セットアップ:

```sh
tokenmaxxing serve setup                    # アプリマニフェストを表示し、2つのトークンの入力を求める
tokenmaxxing serve link <channel-id> <repo> # チャンネルをリポジトリのチェックアウトに紐づける
tokenmaxxing serve                          # デーモンを実行する
```

リンクされたチャンネルでボットにメンションすると、そのスレッド用に、リンクされたリポジトリのチェックアウト内で Claude Code セッションを開きます。すべてのスレッドメッセージは `resume` 付きの1回の Agent SDK `query()` を実行し (持続的なストリーミングクエリではありません)、そのため `ensureBestAccount()` が毎ターンごとにプールを再評価し、デーモンはスレッドを失うことなく再起動できます (スレッドレコードは永続的で、デーモンは起動時にそれらを再購読します)。

注目すべき挙動:

- **ストリーミング**: 返信は思考とツール実行のためのタスクカード、ハイライト付きで描画されるフェンス付きコード、コストと所要時間を含む締めの「Turn」カードとともに Slack へネイティブにストリームされ、ツール実行がストリームされたテキストを中断するたびに新しい Slack メッセージが開かれるため、1つのターンがツール実行の周りで別々のメッセージとして読めます。TodoWrite の呼び出しは1つの安定したチェックリストカードをその場で更新します。
- **権限**: リンクごとの `permissionMode` はデフォルトで `acceptEdits` です。`--yolo` (エイリアス `--dangerous`) はリンクを `bypassPermissions` にオプトインします。対話ダイアログはリレーされたターンでは許可されません。Slack を通じて誰も答えられないためです。そのためモデルは散文で尋ね、あなたのスレッド返信が次のターンになります。同梱のプラグインスキルが、判断が必要なときにリクエスト元をタグ付けしてターンを終える方法を教えます。
- **スラッシュコマンド**: メンションを除いたテキストが `/` で始まるスレッドメッセージは、claude のスラッシュコマンドとして実行されます。Slack のコンポーザーは `/` で始まるメッセージを飲み込むため、メンション優先の形式 (`@bot /usage`) または先頭スペースを使ってください。
- **グレースフルシャットダウン**: SIGTERM/SIGINT はドレインします。新しいターンは声高にドロップされ、進行中のターンには最大5分が与えられ、claude の子プロセスは独自のプロセスグループで detached で動作するため、端末の Ctrl-C がドレインによってターンが保全される前に子プロセスを殺すことはできません。
- **スレッドのクリーンアップ**: 作業が完了したと伝えると、モデルはインプロセスの `finish_thread` ツールを呼びます。ターンが完全に終わった後、デーモンはスレッドレコードを削除し、購読を解除し、確認を1つ投稿します。新しいメンションが新しいセッションを開始します。
- **エラーの衛生**: ターンエラーは、生のエラー本文ではなく、切り詰めたメッセージのみのテキストを投稿します。
