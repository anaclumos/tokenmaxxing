title: การ build และการเผยแพร่
description: "ซอร์ส TypeScript บน npm และ Nix รันด้วย Bun เผยแพร่พร้อม provenance"
---

แพ็กเกจ npm เผยแพร่ซอร์ส TypeScript ไม่ใช่ไฟล์ที่ build แล้ว: bin `tokenmaxxing` ชี้ตรงไปที่ `src/main.ts` ด้วย Bun shebang และ Bun 1.2.6 หรือใหม่กว่าจะรันมันได้เลย นั่นคือเหตุผลที่ Bun เป็นข้อกำหนดที่ต้องมี ไม่มีไบนารีที่คอมไพล์แล้วโดยตั้งใจ: รุ่นแรกๆ เคยเผยแพร่ไบนารี macOS ขนาด 61 MB ไฟล์เดียวไปยังทุกแพลตฟอร์ม และล้มเหลวบน Linux ด้วย `exec format error` อีกทั้งแพ็กเกจที่คอมไพล์แยกตามแพลตฟอร์มก็ต้องมี release pipeline ของตัวเองแต่ละอัน การรันซอร์สด้วย Bun จึงกลายเป็นโมเดลการเผยแพร่

แมป `exports` ของแพ็กเกจเปิดเผย `src/sdk.ts` เป็นจุดเข้าเชิงโปรแกรมตามที่อธิบายไว้ใน [หน้าตาของ Agent SDK](/th/sdk) รุ่นต่างๆ ถูกแท็กเป็น `v<version>` บน GitHub; CI เผยแพร่ไปยัง npm ผ่าน trusted publishing (OIDC พร้อม provenance) และด่านตรวจก่อนเผยแพร่จะรัน typecheck ก่อน

## Nix / nix-darwin

ต้นไม้ซอร์สชุดเดียวกันยังเป็น flake ด้วย ยังคงโมเดลรันซอร์สด้วย Bun (ผ่าน [bun2nix](https://github.com/nix-community/bun2nix) `writeBunApplication`) และเปิดเผย:

| เอาต์พุต | วัตถุประสงค์ |
|---|---|
| `packages.default` | `tokenmaxxing` + `xx` บน PATH |
| `darwinModules.default` / `withOverlay` | nix-darwin: ติดตั้ง CLI (ตัวจับเวลาตรวจสอบแบบ declarative แบบเลือกได้) |
| `homeManagerModules.default` | Home Manager บน macOS หรือ Linux |
| `nixosModules.default` / `withOverlay` | ติดตั้งระดับระบบบน NixOS |

รันครั้งเดียวโดยไม่ติดตั้งลงโปรไฟล์:

```sh
nix run github:anaclumos/tokenmaxxing -- help
```

nix-darwin (เพิ่ม overlay เพื่อให้ `pkgs.tokenmaxxing` resolve ได้):

```nix
{
  inputs.tokenmaxxing.url = "github:anaclumos/tokenmaxxing";
  modules = [
    inputs.tokenmaxxing.darwinModules.withOverlay
    { programs.tokenmaxxing.enable = true; }
  ];
}
```

หรือตั้งแพ็กเกจแบบชัดเจน (ใช้กับ Home Manager ได้ด้วย):

```nix
{
  imports = [ inputs.tokenmaxxing.homeManagerModules.default ];
  programs.tokenmaxxing.enable = true;
  programs.tokenmaxxing.package = inputs.tokenmaxxing.packages.${pkgs.system}.default;
}
```

Nix ใส่แค่ CLI บน PATH การนำเข้าบัญชี, shim supervisor `claude` บน PATH, hook ใน `settings.json` และ (โดยค่าเริ่มต้น) ตัวจับเวลาตรวจสอบเป็นระยะ ยังมาจาก `tokenmaxxing init` — สิ่งเหล่านี้แตะข้อมูลรับรองและการตั้งค่าที่เป็นของยูสเซอร์ ซึ่งโมดูลแบบ pure ไม่ควรเขียนทับ ตั้ง `programs.tokenmaxxing.checkTimer.enable = true` เฉพาะเมื่อต้องการให้ Nix เป็นเจ้าของตัวจับเวลาแทน init

เมื่อ `bun.lock` เปลี่ยน ให้สร้างนิพจน์ dependency ของ Nix ใหม่:

```sh
bun run nix:bun   # writes bun.nix via bun2nix
```
