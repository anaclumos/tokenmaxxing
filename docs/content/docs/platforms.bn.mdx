title: "প্ল্যাটফর্ম নোট: macOS বনাম Linux"
description: "স্টোরেজ, গ্রহণ, এবং টাইমারে macOS ও Linux কীভাবে ভিন্ন"
---

| | macOS | Linux |
|---|---|---|
| লাইভ ক্রেডেনশিয়াল | লগইন কীচেইন জেনেরিক-পাসওয়ার্ড আইটেম | 0600 `.credentials.json` ফাইল |
| পার্ক করা ক্রেডেনশিয়াল | প্রতি-অ্যাকাউন্ট কীচেইন আইটেম | 0700 ডিরেক্টরিতে 0600 ফাইল |
| বদলের পরে গ্রহণ | ~30 সেকেন্ডের মধ্যে (কীচেইন রিড ক্যাশ) | পরবর্তী অনুরোধ (ফাইল mtime পোল) |
| পর্যায়ক্রমিক চেক | launchd এজেন্ট, `policy.checkIntervalMs` ফ্লোর টিক (ডিফল্ট 60s), স্ব-নিয়ন্ত্রিত এক থেকে পাঁচ টিক | systemd ইউজার টাইমার, `policy.checkIntervalMs` ফ্লোর টিক (ডিফল্ট 60s), স্ব-নিয়ন্ত্রিত এক থেকে পাঁচ টিক |
| বিচ্ছিন্ন-লগইন স্টোর | প্রতি কনফিগ ডিরেক্টরিতে হ্যাশ-নেমস্পেসড কীচেইন সার্ভিস | বিচ্ছিন্ন কনফিগ ডিরেক্টরির ভেতরে একটি ফাইল |

জানার মতো দুটি Linux-নির্দিষ্ট বিবরণ: claude তার ক্রেডেনশিয়াল ডিরেক্টরি প্রথমে `CLAUDE_SECURESTORAGE_CONFIG_DIR` থেকে নির্ধারণ করে (তারপর `CLAUDE_CONFIG_DIR`, তারপর `~/.claude`), এবং tokenmaxxing সেই নির্ধারণ হুবহু অনুকরণ করে যাতে দুটি কখনো ডিসিঙ্ক না হয়। আর একই claude সংস্করণের দুটি OS বিল্ড `/usage` রিসেট ঘড়ি ভিন্নভাবে ফরম্যাট করে (একটি " at " জোড়া ব্যবহার করে, অন্যটি একটি কমা); tokenmaxxing-এর পার্সার ঠিক এই দুটি রূপ গ্রহণ করে এবং তৃতীয় যেকোনো কিছুতে অনুমানের পরিবর্তে লগ করে।

macOS-এ, একটি সৎ সীমাবদ্ধতা: `init` এবং `add` ইচ্ছাকৃতভাবে ইন্টারঅ্যাক্টিভভাবে কীচেইন স্পর্শ করে, যাতে প্রথম `security` অ্যাক্সেস একটি হেডলেস হুকের ভেতরে ঠান্ডা না থাকে।
