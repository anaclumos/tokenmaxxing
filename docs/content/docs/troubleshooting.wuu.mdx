**`claude` 看上去呒没被监管牢。**
跑 `tokenmaxxing doctor`。垫片必须勒 PATH 解析里向胜出；检查一记侬 shell rc 里向嗰 `# tokenmaxxing PATH` 埃一行有勿有指向当前嗰 bin 目录、还排勒真嗰 claude 前头。`doctor` 还会对 `alias claude=...` 或者一个 `claude()` shell 函数遮牢包装器发警告，也会对用绝对路径启动一个 claude 二进制嗰别名发警告（搿眼会完全绕过 supervisor）。

**Codex 高头自动切换从来勿触发。**
Codex 会跳过呒没被告知去信任嗰 hook。开 codex，跑 `/hooks`，信任 tokenmaxxing 嗰 Stop hook。信任是对牢 hook 嗰哈希记嗰，所以 hook 万一被改过，就必须重新授一趟。

**一个账户勒 statusline 里向显一个红嗰 `✗`。**
伊嗰刷新 token 死脱类（被吊销，或者勒备份底下被轮换脱）。跑 `tokenmaxxing auth <sel>` 拿伊就地重新认证；搿条命令会告诉侬用啥个邮箱登进，还会拒绝一个落到勿一样账户高头嗰登录。

**为啥伊勿切换到剩余额度顶多嗰账户？**
因为埃个勿是最有可能作废额度嗰账户。目标是自家礼拜进度落后顶多嗰账户：剩余百分比除脱到伊礼拜复位嗰辰光。剩余数量相等嗰辰光，搿就化成先拣到期顶早嗰；到期也相等嗰辰光，就化成先拣剩余顶多嗰。

**伊刚切换过，statusline 还显老账户。**
勒 macOS 高头顶多 30 秒之内是预期之内嗰：跑牢嗰会话勒伊下一趟凭据缓存刷新嗰辰光采用换脱嗰凭据。用量分流勒切换之后压牢 45 秒，就是为了搿个道理。

**`status --force` 会勿会花啥代价？**
会嗰，是特为嗰：伊每个账户发一趟极小嗰计量 haiku 请求，畀每个 5 钟头会话窗口勒埃一刻就起头，勿再躺牢勿动，然后重新采样。普通嗰 `status` 搭 `watch` 从来勿 ping；`/usage` 读是免费嗰。注意服务端嗰用量数据源好比一个刚开嗰窗口滞后几秒到几分钟，所以 ping 之后立刻探测可能还显 ping 之前嗰状态，`status` 会渲染一条说明，勿去假装 ping 失败脱。

**`/usage` 探测对当前活跃账户啥也呒没返回。**
搿是一个已知嗰 claude 行为：等伊内部嗰用量抓取失败或者被限速嗰辰光，`/usage` 只打印本地会话统计，呒没百分比行。tokenmaxxing 从 statusline 推送来采样当前活跃账户，只探测停放账户，就正是为了避开搿桩事体。

**后台 claude 会话。**
Claude 嗰后台守护进程用绝对路径生真嗰带版本嗰二进制，绕过 PATH 垫片，所以后台会话是呒没监管嗰。Hook 照样通过 `settings.json` 触发，凭据采用再加上定期定时器能盖到切换，不过伊拉呒没标记驱动嗰重生。

**有一趟啥物事生出来老许多进程。搿现在还可能发生𠮿？**
supervisor 带一层一层嗰递归防护，就是针对搿个历史故障嗰（一个过时嗰包装器被钉成所谓嗰真 claude）：环境里向一个深度哨兵，到 5 层就中止；一个磁盘高头嗰生进程速率限制器；realpath 身份检查，拒绝任何解析回 tokenmaxxing 自家 bin 目录嗰候选；还有等一个配置好嗰 claude 路径勿再存在嗰辰光就硬失败（从来勿是一趟悄悄嗰 PATH 扫描）。`init` 搭 `doctor` 勒钉一个候选之前会跑 `--version` 核实伊确确实实是 claude。

**卸载。**
`tokenmaxxing uninstall` 拿 supervisor 垫片、设置条目、搭定期定时器删脱，让侬嗰账户搭停放凭据原封不动。伊只删脱伊认得是自家嗰 statusline 条目。
