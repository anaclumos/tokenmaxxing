description: "config.json سکیما، ٹھریش ہولڈ، تے پالیسی نوب"
---

Config `~/.config/tokenmaxxing/config.json` تے JSON اے۔ ہر فیلڈ اختیاری اے؛ طے شدہ قدراں فی فیلڈ لاگو ہندیاں نیں۔

```json
{
  "thresholds": { "session": [90], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 80,
    "greedySwapMargin": 0.15,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000,
    "checkIntervalMs": 60000
  }
}
```

- `thresholds.session`: 5 گھنٹے والی پوڑھی، چڑھدی ترتیب وچ چھانٹی ڈنڈیاں دی اک لسٹ۔ ہر پرکھ اک چالو ڈنڈا چُندی اے، سب توں تھلا اوہ ڈنڈا جِتھے پول دا کوئی اکاؤنٹ ہالی ورتن جوگا ہووے، تے اوہو ڈنڈا ٹریگر وی اے تے اُمیدواراں دی چھانٹی وی۔ Codex صرف سب توں اُتلا ڈنڈا پڑھدا اے۔ ویکھو [سوئچنگ کویں فیصلہ کردی اے](/pnb/switching)۔
- `thresholds.weekly`: ہفتہ وار چھانٹی بار، جیہڑی 7 دن دے کُل جوڑ تے ہر فی ماڈل ہفتہ وار حد نوں ڈھکدی اے۔
- `hardThresholds.session` / `hardThresholds.weekly`: کندھ باراں (طے شدہ 100، ہر اکاؤنٹ دی اصل سرور حد)۔ `hardThresholds.session` نوں سب توں اُتلے سیشن ڈنڈے تے یا اوہدے توں اُتے ہونا چاہیدا اے۔ جدوں ہر اکاؤنٹ اپنی چھانٹی بار توں اُتے ہووے، تاں خودکار Claude فیصلہ پارک کرن توں پہلاں ہر اک نوں اوہدی کندھ تیک نچوڑدا اے - ویکھو [کندھ](/pnb/switching)۔ بند کرن لئی ایہنوں سب توں اُتلے ڈنڈے تے ہفتہ وار بار دے برابر رکھو؛ Codex ایہہ ترتیب نظرانداز کردا اے۔
- `claudeBin` / `codexBin`: اصل بائنریاں تے پن کردا اے جنہاں نوں سُپروائزر چلاندے نیں (`init` / `init --codex` نال لکھیا جاندا اے؛ ری کرشن-گارڈ تشخیصی پیغام تُہانوں ایتھے `claudeBin` ٹھیک کرن نوں آکھدا اے جدوں ایہہ اصل Claude بائنری ول اشارہ کرنا بند کر دیندی اے)۔
- `policy.projectionMargin`: اثردار باراں بنان لئی ہر سیشن ڈنڈے، ہفتہ وار بار، تے کندھ باراں وچوں گھٹایا جاندا اے۔
- `policy.greedySessionFloor`: سیشن ورتوں فیصد جِتھے لالچی اکٹھ چالو ہندا اے۔
- `policy.greedySwapMargin`: لالچی راہ تے موجودہ اکاؤنٹ لئی ہسٹیریسس، 0 توں 1 وچکار اک حصہ (طے شدہ 0.15)۔ موجودہ اکاؤنٹ اپنی سیٹ سنبھالی رکھدا اے جد تیک کسے پارک کیتے اکاؤنٹ دا رفتار دباؤ اوہدے توں ایس حصے توں ودھ نہ ہو جاوے، سو نیڑے نیڑے برابر اکاؤنٹ سیٹ نوں اِدھر اُدھر ونڈنا تے فی تنظیم پرامپٹ کیش ساڑنا چھڈ دیندے نیں۔ پرانے ہمیشہ-بہترین-لے-لَو ورتاؤ لئی ایہنوں 0 تے رکھو۔ ایہہ کدے وی کسے پار کیتی بار یا کندھ نوں ڈھِلا نئیں کردا - صرف اوہناں اکاؤنٹاں وچکار پاسے دے بدلاؤاں تے لگدا اے جیہڑے سارے باراں توں تھلے ہون۔ ہتھیں `tokenmaxxing switch` ایہنوں نظرانداز کردا اے تے ہمیشہ بہترین اکاؤنٹ تے آ ٹِکدا اے۔
- `policy.switchModels`: اوہ ماڈل خاندان جنہاں دی فی ماڈل ہفتہ وار حد اک بدلاؤ نوں گیٹ کردی اے (اِندراج لوڈ ویلے چھوٹے اکھراں وچ کر دِتے جاندے نیں)۔
- `policy.usagePollTtlMs`: اک `/usage` فی ماڈل پول کِنا چِر تازہ رہندا اے۔
- `policy.maxWaitMs`: مُکے پول دی خودکار اڈیک دی حد۔
- `policy.checkIntervalMs`: وقفے وار جانچ دا ٹِک (طے شدہ 60000، گھٹو گھٹ 10000، کیوں جو launchd طے شدہ طور تے کسے کم نوں ہر 10 سیکنڈ وچ اک واری توں ودھ نئیں چلاندا)۔ `init` ایہنوں، پورے سیکنڈاں تیک اُتے گول کر کے، ٹائمر دے وقفے وانگوں لکھدا اے (Linux تے systemd دا `AccuracySec` ایہدا بارھواں حصہ ہندا اے، گھٹو گھٹ اک سیکنڈ)، تے گنجائش دا ہر درجہ ایہدا اک ضرب اے: کسے بار دے نیڑے اک ٹِک، تے کھُلی گنجائش نال پنج ٹِک تیک (ویکھو [جانچ دی چال](/pnb/switching))۔ مُکے پول دی اڈیک تے بدلاؤ توں بعد والا کول ڈاؤن ایہدی بجائے اپنیاں اپنیاں میعاداں تیک سوندے نیں۔ مقررہ ویلے دا حساب اگلی جانچ تے نویں قدر پڑھ لیندا اے، پر انسٹال کیتا ٹائمر اپنا پرانا ٹِک اونی دیر رکھدا اے جِنی دیر تُسیں مُڑ `tokenmaxxing init` نئیں چلاندے، تے ویلے سِر ہون دی چھوٹ ترتیب دِتے ٹِک دا اَدھ ہندی اے، سو بدلیا ہویا ٹِک اوس مُڑ چلان توں بعد ای پورا مندا جاندا اے۔ Nix ولوں سنبھالے ٹائمر نال، `checkTimer.intervalSeconds` نوں اوہو قدر تے رکھو؛ اوس اختیار دی وی اوہو 10 سیکنڈ دی حد اے۔

`tokenmaxxing config` ذرائع نال اثردار config ویکھاندا اے؛ `config set`/`unset` نقطے والیاں کیز سودھدے نیں؛ `config tidy` انجان کیز چھانگدا اے۔
