---
title: Честные ограничения
description: "Компромиссы, которые приходят с объединённой горячей заменой"
---

- **Один холодный ход.** Кэш промптов ограничен организацией, поэтому первый ход на новом аккаунте один раз заново загружает контекст.
- **Заминка при паузе из-за исчерпания.** Только полностью исчерпанный пул останавливает сессию на обратный отсчёт; всё, что напечатано в это мгновение, теряется.
- **Задержка принятия.** На macOS первый ход в пределах ~30 секунд после переключения всё ещё может учитываться на старый аккаунт; запас порогов это поглощает.
- **Общий радиус поражения.** Все сессии профиля по умолчанию используют одни активные учётные данные, поэтому переключение перемещает их все вместе (каждая принимает на месте).
- **Учётные данные в открытом виде на Linux.** Сам Claude Code хранит учётные данные Linux как plaintext-файл с правами 0600; припаркованные копии tokenmaxxing следуют той же модели.
- **Один пул на хост.** Объединение одних и тех же аккаунтов на нескольких машинах работает, но каждый хост паркует и обновляет токены независимо, без межхостовой блокировки: два хоста, одновременно обновляющие токен одного и того же аккаунта, вступают в гонку, а для Codex обновление из устаревшей припаркованной копии фатально для этого логина (OpenAI аннулирует всё семейство грантов при повторном использовании refresh-токена, что вынуждает выполнять `auth` на каждом хосте). Если вы объединяете аккаунт на нескольких машинах, ожидайте периодической необходимости повторной аутентификации для Claude и полностью избегайте этого для Codex.
