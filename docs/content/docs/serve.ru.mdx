---
title: "Мост в Slack: xx serve"
description: "xx serve запускает сессии Claude Code из тредов Slack через Socket Mode"
---

`tokenmaxxing serve` запускает локальный демон Slack через Socket Mode - публичный URL не требуется. Настройка:

```sh
tokenmaxxing serve setup                    # печатает манифест приложения, запрашивает два токена
tokenmaxxing serve link <channel-id> <repo> # привязывает канал к checkout репозитория
tokenmaxxing serve                          # запускает демон
```

Упомяните бота в привязанном канале, и он откроет сессию Claude Code для этого треда в checkout привязанного репозитория. Каждый новый ход запускает один `query()` из Agent SDK с `resume` - поэтому `ensureBestAccount()` заново оценивает пул на каждом ходу, и демон может перезапускаться, не теряя треды (записи тредов долговечны; демон повторно подписывается на них при запуске) - а ответ, пришедший во время выполняющегося запроса, попадает в потоковый ввод этого запроса вместо того, чтобы запускать собственный; ответ, не успевший попасть в окно управления, выполняется как следующий ход.

Заметное поведение:

- **Управление**: ответ, пришедший, пока ход треда ещё выполняется, встраивается в этот ход - та же вставка посреди хода, которую Claude Code использует в интерактивном режиме, - поэтому модель замечает его на следующей границе вызова инструмента и меняет курс, а не доводит до конца не то, что нужно. Ответ, пришедший после последнего вызова инструмента в ходе, выполняется как отдельный ход сразу после него; в обоих случаях ничего не теряется. Такие сообщения несут реакцию в виде песочных часов и завершаются вместе с ходом, а их текст держится на долговечном маркере хода, поэтому перезапуски и возобновления после исчерпания лимита воспроизводят его заново. Встраивание пропускает только сообщение, стоящее в очереди за другим ожидающим сообщением (порядок сохраняется), а если демон находится в процессе слива, такой ответ всё равно громко отбрасывается, а не используется для управления.
- **Потоковая передача**: ответы транслируются в Slack нативно, с карточками задач для размышлений и запусков инструментов, с кодом в ограждённых блоках, отрисованным с подсветкой, и с завершающей карточкой «Turn», содержащей стоимость и длительность; карточки хода сворачиваются в один раскрываемый блок плана, так что ход обычно читается как одно сообщение: ответ плюс один выпадающий список его активности (повторная попытка посреди хода или отклонённое добавление открывает последующее сообщение). Вызовы TodoWrite обновляют одну стабильную карточку-чеклист на месте.
- **Разрешения**: `permissionMode` для каждой привязки по умолчанию равен `acceptEdits`; `--yolo` (псевдоним `--dangerous`) переводит привязку в `bypassPermissions`. Интерактивные диалоги запрещены в ретранслируемых ходах - никто не может ответить на них через Slack - поэтому модель спрашивает прозой, и ваш ответ в треде становится следующим ходом. Встроенный навык плагина учит её отмечать запросившего и завершать ход, когда нужно решение.
- **Реакции-статусы**: сообщение, запустившее ход, несёт его состояние в виде эмодзи-реакции: песочные часы, пока ход выполняется, затем галочка (готово), крестик (сбой) или вопросительный знак (модели нужно ваше решение). Требуется scope `reactions:write` из текущего манифеста; существующим приложениям нужно заново вставить манифест и переустановить.
- **Внимание и напоминания**: когда модель запрашивает у вас решение, она вызывает внутрипроцессный инструмент `need_attention`, поэтому демон знает, что тред ждёт вас. Если вы молчите 10 минут, он один раз отмечает вас в треде. Пока тред ждёт, реакция на вопрос передаётся как ваш ответ (палец вверх выбирает рекомендуемый вариант); любая другая реакция, добавленная вами в отслеживаемом треде, добавляется в следующий ход как контекст. Требуются `reactions:read` и событие `reaction_added`.
- **Slash-команды**: сообщение в треде, чей очищенный текст начинается с `/`, выполняется как slash-команда claude. Редактор Slack проглатывает сообщения, начинающиеся с `/`, поэтому используйте форму с упоминанием в начале (`@bot /usage`) или ведущий пробел.
- **Автовозобновление при исчерпании лимита**: когда лимит исчерпан у всех аккаунтов пула, кратковременный сбой откладывает сообщение и повторяет попытку на месте; более длительный публикует уведомление об ожидании и автоматически возобновляет ход, как только пул восстановится, переживая перезапуски демона. Только лимит без известного времени восстановления просит вас отправить сообщение заново.
- **Плавное завершение**: SIGTERM/SIGINT выполняет слив - новые ходы громко отбрасываются, выполняющимся ходам даётся до 5 минут, а дочерний процесс claude запускается отсоединённым в собственной группе процессов, чтобы Ctrl-C в терминале не мог убить его до того, как слив сохранит ход.
- **Очистка треда**: когда вы сообщаете, что работа завершена, модель вызывает внутрипроцессный инструмент `finish_thread`; после того как ход полностью завершается, демон удаляет запись треда, отписывается и публикует одно подтверждение. Новое упоминание запускает новую сессию.
- **Гигиена ошибок**: ошибки хода публикуют только обрезанный текст сообщения, никогда сырые тела ошибок.
