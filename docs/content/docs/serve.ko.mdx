---
title: "Slack 브리지: xx serve"
description: "xx serve는 Socket Mode로 Slack 스레드에서 Claude Code 세션을 실행합니다"
---

`tokenmaxxing serve`는 Socket Mode로 로컬 Slack 데몬을 실행합니다. 공개 URL은 필요 없습니다. 설정:

```sh
tokenmaxxing serve setup                    # 앱 매니페스트를 출력하고 두 개의 토큰을 입력받습니다
tokenmaxxing serve link <channel-id> <repo> # 채널을 저장소 체크아웃에 연결합니다
tokenmaxxing serve                          # 데몬을 실행합니다
```

연결된 채널에서 봇을 멘션하면 그 스레드용 Claude Code 세션이 연결된 저장소 체크아웃에서 열립니다. 새 턴마다 `resume`을 사용한 Agent SDK `query()` 하나를 새로 실행합니다. 그래서 `ensureBestAccount()`가 매 턴마다 풀을 다시 평가하며 데몬은 스레드를 잃지 않고 재시작할 수 있습니다(스레드 기록은 영속적이며 데몬은 시작할 때 다시 구독합니다). 다만 쿼리가 진행 중일 때 도착한 답장은 그 자체의 쿼리를 새로 실행하는 대신 진행 중인 쿼리의 스트리밍 입력으로 전달되어 턴을 조종하며, 조종 시점을 놓친 답장은 다음 턴으로 실행됩니다.

주목할 만한 동작:

- **조종**: 스레드의 턴이 아직 진행 중일 때 도착한 답장은 그 턴에 접혀 들어갑니다. Claude Code가 대화형으로 사용하는 것과 같은 턴 중간 주입입니다. 그래서 모델은 다음 도구 경계에서 그것을 확인하고, 잘못된 일을 끝까지 마치는 대신 방향을 바로잡습니다. 턴의 마지막 도구 호출 이후에 도착한 답장은 곧바로 그 자체의 턴으로 실행되며, 어느 쪽이든 아무것도 누락되지 않습니다. 조종된 메시지는 모래시계 리액션을 달고 턴과 함께 마무리되고, 그 텍스트는 턴의 영속적인 마커에 실리므로 재시작과 사용량 한도 재개 시에도 다시 재생됩니다. 다른 대기 메시지 뒤에 줄 선 메시지만 접히기를 건너뛰며(순서는 보존됩니다), 드레인 중인 데몬은 조종 대신 여전히 명시적으로 거부합니다.
- **스트리밍**: 응답은 Slack에 네이티브로 스트리밍됩니다. 사고 과정과 도구 실행을 보여주는 작업 카드, 하이라이팅이 적용된 펜스 코드, 비용과 소요 시간이 담긴 마무리 "Turn" 카드가 함께 나옵니다. 한 턴의 카드는 모두 펼칠 수 있는 플랜 블록 하나로 접힙니다. 그래서 한 턴은 보통 응답에 활동 드롭다운 하나를 더한 하나의 메시지로 읽힙니다(턴 중간의 재시도나 거부된 추가는 후속 메시지를 엽니다). TodoWrite 호출은 안정적인 체크리스트 카드 하나를 제자리에서 갱신합니다.
- **권한**: 링크별 `permissionMode`는 기본값이 `acceptEdits`입니다. `--yolo`(별칭 `--dangerous`)는 링크를 `bypassPermissions`로 설정합니다. 중계된 턴에서는 사용자 응답이 필요한 대화 상자를 띄우지 못합니다. 아무도 Slack에서 답할 수 없기 때문입니다. 그래서 모델은 글로 묻고 스레드 답장이 다음 턴이 됩니다. 번들된 플러그인 스킬은 결정이 필요할 때 요청자를 태그하고 턴을 끝내라고 모델에게 알려 줍니다.
- **상태 리액션**: 턴을 시작시킨 메시지는 자기 상태를 이모지 리액션으로 표시합니다. 턴이 도는 동안에는 모래시계, 그다음 체크 표시(완료), 엑스(실패), 물음표(모델이 사용자의 결정을 기다림)입니다. 현재 매니페스트의 `reactions:write` 스코프가 필요합니다. 기존 앱은 매니페스트를 다시 붙여넣고 재설치해야 합니다.
- **주의 요청과 재촉**: 모델이 결정을 물을 때는 인프로세스 `need_attention` 도구를 호출합니다. 그래서 데몬은 그 스레드가 사용자를 기다리고 있음을 압니다. 10분 동안 조용하면 스레드에서 한 번 태그합니다. 스레드가 기다리는 동안 질문에 리액션을 달면 답변으로 전달됩니다(따봉은 권장 선택지를 고릅니다). 추적 중인 스레드에 다는 그 밖의 리액션은 다음 턴에 컨텍스트로 접혀 들어갑니다. `reactions:read` 스코프와 `reaction_added` 이벤트가 필요합니다.
- **슬래시 명령**: 정리된 텍스트가 `/`로 시작하는 스레드 메시지는 claude 슬래시 명령으로 실행됩니다. Slack 작성기는 `/`로 시작하는 메시지를 삼키므로 멘션 우선 형식(`@bot /usage`)이나 앞에 공백을 붙여 사용하세요.
- **사용량 한도 자동 재개**: 풀의 모든 계정이 한도에 도달하면, 짧은 중단에는 메시지를 보류했다가 제자리에서 재시도합니다. 더 긴 중단에는 대기 안내를 게시하고 풀이 회복되면 턴을 자동으로 재개하며, 이는 데몬이 재시작되어도 유지됩니다. 복구 시점을 알 수 없는 한도일 때만 다시 보내 달라고 요청합니다.
- **우아한 종료**: SIGTERM/SIGINT를 받으면 드레인에 들어갑니다. 새 턴은 명시적으로 거부되고 진행 중인 턴에는 최대 5분이 주어집니다. claude 자식 프로세스는 자체 프로세스 그룹으로 분리되어 실행됩니다. 덕분에 터미널에서 Ctrl-C를 눌러도 드레인이 턴을 보존하기 전에는 프로세스가 죽지 않습니다.
- **스레드 정리**: 작업이 끝났다고 알리면 모델은 인프로세스 `finish_thread` 도구를 호출합니다. 턴이 완전히 끝난 뒤 데몬은 스레드 기록을 삭제하고 구독을 해제하며 확인 메시지 하나를 게시합니다. 새로 멘션하면 새 세션이 시작됩니다.
- **오류 위생**: 턴 오류는 다듬어진 메시지 텍스트만 게시하며 원본 오류 본문은 절대 게시하지 않습니다.
