---
title: State directory layout
description: Every file and directory under ~/.config/tokenmaxxing
---

Everything lives under `~/.config/tokenmaxxing/`. Override with `TOKENMAXXING_HOME`. Every external path has an env override so tests stay hermetic; the timer unit is not a path, so a hermetic run of `init` builds a full isolated `HOME` and sets `TOKENMAXXING_SKIP_TIMER=1`, and `uninstall` addresses the login user's timer instance only when `HOME` is the login home (see [Troubleshooting](/troubleshooting)).

| Path | What it holds |
|---|---|
| `config.json` | Your configuration (sparse; defaults apply per field) |
| `accounts.json` | Non-secret index of pooled Claude accounts: `id`, `label`, `email`, `tier`, the cached `windows` (the session and weekly windows unnamed, per-model caps named, each with its duration and sample time), `lastUsageAt`, `lastProbeAt`, `probeFails` (consecutive silent seat probes, for the backoff), `storeFails` (consecutive failed store reads on the check tick; five stamp `needsReauth`), `enforcedUntil`, `needsReauth`, and the `oauthAccount` object the probe home is seeded with. `activeId` is always `null`: there is no pool-wide active account, each session has its own seat. Never tokens |
| `stores/<uuid8>/` | One Claude Code credential store per pooled account. On Linux it holds the account's `.credentials.json` (0600 in a 0700 directory) and Claude Code's refresh lock; on macOS the credential is the keychain item keyed by this path and the directory holds only the lock |
| `usage/<uuid8>.json` | The statusline tee per account: the aggregate window snapshot pushed by the sessions running on that account; its mtime is the feed's liveness heartbeat |
| `live/<session-id>` | One PID-validated presence file per running supervised Claude session (the account id, the pid, and the start time); placement counts them, and `rm` refuses an account with a living session |
| `lock` | The `flock` file that serializes decisions, placement, and sampling |
| `update.json`, `update.lock` | The last self-update attempt's timestamp and the `flock` file that serializes it (Bun global installs only; see [Automatic updates](/distribution#automatic-updates)) |
| `sessions/<session-id>.json` | Per-managed-session launch flags the supervisor persists for respawns; pruned after 30 days idle (matching claude's own transcript retention) |
| `tokenmaxxing.log` | Append-only event log, rotated to `tokenmaxxing.log.old` once it passes 5 MB |
| `spawnrate.json` | The supervisor's wrapper-entry rate limiter, one of the recursion guards |
| `check.stderr.log` | macOS only: the launchd check job's stderr (systemd sends it to the journal) |
| `bin/` | The PATH shims: `claude`, `codex`, and the `tokenmaxxing` / `xx` entry points |
| `respawn/<session-id>` | Respawn markers the supervisor watches: the target account, the session to resume, a `waitUntil` (now for a plain move, the reset for a depleted-pool wait), whether to compact first, and the launch time of the process the marker was written for |
| `onboard/`, `sample/` | Throwaway config homes: `onboard/` for `init`, `add`, and `auth` logins (deleted after harvest, credential included); `sample/<uuid8>` and `sample/<uuid8>-tick` for `/usage` probes, the fallback for a near-expiry token or a failed direct read (a `.claude.json` seeded when a probe runs; the credential comes from the account's store) |
| `setup-tokens.json` | Cursor Cloud only: `{accountUuid, label, token, mintedAt}` per pooled account, mode 0600, the source of the `TOKENMAXXING_TOKENS` secret value that `setup-token` prints (keyed by account, so a rename does not orphan a token) |
| `setup-token/` | Throwaway isolated config homes for `setup-token` mints, deleted after each run |
| `cloud/` | On a Cursor Cloud VM only: `sessions.json` (session id to token label), `walled.json` (label to reset time), and the `lock` that serializes `cloud run` picks |
| `codex-*` | The Codex pool's own state: `codex-accounts.json` (the same index shape as `accounts.json`, without `oauthAccount`; `activeId` is always `null`, each session has its own seat), `codex-lock`, `codex-stores/<uuid8>/` (one store per pooled Codex account: its `auth.json`, everything else symlinked to the shared `~/.codex`), `codex-onboard/`, `codex-respawn/`, and `codex-live/` (one PID-validated presence file per running supervised codex session, so a live account is never a placement or move target) |
| `grok-*`, `opencode-go-*` | The two status-only pools: `grok-accounts.json` and `opencode-go-accounts.json` (the same index shape), `grok-lock` and `opencode-go-lock`, `grok-stores/<uuid8>/auth.json` and `opencode-go-stores/<uuid8>/auth.json` (one 0600 store per account), `grok-onboard/` and `opencode-go-onboard/` (throwaway login homes). See [Status-only pools](/status-only-pools) |

## After upgrading

Version 1.37.0 moves every Claude credential into a per-account store, and there is no migration. The parked backups earlier versions kept (the `creds/` files on Linux, the `tokenmaxxing-cred-<uuid8>` keychain items on macOS) and the copy in Claude Code's default store are no longer read: a session started by the supervisor runs on `stores/<uuid8>/` and nothing else, and tokenmaxxing no longer writes the default store. Rebuild the pool: `tokenmaxxing init` logs the first account in through an isolated browser sign-in and `tokenmaxxing add` each other account; both write the store from a fresh grant, and `accounts.json` keeps its records, so labels and cached figures survive. Then delete the old backups yourself: `creds/`, the keychain items, `usage.json`, `lastswap.json`, and `depleted.json`. Claude Code's default store keeps your own login for sessions started outside the supervisor.

The Codex pool moves to per-account stores the same way, and there is no migration either. The shared live `auth.json` rewrite, the `codex-creds/` parked copies, the `activeId` label, the `codex-lastswap.json` cooldown clock, and the `codex-reconcile/` signals are no longer read or written: a session started by the codex supervisor runs on `codex-stores/<uuid8>/` and nothing else. Rebuild the pool: `tokenmaxxing init --codex` logs the first account in through an isolated device-auth login and `tokenmaxxing add --codex` each other account; both write the store from a fresh grant, and `codex-accounts.json` keeps its records, so labels and cached figures survive. Then delete the old state yourself: `codex-creds/`, `codex-lastswap.json`, and `codex-reconcile/`. Codex's default `~/.codex/auth.json` keeps your own login for sessions started outside the supervisor.

`accounts.json` and `codex-accounts.json` are schema version 2 (unchanged since 1.35.0): `version` is `2`, the active field is `activeId` (always `null`), and each account has `id`, `label`, `email`, `tier`, `addedAt`, `windows`, and the optional `lastUsageAt`, `lastProbeAt`, `probeFails`, `storeFails`, `enforcedUntil`, `needsReauth`, and `oauthAccount`. A window is `{name, usedPercentage, resetsAt, windowSeconds, sampledAt}`; `name` is `null` for the session and weekly windows and the limit or model name otherwise. A version 1 index fails the schema check and every command throws `does not match the accounts schema` until the file is repaired or removed.

Outside its own directory, tokenmaxxing touches: Claude Code's `settings.json` (the hook and statusline entries), the keychain items of its own stores on macOS, codex's `hooks.json`, the periodic-check unit in launchd or systemd, and the `# tokenmaxxing PATH` line in your shell rc. It reads codex's `config.toml` (the credential-store setting and hook trust) and never writes it, and every onboarding login runs in a throwaway home under the state directory, never in the vendor CLI's own. It no longer writes `~/.claude.json`, Claude Code's default credential store, or codex's live `auth.json`. `cursor init` additionally writes `.cursor/agents/claude.md` and `.cursor/environment.json` into the repo you point it at.
