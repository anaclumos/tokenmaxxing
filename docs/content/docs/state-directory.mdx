---
title: State directory layout
description: Every file and directory under ~/.config/tokenmaxxing
---

Everything lives under `~/.config/tokenmaxxing/`. Override with `TOKENMAXXING_HOME`. Every external path has an env override so tests stay hermetic.

| Path | What it holds |
|---|---|
| `config.json` | Your configuration (sparse; defaults apply per field) |
| `accounts.json` | Non-secret index of pooled Claude accounts: `id`, `label`, `email`, `tier`, the cached `windows` (the session and weekly windows unnamed, per-model caps named, each with its duration and sample time), `lastUsageAt`, `lastProbeAt`, `enforcedUntil`, `needsReauth`, and the `oauthAccount` object a swap writes into `~/.claude.json`. Never tokens |
| `usage.json` | The statusline tee's aggregate window snapshot; its mtime is the feed's liveness heartbeat |
| `lastswap.json` | Epoch timestamp of the last swap; drives the 45-second cooldown |
| `depleted.json` | The recorded depleted-pool wait, replayed by sibling hooks until the reset passes, the live seat moves, or any swap completes |
| `lock` | The `flock` file that serializes swaps |
| `sessions/<session-id>.json` | Per-managed-session launch flags the supervisor persists for respawns; pruned after 30 days idle (matching claude's own transcript retention) |
| `tokenmaxxing.log` | Append-only event log |
| `bin/` | The PATH shims: `claude`, `codex`, and the `tokenmaxxing` / `xx` entry points |
| `respawn/<session-id>` | Respawn markers the supervisor watches: a depleted-pool wait, or a StopFailure relaunch onto the fresh account |
| `creds/` | Linux only: parked credential files, 0600 in a 0700 directory (macOS parks credentials as per-account keychain items instead) |
| `onboard/`, `sample/` | Throwaway isolated config homes for `add`/`auth` logins and parked-account `/usage` probes; onboard homes holding plaintext credentials are deleted after harvest |
| `setup-tokens.json` | Cursor Cloud only: `{accountUuid, label, token, mintedAt}` per pooled account, mode 0600, the source of the `TOKENMAXXING_TOKENS` secret value that `setup-token` prints (keyed by account, so a rename does not orphan a token) |
| `setup-token/` | Throwaway isolated config homes for `setup-token` mints, deleted after each run |
| `cloud/` | On a Cursor Cloud VM only: `sessions.json` (session id to token label), `walled.json` (label to reset time), and the `lock` that serializes `cloud run` picks |
| `codex-*` | The Codex pool's own state: `codex-accounts.json` (the same index shape as `accounts.json`, without `oauthAccount`), `codex-lastswap.json`, `codex-lock`, `codex-creds/`, `codex-onboard/`, `codex-respawn/`, `codex-reconcile/` (cross-session signals asking a sibling session's supervisor to respawn onto the live account), and `codex-live/` (one PID-validated presence file per running supervised codex session, so a live account is never a swap target) |

## After upgrading

`accounts.json` and `codex-accounts.json` are schema version 2, and there is no migration: a version 1 index fails the schema check and every command throws `does not match the accounts schema` until the file is repaired or removed. Parked credentials are not affected: the keychain items and the `creds/` and `codex-creds/` files are named from the first 8 characters of the account id in both versions, so nothing is orphaned. Remove `depleted.json` as well if it exists: the 1.34.0 marker stores `accountUuid` where version 2 reads `id`, so `check` and every hook evaluation throw on it until it is gone, and it is only the transient depleted-wait record (at most `policy.maxWaitMs` old), which the next depleted decision rewrites. `setup-tokens.json` keeps `accountUuid` as its key and needs no change.

Either rebuild an index (remove the file, run `tokenmaxxing init` or `init --codex` for the live login, then `add` or `add --codex` for every other account) or rewrite it by hand. Both files share one shape: `version` is `2`, the active field is `activeId`, and each account has `id`, `label`, `email`, `tier`, `addedAt`, `windows`, and the optional `lastUsageAt`, `lastProbeAt`, `enforcedUntil`, `needsReauth`, and `oauthAccount`. A window is `{name, usedPercentage, resetsAt, windowSeconds, sampledAt}`; `name` is `null` for the session and weekly windows and the limit or model name otherwise.

- Claude, from version 1: `activeAccountUuid` becomes `activeId` and `accountUuid` becomes `id`; `keychainItem`, `organizationUuid`, `subscriptionType`, and `rateLimitTier` are dropped (`tier` may be `null`; the next probe stamps it); `lastUsage.fiveHour` becomes an unnamed window with `windowSeconds` `18000`, `lastUsage.sevenDay` an unnamed window with `604800`, and each `lastUsage.perModel` entry a window named after the model with `604800`; `sampledAt` is the old `lastUsageAt` (`rowsAt` for the per-model rows).
- Codex, from version 1: `activeAccountId` becomes `activeId`, `accountId` becomes `id`, `planType` becomes `tier`, and `credFile` is dropped; every entry of `lastUsage.aggregate` becomes an unnamed window and every entry of `lastUsage.perLimit[name]` a window with that `name`, each keeping its `usedPercentage`, `resetsAt`, and `windowSeconds`, with `sampledAt` the old `lastUsageAt`.

Outside its own directory, tokenmaxxing touches exactly: `~/.claude.json` (the `oauthAccount` swap), Claude Code's `settings.json` (the hook and statusline entries), the live credential store (the `Claude Code-credentials` keychain item on macOS, `.credentials.json` on Linux), claude's own refresh locks taken during swaps (the primary `.oauth_refresh.lock` inside claude's config dir, plus the legacy `~/.claude.lock` sibling), codex's `auth.json` and `hooks.json`, and the periodic-check unit in launchd or systemd. `cursor init` additionally writes `.cursor/agents/claude.md` and `.cursor/environment.json` into the repo you point it at.
