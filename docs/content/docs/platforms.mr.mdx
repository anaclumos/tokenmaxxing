---
title: "प्लॅटफॉर्म नोंदी: macOS विरुद्ध Linux"
description: "साठवण, स्वीकार, आणि टायमरमध्ये macOS आणि Linux कसे वेगळे आहेत"
---

| | macOS | Linux |
|---|---|---|
| थेट क्रेडेन्शियल | लॉगिन कीचेन generic-password आयटम | 0600 `.credentials.json` फाइल |
| पार्क केलेली क्रेडेन्शियल्स | प्रति-खाते कीचेन आयटम्स | 0700 डिरेक्टरीमध्ये 0600 फाइल्स |
| बदलानंतर स्वीकार | सुमारे ३० सेकंदांत (कीचेन वाचन कॅश) | पुढील विनंती (फाइल mtime पोल) |
| नियतकालिक तपासणी | launchd एजंट, दर १८०सेकंद | systemd यूजर टायमर, दर १८०सेकंद |
| वेगळ्या-लॉगिनचे स्टोअर | प्रति कॉन्फिग डिरेक्टरी हॅश-नेमस्पेस केलेली कीचेन सेवा | वेगळ्या कॉन्फिग डिरेक्टरीमधील फाइल |

जाणून घेण्यासारखे दोन Linux-विशिष्ट तपशील: claude आपली क्रेडेन्शियल डिरेक्टरी प्रथम `CLAUDE_SECURESTORAGE_CONFIG_DIR` वरून सोडवते (नंतर `CLAUDE_CONFIG_DIR`, नंतर `~/.claude`), आणि tokenmaxxing ती सोडवणी अगदी अचूक प्रतिबिंबित करते जेणेकरून त्या दोघी कधीही डीसिंक होणार नाहीत. आणि तीच claude आवृत्ती दोन OS बिल्ड्स `/usage` रीसेट घड्याळे वेगवेगळ्या स्वरूपात करतात (एक " at " ग्लू वापरते, दुसरी स्वल्पविराम); tokenmaxxing चा पार्सर नेमके त्या दोन स्वरूपांना स्वीकारतो आणि कोणत्याही तिसऱ्यावर अंदाज लावण्याऐवजी लॉग करतो.

macOS वर, एक प्रामाणिक मर्यादा: `init` आणि `add` मुद्दाम कीचेनला इंटरॲक्टिव्हपणे स्पर्श करतात, जेणेकरून हेडलेस हुकच्या आत पहिला `security` अॅक्सेस थंड नसतो.
