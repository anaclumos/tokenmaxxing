---
title: Status-only pools
description: grok and Muse Code accounts, pooled for inventory with no supervisor and no switching
---

The grok and Muse Code pools share the account commands, the state layout, and the `status` view with the Claude and Codex pools, and nothing else: no supervisor shim, no hooks, no statusline tee, no session presence, and no switching. Each keeps an inventory of accounts and the credential each one holds. `status` reads each grok account's subscription credit window and each Muse Code account's 5-hour and weekly windows.

```sh
tokenmaxxing init --grok          # pool the first grok login (status-only)
tokenmaxxing add --grok           # pool another one through an isolated login
tokenmaxxing init --muse          # pool the first Muse Code login (status-only)
tokenmaxxing add --muse           # pool another one through an isolated login
```

`init`, `add`, `auth`, `emails`, `rm`, and `rename` take `--grok` or `--muse`; every other command refuses the flag with exit code 2, and the pool flags are mutually exclusive. `init` verifies the vendor CLI and pins its path (`grokBin` or `museBin` in `config.json`; `TOKENMAXXING_GROK_BIN` and `TOKENMAXXING_MUSE_BIN` override them), then prints that the pool is status-only. `doctor`, `check`, and the periodic timer ignore both pools, and `uninstall` keeps their stores.

## grok

An account is a grok CLI login. `init --grok` imports the first entry of `~/.grok/auth.json` (`GROK_HOME` is honored) and points at `add --grok` for the rest; with no live login it runs `grok login` in a throwaway `GROK_HOME` under the state directory. `add --grok` and `auth --grok` always use the isolated login. Identity is the entry's user id, the label defaults to the email in the entry, and the harvested entry is written verbatim to `grok-stores/<uuid8>/auth.json` at mode 0600.

Usage is the weekly subscription credit window from `GET https://cli-chat-proxy.grok.com/v1/billing?format=credits` (`creditUsagePercent`, classified by the period's duration). The endpoint leaves `creditUsagePercent` out while the period's use is 0, so a credits body without it reads as 0%. `TOKENMAXXING_GROK_USAGE_URL` overrides that URL for hermetic runs. The dollar billing body (`GET /v1/billing` without `format=credits`) is not quota: subscription accounts report `monthlyLimit` 0 there while credits remain, and a parser that treats that body as usage reports the account depleted. tokenmaxxing does not refresh grok tokens; a stored access token that has expired is retried against the live `GROK_HOME` login when that login is the same account. A failed read does not write the dollar body: an account with no stored window stays unmeasured, and one with a stored credits window keeps that figure as stale as it was.

## Muse Code

An account is a Muse Code login. `init --muse` imports the first provider entry with a `user_email` from `$XDG_CONFIG_HOME/muse/auth.json` (`~/.config/muse/auth.json` when `XDG_CONFIG_HOME` is unset) and points at `add --muse` for the rest; with no live login it runs `muse login` with `XDG_CONFIG_HOME` set to a throwaway directory under the state directory, so the login lands in `muse/auth.json` there. `add --muse` and `auth --muse` always use the isolated login. The entry carries no account id, so identity is the sha256 of the entry's `user_email`, lowercased; the label defaults to that email, and an entry without an email is skipped, so a login that holds no email adds nothing and says so. The harvested entry is written with the file's other top-level fields to `muse-stores/<uuid8>/auth.json` at mode 0600. A store is usable when its entry holds an `access_token` or an `api_key`.

Muse Code has no read-only quota endpoint. `GET /muse-code/models` carries only per-model token limits, and the key mint response (`POST /muse-code/key`) returns `subs_usage` as `null`. The window arrives only as the `response.subscription_usage` event of a model response stream. So the live sample sends `POST https://api.meta.ai/v1/responses` with the store's `api_key`, the model `muse-spark-1.3`, the input `hi`, `max_output_tokens` 16, and `stream` true, and reads that event. Each live `status` spends that request's quota once per account. `TOKENMAXXING_MUSE_USAGE_URL` overrides the URL for hermetic runs. The event's `window` is the 5-hour window, with its duration in `window_duration_mins`, and its `weekly` is the 7-day window; each carries `used_percent` and `resets_at` in epoch seconds. A failed read keeps the stored windows as stale as they were, and an account with no stored window stays unmeasured.

## What status shows

`status` renders the pool after Claude and Codex, headed `grok  (N accounts, status-only)` and skipped when empty. A grok account renders the weekly credit bar from the credits billing read. The live sample is the credits GET (and a live-login retry when the stored access token is expired). `status` shows `sampling grok usage...` on a terminal while the check runs, erases it, then reports `live sample failed` when the read fails (run `auth --grok` when the store has no usable credential); `status --cached` skips the check and notes `never sampled` when nothing is stored. `status --json` always carries the pool under `grok`, with the same pool shape as the others. `usage` is the weekly credit window when a sample has landed. `sessions` is 0. `exhausted` follows the same bars as the other pools when the account has a stored window, and is `false` when the account is unmeasured.

The Muse Code pool renders after grok, headed `muse  (N accounts, status-only)` and skipped when empty, and `status --json` always carries it under `muse`. Each account renders the 5-hour and weekly bars once a sample has landed, `usage` carries both windows, `sessions` is 0, and `exhausted` follows the same bars as the other pools; an unmeasured account has `usage` null and `exhausted` `false`.

## State

| Path | What it holds |
|---|---|
| `grok-accounts.json` | The pool index, the same schema as `accounts.json`; it names no active account |
| `grok-lock` | The `flock` file that serializes the pool's commands |
| `grok-stores/<uuid8>/auth.json` | One 0600 store per account |
| `muse-accounts.json` | The Muse Code pool index, the same schema |
| `muse-lock` | The `flock` file of the Muse Code pool |
| `muse-stores/<uuid8>/auth.json` | One 0600 store per account |
| `onboard/grok-<pid>-<random>/`, `onboard/muse-<pid>-<random>/` | The throwaway home of one isolated login (for Muse Code, its `XDG_CONFIG_HOME`), deleted after it |
