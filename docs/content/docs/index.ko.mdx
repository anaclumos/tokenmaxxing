tokenmaxxing은 자동 Claude Code 계정 전환을 위한 CLI입니다. 직접 보유한 여러 구독(Pro/Max) 계정을 모아 관리하고, 사용 중인 계정이 사용 한도에 가까워지면 활성 자격 증명을 더 여유로운 계정으로 즉시 교체합니다. `claude`는 늘 하던 그대로 실행하면 됩니다. 교체는 안전한 턴 경계에서 이뤄지며, 실행 중인 세션은 재시작 없이 새 계정에서 동일한 대화를 계속 이어갑니다. 동시에 실행되는 여러 세션에서도 함께 작동합니다.

겉으로 드러나는 유일한 동작은 최악의 경우입니다. 풀 전체가 한도에 도달하면 세션은 카운트다운과 함께 일시 정지했다가 가장 먼저 초기화되는 계정에서 자동으로 재개됩니다(Ctrl-C를 누르면 즉시 재개됩니다).

<Callout>
범위: macOS와 Linux의 Claude Code, 그리고 두 번째 병렬 풀로서의 OpenAI Codex CLI. API 키가 아니라 구독 계정을 모아 관리합니다. 이는 직접 보유한 계정을, 직접 실행하는 세션과 에이전트에서 모아 쓰기 위한 개인용 도구입니다. [개인적 사용과 이용약관](/ko/terms)을 참고하세요.
</Callout>

## 문제

Claude 구독은 세 가지 한도를 동시에 측정합니다(모두 `/usage`로 확인됨):

- **현재 세션**: 5시간 롤링 윈도우.
- **현재 주간(전체 모델)**: 7일 합산.
- **현재 주간, 모델별**: 개별 모델 계열마다 별도의 주간 상한. 현재 이 상한은 Sonnet과 Fable에만 존재하며, 그중 Fable 상한만이 유의미할 만큼 빡빡합니다. 이 상한은 합산 한도보다 훨씬 먼저 걸립니다. 어떤 머신은 주간 전체가 50%인데도 주간 Fable은 이미 80%에 도달해 있을 수 있습니다.

주간 할당량은 쓰지 않으면 사라집니다(use-it-or-lose-it). 계정이 고정된 주간 초기화 시점까지 소비하지 않은 분량은 모두 소멸됩니다. 여러 계정을 보유하고 있다면, 합리적인 전략은 자기 주간 진행률에서 가장 뒤처진 계정에 계속 할당량을 소진하고, 어떤 한도든 세션 도중 벽에 부딪히기 전에 다른 계정으로 전환하는 것입니다.

이 작업을 손으로 하려면 로그아웃하고, 로그인하고, 대화를 잃어야 합니다. tokenmaxxing은 이를 자동화합니다. 실행 중인 `claude`는 요청 사이에 자격 증명 저장소를 다시 확인하므로, 그 아래에서 교체된 자격 증명은 그 자리에서 곧바로 채택됩니다(macOS에서는 약 30초 이내, Linux에서는 다음 요청 시). 단순 교체는 세션을 결코 재시작하지 않습니다. 여전히 프로세스 관리가 필요한 유일한 경우는 풀이 완전히 소진된 상황입니다. 세션은 스스로를 일시 정지할 수 없기 때문입니다. 얇은 supervisor가 존재하는 이유가 바로 이것입니다.

`claude`의 나머지 모든 것은 그대로입니다. 모든 플래그, MCP 서버, 훅, 스킬이 그대로 통과됩니다.
