---
title: प्रामाणिक मर्यादा
description: "पूल केलेल्या हॉट-स्वॅपिंगसह येणारे तडजोडी"
---

- **एक थंड टर्न.** प्रॉम्प्ट कॅश संस्था-व्याप्तीचा आहे, त्यामुळे नवीन खात्यावरील पहिला टर्न संदर्भ एकदा पुन्हा-अपलोड करतो.
- **संपलेल्या-थांब्याचा अडथळा.** फक्त पूर्णपणे संपलेला पूल काउंटडाउनसाठी सत्र थांबवतो; त्या क्षणार्धात टाइप केलेले काहीही गमावले जाते.
- **स्वीकार विलंब.** macOS वर बदलानंतरच्या सुमारे ३० सेकंदांतील पहिला टर्न अजूनही जुने खाते मोजू शकतो; बारांची मोकळीक ते शोषून घेते.
- **सामायिक स्फोट त्रिज्या.** सर्व डीफॉल्ट-प्रोफाइल सत्रे एक थेट क्रेडेन्शियल सामायिक करतात, त्यामुळे एक बदल त्या सर्वांना एकत्र हलवतो (प्रत्येक जागच्या जागी स्वीकारतो).
- **Linux वर साध्या-मजकूर क्रेडेन्शियल्स.** Claude Code स्वतः Linux क्रेडेन्शियल्स 0600 साध्या-मजकूर फाइल म्हणून साठवते; tokenmaxxing च्या पार्क केलेल्या प्रती तेच मॉडेल अनुसरतात.
- **प्रति होस्ट एक पूल.** एकाच खात्यांना अनेक मशीन्सवर पूल करणे काम करते, पण प्रत्येक होस्ट स्वतंत्रपणे टोकन्स पार्क आणि फिरवतो, क्रॉस-होस्ट लॉकशिवाय: एकाच खात्याचे टोकन एकाचवेळी रीफ्रेश करणारे दोन होस्ट्स शर्यत लावतात, आणि Codex साठी जुन्या पार्क केलेल्या प्रतीवरून केलेले रीफ्रेश त्या लॉगिनसाठी घातक ठरते (रीफ्रेश-टोकन पुनर्वापरावर OpenAI संपूर्ण ग्रँट फॅमिली अवैध ठरवते, ज्यामुळे प्रत्येक होस्टवर `auth` सक्ती होते). एकापेक्षा जास्त मशीनवर खाते पूल केल्यास, Claude वर अधूनमधून पुन्हा-प्रमाणीकरणाची झीज अपेक्षित धरा आणि Codex साठी ते पूर्णपणे टाळा.
