---
title: Agent SDK サーフェス
description: "自分で動かすエージェントでプールを Claude Agent SDK と組み合わせる"
---

パッケージのプログラム的エントリ (`exports["."]` は `src/sdk.ts` を指します) は、自分でプールしたアカウントを使って構築するエージェント向けに、tokenmaxxing を Claude Agent SDK と組み合わせます。アプリは Bun 上で動作する必要があります (tokenmaxxing は TypeScript ソースを配布し `bun:ffi` を使うためです)。

```ts
import { query } from "@anthropic-ai/claude-agent-sdk";
import { ensureBestAccount, pooledOptions, stopHookCheck } from "tokenmaxxing";

await ensureBestAccount();

for await (const message of query({
  prompt: "...",
  options: {
    ...pooledOptions(),
    hooks: { Stop: [{ hooks: [stopHookCheck] }] },
  },
})) {
}
```

ループ本体はメッセージストリームを受け取ります。切り替えをまたいで `resume` したい場合は、init メッセージのセッション ID を控えておいてください。

Agent SDK は `query()` ごとに claude サブプロセスを起動し、認証情報を起動時に1度だけ読みます (statusline なし、クエリ途中のホットスワップなし)。そのため統合は境界駆動です。

- `ensureBestAccount()` は CLI のフックとタイマーが実行するのとまったく同じ判断であり (バー、ペースプレッシャー、クールダウン、すべて共有コード)、決して先読み的ではありません。枯渇カウントダウンのために SDK セッションが一時停止されることはありません。
- `pooledOptions()` は `pathToClaudeCodeExecutable` を本物の claude バイナリ (スーパーバイザーラッパーではない) に固定し、環境側のあらゆる認証情報オーバーライドを消去した完全な置き換え用の `env` を用意します。アプリの環境に `CLAUDE_CONFIG_DIR` または `CLAUDE_SECURESTORAGE_CONFIG_DIR` が設定されている場合は速やかに失敗します。Linux では、切り替えがそれらの指す先にライブ認証情報を書き込む一方で、消去されたサブプロセスはデフォルトのストアを読むという、気づかないうちに誤ったアカウントとの不整合が生じるためです。
- `stopHookCheck` はターン境界で判断を再実行します。そこで確定した切り替えは次の起動時に反映されます。自身のエラーを (stderr とログに記録して) キャッチし、再スローしません。未処理のフック例外はエージェントを中断しうるため、そして壊れた切り替えチェックのためにターンを中断するコストは、現在のアカウントに乗り続けるコストより大きいためです。

`sdk.ts` は Agent SDK 自体からは何もインポートしません。その値は SDK のオプションに構造的にスプレッドされます。
