---
title: 命令
description: "每一个 tokenmaxxing 命令及其作用"
---

| 命令 | 作用 |
|---|---|
| `tokenmaxxing init` | 导入当前账户，安装监督进程、hooks 和 statusline |
| `tokenmaxxing init --codex` | 对 Codex 执行同样操作：导入登录、安装 codex 监督进程和 Stop hook |
| `tokenmaxxing add` | 注册额外账户（隔离登录，收集进池中） |
| `tokenmaxxing add --codex` | 注册额外的 Codex 账户（隔离登录） |
| `tokenmaxxing auth [sel \| --all]` | 就地重新认证池内账户。裸执行会列出账户池并询问选哪个；选择器定位到某一账户并告诉你该用哪个邮箱登录；`--all` 会逐个走完所有需重新认证的账户 |
| `tokenmaxxing switch [sel]` | 切换到最佳账户（贪心、幂等），或强制指定某一账户 |
| `tokenmaxxing switch --codex [sel]` | 切换 Codex 账户池（在下一次 codex 启动时生效） |
| `tokenmaxxing ls` | 列出池内账户 |
| `tokenmaxxing status` | 展示各账户的 5 小时 / 周 / 按模型用量条，以及活动和已耗尽到重置的状态 |
| `tokenmaxxing status --force` | 额外对每个账户发一次 ping（每个一个极小的 haiku 请求），让所有 5 小时会话计时器立即开始，然后重新采样 |
| `tokenmaxxing watch [seconds]` | 实时状态，每 N 秒重新渲染一次（默认 120，最低 30；从不 ping） |
| `tokenmaxxing config [get\|set\|unset\|tidy]` | 显示带来源的有效配置；编辑点分键；`tidy` 清除未知键 |
| `tokenmaxxing check` | 评估一次切换决策（这正是周期性定时器所运行的） |
| `tokenmaxxing doctor` | 校验监督进程和设置条目是否仍然存在 |
| `tokenmaxxing rename [--codex] <sel> <label>` | 重新标注池内账户 |
| `tokenmaxxing rm [--codex] <sel>` | 从 claude 或 codex 池中移除账户（及其已保存的凭证） |
| `tokenmaxxing uninstall` | 移除监督进程和设置条目（账户与凭证会保留） |
