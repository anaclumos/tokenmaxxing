npm पैकेज एक बिल्ड नहीं, बल्कि TypeScript सोर्स भेजता है: `tokenmaxxing` bin एक Bun shebang के साथ सीधे `src/main.ts` की ओर इशारा करता है, और Bun 1.2.6 या नया इसे जैसा है वैसा ही चलाता है। यही कारण है कि Bun एक कठोर आवश्यकता है। डिज़ाइन के अनुसार कोई संकलित बाइनरी नहीं है: एक शुरुआती रिलीज़ ने हर प्लेटफ़ॉर्म पर एक अकेली 61 MB macOS बाइनरी भेजी और Linux पर `exec format error` के साथ विफल हो गई, और प्रति-प्लेटफ़ॉर्म संकलित पैकेजों में से हर एक को अपनी स्वयं की रिलीज़ पाइपलाइन की आवश्यकता होती, इसलिए Bun-द्वारा-चलाया-गया-सोर्स वितरण मॉडल बन गया।

पैकेज का `exports` मानचित्र `src/sdk.ts` को [एजेंट SDK सतह](/hi/sdk) में वर्णित प्रोग्रामेटिक प्रवेश के रूप में उजागर करता है। रिलीज़ GitHub पर `v<version>` के रूप में टैग की जाती हैं; CI विश्वसनीय प्रकाशन (OIDC, provenance के साथ) के माध्यम से npm पर प्रकाशित करता है, और प्रकाशन द्वार पहले टाइपचेक चलाता है।

## Nix / nix-darwin

वही सोर्स ट्री एक flake भी है। यह Bun-द्वारा-चलाया-गया-सोर्स मॉडल रखता है ([bun2nix](https://github.com/nix-community/bun2nix) के `writeBunApplication` के ज़रिए) और ये दिखाता है:

| आउटपुट | उद्देश्य |
|---|---|
| `packages.default` | PATH पर `tokenmaxxing` + `xx` |
| `darwinModules.default` / `withOverlay` | nix-darwin: CLI इंस्टॉल करें (वैकल्पिक घोषणात्मक जाँच टाइमर) |
| `homeManagerModules.default` | macOS या Linux पर Home Manager |
| `nixosModules.default` / `withOverlay` | NixOS सिस्टम इंस्टॉल |

प्रोफ़ाइल में इंस्टॉल करें (ताकि `init` के सुपरवाइज़र shim PATH पर एक स्थिर `tokenmaxxing` resolve कर सकें), फिर init चलाएँ:

```sh
nix profile install github:anaclumos/tokenmaxxing
tokenmaxxing init
```

बिना इंस्टॉल किए एक बार चलाना (केवल help / status, `init` इस तरह न करें):

```sh
nix run github:anaclumos/tokenmaxxing -- help
```

nix-darwin (overlay जोड़ता है ताकि `pkgs.tokenmaxxing` resolve हो):

```nix
{
  inputs.tokenmaxxing.url = "github:anaclumos/tokenmaxxing";
  modules = [
    inputs.tokenmaxxing.darwinModules.withOverlay
    { programs.tokenmaxxing.enable = true; }
  ];
}
```

Home Manager (पैकेज स्पष्ट रूप से सेट करें, या इस flake का overlay उन pkgs पर लागू करें जिन्हें Home Manager इस्तेमाल करता है):

```nix
{
  imports = [ inputs.tokenmaxxing.homeManagerModules.default ];
  programs.tokenmaxxing.enable = true;
  programs.tokenmaxxing.package = inputs.tokenmaxxing.packages.${pkgs.system}.default;
}
```

Nix केवल CLI को PATH पर रखता है। खाता आयात, PATH पर `claude` सुपरवाइज़र shim, `settings.json` हुक, और (डिफ़ॉल्ट रूप से) आवधिक जाँच टाइमर अभी भी `tokenmaxxing init` से आते हैं। ये क्रेडेंशियल और उपयोगकर्ता-स्वामित्व वाली सेटिंग्स छूते हैं जिन्हें एक शुद्ध मॉड्यूल को फिर से नहीं लिखना चाहिए। `programs.tokenmaxxing.checkTimer.enable = true` तभी सेट करें जब आप चाहते हों कि टाइमर init के बजाय Nix के पास हो (यह `TOKENMAXXING_SKIP_TIMER=1` भी निर्यात करता है ताकि init दूसरी यूनिट न लिखे)। घोषणात्मक टाइमर एक उपयोगकर्ता-सेशन टाइमर है, बिल्कुल init की तरह। हेडलेस Linux पर उसे बिना लॉगिन के चलने के लिए `loginctl enable-linger` चाहिए।

`bun.lock` बदलने पर Nix निर्भरता व्यंजक फिर से बनाएँ:

```sh
bun run nix:bun   # writes bun.nix via bun2nix@2.1.2
```
