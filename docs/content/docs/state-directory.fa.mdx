---
title: چیدمان دایرکتوری وضعیت
description: "هر فایل و دایرکتوری زیر ~/.config/tokenmaxxing"
---

همه چیز زیر `~/.config/tokenmaxxing/` زندگی می‌کند (قابل بازنویسی با `TOKENMAXXING_HOME`؛ هر مسیر قابل مشاهده از بیرون یک بازنویسی محیطی دارد تا کل ابزار بتواند به‌صورت محصور در تست‌ها اجرا شود).

| مسیر | چه نگه می‌دارد |
|---|---|
| `config.json` | پیکربندی شما (پراکنده؛ پیش‌فرض‌ها به‌ازای هر فیلد اعمال می‌شوند) |
| `accounts.json` | نمایه غیرمحرمانه حساب‌های استخرشده Claude: برچسب‌ها، شناسه‌ها، پنجره‌های مصرف نهانی‌شده. هرگز توکن‌ها |
| `usage.json` | عکس فوری پنجره مجموع مربوط به شاخه statusline؛ mtime آن ضربان زنده‌بودن خوراک است |
| `model-usage.json` | سقف‌های هفتگی به‌ازای هر مدل نهانی‌شده با TTL از `/usage` |
| `lastswap.json` | برچسب زمانی اپوک آخرین جابه‌جایی؛ دوره خنک‌شدن ۴۵ ثانیه‌ای را هدایت می‌کند |
| `depleted.json` | انتظار استخر تهی ثبت‌شده، که توسط قلاب‌های خواهر/برادر تکرار می‌شود تا زمانی که بازنشانی بگذرد، جایگاه زنده جابه‌جا شود، یا هر جابه‌جایی‌ای کامل شود |
| `lock` | فایل `flock` که جابه‌جایی‌ها را ترتیبی‌سازی می‌کند |
| `serve-lock` | فلاک تک‌نمونه‌ای `xx serve`: نسل جدید یک شبح تا خروج کامل نسل قبلی این‌جا مسدود می‌ماند |
| `sessions/<session-id>.json` | پرچم‌های اجرای هر نشست تحت‌نظارت که ناظر برای بازآفرینی‌ها ماندگار می‌کند؛ پس از ۳۰ روز بی‌کاری هرس می‌شود (مطابق با نگه‌داری رونوشت خود claude) |
| `tokenmaxxing.log` | گزارش رویداد فقط-افزودنی |
| `bin/` | شیم‌های PATH: `claude`، `codex`، و نقاط ورود `tokenmaxxing` / `xx` |
| `respawn/<session-id>` | نشانگرهای بازآفرینی انتظار-تهی که ناظر مراقب آن‌هاست |
| `creds/` | فقط Linux: فایل‌های اعتبارنامه پارک‌شده، ۰۶۰۰ در یک دایرکتوری ۰۷۰۰ (در macOS به‌جای آن، اعتبارنامه‌ها به‌عنوان اقلام keychain به‌ازای هر حساب پارک می‌شوند) |
| `onboard/`، `sample/` | خانه‌های پیکربندی ایزوله یک‌بارمصرف برای ورودهای `add`/`auth` و کاوش‌های `/usage` حساب‌های پارک‌شده؛ خانه‌های onboard که اعتبارنامه‌های متن ساده را نگه می‌دارند پس از برداشت حذف می‌شوند |
| `slack.json` | توکن‌ها و پیوندهای کانال `xx serve` (۰۶۰۰) |
| `slack-threads/` | رکوردهای نشست به‌ازای هر رشته برای `xx serve` |
| `codex-*` | استخر موازی Codex: `codex-accounts.json`، `codex-lastswap.json`، `codex-lock`، `codex-creds/`، `codex-onboard/`، `codex-respawn/`، `codex-reconcile/` (سیگنال‌های میان‌نشستی که از ناظر یک نشست خواهر/برادر می‌خواهند تا روی حساب زنده بازآفرینی شود)، و `codex-live/` (یک فایل حضور اعتبارسنجی‌شده با PID به‌ازای هر نشست codex تحت نظارت در حال اجرا، بنابراین یک حساب زنده هرگز یک هدف جابه‌جایی نیست) |

بیرون از دایرکتوری خودش، tokenmaxxing دقیقاً این‌ها را دست می‌زند: `~/.claude.json` (جابه‌جایی `oauthAccount`)، `settings.json` مربوط به Claude Code (ورودی‌های قلاب و statusline)، مخزن اعتبارنامه زنده (قلم keychain با نام `Claude Code-credentials` روی macOS، `.credentials.json` روی Linux)، قفل‌های نوسازی خود claude که در حین جابه‌جایی‌ها گرفته می‌شوند (قفل اصلی `.oauth_refresh.lock` درون دایرکتوری پیکربندی claude، به‌علاوه خواهر/برادر قدیمی `~/.claude.lock`)، `auth.json` و `hooks.json` مربوط به codex، و واحد بررسی دوره‌ای در launchd یا systemd.
