---
title: स्थिती डिरेक्टरी मांडणी
description: "~/.config/tokenmaxxing अंतर्गत प्रत्येक फाइल आणि डिरेक्टरी"
---

सर्व काही `~/.config/tokenmaxxing/` अंतर्गत राहते (`TOKENMAXXING_HOME` ने ओव्हरराइड करता येते; प्रत्येक बाह्यरित्या निरीक्षण करण्यायोग्य मार्गाला एक env ओव्हरराइड आहे जेणेकरून संपूर्ण साधन चाचण्यांमध्ये पूर्णपणे विलगपणे चालू शकते).

| मार्ग | ते काय धरते |
|---|---|
| `config.json` | तुमचे कॉन्फिगरेशन (विरळ; डीफॉल्ट्स प्रति फील्ड लागू होतात) |
| `accounts.json` | पूल केलेल्या Claude खात्यांचा गुप्त-नसलेला निर्देशांक: लेबले, ids, कॅश केलेल्या वापर विंडोज. कधीही टोकन्स नाहीत |
| `usage.json` | statusline टीचा एकत्रित विंडो स्नॅपशॉट; त्याचा mtime फीडचा जिवंतपणा दर्शवणारा ठोका आहे |
| `model-usage.json` | `/usage` कडून TTL-कॅश केलेल्या प्रति-मॉडेल साप्ताहिक मर्यादा |
| `lastswap.json` | शेवटच्या बदलाचा युग टाइमस्टॅम्प; ४५-सेकंदांचा कूलडाउन चालवतो |
| `depleted.json` | संपलेल्या-पूलची नोंदवलेली प्रतीक्षा, जी सिबलिंग हुक्स रीसेट होईपर्यंत, थेट सीट हलेपर्यंत, किंवा कोणताही बदल पूर्ण होईपर्यंत पुन्हा वाजवतात |
| `lock` | बदलांना क्रमवार करणारी `flock` फाइल |
| `sessions/<session-id>.json` | पर्यवेक्षक respawn साठी टिकवून ठेवणाऱ्या प्रति-व्यवस्थापित-सत्र लाँच फ्लॅग्ज; ३० दिवस निष्क्रिय राहिल्यावर छाटल्या जातात (claude च्या स्वतःच्या ट्रान्स्क्रिप्ट धारणेशी जुळणारे) |
| `tokenmaxxing.log` | केवळ-जोडणी घटना लॉग |
| `bin/` | PATH शिम्स: `claude`, `codex`, आणि `tokenmaxxing` / `xx` एंट्री पॉइंट्स |
| `respawn/<session-id>` | पर्यवेक्षक ज्यांवर लक्ष ठेवतो ते संपलेल्या-प्रतीक्षेचे respawn मार्कर्स |
| `creds/` | फक्त Linux: पार्क केलेल्या क्रेडेन्शियल फाइल्स, 0700 डिरेक्टरीमध्ये 0600 (macOS त्याऐवजी क्रेडेन्शियल्स प्रति-खाते कीचेन आयटम्स म्हणून पार्क करते) |
| `onboard/`, `sample/` | `add`/`auth` लॉगिन आणि पार्क-खाते `/usage` प्रोब्ससाठी टाकाऊ विलग कॉन्फिग होम्स; साध्या-मजकूर क्रेडेन्शियल्स धरणारी onboard होम्स संकलनानंतर हटवली जातात |
| `codex-*` | समांतर Codex पूल: `codex-accounts.json`, `codex-lastswap.json`, `codex-lock`, `codex-creds/`, `codex-onboard/`, `codex-respawn/`, `codex-reconcile/` (सिबलिंग सत्राच्या पर्यवेक्षकाला थेट खात्यावर respawn करण्यास सांगणारे क्रॉस-सेशन सिग्नल्स), आणि `codex-live/` (प्रति चालू पर्यवेक्षित codex सत्र एक PID-पडताळलेली उपस्थिती फाइल, त्यामुळे थेट खाते कधीही बदल लक्ष्य नसते) |

स्वतःच्या डिरेक्टरीबाहेर, tokenmaxxing नेमके यांनाच स्पर्श करते: `~/.claude.json` (`oauthAccount` बदल), Claude Code ची `settings.json` (हुक आणि statusline नोंदी), थेट क्रेडेन्शियल स्टोअर (macOS वर `Claude Code-credentials` कीचेन आयटम, Linux वर `.credentials.json`), बदलांदरम्यान घेतलेले claude चे स्वतःचे रीफ्रेश लॉक्स (claude च्या कॉन्फिग डिरेक्टरीमधील प्राथमिक `.oauth_refresh.lock`, तसेच लेगसी सिबलिंग `~/.claude.lock`), codex ची `auth.json` आणि `hooks.json`, आणि launchd किंवा systemd मधील नियतकालिक-तपासणी युनिट.
