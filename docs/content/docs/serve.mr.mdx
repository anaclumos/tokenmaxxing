---
title: "Slack ब्रिज: xx serve"
description: "xx serve Socket Mode वर Slack थ्रेड्समधून Claude Code सत्रे चालवते"
---

`tokenmaxxing serve` Socket Mode वर एक स्थानिक Slack डिमन चालवतो - कोणत्याही सार्वजनिक URL ची गरज नाही. सेटअप:

```sh
tokenmaxxing serve setup                    # अॅप मॅनिफेस्ट प्रिंट करते, दोन टोकन्ससाठी विचारते
tokenmaxxing serve link <channel-id> <repo> # एक चॅनेल एका रेपो चेकआउटशी जोडा
tokenmaxxing serve                          # डिमन चालवा
```

लिंक केलेल्या चॅनेलमध्ये बॉटचा उल्लेख करा आणि तो त्या थ्रेडसाठी, लिंक केलेल्या रेपो चेकआउटमध्ये एक Claude Code सत्र उघडतो. प्रत्येक थ्रेड संदेश `resume` सह एक Agent SDK `query()` चालवतो - कधीही सतत स्ट्रीमिंग क्वेरी नाही - त्यामुळे `ensureBestAccount()` प्रत्येकाच टर्नला पूलचे पुन्हा-मूल्यांकन करते आणि डिमन थ्रेड्स न गमावता पुन्हा सुरू होऊ शकतो (थ्रेड नोंदी टिकाऊ आहेत; डिमन सुरुवातीला त्यांना पुन्हा-सबस्क्राइब करतो).

लक्षणीय वर्तन:

- **स्ट्रीमिंग**: उत्तरे मूळतः Slack मध्ये स्ट्रीम होतात, विचारांसाठी आणि साधन धावांसाठी कार्य कार्ड्ससह, हायलाइटिंगसह प्रस्तुत केलेला फेन्स्ड कोड, किंमत आणि कालावधीसह एक शेवटचे "Turn" कार्ड, आणि जेव्हा साधन धाव स्ट्रीम केलेल्या मजकुरात व्यत्यय आणते तेव्हा एक नवीन Slack संदेश उघडला जातो, त्यामुळे एक टर्न साधन धावांभोवती वेगवेगळे संदेश म्हणून वाचला जातो. TodoWrite कॉल्स एक स्थिर चेकलिस्ट कार्ड जागच्या जागी अद्यतनित करतात.
- **परवानग्या**: प्रति-लिंक `permissionMode` डीफॉल्ट `acceptEdits` असतो; `--yolo` (टोपणनाव `--dangerous`) एका लिंकला `bypassPermissions` मध्ये निवडतो. रिले केलेल्या टर्नमध्ये इंटरॲक्टिव्ह संवाद अनुमत नाहीत - कोणीही Slack द्वारे एकाचे उत्तर देऊ शकत नाही - त्यामुळे मॉडेल गद्यात विचारते आणि तुमचे थ्रेड उत्तर पुढील टर्न असते. एक बंडल केलेली प्लगइन स्किल त्याला विनंतीकर्त्याला टॅग करायला आणि निर्णय आवश्यक असताना टर्न संपवायला शिकवते.
- **स्थिती रिॲक्शन्स**: ज्या संदेशाने टर्न सुरू केला तो त्याची स्थिती इमोजी रिॲक्शन म्हणून वाहतो: टर्न चालू असताना एक hourglass, नंतर एक चेक मार्क (पूर्ण), एक x (अयशस्वी), किंवा एक प्रश्नचिन्ह (मॉडेलला तुमचा निर्णय हवा आहे). सध्याच्या मॅनिफेस्टमधील `reactions:write` स्कोप आवश्यक आहे; विद्यमान अॅप्सनी मॅनिफेस्ट पुन्हा पेस्ट करून पुन्हा इन्स्टॉल करावे.
- **लक्ष आणि स्मरण**: जेव्हा मॉडेल तुम्हाला निर्णय विचारते, तेव्हा ते एका इन-प्रोसेस `need_attention` साधनाला कॉल करते, त्यामुळे डिमनला कळते की थ्रेड तुमची वाट पाहत आहे. तुम्ही १० मिनिटे शांत राहिल्यास ते थ्रेडमध्ये तुम्हाला एकदा टॅग करते. थ्रेड वाट पाहत असताना, प्रश्नावर रिॲक्शन देणे तुमचे उत्तर म्हणून रिले होते (thumbs up शिफारस केलेला पर्याय निवडतो); ट्रॅक केलेल्या थ्रेडमध्ये तुम्ही जोडलेली इतर कोणतीही रिॲक्शन पुढील टर्नमध्ये संदर्भ म्हणून समाविष्ट होते. `reactions:read` आणि `reaction_added` इव्हेंट आवश्यक आहेत.
- **स्लॅश कमांड्स**: ज्या थ्रेड संदेशाचा छाटलेला मजकूर `/` ने सुरू होतो तो एक claude स्लॅश कमांड म्हणून चालतो. Slack चा कंपोझर `/` ने सुरू होणारे संदेश खातो, त्यामुळे उल्लेख-प्रथम स्वरूप (`@bot /usage`) किंवा एक अग्रगण्य स्पेस वापरा.
- **सुरळीत बंद**: SIGTERM/SIGINT निचरा करते - नवीन टर्न मोठ्याने टाकले जातात, उड्डाणातील टर्नना ५ मिनिटांपर्यंत वेळ मिळतो, आणि claude मूल त्याच्या स्वतःच्या प्रक्रिया गटात वेगळे चालते जेणेकरून टर्मिनल Ctrl-C निचरा टर्न जतन करण्याआधी त्याला मारू शकत नाही.
- **थ्रेड साफसफाई**: जेव्हा तुम्ही त्याला काम पूर्ण झाल्याचे सांगता, तेव्हा मॉडेल एका इन-प्रोसेस `finish_thread` साधनाला कॉल करते; टर्न पूर्णपणे संपल्यानंतर, डिमन थ्रेड नोंद टाकतो, अनसबस्क्राइब करतो, आणि एक पुष्टीकरण पोस्ट करतो. एक ताजा उल्लेख नवीन सत्र सुरू करतो.
- **त्रुटी स्वच्छता**: टर्न त्रुटी छाटलेला केवळ-संदेश मजकूर पोस्ट करतात, कधीही कच्च्या त्रुटी बॉडी नाहीत.
