---
title: Honest limitations
description: "The tradeoffs wey dey come with pooled hot-swapping"
---

- **One cold turn.** Prompt cache na org-scoped, so the first turn for one new account go re-upload context one time.
- **Depleted-pause hiccup.** Only one fully depleted pool dey stop the session for the countdown; anything wey you type for dat split second na loss.
- **Adoption lag.** For macOS the first turn within ~30 seconds of one swap fit still meter the old account; the bars im headroom dey absorb am.
- **Shared blast radius.** All default-profile sessions dey share one live credential, so one swap dey move dem all together (each dey adopt for the same place).
- **Plaintext credentials for Linux.** Claude Code imself dey store Linux credentials as one 0600 plaintext file; tokenmaxxing im parked copies dey follow the same model.
- **One pool per host.** To pool the same accounts for several machines dey work, but every host dey park and rotate tokens on im own, no cross-host lock dey: if two hosts dey refresh the same account token for the same time, dem go race, and for Codex, if refresh come from one stale parked copy, e go kill dat login finish (OpenAI dey invalidate the whole grant family once refresh-token repeat, so e go force `auth` for every host). If you pool one account for more than one machine, expect say Claude go sometimes need re-auth, and for Codex make you no do am at all.
