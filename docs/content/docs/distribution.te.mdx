---

npm ప్యాకేజీ TypeScript సోర్స్‌ను పంపుతుంది, బిల్డ్‌ను కాదు: `tokenmaxxing` బిన్ నేరుగా Bun షెబ్యాంగ్‌తో `src/main.ts`ను సూచిస్తుంది, మరియు Bun 1.2.6 లేదా అంతకంటే కొత్తది దాన్ని ఉన్నదున్నట్లే నడుపుతుంది. అందుకే Bun ఒక కఠినమైన అవసరం. రూపకల్పన ప్రకారం సంకలనం చేయబడిన బైనరీలు ఏవీ లేవు: ఒక ప్రారంభ విడుదల ప్రతి ప్లాట్‌ఫారమ్‌కు ఒకే 61 MB macOS బైనరీని పంపింది మరియు Linux పై `exec format error`తో విఫలమైంది, మరియు ప్రతి-ప్లాట్‌ఫారమ్ సంకలనం చేయబడిన ప్యాకేజీలకు ప్రతిదానికీ దాని స్వంత విడుదల పైప్‌లైన్ అవసరమవుతుంది, కాబట్టి సోర్స్-Bun-చే-నడపబడేది పంపిణీ నమూనాగా మారింది.

ప్యాకేజీ యొక్క `exports` మ్యాప్ [ఏజెంట్ SDK ఉపరితలం](/te/sdk)లో వివరించిన ప్రోగ్రామాటిక్ ఎంట్రీగా `src/sdk.ts`ను బహిర్గతం చేస్తుంది. విడుదలలు GitHub పై `v<version>`గా ట్యాగ్ చేయబడతాయి; CI ట్రస్టెడ్ పబ్లిషింగ్ (OIDC, ప్రొవెనెన్స్‌తో) ద్వారా npmకి ప్రచురిస్తుంది, మరియు ప్రచురణ గేట్ మొదట టైప్‌చెక్‌ను నడుపుతుంది.

## Nix / nix-darwin

అదే సోర్స్ ట్రీ ఒక flake కూడా. సోర్స్-Bun-చే-నడపబడే మోడల్‌ను ఉంచుతుంది ([bun2nix](https://github.com/nix-community/bun2nix) యొక్క `writeBunApplication` ద్వారా) మరియు వీటిని బహిర్గతం చేస్తుంది:

| అవుట్‌పుట్ | ప్రయోజనం |
|---|---|
| `packages.default` | PATHపై `tokenmaxxing` + `xx` |
| `darwinModules.default` / `withOverlay` | nix-darwin: CLIని ఇన్‌స్టాల్ చేయి (ఐచ్ఛిక డిక్లరేటివ్ చెక్ టైమర్) |
| `homeManagerModules.default` | macOS లేదా Linuxపై Home Manager |
| `nixosModules.default` / `withOverlay` | NixOS సిస్టమ్ ఇన్‌స్టాల్ |

ప్రొఫైల్‌లో ఇన్‌స్టాల్ చేయండి (తద్వారా `init` రాసే సూపర్‌వైజర్ shimలు PATHపై స్థిరమైన `tokenmaxxing`ను resolve చేయగలవు), ఆపై init చేయండి:

```sh
nix profile install github:anaclumos/tokenmaxxing
tokenmaxxing init
```

ఇన్‌స్టాల్ చేయకుండా ఒక్కసారి నడపడం (help / status మాత్రమే, ఈ పద్ధతిలో `init` చేయవద్దు):

```sh
nix run github:anaclumos/tokenmaxxing -- help
```

nix-darwin (`pkgs.tokenmaxxing` resolve అయ్యేలా overlay జోడిస్తుంది):

```nix
{
  inputs.tokenmaxxing.url = "github:anaclumos/tokenmaxxing";
  modules = [
    inputs.tokenmaxxing.darwinModules.withOverlay
    { programs.tokenmaxxing.enable = true; }
  ];
}
```

Home Manager (ప్యాకేజీని స్పష్టంగా సెట్ చేయండి, లేదా Home Manager వాడే pkgsకు ఈ flake యొక్క overlayను వర్తింపజేయండి):

```nix
{
  imports = [ inputs.tokenmaxxing.homeManagerModules.default ];
  programs.tokenmaxxing.enable = true;
  programs.tokenmaxxing.package = inputs.tokenmaxxing.packages.${pkgs.system}.default;
}
```

Nix CLIని PATHపై మాత్రమే ఉంచుతుంది. ఖాతా దిగుమతి, PATHపై `claude` సూపర్‌వైజర్ shim, `settings.json` హుక్స్, మరియు (డిఫాల్ట్‌గా) కాలానుగుణ చెక్ టైమర్ ఇంకా `tokenmaxxing init` నుండి వస్తాయి. ఇవి క్రెడెన్షియల్స్ మరియు వినియోగదారు యాజమాన్య సెట్టింగ్‌లను తాకుతాయి; స్వచ్ఛమైన మాడ్యూల్ వాటిని తిరిగి రాయకూడదు. టైమర్ initకి బదులు Nixకి ఉండాలనుకున్నప్పుడు మాత్రమే `programs.tokenmaxxing.checkTimer.enable = true` సెట్ చేయండి (అది `TOKENMAXXING_SKIP_TIMER=1`ను కూడా ఎగుమతి చేస్తుంది, తద్వారా init రెండవ యూనిట్‌ను రాయదు). డిక్లరేటివ్ టైమర్ initలాగే ఒక యూజర్-సెషన్ టైమర్. హెడ్‌లెస్ Linuxలో లాగిన్ లేకుండా అది ప్రేరేపించబడాలంటే `loginctl enable-linger` అవసరం.

`bun.lock` మారినప్పుడు, Nix డిపెండెన్సీ ఎక్స్‌ప్రెషన్‌ను మళ్లీ రూపొందించండి:

```sh
bun run nix:bun   # writes bun.nix via bun2nix@2.1.2
```
