---
title: 正直な制限
description: "プールされたホットスワップに伴うトレードオフ"
---

- **1回のコールドターン。** プロンプトキャッシュは組織スコープであるため、新しいアカウントでの最初のターンは1度だけコンテキストを再アップロードします。
- **枯渇一時停止の引っかかり。** 完全に枯渇したプールだけがカウントダウンのためにセッションを止めます。その一瞬に入力したものは失われます。
- **採用ラグ。** macOS では切り替えから約30秒以内の最初のターンが依然として古いアカウントを計測することがあります。バーの余裕が吸収します。
- **共有の爆発半径。** デフォルトプロファイルのすべてのセッションが1つのライブ認証情報を共有するため、切り替えるとすべてがまとめて移動します (各セッションがその場で採用します)。
- **Linux での平文認証情報。** Claude Code 自身が Linux の認証情報を0600の平文ファイルとして保存します。tokenmaxxing のパークコピーも同じ方式に従います。
- **ホストごとに1つのプール。** 同じアカウントを複数のマシンでプールすること自体は可能ですが、各ホストはトークンのパークと更新をクロスホストロックなしで独立して行うため、同じアカウントのトークンを複数のホストが同時にリフレッシュすると競合が起こります。Claude では、リフレッシュのローテーションが直前のアクセストークンを即座に失効させるため、もう一方のホストのセッションは401で失敗し、その古いリフレッシュトークンは `invalid_grant` (再認証が必要) として返ってきます。Codex の場合、古いパーク済みコピーからのリフレッシュはそのログインにとって致命的です (OpenAI はリフレッシュトークンの再利用を検知するとグラントファミリー全体を無効化し、すべてのホストで `auth` が必要になります)。1つのアカウントを複数のマシンでプールする場合、Claude では再認証の手間を覚悟し、Codex ではそれを完全に避けてください。
