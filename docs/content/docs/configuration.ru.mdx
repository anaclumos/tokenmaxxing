---
title: Конфигурация
description: "Схема config.json, пороги и параметры политики"
---

Конфигурация - это JSON в `~/.config/tokenmaxxing/config.json`. Каждое поле необязательно; значения по умолчанию применяются к каждому полю.

```json
{
  "thresholds": { "session": [50, 80, 95], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 50,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000
  }
}
```

- `thresholds.session`: 5-часовая лестница, восходящий список ступеней отсева. Каждая оценка выбирает одну активную ступень - самую низкую ступень, на которой ещё пригоден хотя бы один аккаунт из пула, - и эта ступень служит одновременно триггером и фильтром кандидатов. Codex читает только верхнюю ступень. См. [Как принимается решение о переключении](/ru/switching).
- `thresholds.weekly`: недельный барьер отсева, покрывающий и 7-дневный агрегат, и каждый недельный лимит по модели.
- `hardThresholds.session` / `hardThresholds.weekly`: барьеры стены (по умолчанию 100, реальный серверный лимит каждого аккаунта). `hardThresholds.session` должен быть не ниже верхней ступени сессии. Когда каждый аккаунт превышает свой барьер отсева, автоматическое решение Claude дожимает каждый из них до его стены перед парковкой - см. [Стена](/ru/switching). Установите их равными верхней ступени и недельному барьеру, чтобы отключить; Codex игнорирует эту настройку.
- `claudeBin` / `codexBin`: закрепляет РЕАЛЬНЫЕ бинарники, которые запускают супервизоры (записываются командами `init` / `init --codex`; диагностика защиты от рекурсии подсказывает исправить здесь `claudeBin`, когда он перестаёт указывать на настоящий бинарник Claude).
- `policy.projectionMargin`: вычитается из каждой ступени сессии, недельного барьера и барьеров стены для формирования действующих порогов.
- `policy.greedySessionFloor`: процент использования сессии, при котором вовлекается жадное схождение.
- `policy.switchModels`: семейства моделей, чей недельный лимит по модели блокирует переключение (записи приводятся к нижнему регистру при загрузке).
- `policy.usagePollTtlMs`: как долго остаётся свежим опрос `/usage` по моделям.
- `policy.maxWaitMs`: граница автоожидания при исчерпанном пуле.

`tokenmaxxing config` показывает действующую конфигурацию с источниками; `config set`/`unset` редактируют ключи через точку; `config tidy` удаляет неизвестные ключи.
