---
title: "جسر Slack: xx serve"
description: "xx serve بيشغّل sessions بتاعت Claude Code من threads بتاعت Slack عبر Socket Mode"
---

`tokenmaxxing serve` بيشغّل daemon محلي لـ Slack عن طريق Socket Mode، من غير حاجة لـ URL عام. الإعداد:

```sh
tokenmaxxing serve setup                    # بيطبع manifest التطبيق، وبيطلب الـ token الاتنين
tokenmaxxing serve link <channel-id> <repo> # اربط قناة بـ checkout لريبو
tokenmaxxing serve                          # شغّل الـ daemon
```

منشِن البوت في قناة مربوطة وهيفتح Claude Code session للـ thread ده، في الـ repo checkout المربوط. كل turn جديد بيشغّل `query()` واحدة من الـ Agent SDK مع `resume`، عشان `ensureBestAccount()` بيعيد تقييم الـ pool في كل turn والـ daemon يقدر يعمل restart من غير ما يخسر الـ threads (سجلات الـ thread دايمة؛ الـ daemon بيعيد الاشتراك فيها عند الإقلاع)، أما الرد اللي بيوصل والـ query لسه شغّال فبيتغذّى في الـ streaming input بتاعه بدل ما يشغّل query لوحده؛ والرد اللي بيفوّت شبّاك التوجيه بيشتغل كـ الـ turn اللي بعده.

سلوك ملحوظ:

- **التوجيه**: أي رد بيوصل والـ turn بتاع الـ thread لسه شغّال بيتلمّ جوّه نفس الـ turn ده. ده نفس فكرة الحقن في نص الـ turn اللي Claude Code بيستخدمها وهو شغّال تفاعليًا، عشان كده الموديل يشوف الرد ده عند أقرب حدّ أداة وياخد قرار يعدّل بيه مساره بدل ما يخلّص الحاجة الغلط الأول. الرد اللي بيوصل بعد آخر استدعاء أداة في الـ turn بيشتغل كـ turn لوحده على طول بعديه؛ في الحالتين الاتنين مفيش حاجة بتضيع. الرسايل اللي اتوجّهت بالشكل ده بتاخد ريأكشن الساعة الرملية وبتخلص مع الـ turn، ونصها بيركب على العلامة الدايمة بتاعة الـ turn، عشان كده أي restart أو استئناف لحد الاستخدام يرجع يشغّلها تاني. الرسالة الوحيدة اللي مش بتتلمّ هي اللي مصطفة ورا رسالة تانية مستنية (الترتيب بيتحفظ)، والـ daemon وهو بيصرّف لسه بيرمي الرسايل بصوت عالي بدل ما يوجّهها.
- **البث**: الردود بتتبثّ بشكل أصلي في Slack، مع task cards للتفكير وتشغيل الأدوات، وكود محاط برندره بتظليل، وكارت "Turn" ختامي بالتكلفة والمدة؛ كل كروت الـ turn بتتلم في plan block واحد قابل للفتح، عشان الـ turn عادةً يتقرا كرسالة واحدة: الرد زائد dropdown واحد فيه نشاطه (إعادة محاولة في نص الـ turn أو append مرفوض بيفتح رسالة متابعة). استدعاءات TodoWrite بتحدّث كارت checklist ثابت واحد في مكانه.
- **الصلاحيات**: `permissionMode` لكل رابط بيكون الافتراضي `acceptEdits`؛ `--yolo` (الاسم المختصر `--dangerous`) بيخلّي الرابط يختار `bypassPermissions`. الحوارات التفاعلية ممنوعة في الـ turns المُمرَّرة. مفيش حد يقدر يجاوب واحدة عن طريق Slack، فالموديل بيسأل بالكلام وردّك في الـ thread هو الـ turn اللي بعده. فيه skill إضافي مدمج بيعلّمه إنه يعمل tag للطالب وينهي الـ turn لما يحتاج قرار.
- **ريأكشنات الحالة**: الرسالة اللي شغّلت الـ turn بتشيل حالتها كـ emoji reaction: ساعة رملية والـ turn شغّال، وبعدين علامة صح (خلص)، أو x (فشل)، أو علامة استفهام (الموديل محتاج قرارك). محتاجة صلاحية `reactions:write` من الـ manifest الحالي؛ التطبيقات الموجودة لازم تلزق الـ manifest تاني وتعيد التثبيت.
- **الانتباه والتنبيهات**: لما الموديل يسألك عن قرار بينادي أداة `need_attention` جوّا العملية، فالـ daemon يعرف إن الـ thread مستني ردّك. لو سكتّ 10 دقايق بيعملك tag مرة واحدة في الـ thread. وطول ما الـ thread مستني، لما تعمل reaction على السؤال بتتمرّر كإجابتك (اللايك بيختار الخيار الموصى بيه)؛ وأي reaction تانية تضيفها في thread متتبَّع بتتضاف كسياق في الـ turn اللي بعده. محتاجة `reactions:read` وحدث `reaction_added`.
- **أوامر السلاش**: رسالة thread نصها بعد التجريد بيبدأ بـ `/` بتشتغل كـ claude slash command. الـ composer بتاع Slack بياكل الرسايل اللي بتبدأ بـ `/`، فاستخدم صيغة المنشِن الأول (`@bot /usage`) أو مسافة في الأول.
- **الاستئناف التلقائي عند حد الاستخدام**: لما كل حساب في الـ pool يوصل لحده، انقطاع قصير بيركن الرسالة وبيعيد المحاولة في مكانها؛ انقطاع أطول بيبعت إشعار انتظار ويستأنف الـ turn تلقائيًا لما الـ pool يرجع يشتغل، وده بيفضل شغال حتى لو الـ daemon عمل restart. الحد اللي مالوش وقت رجوع معروف بس هو اللي بيطلب منك تبعت الرسالة تاني.
- **الإغلاق السلس**: SIGTERM/SIGINT بيصرّف: الـ turns الجديدة بتتشال بصوت عالي، والـ turns اللي شغّالة بتاخد لغاية 5 دقايق، والـ claude child بيشتغل منفصل في مجموعة العمليات الخاصة بيه عشان Ctrl-C من التيرمينال مايقدرش يقتله قبل ما التصريف يحافظ على الـ turn.
- **تنظيف الـ thread**: لما تقوله الشغل خلص، الموديل بينادي أداة `finish_thread` جوّا العملية؛ بعد ما الـ turn يخلص تمامًا، الـ daemon بيشيل سجل الـ thread، وبيلغي الاشتراك، وبيبعت تأكيد واحد. أي منشِن جديد بيبدأ session جديدة.
- **نظافة الأخطاء**: أخطاء الـ turn بتبعت نص مقصوص رسالة بس، عمره ما أجسام أخطاء خام.
