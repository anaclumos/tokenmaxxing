tokenmaxxing은 하나의 다중 호출 진입점(`src/main.ts`)입니다. 그 이름으로 호출되면 `claude` supervisor로 동작하고, 내부 서브커맨드로 훅과 statusline shim을 제공하며, 그 외에는 CLI를 디스패치합니다. Bun 위에서 직접 실행됩니다. npm 패키지는 빌드 산출물이 아니라 TypeScript 소스를 배포합니다.

구성 요소는 다음과 같습니다.

## supervisor shim

`init`은 `claude`라는 이름의 두 줄짜리 셸 shim을 `~/.config/tokenmaxxing/bin/`에 작성하고 그 디렉터리를 PATH 맨 앞에 둡니다. `claude`를 입력하면 shim이 supervisor를 실행하고, supervisor는 상속된 stdio와 저장된 `stty -g` 터미널 스냅샷으로 실제 claude 바이너리를 생성합니다. 오직 프로세스와 터미널을 관리할 뿐입니다. API 트래픽을 프록시하지 않으며 전송 중인 토큰을 절대 건드리지 않습니다.

프린트 모드 호출(`claude -p`, `--version`, `--help`), 비대화형 서브커맨드(`claude mcp`, `claude config` 등), tokenmaxxing 자체의 프로브는 세션 관리 없이 그대로 통과합니다. 대화형 세션의 경우 supervisor는 세션 id를 고정하고(새로 생성하거나 `--session-id` / `-r` / `-c`로 전달한 값을 재사용) 나중에 다시 실행할 때 재현할 수 있도록 실행 플래그를 저장한 다음, 그 세션에 연결된 respawn 마커 파일을 감시합니다.

## statusline tee

Claude Code는 매 턴마다 rate-limit 데이터(`rate_limits.five_hour`와 `rate_limits.seven_day`)를 statusline의 stdin으로 밀어 넣습니다. tokenmaxxing이 statusline 슬롯을 소유하므로 그 렌더러는 무료 푸시 기반 사용량 피드 역할을 겸합니다. 매 틱마다 합산 윈도우와 활성 모델을 `usage.json`으로 tee합니다. 모델별 상한은 statusline stdin에 없습니다. 오직 `claude -p '/usage'`(무료, 토큰 0개)에서만 나오며 TTL로 폴링되어 활성 모델이 용량 제약을 받을 때 `model-usage.json`에 캐시됩니다.

tee는 변경 시에만 기록합니다(write-on-change). 수치가 바뀌지 않으면 파일의 mtime만 갱신하고, 이 mtime이 피드가 살아 있음을 알리는 하트비트 역할을 합니다. 최신성은 항상 mtime으로 판단하며 내장된 타임스탬프로는 절대 판단하지 않습니다.

## Stop 훅과 교체

매 턴 경계마다 Stop 훅은 전환 결정을 실행합니다([전환 결정 방식](/ko/switching) 참고). 교체가 필요할 때는 `flock(2)` 배타 잠금 아래에서 이뤄지며(macOS에는 `flock(1)` 바이너리가 없으므로 `bun:ffi`로 획득), 자격 증명 쓰기는 추가로 Claude Code 자체의 갱신 잠금과 맞물립니다. 임계 구역 안에서 한 번의 교체는 다음을 수행합니다.

1. 현재 라이브 자격 증명을 그 실제 소유자의 보관 백업으로 수확합니다.
2. 대상 계정의 새로 갱신된 자격 증명을 라이브로 설치하며 기존 라이브 blob에 병합하여 형제 상태(예: MCP 서버별 OAuth 토큰)가 유지되도록 합니다. (대상의 회전된 갱신 토큰은 갱신이 반환되는 순간, flock 아래에서 다만 이 갱신 잠금 임계 구역보다는 앞서 자체 백업에 이미 저장되었습니다.)
3. `~/.claude.json`의 `oauthAccount` 필드를 원자적으로 다시 씁니다.
4. 잠금이 해제되기 전에 새 활성 라벨을 커밋하고 오래된 사용량 스냅샷을 지웁니다. 이 파일들은 함께 크래시 원자성을 가질 수 없으므로 크래시가 나면 중간 상태가 남을 수 있습니다. 다음 교체가 라벨과 무관하게 라이브 자격 증명의 실제 소유자를 판별하고, 감지된 어긋남은 로그에 남깁니다.

모든 기본 프로필 세션이 하나의 라이브 자격 증명을 공유하므로 단 한 번의 교체로 모든 세션이 한꺼번에 이전됩니다. flock과 잠금 아래의 재확인은 경쟁하는 훅이 두 계정을 소진하지 못하게 막습니다.

## 그 자리에서의 채택

실행 중인 claude 세션은 요청 사이에 자격 증명 저장소를 폴링합니다. macOS에서는 짧은 캐시를 거쳐 키체인을 다시 읽고 액세스 토큰을 비교하며, Linux에서는 자격 증명 파일의 mtime을 확인하고 변경 시 토큰 캐시를 비웁니다. 결국 교체된 자격 증명은 재시작 없이 macOS에서는 약 30초 안에, Linux에서는 바로 다음 요청에 실행 중인 모든 세션에 채택됩니다. 그래서 단순 교체는 마커를 쓰지 않고 respawn도 일으키지 않습니다. 세션은 그저 새 계정에서 계속됩니다. 세션 내 `/usage`도 동일한 토큰 캐시를 공유하므로 그 계정 표시도 채택과 함께 바뀝니다.

## 풀 소진 시 대기와 자동 재개

풀의 모든 계정이 각자의 기준선을 넘었을 때에만 Stop 훅이 respawn 마커를 기록합니다(마커 스키마는 `waitUntil` 타임스탬프를 요구하며, 단순 교체는 이 값을 결코 만들 수 없습니다). supervisor는 마커를 감지하면 이미 커밋된 턴 경계에서 자식 프로세스에 SIGTERM을 보냅니다(Stop 훅은 트랜스크립트가 디스크에 기록되고 claude가 유휴 상태가 된 뒤에 실행되므로 손실되는 것이 없습니다). 그런 다음 터미널을 복원하고 가장 빠른 초기화까지 카운트다운을 표시한 뒤 복구된 계정에서 `claude --resume <session-id>`를 다시 실행합니다. 카운트다운 도중 Ctrl-C를 누르면 즉시 재개됩니다. 자동 대기는 `policy.maxWaitMs`(기본 1시간)로 제한됩니다. 그 이상이면 결정은 대기하는 대신 풀이 소진되었다고 보고합니다.

## 주기적 확인 타이머

훅은 턴 경계에서만 발동하는데, 긴 에이전트 턴 하나는 경계가 단 한 번도 없이 윈도우를 건강한 상태에서 소진 상태까지 태워버릴 수 있습니다. 그래서 `init`은 턴 활동과 무관하게 60초마다 `tokenmaxxing check --if-due`를 실행하는 주기적 타이머(macOS에서는 launchd 에이전트, Linux에서는 systemd 사용자 타이머)도 설치합니다. 점검은 라이브 계정의 여유에 맞춰 스스로 주기를 조절합니다. 모든 기준선까지 여유가 넉넉하면 5분마다 평가하고, 기준선에 가까우면 매 틱마다 평가합니다([전환 결정 방식](/ko/switching) 참고).

## SessionStart 훅

세션이 시작되거나 재개될 때 동일한 평가를 실행하여 새 세션이 올바른 계정에서 시작되도록 합니다. 교체 후 쿨다운 덕분에 respawn 직후에는 올바르게 아무 동작도 하지 않습니다.
