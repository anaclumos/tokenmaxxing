---
title: Slack bridge ው፦ xx serve
description: "xx serve የ Claude Code sessionዎችን ከ Slack threadዎች በ Socket Mode ላይ ያሄዳል"
---

`tokenmaxxing serve` local Slack daemon ን በ Socket Mode ያሄዳል - ይፋዊ URL አያስፈልግም። ማዋቀር፦

```sh
tokenmaxxing serve setup                    # የ app manifest ን ያትማል፣ ለሁለቱ tokenዎች ይጠይቃል
tokenmaxxing serve link <channel-id> <repo> # channel ን ከ repo checkout ጋር ያስተሳስራል
tokenmaxxing serve                          # daemon ን ያሄዳል
```

bot ን በተገናኘ channel ውስጥ ይጥቀሱ እና ለዚያ thread በተገናኘ repo checkout ውስጥ Claude Code session ይከፍታል። እያንዳንዱ የ thread መልእክት አንድ Agent SDK `query()` ን ከ `resume` ጋር ያሄዳል - በጭራሽ ቋሚ streaming query አይደለም - ስለዚህ `ensureBestAccount()` pool ን በእያንዳንዱ turn እንደገና ይገመግማል እና daemon ው threadዎችን ሳያጣ ዳግም ማስጀመር ይችላል (የ thread መዝገቦች ዘላቂ ናቸው፤ daemon ው በ startup ላይ እንደገና ይመዘግባቸዋል)።

ትኩረት የሚሹ ባህሪያት፦

- **Streaming**፦ ምላሾች በnative ወደ Slack ይተላለፋሉ፣ ለ thinking እና tool runዎች የ task cardዎች ጋር፣ fenced code በ highlighting የቀረበ፣ እና ከ cost እና duration ጋር የመዝጊያ "Turn" card፤ የአንድ turn cardዎች ሁሉ ወደ አንድ ሊከፈት የሚችል plan block ይታጠፋሉ፣ ስለዚህ turn አብዛኛውን ጊዜ እንደ አንድ መልእክት ይነበባል፦ ምላሹ እና እንቅስቃሴውን የያዘ አንድ dropdown (turn መሃል ላይ ያለ retry ወይም ውድቅ የተደረገ append ተከታይ መልእክት ይከፍታል)። TodoWrite ጥሪዎች አንድ የተረጋጋ checklist card ን በቦታው ያዘምናሉ።
- **Permissions**፦ በ-link `permissionMode` ነባሪው `acceptEdits` ነው፤ `--yolo` (ተለዋጭ ስም `--dangerous`) link ን ወደ `bypassPermissions` ያስገባል። Interactive dialogዎች በተላለፉ turnዎች ውስጥ አይፈቀዱም - ማንም በ Slack በኩል መመለስ አይችልም - ስለዚህ ሞዴሉ በ prose ይጠይቃል እና የ thread ምላሽዎ ቀጣዩ turn ነው። የተጣመረ plugin skill ውሳኔ ሲፈልግ ጠያቂውን እንዲጠቅስ እና turn ን እንዲያጠናቅቅ ያስተምረዋል።
- **የ status reactionዎች**፦ turn ን የቀሰቀሰው መልእክት ሁኔታውን እንደ emoji reaction ይይዛል፦ turn ው በሚሄድበት ጊዜ hourglass፣ ከዚያ check mark (ተጠናቋል)፣ x (አልተሳካም)፣ ወይም question mark (ሞዴሉ ውሳኔዎን ይፈልጋል)። ከአሁኑ manifest የ `reactions:write` scope ን ይፈልጋል፤ ነባር appዎች manifest ን እንደገና መለጠፍ እና እንደገና መጫን አለባቸው።
- **ትኩረት እና ማንቂያዎች**፦ ሞዴሉ ውሳኔ ሲጠይቅዎት in-process `need_attention` tool ን ይጠራል፣ ስለዚህ daemon ው thread ው እርስዎን እየጠበቀ መሆኑን ያውቃል። ለ10 ደቂቃ ዝም ካሉ በ thread ውስጥ አንድ ጊዜ ይጠቅስዎታል። thread እየጠበቀ ሳለ፣ በጥያቄው ላይ reaction ማድረግ እንደ መልስዎ ይተላለፋል (thumbs up የተመከረውን አማራጭ ይመርጣል)፤ በሚከታተል thread ውስጥ የሚጨምሩት ማንኛውም ሌላ reaction ወደ ቀጣዩ turn እንደ context ይታጠፋል። `reactions:read` እና የ `reaction_added` event ን ይፈልጋል።
- **Slash commandዎች**፦ የተከረከመ ጽሁፉ በ `/` የሚጀምር የ thread መልእክት እንደ claude slash command ይሄዳል። የ Slack composer በ `/` የሚጀምሩ መልእክቶችን ይበላል፣ ስለዚህ mention-first ቅጹን (`@bot /usage`) ወይም መጀመሪያ ላይ ክፍተት ይጠቀሙ።
- **Usage-limit auto-resume**፦ በ pool ውስጥ ያለ እያንዳንዱ መለያ ገደቡ ላይ በሚሆንበት ጊዜ፣ አጭር መቆራረጥ መልእክቱን ያቆየዋል እና በቦታው retry ያደርገዋል፤ ረዘም ያለ መቆራረጥ ግን የመጠባበቂያ ማስታወቂያ ይለጥፋል እና pool ው ካገገመ በኋላ turn ውን daemon ዳግም ማስጀመሮችን ተርፎ በራስ-ሰር ይቀጥላል። የማይታወቅ የማገገሚያ ጊዜ ያለው ገደብ ብቻ ዳግም እንዲልኩ ይጠይቅዎታል።
- **Graceful shutdown**፦ SIGTERM/SIGINT ያፈሳል - አዲስ turnዎች በጩኸት ይጣላሉ፣ በበረራ ላይ ያሉ turnዎች እስከ 5 ደቂቃ ያገኛሉ፣ እና claude child በራሱ process group ውስጥ ተነጥሎ ይሄዳል ስለዚህ terminal Ctrl-C drain ው turn ን ከመጠበቁ በፊት ሊገድለው አይችልም።
- **Thread cleanup**፦ ስራው መጠናቀቁን ሲነግሩት፣ ሞዴሉ in-process `finish_thread` tool ን ይጠራል፤ turn ሙሉ በሙሉ ካበቃ በኋላ፣ daemon ው የ thread መዝገቡን ይጥላል፣ ይሰርዛል፣ እና አንድ ማረጋገጫ ይለጥፋል። አዲስ mention አዲስ session ይጀምራል።
- **Error hygiene**፦ የ turn ስህተቶች የተከረከመ መልእክት-ብቻ ጽሁፍ ይለጥፋሉ፣ በጭራሽ ጥሬ የስህተት አካላት አይደሉም።
