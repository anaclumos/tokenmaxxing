npm paketi bir derleme değil, TypeScript kaynağı gönderir: `tokenmaxxing` bin'i bir Bun shebang'ı ile doğrudan `src/main.ts`'i işaret eder ve Bun 1.2.6 veya daha yenisi onu olduğu gibi çalıştırır. Bun'ın katı bir gereklilik olmasının nedeni budur. Tasarım gereği hiçbir derlenmiş ikili dosya yoktur: erken bir sürüm her platforma tek bir 61 MB'lık macOS ikili dosyası gönderdi ve Linux'ta `exec format error` ile başarısız oldu ve platform başına derlenmiş paketlerin her biri kendi yayınlama hattına ihtiyaç duyardı, bu yüzden kaynağın Bun tarafından çalıştırılması dağıtım modeli haline geldi.

Paketin `exports` haritası, [Agent SDK yüzeyi](/tr/sdk) sayfasında açıklanan programatik giriş olarak `src/sdk.ts`'i açığa çıkarır. Sürümler GitHub'da `v<version>` olarak etiketlenir; CI, güvenilir yayınlama (OIDC, provenance ile) yoluyla npm'e yayınlar ve yayınlama kapısı önce typecheck'i çalıştırır.

## Nix / nix-darwin

Aynı kaynak ağacı aynı zamanda bir flake'tir. Kaynağın Bun tarafından çalıştırıldığı modeli korur ([bun2nix](https://github.com/nix-community/bun2nix) `writeBunApplication` üzerinden) ve şunları sunar:

| Çıktı | Amaç |
|---|---|
| `packages.default` | PATH üzerinde `tokenmaxxing` + `xx` |
| `darwinModules.default` / `withOverlay` | nix-darwin: CLI'yi kur (isteğe bağlı bildirimsel denetim zamanlayıcısı) |
| `homeManagerModules.default` | macOS veya Linux'ta Home Manager |
| `nixosModules.default` / `withOverlay` | NixOS sistem kurulumu |

Bir profile kurun (böylece `init`'in gözetmen shim'leri PATH üzerinde kararlı bir `tokenmaxxing` çözebilsin), ardından init çalıştırın:

```sh
nix profile install github:anaclumos/tokenmaxxing
tokenmaxxing init
```

Kurmadan tek seferlik çalıştırma (yalnızca help / status, `init`'i bu yolla çalıştırmayın):

```sh
nix run github:anaclumos/tokenmaxxing -- help
```

nix-darwin (`pkgs.tokenmaxxing` çözülsün diye overlay ekler):

```nix
{
  inputs.tokenmaxxing.url = "github:anaclumos/tokenmaxxing";
  modules = [
    inputs.tokenmaxxing.darwinModules.withOverlay
    { programs.tokenmaxxing.enable = true; }
  ];
}
```

Home Manager (paketi açıkça ayarlayın ya da bu flake'in overlay'ini Home Manager'ın kullandığı pkgs'e uygulayın):

```nix
{
  imports = [ inputs.tokenmaxxing.homeManagerModules.default ];
  programs.tokenmaxxing.enable = true;
  programs.tokenmaxxing.package = inputs.tokenmaxxing.packages.${pkgs.system}.default;
}
```

Nix yalnızca CLI'yi PATH'e koyar. Hesap içe aktarma, PATH'teki `claude` supervisor shim'i, `settings.json` kancaları ve (varsayılan olarak) periyodik denetim zamanlayıcısı hâlâ `tokenmaxxing init`'ten gelir. Bunlar kimlik bilgilerine ve kullanıcının kendi ayarlarına dokunur; saf bir modül bunları yeniden yazmamalıdır. `programs.tokenmaxxing.checkTimer.enable = true` seçeneğini yalnızca zamanlayıcının init yerine Nix'e ait olmasını istediğinizde ayarlayın (bu aynı zamanda `TOKENMAXXING_SKIP_TIMER=1` dışa aktarır, böylece init ikinci bir birim yazmaz). Bildirimsel zamanlayıcı, init ile aynı şekilde bir kullanıcı oturumu zamanlayıcısıdır; başsız Linux'ta bir oturum açma olmadan tetiklenmesi için `loginctl enable-linger` gerekir.

`bun.lock` değişince Nix bağımlılık ifadesini yeniden üret:

```sh
bun run nix:bun   # writes bun.nix via bun2nix@2.1.2
```
