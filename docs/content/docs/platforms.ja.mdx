---
title: "プラットフォームメモ: macOS と Linux"
description: "ストレージ、採用、タイマーで macOS と Linux がどう異なるか"
---

| | macOS | Linux |
|---|---|---|
| ライブ認証情報 | ログインキーチェーンの generic-password アイテム | 0600 `.credentials.json` ファイル |
| パーク済み認証情報 | アカウントごとのキーチェーンアイテム | 0700ディレクトリ内の0600ファイル |
| 切り替え後の採用 | 約30秒以内 (キーチェーン読み取りキャッシュ) | 次のリクエスト (ファイル mtime ポーリング) |
| 定期チェック | launchd エージェント、60秒のフロアティック、60秒から300秒の自己ペース調整 | systemd ユーザータイマー、60秒のフロアティック、60秒から300秒の自己ペース調整 |
| 分離ログインストア | 設定ディレクトリごとにハッシュ名前空間化されたキーチェーンサービス | 分離設定ディレクトリ内のファイル |

Linux 固有で知っておきたい詳細が2つあります。claude は認証情報ディレクトリをまず `CLAUDE_SECURESTORAGE_CONFIG_DIR` から解決し (次に `CLAUDE_CONFIG_DIR`、最後に `~/.claude`)、tokenmaxxing も同じ順序で解決するので、両者がずれることはありません。もう1つは、同じ claude バージョンでも OS ビルドが違うと `/usage` のリセット時刻の書式が変わる点です (一方は " at " でつなぎ、もう一方はカンマで区切ります)。tokenmaxxing のパーサーはこの2つの書式だけを受け付け、それ以外の形式が来ても推測はせず、ログに記録します。

macOS には、正直なところ制限が1つあります。`init` と `add` はあえて対話的にキーチェーンへアクセスするので、最初の `security` アクセスがヘッドレスフック内でコールドにならずに済みます。
