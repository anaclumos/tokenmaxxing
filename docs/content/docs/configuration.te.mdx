---
title: కాన్ఫిగరేషన్
description: "config.json స్కీమా, థ్రెషోల్డ్‌లు, మరియు పాలసీ నాబ్‌లు"
---

కాన్ఫిగ్ `~/.config/tokenmaxxing/config.json` వద్ద JSON. ప్రతి ఫీల్డ్ ఐచ్ఛికం; డిఫాల్ట్‌లు ప్రతి-ఫీల్డ్‌కు వర్తిస్తాయి.

```json
{
  "thresholds": { "session": [90], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 80,
    "greedySwapMargin": 0.15,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000,
    "checkIntervalMs": 60000
  }
}
```

- `thresholds.session`: 5-గంటల నిచ్చెన, అంటే ఆరోహణ క్రమంలో ఉన్న స్క్రీనింగ్ మెట్ల జాబితా. ప్రతి మూల్యాంకనం ఒకే ఒక క్రియాశీల మెట్టును తేల్చుతుంది, అంటే పూల్‌లోని ఏదో ఒక ఖాతా ఇంకా దాటగలిగే అత్యల్ప మెట్టు, మరియు ఆ మెట్టే ట్రిగర్ కూడా, అభ్యర్థి స్క్రీన్ కూడా. Codex పైమెట్టును మాత్రమే చదువుతుంది. [స్విచింగ్ ఎలా నిర్ణయిస్తుంది](/te/switching) చూడండి.
- `thresholds.weekly`: వారపు స్క్రీనింగ్ బార్, ఇది 7-రోజుల మొత్తాన్ని మరియు ప్రతి-మోడల్ వారపు పరిమితి ప్రతిదానినీ కవర్ చేస్తుంది.
- `hardThresholds.session` / `hardThresholds.weekly`: గోడ బార్‌లు (డిఫాల్ట్ 100, ప్రతి ఖాతా నిజమైన సర్వర్ పరిమితి). `hardThresholds.session` పైమెట్టు వద్ద లేదా దాని కంటే పైన ఉండాలి. ప్రతి ఖాతా తన స్క్రీనింగ్ బార్‌ను దాటినప్పుడు, స్వయంచాలక Claude నిర్ణయం పార్క్ చేయడానికి ముందు ప్రతి దానినీ తన గోడ వరకు పిండుతుంది - [గోడ](/te/switching) చూడండి. నిలిపివేయడానికి పైమెట్టుకు మరియు వారపు బార్‌కు సమానంగా సెట్ చేయండి; Codex ఈ సెట్టింగ్‌ను విస్మరిస్తుంది.
- `claudeBin` / `codexBin`: సూపర్‌వైజర్‌లు స్పాన్ చేసే నిజమైన బైనరీలకు పిన్ చేస్తుంది (`init` / `init --codex` ద్వారా వ్రాయబడుతుంది; `claudeBin` ఇక్కడ నిజమైన Claude బైనరీని సూచించడం మానేసినప్పుడు దాన్ని సరిచేయమని రికర్షన్-గార్డ్ డయాగ్నస్టిక్ మీకు చెబుతుంది).
- `policy.projectionMargin`: అమలు బార్‌లను ఏర్పరచడానికి ప్రతి సెషన్ మెట్టు నుండి, వారపు బార్ నుండి, మరియు గోడ బార్‌ల నుండి తీసివేయబడుతుంది.
- `policy.greedySessionFloor`: అత్యాశ కేంద్రీకరణ ఎంగేజ్ అయ్యే సెషన్-వాడిన శాతం.
- `policy.greedySwapMargin`: అత్యాశ మార్గంలో ప్రస్తుత ఖాతాకు ఇచ్చే హిస్టెరిసిస్, 0 నుండి 1 మధ్య ఒక భిన్నం (డిఫాల్ట్ 0.15). పార్క్ చేసిన ఖాతా వేగ ఒత్తిడి ప్రస్తుత ఖాతా వేగ ఒత్తిడిని ఈ భిన్నం కంటే ఎక్కువగా మించితే తప్ప, ప్రస్తుత ఖాతా తన స్థానాన్ని నిలుపుకుంటుంది, తద్వారా దాదాపు సమానంగా ఉన్న ఖాతాలు స్థానాన్ని ముందుకూ వెనుకకూ మార్చుకోవడం, తద్వారా ప్రతి-సంస్థ ప్రాంప్ట్ కాష్‌ను పాడు చేయడం ఆగిపోతుంది. పాత ఎప్పుడూ-ఉత్తమమైనదాన్నే-తీసుకునే ప్రవర్తన కోసం 0కు సెట్ చేయండి. ఇది దాటిన బార్‌ను గానీ గోడను గానీ ఎప్పుడూ సడలించదు - అన్నీ బార్‌ల కింద ఉన్న ఖాతాల మధ్య పక్కపక్క మార్పిడులకు మాత్రమే వర్తిస్తుంది. మాన్యువల్ `tokenmaxxing switch` దీన్ని విస్మరించి ఎల్లప్పుడూ ఉత్తమ ఖాతాపై కేంద్రీకృతమవుతుంది.
- `policy.switchModels`: ప్రతి-మోడల్ వారపు పరిమితి మార్పిడిని గేట్ చేసే మోడల్ కుటుంబాలు (లోడ్ అయ్యేటప్పుడు ఎంట్రీలు చిన్న అక్షరాలుగా మార్చబడతాయి).
- `policy.usagePollTtlMs`: `/usage` ప్రతి-మోడల్ పోల్ ఎంతసేపు తాజాగా ఉంటుంది.
- `policy.maxWaitMs`: ఖాళీ-పూల్ స్వయంచాలక-నిరీక్షణ పరిమితి.
- `policy.checkIntervalMs`: ఆవర్తన తనిఖీ టిక్ (డిఫాల్ట్ 60000, కనిష్ఠం 10000, ఎందుకంటే launchd డిఫాల్ట్‌గా ప్రతి 10 సెకన్లకు ఒకసారి కంటే ఎక్కువగా ఒక జాబ్‌ను స్పాన్ చేయదు). `init` దీన్ని పూర్తి సెకన్లకు పైకి గుండ్రం చేసి టైమర్ విరామంగా రాస్తుంది (Linux పై systemd `AccuracySec` దీనిలో పన్నెండో వంతు, కనీసం ఒక సెకను), మరియు ప్రతి వెసులుబాటు బ్యాండ్ దీనికి గుణిజం: బార్‌కు దగ్గరగా ఒక టిక్, పుష్కలంగా వెసులుబాటు ఉంటే ఐదు టిక్‌ల వరకు ([తనిఖీ లయ](/te/switching) చూడండి). ఖాళీ నిరీక్షణ మరియు మార్పిడి-తర్వాత కూల్‌డౌన్ మాత్రం తమ సొంత గడువుల వరకు నిద్రపోతాయి. షెడ్యూల్ తదుపరి తనిఖీలో కొత్త విలువను చదువుతుంది, కానీ మీరు మళ్ళీ `tokenmaxxing init` నడిపే వరకు ఇన్‌స్టాల్ చేసిన టైమర్ తన పాత టిక్‌నే ఉంచుకుంటుంది, మరియు గడువు-సమయ సడలింపు కాన్ఫిగర్ చేసిన టిక్‌లో సగం, కాబట్టి మార్చిన టిక్ ఆ పునఃనిర్వహణ తర్వాతే పూర్తిగా అమలవుతుంది. Nix-నిర్వహిత టైమర్‌తో, `checkTimer.intervalSeconds`ను అదే విలువకు సెట్ చేయండి; ఆ ఐచ్ఛికానికి కూడా అదే 10-సెకన్ల ఫ్లోర్ ఉంది.

`tokenmaxxing config` మూలాలతో అమలు కాన్ఫిగ్‌ను చూపుతుంది; `config set`/`unset` డాట్ చేసిన కీలను సవరిస్తాయి; `config tidy` తెలియని కీలను తొలగిస్తుంది.
