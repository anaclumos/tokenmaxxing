---
title: Honest limitations
description: The tradeoffs that come with pooled hot-swapping
---

- **Cache rewrites.** A change of organization can require every active conversation to rebuild its cache, while same-organization swaps can also miss because cache keys and workspace boundaries matter. See the [measured profile](/switching-profile).
- **Weekly allowance tradeoff.** Automatic lateral moves stay within the current organization, so a single-seat organization may hold usable quota while another organization's allowance expires.
- **Incomplete verification.** Candidate probes are bounded and cannot always read usage, so a handoff may still rely on stale cached figures.
- **Depleted-pause hiccup.** Only a fully depleted pool stops the session for the countdown; anything typed in that split second is lost.
- **Retrigger prompt.** When a supervised turn dies on an enforced limit, the relaunch on the fresh account submits one fixed continuation prompt; the model resumes from the transcript, so a turn that was mid-tool-call re-plans that step rather than replaying it.
- **Adoption lag.** On macOS the first turn within ~30 seconds of a swap can still meter the old account; the bars' headroom absorbs it.
- **Shared blast radius.** All default-profile sessions share one live credential, so a swap moves them all together (each adopts in place).
- **Plaintext credentials on Linux.** Claude Code itself stores Linux credentials as a 0600 plaintext file; tokenmaxxing's parked copies follow the same model.
- **One pool per host.** Pooling the same accounts on several machines works, but each host parks and rotates tokens independently, with no cross-host lock: two hosts refreshing the same account's token concurrently race. On Claude, a refresh rotation revokes the previous access token immediately, so the sessions on the other host fail with 401 and its stale refresh token comes back `invalid_grant` (needs-reauth). For Codex a refresh from a stale parked copy is fatal to that login (OpenAI invalidates the whole grant family on refresh-token reuse, forcing `auth` on every host). If you pool an account on more than one machine, expect re-auth churn on Claude and avoid it entirely for Codex.
