title: 솔직한 제약
description: "풀 기반 hot-swap에 따르는 트레이드오프"
---

- **한 번의 콜드 턴.** 프롬프트 캐시는 조직 범위이므로 새 계정의 첫 턴은 컨텍스트를 한 번 다시 업로드합니다.
- **소진 일시 정지의 작은 문제.** 완전히 소진된 풀만이 카운트다운 동안 세션을 멈춥니다. 그 찰나에 입력한 것은 모두 사라집니다.
- **채택 지연.** macOS에서는 교체 후 약 30초 안에 실행되는 첫 턴이 여전히 이전 계정에 집계될 수 있습니다. 기준선의 여유분이 이를 흡수합니다.
- **공유되는 영향 범위.** 모든 기본 프로필 세션이 하나의 라이브 자격 증명을 공유하므로 한 번 교체하면 모두 함께 넘어갑니다(각자 그 자리에서 채택합니다).
- **Linux의 평문 자격 증명.** Claude Code 자체가 Linux 자격 증명을 0600 평문 파일로 저장합니다. tokenmaxxing의 보관 사본도 같은 방식을 따릅니다.
- **호스트당 하나의 풀.** 같은 계정들을 여러 머신에서 함께 풀링하는 것은 가능하지만, 각 호스트는 크로스 호스트 잠금 없이 독립적으로 토큰을 보관하고 회전시킵니다. 두 호스트가 같은 계정의 토큰을 동시에 갱신하면 경합이 생깁니다. Claude에서는 갱신 회전이 이전 access token을 즉시 폐기하므로 다른 호스트의 세션은 401로 실패하고, 그 호스트의 오래된 refresh token은 `invalid_grant`로 돌아옵니다(재인증 필요). Codex의 경우 오래된 보관 사본으로부터의 갱신은 그 로그인에 치명적입니다(OpenAI는 refresh token 재사용 시 전체 grant family를 무효화하므로 모든 호스트에서 `auth`가 강제됩니다). 하나의 계정을 두 대 이상의 머신에서 풀링한다면 Claude에서는 재인증이 발생할 수 있음을 감안하고, Codex에서는 이를 아예 피하십시오.
