---
title: Configuration
description: The config.json schema, thresholds, and policy knobs
---

Config is JSON at `~/.config/tokenmaxxing/config.json`. Every field is optional; defaults apply per-field.

```json
{
  "thresholds": {
    "session": 98,
    "weekly": 98,
    "accounts": { "shared-seat": { "session": 75, "weekly": 75 } }
  },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "grokBin": "/path/to/real/grok",
  "opencodeBin": "/path/to/real/opencode",
  "piBin": "/path/to/real/pi",
  "policy": {
    "projectionMargin": 0,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000,
    "checkIntervalMs": 60000,
    "accountReleaseMs": { "session": 1800000, "weekly": 18000000 }
  },
  "hub": { "port": 8317 }
}
```

- `thresholds.session`: the 5-hour session bar, one number (default 98). It is both the trigger and the candidate screen, for Claude and Codex alike. See [How switching decides](/switching). The former array form (the session ladder) is rejected: config loading fails with a zod message naming `thresholds.session`.
- `thresholds.weekly`: the weekly bar (default 98), covering the 7-day aggregate and every per-model weekly cap.
- `thresholds.accounts`: per-account thresholds keyed by account label, each with both `session` and `weekly` (default `{}`). An account named here uses its own pair in place of `thresholds.session` and `thresholds.weekly`, in any pool, with the same projection margin on the session threshold, until a window nears its reset (`policy.accountReleaseMs`). An entry with `"credits": true` (default `false`) marks an account that carries purchased usage credits: its windows never make it exhausted, so it stays usable past 100 percent of them, and its pair only ranks it. A label that names no pooled account has no effect. See [How switching decides](/switching#the-bars).
- `claudeBin` / `codexBin` / `grokBin` / `opencodeBin` / `piBin`: pins to the REAL binaries the supervisors and the status-only pools spawn (written by `init` for each pool and by `init --pi`; the recursion-guard diagnostic tells you to fix `claudeBin` here when it stops pointing at the real Claude binary). `TOKENMAXXING_CLAUDE_BIN`, `TOKENMAXXING_CODEX_BIN`, `TOKENMAXXING_GROK_BIN`, `TOKENMAXXING_OPENCODE_BIN`, and `TOKENMAXXING_PI_BIN` override the file values for one process, except that `init` pins the binary it resolved into `config.json`, so an override set for `init` persists.
- `policy.projectionMargin`: subtracted from the session threshold only (default 0), so one large turn is less likely to jump the 5-hour window from under the bar to over the hard limit; it must stay below every session threshold, `thresholds.accounts` included. The weekly bar takes no margin because a single turn is too small a fraction of the week to overshoot it, and margin there would only strand use-it-or-lose-it headroom.
- `policy.switchModels`: model families whose per-model weekly cap gates a switch (entries are lowercased on load).
- `policy.usagePollTtlMs`: the shortest sample interval of a Claude account, the one an account near a bar gets. Each account's interval follows its cached figures: the window closest to its bar sets it, as 15 minutes times the fraction of that bar still unused, never under this value, so a value above 15 minutes sets every interval. With the default value, an empty account is sampled every 15 minutes, one at half its session bar about every 7.5 minutes, and one within a tenth of a bar every 90 seconds. An account whose session or weekly aggregate is at or over its bar gets 15 minutes, or this value when it is longer, and so does an account with no session or borrower on this host; an account with no stored figure gets this value (see [Periodic check](/switching#periodic-check)). The check tick, `status`, and a seat's sample inside a hook decision all wait out the interval, and the hook decision samples only when the seat's tee is older than this value or the session's model is a gated family. A seat whose sample keeps failing backs off exponentially from its interval, doubling per consecutive failure up to 30 minutes, and resets on the first success. A Codex seat reads its usage GET when its cached figure is older than this value.
- `policy.maxWaitMs`: the depleted-pool auto-wait bound. Waiters fill resets within this bound first; when those are full, the overflow waits for the next reset with room up to twice this bound out, joining the least-crowded reset when the horizon is full (see [When nothing is usable](/switching#when-nothing-is-usable)).
- `policy.checkIntervalMs`: the periodic check tick (default 60000, minimum 10000 because launchd does not spawn a job more than once every 10 seconds by default). `init` writes it, rounded up to whole seconds, as the timer's interval (on Linux the systemd `AccuracySec` is a twelfth of it, at least one second), and every tick evaluates (see [Periodic check](/switching)). The installed timer keeps its old tick until you run `tokenmaxxing init` again. With a Nix-managed timer, set `checkTimer.intervalSeconds` to the same value; that option has the same 10-second floor.
- `policy.accountReleaseMs`: how close to its reset a window is when a `thresholds.accounts` entry stops holding the account under the global bar, one value for the session window and one for the weekly windows (defaults 1800000 and 18000000, 30 minutes and 5 hours). Inside that period the window's bar is the higher of the account's bar and the global bar.
- `hub.port`: the loopback port the usage hub listens on (`tokenmaxxing serve` and its background service; default 8317, the CLIProxyAPI default). See [Usage hub](/hub).

`tokenmaxxing config` prints the path and the effective values. Edit the file in an editor; a wrong-typed or out-of-range value fails the next load (`check`, `status`, the hooks) with the zod message naming the field. Unknown keys are ignored, the removed `hardThresholds`, `policy.greedySessionFloor`, and `policy.greedySwapMargin` included.
