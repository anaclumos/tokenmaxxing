---
title: Configuration
description: The config.json schema, thresholds, and policy knobs
---

Config is JSON at `~/.config/tokenmaxxing/config.json`. Every field is optional; defaults apply per-field.

```json
{
  "thresholds": { "session": [90], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 80,
    "greedySwapMargin": 0.15,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000,
    "checkIntervalMs": 60000
  }
}
```

- `thresholds.session`: the 5-hour ladder, an ascending list of screening rungs. Each evaluation resolves one active rung, the lowest rung some pooled account still clears, and that rung is both the trigger and the candidate screen. Codex reads the top rung only. See [How switching decides](/switching).
- `thresholds.weekly`: the weekly screening bar, covering the 7-day aggregate and every per-model weekly cap.
- `hardThresholds.session` / `hardThresholds.weekly`: the wall bars (default 100, each account's real server limit). `hardThresholds.session` must be at or above the top session rung. When every account is over its screening bar, the automatic Claude decision squeezes each one up to its wall before parking - see [The wall](/switching). Set equal to the top rung and the weekly bar to disable; Codex ignores this setting.
- `claudeBin` / `codexBin`: pins to the REAL binaries the supervisors spawn (written by `init` / `init --codex`; the recursion-guard diagnostic tells you to fix `claudeBin` here when it stops pointing at the real Claude binary).
- `policy.projectionMargin`: subtracted from every session rung, the weekly bar, and the wall bars to form the effective bars.
- `policy.greedySessionFloor`: session-used percent at which the greedy convergence engages.
- `policy.greedySwapMargin`: incumbent hysteresis on the greedy path, a fraction from 0 to 1 (default 0.15). The current account holds its seat unless a parked account's pace pressure exceeds it by more than this fraction, so near-tied accounts stop trading the seat back and forth and busting the per-organization prompt cache. Set to 0 for the old always-take-the-best behavior. It never softens a crossed bar or the wall - only lateral swaps between accounts that are all under the bars. Manual `tokenmaxxing switch` ignores it and always converges on the best account.
- `policy.switchModels`: model families whose per-model weekly cap gates a switch (entries are lowercased on load).
- `policy.usagePollTtlMs`: how long a `/usage` per-model poll stays fresh.
- `policy.maxWaitMs`: the depleted-pool auto-wait bound.
- `policy.checkIntervalMs`: the periodic check tick (default 60000, minimum 1000). `init` writes it, rounded up to whole seconds, as the timer's interval, and every self-paced sleep is a multiple of it: one tick near a bar, up to five ticks with plenty of headroom (see [Check cadence](/switching)). The schedule reads the new value on the next check, but the installed timer keeps its old tick until you run `tokenmaxxing init` again, so a shorter tick only takes effect after that. With a Nix-managed timer, set `checkTimer.intervalSeconds` to the same value.

`tokenmaxxing config` shows the effective config with sources; `config set`/`unset` edit dotted keys; `config tidy` prunes unknown keys.
