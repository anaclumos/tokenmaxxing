---
title: 诚实的限制
description: "汇集式热切换所带来的权衡"
---

- **一个冷回合。** 提示缓存按组织划分，因此新账户上的第一个回合会重新上传一次上下文。
- **耗尽暂停的小顿挫。** 只有彻底耗尽的账户池才会为倒计时停下会话；那一瞬间键入的内容都会丢失。
- **采用延迟。** 在 macOS 上，切换后约 30 秒内的第一个回合仍可能计量到旧账户；阈值条留出的余量足以吸收。
- **共享的波及范围。** 所有默认配置的会话共享一份活动凭证，因此一次切换会同时带动全部会话（各自就地采用）。
- **Linux 上的明文凭证。** Claude Code 本身就把 Linux 凭证存储为 0600 明文文件；tokenmaxxing 的停放副本沿用同样的做法。
- **每台主机各自一个账户池。** 在多台机器上汇集同一批账户是可行的，但每台主机各自独立地停放和轮换 token，没有跨主机的锁：两台主机同时刷新同一账户的 token 会产生竞态。在 Claude 上，一次刷新轮换会立即吊销此前的 access token，导致另一台主机上的会话以 401 失败，其过期的 refresh token 随后会返回 `invalid_grant`（需要重新认证）；对 Codex 来说，用一份过期的停放副本刷新对该登录是致命的（OpenAI 会在检测到刷新 token 被重复使用时，作废整个授权族群，迫使每台主机都要重新 `auth`）。如果你在多台机器上汇集同一个账户，预期 Claude 端会反复出现重新认证的情况，Codex 端则应完全避免这样做。
