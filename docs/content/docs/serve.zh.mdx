title: Slack 桥接：xx serve
description: "xx serve 通过 Socket Mode 从 Slack 线程运行 Claude Code 会话"
---

`tokenmaxxing serve` 通过 Socket Mode 运行一个本地 Slack 守护进程 - 无需公网 URL。设置：

```sh
tokenmaxxing serve setup                    # 打印应用清单，提示输入两个 token
tokenmaxxing serve link <channel-id> <repo> # 把一个频道绑定到一个仓库检出
tokenmaxxing serve                          # 运行守护进程
```

在一个已链接的频道里提及机器人，它就会为那个线程打开一个 Claude Code 会话，在已链接的仓库检出中运行。每条线程消息运行一次带 `resume` 的 Agent SDK `query()` - 绝不是一个持久的流式 query - 因此 `ensureBestAccount()` 会在每一个回合重新评估账户池，且守护进程可以重启而不丢失线程（线程记录是持久的；守护进程在启动时会重新订阅它们）。

值得注意的行为：

- **流式**：回复原生地流入 Slack，思考和工具运行有任务卡片，围栏代码带高亮渲染，一张收尾的 "Turn" 卡片带成本和时长，每当一次工具运行打断流式文本时就打开一条新的 Slack 消息，因此一个回合读起来像是围绕工具运行的一系列独立消息。TodoWrite 调用会就地更新同一张稳定的清单卡片。
- **权限**：按链接的 `permissionMode` 默认为 `acceptEdits`；`--yolo`（别名 `--dangerous`）让一个链接切换到 `bypassPermissions`。中继回合中不允许交互式对话框 - 没人能通过 Slack 回答一个 - 因此模型会以文字提问，你的线程回复就是下一个回合。一个捆绑的插件 skill 会教它在需要一个决策时提及请求者并结束回合。
- **斜杠命令**：一条经过剥离后以 `/` 开头的线程消息会作为一个 claude 斜杠命令运行。Slack 的输入框会吞掉以 `/` 开头的消息，所以请用先提及的形式（`@bot /usage`）或用一个前导空格。
- **优雅关停**：SIGTERM/SIGINT 会排空 - 新回合被大声丢弃，进行中的回合最多有 5 分钟，且 claude 子进程在它自己的进程组中分离运行，这样一个终端 Ctrl-C 就无法在排空保住该回合之前杀掉它。
- **线程清理**：当你告诉它工作完成时，模型会调用一个进程内的 `finish_thread` 工具；在回合彻底结束之后，守护进程丢弃线程记录、取消订阅，并发一条确认消息。一次新的提及会开启一个新会话。
- **错误卫生**：回合错误只发送裁剪过的纯消息文本，绝不发送原始错误正文。
