title: Slack 桥接：xx serve
description: "xx serve 通过 Socket Mode 从 Slack 线程运行 Claude Code 会话"
---

`tokenmaxxing serve` 通过 Socket Mode 运行本地 Slack 守护进程，无需公网 URL。设置：

```sh
tokenmaxxing serve setup                    # 打印应用清单，提示输入两个 token
tokenmaxxing serve link <channel-id> <repo> # 把一个频道绑定到一个仓库检出
tokenmaxxing serve                          # 运行守护进程
```

在已链接的频道里提及机器人，它就会为该线程打开 Claude Code 会话，并在已链接的仓库检出中运行。每条线程消息运行一次带 `resume` 的 Agent SDK `query()`（绝不是持久的流式 query），因此 `ensureBestAccount()` 会在每个回合重新评估账户池，且守护进程可以重启而不丢失线程（线程记录是持久的，守护进程会在启动时重新订阅）。

需要留意的行为：

- **流式**：回复原生地流入 Slack，思考和工具运行有任务卡片，围栏代码带高亮渲染，一张收尾的 "Turn" 卡片带成本和时长；一个回合的卡片会折叠成一个可展开的计划区块，因此一个回合通常读起来像一条消息：回复加一个活动下拉菜单（回合中途的重试或被拒绝的续写会另开一条后续消息）。TodoWrite 调用会就地更新同一张清单卡片。
- **权限**：按链接的 `permissionMode` 默认为 `acceptEdits`；`--yolo`（别名 `--dangerous`）让链接切换到 `bypassPermissions`。中继回合中不允许交互式对话框（没人能通过 Slack 作答），因此模型会以文字提问，你在线程里的回复就是下一个回合。捆绑的插件 skill 会教它在需要决策时提及请求者并结束回合。
- **斜杠命令**：一条线程消息在去掉开头提及后若以 `/` 开头，就会作为 claude 斜杠命令运行。Slack 的输入框会吞掉以 `/` 开头的消息，所以请用先提及的形式（`@bot /usage`）或加一个前导空格。
- **优雅关停**：SIGTERM/SIGINT 会触发排空：新回合会被显式丢弃，进行中的回合最多有 5 分钟，claude 子进程则在自己的进程组中分离运行，这样终端的 Ctrl-C 就无法在排空保住该回合之前将其杀掉。
- **线程清理**：当你表示工作已完成时，模型会调用进程内的 `finish_thread` 工具；在回合彻底结束之后，守护进程丢弃线程记录、取消订阅，并发出一条确认消息。重新提及即可开启新会话。
- **错误卫生**：回合出错时只发送裁剪过的纯消息文本，绝不发送原始错误正文。
