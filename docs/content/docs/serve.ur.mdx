title: "Slack برج: xx serve"
description: "xx serve Slack تھریڈز سے Socket Mode پر Claude Code سیشنز چلاتا ہے"
---

`tokenmaxxing serve` Socket Mode پر ایک مقامی Slack ڈیمن چلاتا ہے - کوئی عوامی URL درکار نہیں۔ سیٹ اپ:

```sh
tokenmaxxing serve setup                    # ایپ مینی فیسٹ پرنٹ کرتا ہے، دو ٹوکنز مانگتا ہے
tokenmaxxing serve link <channel-id> <repo> # ایک چینل کو ایک ریپو چیک آؤٹ سے باندھتا ہے
tokenmaxxing serve                          # ڈیمن چلاتا ہے
```

ایک منسلک چینل میں بوٹ کو مینشن کریں اور یہ اس تھریڈ کے لیے، منسلک ریپو چیک آؤٹ میں ایک Claude Code سیشن کھولتا ہے۔ ہر تھریڈ پیغام اب بھی ایک Agent SDK `query()` کو `resume` کے ساتھ چلاتا ہے - لہٰذا `ensureBestAccount()` ہر ٹرن پر پول کا دوبارہ جائزہ لیتا ہے اور ڈیمن تھریڈز کھوئے بغیر دوبارہ شروع ہو سکتا ہے (تھریڈ ریکارڈز پائیدار ہیں؛ ڈیمن آغاز پر انہیں دوبارہ سبسکرائب کرتا ہے) - لیکن ہر کوئری اسٹریمنگ ان پٹ قبول کرتی ہے، جو یہ ممکن بناتا ہے کہ ایک جواب پہلے سے جاری ٹرن کا رخ موڑ دے۔

قابلِ ذکر رویہ:

- **اسٹیئرنگ**: ایک جواب جو اس وقت آئے جب تھریڈ کا ٹرن ابھی چل رہا ہو وہ اسی ٹرن میں شامل ہو جاتا ہے - وہی انجیکشن جو Claude Code ٹرن کے دوران انٹرایکٹو طور پر استعمال کرتا ہے - لہٰذا ماڈل اسے اپنی اگلی ٹول باؤنڈری پر دیکھتا ہے اور غلط چیز مکمل کرنے کے بجائے راستہ درست کر لیتا ہے۔ ایک جواب جو ٹرن کی آخری ٹول کال کے بعد آئے وہ فوراً اپنے ایک الگ ٹرن کے طور پر چلتا ہے؛ دونوں صورتوں میں کچھ ضائع نہیں ہوتا۔ اسٹیئر شدہ پیغامات ریت گھڑی ری ایکشن پہنتے ہیں اور ٹرن کے ساتھ ہی طے ہوتے ہیں، اور ان کا متن ٹرن کے پائیدار مارکر پر سوار ہوتا ہے، لہٰذا دوبارہ شروع ہونا اور استعمال کی حد پر دوبارہ شروع ہونا اسے دہراتے ہیں۔ صرف وہ پیغام جو کسی دوسرے منتظر پیغام کے پیچھے قطار میں ہو شمولیت سے رہ جاتا ہے (ترتیب برقرار رہتی ہے)، اور خالی ہوتا ڈیمن اب بھی اسٹیئرنگ کے بجائے بلند آواز سے گراتا ہے۔
- **اسٹریمنگ**: جوابات نیٹو طور پر Slack میں اسٹریم ہوتے ہیں، سوچ اور ٹول رنز کے لیے ٹاسک کارڈز کے ساتھ، ہائی لائٹنگ کے ساتھ رینڈر شدہ فینسڈ کوڈ، اور لاگت اور دورانیے کے ساتھ ایک اختتامی "Turn" کارڈ؛ ایک ٹرن کے کارڈز ایک ہی قابلِ توسیع پلان بلاک میں سمٹ جاتے ہیں، تاکہ ایک ٹرن عام طور پر ایک واحد پیغام کے طور پر پڑھا جائے: جواب کے ساتھ اس کی سرگرمی کا ایک ڈراپ ڈاؤن (ٹرن کے دوران ایک دوبارہ کوشش، یا Slack کے پیغام میں مزید مواد جوڑنا ناممکن ہو جانا، ایک اور پیغام کھولتا ہے)۔ TodoWrite کالز ایک مستحکم چیک لسٹ کارڈ کو اپنی جگہ اپ ڈیٹ کرتی ہیں۔
- **اجازتیں**: فی لنک `permissionMode` بطور ڈیفالٹ `acceptEdits` ہے؛ `--yolo` (عرف `--dangerous`) ایک لنک کو `bypassPermissions` میں شامل کرتا ہے۔ ریلے شدہ ٹرنز میں انٹرایکٹو ڈائیلاگز کی اجازت نہیں ہے - کوئی بھی Slack کے ذریعے ان کا جواب نہیں دے سکتا - لہٰذا ماڈل نثر میں پوچھتا ہے اور آپ کا تھریڈ جواب اگلا ٹرن ہوتا ہے۔ ایک بنڈل شدہ پلگ اِن اسکل اسے سکھاتی ہے کہ درخواست کنندہ کو ٹیگ کرے اور جب اسے کوئی فیصلہ درکار ہو تو ٹرن ختم کر دے۔
- **اسٹیٹس ری ایکشنز**: جس پیغام نے ایک ٹرن شروع کیا وہ اپنی حالت ایک ایموجی ری ایکشن کے طور پر رکھتا ہے: ٹرن چلنے کے دوران ایک ریت گھڑی، پھر ایک چیک مارک (مکمل)، ایک x (ناکام)، یا ایک سوالیہ نشان (ماڈل کو آپ کا فیصلہ درکار ہے)۔ موجودہ مینی فیسٹ سے `reactions:write` اسکوپ درکار ہے؛ موجودہ ایپس کو مینی فیسٹ دوبارہ پیسٹ کر کے دوبارہ انسٹال کرنا ہوگا۔
- **توجہ اور یاد دہانیاں**: جب ماڈل آپ سے کوئی فیصلہ مانگتا ہے تو یہ ایک اِن پروسیس `need_attention` ٹول کال کرتا ہے، تاکہ ڈیمن جان لے کہ تھریڈ آپ کا منتظر ہے۔ اگر آپ 10 منٹ تک خاموش رہیں تو یہ تھریڈ میں آپ کو ایک بار ٹیگ کرتا ہے۔ جب ایک تھریڈ منتظر ہو، تو سوال پر ری ایکشن دینا آپ کے جواب کے طور پر ریلے ہوتا ہے (ایک تھمبس اپ تجویز کردہ آپشن چنتا ہے)؛ کسی ٹریک شدہ تھریڈ میں آپ کا شامل کیا گیا کوئی بھی دوسرا ری ایکشن اگلے ٹرن میں سیاق کے طور پر شامل کر لیا جاتا ہے۔ `reactions:read` اور `reaction_added` ایونٹ درکار ہیں۔
- **سلیش کمانڈز**: ایک تھریڈ پیغام جس کا صاف کیا گیا متن `/` سے شروع ہو ایک claude سلیش کمانڈ کے طور پر چلتا ہے۔ Slack کا کمپوزر `/` سے شروع ہونے والے پیغامات کھا جاتا ہے، لہٰذا مینشن-پہلے فارم (`@bot /usage`) یا ایک ابتدائی خالی جگہ استعمال کریں۔
- **استعمال کی حد پر خودکار دوبارہ شروع ہونا**: جب ہر پول شدہ اکاؤنٹ اپنی حد پر ہو، تو ایک مختصر تعطل پیغام کو روک کر اسی جگہ دوبارہ کوشش کرتا ہے؛ ایک طویل تعطل ایک ہولڈنگ نوٹس پوسٹ کرتا ہے اور پول کے بحال ہوتے ہی ٹرن کو خودکار طور پر دوبارہ شروع کرتا ہے، ڈیمن کے دوبارہ شروع ہونے پر بھی۔ صرف وہ حد جس کی بحالی کا وقت معلوم نہ ہو آپ سے دوبارہ بھیجنے کو کہتی ہے۔
- **خوش اسلوبی سے بند ہونا**: SIGTERM/SIGINT خالی کرتا ہے - نئے ٹرنز کو بلند آواز سے گرا دیا جاتا ہے، جاری ٹرنز کو 5 منٹ تک ملتے ہیں، اور claude چائلڈ اپنے خود کے پروسیس گروپ میں الگ چلتا ہے تاکہ ایک ٹرمینل Ctrl-C ڈرین کے ٹرن محفوظ کرنے سے پہلے اسے ختم نہ کر سکے۔
- **تھریڈ صفائی**: جب آپ اسے بتاتے ہیں کہ کام مکمل ہو گیا، تو ماڈل ایک اِن پروسیس `finish_thread` ٹول کال کرتا ہے؛ ٹرن مکمل ختم ہونے کے بعد، ڈیمن تھریڈ ریکارڈ گرا دیتا ہے، ان سبسکرائب کرتا ہے، اور ایک تصدیق پوسٹ کرتا ہے۔ ایک تازہ مینشن ایک نیا سیشن شروع کرتا ہے۔
- **خرابی حفظانِ صحت**: ٹرن خرابیاں صرف چھانٹے گئے پیغام-متن پوسٹ کرتی ہیں، کبھی خام خرابی باڈیز نہیں۔
