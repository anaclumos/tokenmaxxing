---
title: "Ang Slack bridge: xx serve"
description: "Nagpapatakbo ang xx serve ng mga Claude Code session mula sa mga Slack thread sa pamamagitan ng Socket Mode"
---

Nagpapatakbo ang `tokenmaxxing serve` ng isang lokal na Slack daemon sa pamamagitan ng Socket Mode - walang kinakailangang pampublikong URL. Setup:

```sh
tokenmaxxing serve setup                    # ipinipirinta ang app manifest, humihingi ng dalawang token
tokenmaxxing serve link <channel-id> <repo> # itali ang isang channel sa isang repo checkout
tokenmaxxing serve                          # patakbuhin ang daemon
```

Banggitin ang bot sa isang naka-link na channel at magbubukas ito ng isang Claude Code session para sa thread na iyon, sa naka-link na repo checkout. Ang bawat thread message ay nagpapatakbo pa rin ng isang Agent SDK `query()` na may `resume` - kaya't muling sinusuri ng `ensureBestAccount()` ang pool sa bawat isang turn at maaaring mag-restart ang daemon nang hindi nawawala ang mga thread (matibay ang mga thread record; muling nag-su-subscribe ang daemon sa mga ito sa startup) - pero tumatanggap ang bawat query ng streaming input, at iyon ang nagbibigay-daan sa isang reply na i-steer ang turn na tumatakbo na.

Kapansin-pansing gawi:

- **Steering**: ang isang reply na dumarating habang tumatakbo pa ang turn ng thread ay natitiklop sa turn na iyon - ang parehong mid-turn injection na ginagamit ng Claude Code nang interactive - kaya't nakikita ito ng modelo sa susunod nitong tool boundary at inaayos ang direksyon sa halip na tapusin muna ang maling bagay. Ang isang reply na dumarating pagkatapos ng huling tool call ng turn ay tumatakbo bilang sarili nitong turn kaagad pagkatapos; wala talagang natatapon sa alinmang kaso. Ang mga na-steer na mensahe ay nagsusuot ng hourglass reaction at natatapos kasabay ng turn, at ang teksto nito ay sumasakay sa matibay na marker ng turn, kaya't ino-oplay itong muli ng mga restart at ng mga usage-limit resume. Tanging ang isang mensaheng naka-queue sa likod ng ibang naghihintay na mensahe ang lumalaktaw sa pagtitiklop na ito (napapanatili ang pagkakasunod-sunod), at ang isang daemon na nagd-drain ay maingay pa ring ibinabagsak sa halip na mag-steer.
- **Streaming**: ang mga tugon ay nagse-stream nang natively papunta sa Slack, na may mga task card para sa pag-iisip at pagtakbo ng tool, fenced code na nire-render na may highlighting, at isang panghuling "Turn" card na may cost at tagal; ang lahat ng card ng isang turn ay natitiklop sa iisang nabubuksang plan block, kaya't ang isang turn ay karaniwang nababasa bilang iisang mensahe: ang tugon kasama ang isang dropdown ng aktibidad nito (isang retry sa gitna ng turn o isang tinanggihang append ay nagbubukas ng isang follow-on na mensahe). Ina-update ng mga TodoWrite call ang isang stable na checklist card nang nasa lugar.
- **Permissions**: ang per-link na `permissionMode` ay nagde-default sa `acceptEdits`; ang `--yolo` (alias `--dangerous`) ay nagpapasok ng isang link sa `bypassPermissions`. Ang mga interactive na dialog ay hindi pinapayagan sa mga naka-relay na turn - walang makakasagot sa isa sa pamamagitan ng Slack - kaya't nagtatanong ang modelo sa prosa at ang iyong thread reply ang susunod na turn. Isang naka-bundle na plugin skill ang nagtuturo dito na i-tag ang humihiling at tapusin ang turn kapag kailangan nito ng isang desisyon.
- **Status reactions**: ang mensaheng nag-trigger ng isang turn ay nagdadala ng estado nito bilang isang emoji reaction: isang hourglass habang tumatakbo ang turn, pagkatapos ay isang check mark (tapos), isang x (nabigo), o isang question mark (kailangan ng modelo ang iyong desisyon). Nangangailangan ng `reactions:write` scope mula sa kasalukuyang manifest; ang mga umiiral na app ay kailangang muling i-paste ang manifest at muling i-install.
- **Attention and nudges**: kapag humihingi sa iyo ang modelo ng isang desisyon, tumatawag ito ng isang in-process na `need_attention` na tool, kaya't alam ng daemon na naghihintay sa iyo ang thread. Kung mananatili kang tahimik nang 10 minuto, ita-tag ka nito nang isang beses sa thread. Habang naghihintay ang isang thread, ang pag-react sa tanong ay nire-relay bilang iyong sagot (ang isang thumbs up ay pumipili ng inirerekomendang opsyon); anumang ibang reaction na idinagdag mo sa isang sinusubaybayang thread ay isinasama sa susunod na turn bilang konteksto. Nangangailangan ng `reactions:read` at ng `reaction_added` na event.
- **Slash commands**: ang isang thread message na ang stripped na text ay nagsisimula sa `/` ay tumatakbo bilang isang claude slash command. Kinakain ng composer ng Slack ang mga mensaheng nagsisimula sa `/`, kaya't gamitin ang mention-first na anyo (`@bot /usage`) o isang paunang espasyo.
- **Usage-limit auto-resume**: kapag nasa sariling limitasyon na ang bawat naka-pool na account, isang maikling outage ang nagpa-park sa mensahe at muling sinusubukan ito nang nasa lugar; ang isang mas mahabang outage ay nagpo-post ng isang paunawa habang naghihintay at awtomatikong ipinagpapatuloy ang turn kapag naka-recover na ang pool, na nakakaligtas sa mga pag-restart ng daemon. Tanging ang isang limitasyong walang kilalang oras ng recovery ang humihingi sa iyong muling magpadala.
- **Graceful shutdown**: nagd-drain ang SIGTERM/SIGINT - ang mga bagong turn ay maingay na ibinabagsak, ang mga in-flight na turn ay binibigyan ng hanggang 5 minuto, at ang claude child ay tumatakbo nang nakahiwalay sa sarili nitong process group upang hindi ito mapatay ng isang terminal na Ctrl-C bago maisalba ng drain ang turn.
- **Thread cleanup**: kapag sinabi mo dito na tapos na ang trabaho, tumatawag ang modelo ng isang in-process na `finish_thread` na tool; pagkatapos ganap na matapos ang turn, ibinabagsak ng daemon ang thread record, nag-u-unsubscribe, at nagpo-post ng isang kumpirmasyon. Ang isang sariwang pagbanggit ay nagsisimula ng isang bagong session.
- **Error hygiene**: ang mga turn error ay nagpo-post ng pinutol na message-only na text, hindi kailanman hilaw na error body.
