npm-пакет поставляется как исходный код на TypeScript, а не как сборка: бинарник `tokenmaxxing` указывает прямо на `src/main.ts` с shebang-ом Bun, и Bun 1.2.6 или новее запускает его как есть. Именно поэтому Bun - жёсткое требование. Скомпилированных бинарников нет по замыслу: ранний релиз поставил единственный бинарник macOS на 61 МБ на все платформы и упал в Linux с `exec format error`, а скомпилированные пакеты для каждой платформы потребовали бы собственного конвейера релиза, поэтому моделью распространения стал запуск исходного кода через Bun.

Карта `exports` пакета предоставляет `src/sdk.ts` в качестве программной точки входа, описанной в разделе [Интерфейс Agent SDK](/ru/sdk). Релизы помечаются тегом `v<version>` на GitHub; CI публикует в npm через доверенную публикацию (OIDC, с provenance), и вентиль публикации сначала запускает проверку типов.

## Nix / nix-darwin

То же дерево исходников — ещё и flake. Оно сохраняет модель «исходники запускает Bun» (через [bun2nix](https://github.com/nix-community/bun2nix) `writeBunApplication`) и предоставляет:

| Выход | Назначение |
|---|---|
| `packages.default` | `tokenmaxxing` + `xx` в PATH |
| `darwinModules.default` / `withOverlay` | nix-darwin: установить CLI (опциональный декларативный таймер проверки) |
| `homeManagerModules.default` | Home Manager на macOS или Linux |
| `nixosModules.default` / `withOverlay` | системная установка на NixOS |

Установите в профиль (чтобы shim-ы супервизора из `init` находили в PATH стабильный `tokenmaxxing`), затем выполните init:

```sh
nix profile install github:anaclumos/tokenmaxxing
tokenmaxxing init
```

Разовый запуск без установки (только help / status, `init` так делать нельзя):

```sh
nix run github:anaclumos/tokenmaxxing -- help
```

nix-darwin (добавляет overlay, чтобы резолвился `pkgs.tokenmaxxing`):

```nix
{
  inputs.tokenmaxxing.url = "github:anaclumos/tokenmaxxing";
  modules = [
    inputs.tokenmaxxing.darwinModules.withOverlay
    { programs.tokenmaxxing.enable = true; }
  ];
}
```

Home Manager (задайте пакет явно или примените overlay этого flake к тем pkgs, которые использует Home Manager):

```nix
{
  imports = [ inputs.tokenmaxxing.homeManagerModules.default ];
  programs.tokenmaxxing.enable = true;
  programs.tokenmaxxing.package = inputs.tokenmaxxing.packages.${pkgs.system}.default;
}
```

Nix только кладёт CLI в PATH. Импорт аккаунтов, supervisor-shim `claude` в PATH, хуки в `settings.json` и (по умолчанию) периодический таймер проверки по-прежнему идут из `tokenmaxxing init`. Они трогают учётные данные и пользовательские настройки, которые чистый модуль не должен переписывать. Ставьте `programs.tokenmaxxing.checkTimer.enable = true` только когда хотите, чтобы таймером владел Nix, а не init (это заодно экспортирует `TOKENMAXXING_SKIP_TIMER=1`, чтобы init не записал второй юнит). Декларативный таймер работает в пользовательской сессии, как и у init, поэтому на безголовом Linux нужен `loginctl enable-linger`, чтобы он срабатывал без входа в систему.

Когда меняется `bun.lock`, перегенерируйте выражение зависимостей Nix:

```sh
bun run nix:bun   # записывает bun.nix через bun2nix@2.1.2
```
