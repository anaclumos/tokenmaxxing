نفس التجميع بيشتغل مع Codex CLI بتاع OpenAI، مقابل حسابات اشتراك ChatGPT بتاعتك:

```sh
tokenmaxxing init --codex   # استورد تسجيل دخول codex الحالي بتاعك + ثبّت الـ codex supervisor و Stop hook
tokenmaxxing add --codex    # سجّل دخول حساب تاني، معزول: تسجيل دخولك الأساسي مايتلمسش
codex                       # استخدم codex زي العادة
```

الـ Codex pool حالة متوازية بالكامل: index حسابات خاص بيه، ملفات credential مركونة خاصة بيه (ملفات 0600 على المنصتين، لأن مخزن codex نفسه ملف نص عادي)، قفل خاص بيه، timestamp آخر تبديل خاص بيه. مفيش حاجة بتتشارك مع الـ Claude pool غير كود سياسة القرار.

## ليه الـ hot-swap مستحيل على Codex

عملية codex اللي شغّالة بتمسك auth manager واحد في الذاكرة وبترفض صراحة إنها تعيد تحميل `auth.json` لما يبقى بيسمّي حساب مختلف. مفيش file watcher ومفيش poll للـ credential لكل طلب، فالـ credential اللي اتبدّل تحت codex شغّال ببساطة عمره ما بيسري مفعوله على الـ inference. إعادة التشغيل هي التبديل: `codex resume <session-id>` بيكمّل الـ transcript المحلي على أي حساب `auth.json` ماسكه دلوقتي.

tokenmaxxing بيتعامل مع ده عن طريق codex supervisor shim: الـ Stop hook بيشغّل نفس قرار ضغط الإيقاع الـ greedy عند كل حدود turn، ولما بيبدّل، بيكتب marker بيخلّي الـ supervisor يبعت SIGTERM للـ session عند الحدود المُثبَّتة ويعيد تشغيل `codex resume <session-id>` على الحساب الجديد، والـ transcript سليم. لأن كل تبديل codex هو إعادة تشغيل ظاهرة، مسار codex الـ greedy بيحمل هامش تحسين 1.2x: المُتحدّي لازم يتفوّق على ضغط الإيقاع بتاع الحساب الحالي بـ 20%، مش بشعرة. مسار الـ hard (bar اتعدّى) بيتجاهل الهامش. كمان مفيش عدّاد تنازلي للـ pool المستنفد بالنسبة لـ codex. مفيش حاجة تقدر توقّف codex session، فالـ codex pool المستنفد بالكامل بيفضل مكانه.

ميكانيكيات تانية خاصة بـ codex:

- الاستخدام بيتقرا من GET مصادَق عليه مجاني على الـ rate-limit endpoint بتاع codex نفسه (نفس الاستدعاء اللي `/status` بتاع الـ CLI بيعمله): نسب مئوية بالإضافة لأوقات reset مطلقة بالـ epoch، النوافذ الإجمالية والحدود لكل موديل على حد سوا. تصنيف النافذة بيتحدّد بالمدة، عمره ما بالموضع، لأن الخطط الحالية ممكن مايبقاش عندها نافذة 5 ساعات خالص والنافذة الأسبوعية بتقعد في الخانة الأساسية.
- الـ refresh tokens بتاعت Codex بتتدوّر، وإعادة استخدام واحد اتبدّل بيقتل عيلة المنحة كلها. كل تدوير بيتحفظ في اللحظة اللي بيرجع فيها، والحساب النشط بيتاخد منه عيّنة بس عن طريق الـ blob الحي (عمره ما نسخة مركونة قديمة)، وملفات الحضور لكل session بتضمن إن الحساب اللي شغّال في session شقيقة حية عمره ما يبقى هدف تبديل وعمره ما الـ token المركون بتاعه يتحدّث.
- Codex بيتطلّب مخزن الـ credential الملف: `init --codex` بيفشل بسرعة لو مخزن الـ keyring مثبّت، و `add --codex` بيكتب إعداد وضع الملف في الـ home المعزول بتاع الإعداد الأولي عشان تسجيل الدخول ينزل قابل للحصاد.
- خطوة يدوية واحدة: codex بيتخطّى الـ hooks اللي ماتقالوش يثق فيها. بعد `init --codex`، افتح codex مرة وثِق في الـ tokenmaxxing Stop hook عن طريق `/hooks`، وإلا التبديل التلقائي بيفضل خامل في صمت. `init --codex` بيطبع التذكير ده.
