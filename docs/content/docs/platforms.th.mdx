---
title: "หมายเหตุแพลตฟอร์ม: macOS กับ Linux"
description: "macOS กับ Linux ต่างกันอย่างไรในด้านการจัดเก็บ การนำมาใช้ และตัวจับเวลา"
---

| | macOS | Linux |
|---|---|---|
| credential สด | รายการ generic-password ใน login keychain | ไฟล์ `.credentials.json` สิทธิ์ 0600 |
| credential ที่ park ไว้ | รายการ keychain ต่อบัญชี | ไฟล์สิทธิ์ 0600 ในไดเรกทอรีสิทธิ์ 0700 |
| การนำมาใช้หลังการสลับ | ภายในประมาณ 30 วินาที (แคชการอ่าน keychain) | คำขอถัดไป (การ poll ค่า mtime ของไฟล์) |
| การตรวจสอบเป็นระยะ | launchd agent ทุก 180 วินาที | systemd user timer ทุก 180 วินาที |
| ที่เก็บล็อกอินแบบแยกส่วน | บริการ keychain ที่ตั้ง namespace ด้วยแฮชต่อไดเรกทอรี config | ไฟล์ภายในไดเรกทอรี config ที่แยกส่วน |

รายละเอียดเฉพาะของ Linux สองข้อที่ควรทราบ: claude จะระบุไดเรกทอรี credential จาก `CLAUDE_SECURESTORAGE_CONFIG_DIR` ก่อน (จากนั้น `CLAUDE_CONFIG_DIR` แล้วจึง `~/.claude`) และ tokenmaxxing ทำตามการระบุนั้นแบบเป๊ะๆ เพื่อไม่ให้ทั้งสองไม่ตรงกัน และ build ของทั้งสองระบบปฏิบัติการในเวอร์ชัน claude เดียวกันจัดรูปแบบนาฬิการีเซ็ตของ `/usage` ต่างกัน (อันหนึ่งใช้ตัวเชื่อม " at " อีกอันใช้จุลภาค) ตัวแยกวิเคราะห์ (parser) ของ tokenmaxxing รับเฉพาะสองรูปแบบนั้นพอดี และจะบันทึกลง log แทนที่จะเดา หากพบรูปแบบที่สาม

บน macOS มีข้อจำกัดที่ต้องบอกตามตรงหนึ่งข้อ: `init` และ `add` จะแตะ keychain แบบโต้ตอบโดยเจตนา เพื่อให้การเข้าถึง `security` ครั้งแรกไม่ใช่การเข้าถึงแบบเย็น (cold) ภายในฮุกแบบ headless
