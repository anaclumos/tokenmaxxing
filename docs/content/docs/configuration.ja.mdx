---
title: 設定
description: "config.json のスキーマ、しきい値、ポリシーの調整項目"
---

設定は `~/.config/tokenmaxxing/config.json` の JSON です。すべてのフィールドは任意で、デフォルトはフィールドごとに適用されます。

```json
{
  "thresholds": { "session": [90], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 80,
    "greedySwapMargin": 0.15,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000,
    "checkIntervalMs": 60000
  }
}
```

- `thresholds.session`: 5時間ウィンドウのラダーで、スクリーニングの段を昇順に並べたリストです。評価のたびにアクティブな段を1つ決めます。プールのどれかのアカウントがまだクリアできる最も低い段で、その段がトリガーであると同時に候補のスクリーニング基準にもなります。Codex は最上段だけを読みます。[切り替えの判断方法](/ja/switching)を参照してください。
- `thresholds.weekly`: 週次のスクリーニングバー。7日間の集計とすべてのモデルごとの週次上限をカバーします。
- `hardThresholds.session` / `hardThresholds.weekly`: ウォールバー (デフォルト100、各アカウントの実際のサーバー制限)。`hardThresholds.session` はセッションの最上段以上でなければなりません。すべてのアカウントがスクリーニングバーを超えると、自動の Claude 判断はパークする前に各アカウントをウォールまで絞り出します ([ウォール](/ja/switching)を参照)。最上段と週次バーに等しい値に設定すると無効になります。Codex はこの設定を無視します。
- `claudeBin` / `codexBin`: スーパーバイザーが起動する本物のバイナリを固定する設定 (`init` / `init --codex` によって書き込まれる。再帰防止ガードの診断メッセージは、`claudeBin` が本物の Claude バイナリを指さなくなったとき、ここを修正するよう案内する)。
- `policy.projectionMargin`: すべてのセッションの段、週次バー、ウォールバーから差し引いて有効バーを求める値。
- `policy.greedySessionFloor`: グリーディ収束が作動するセッション使用率。
- `policy.greedySwapMargin`: グリーディパスで現在のアカウントを優先するヒステリシスで、0から1の割合です (デフォルト0.15)。パーク済みアカウントのペースプレッシャーが現在のアカウントをこの割合より大きく上回らないかぎり、現在のアカウントが席を保持します。これにより、ほぼ同点のアカウントどうしが席を行ったり来たりさせて組織ごとのプロンプトキャッシュを壊すことがなくなります。0に設定すると、常に最良を取る従来の挙動になります。超えたバーやウォールを緩めることは決してなく、対象はすべてバー未満のアカウントどうしの横並びの切り替えだけです。手動の `tokenmaxxing switch` はこれを無視し、常に最良のアカウントへ収束します。
- `policy.switchModels`: モデルごとの週次上限が切り替えの条件となるモデルファミリー (エントリは読み込み時に小文字化されます)。
- `policy.usagePollTtlMs`: `/usage` のモデルごとのポーリングが有効なまま保たれる期間。
- `policy.maxWaitMs`: プール枯渇時の自動待機の上限。
- `policy.checkIntervalMs`: 定期チェックのティック (デフォルト60000、最小10000。launchd は既定で10秒に1回を超える頻度ではジョブを起動しないためです)。`init` はこの値を秒単位に切り上げてタイマーの間隔として書き込み (Linux では systemd の `AccuracySec` がその12分の1、最低でも1秒になります)、余裕に応じた各バンドはすべてこの値の倍数です。バーが近ければ1ティック、余裕が十分あれば最大5ティックです ([チェックの間隔](/ja/switching)を参照)。枯渇待機と切り替え後のクールダウンは、代わりにそれぞれの期限までスリープします。スケジュールは次回のチェックで新しい値を読みますが、インストール済みのタイマーは `tokenmaxxing init` を再実行するまで古いティックのままで、予定到来の許容幅は設定されたティックの半分なので、変更したティックが完全に反映されるのはその再実行の後です。Nix が管理するタイマーでは、`checkTimer.intervalSeconds` に同じ値を設定してください。このオプションにも同じ10秒のフロアがあります。

`tokenmaxxing config` は有効な設定をソースとともに表示します。`config set` / `unset` はドット区切りのキーを編集し、`config tidy` は不明なキーを削除します。
