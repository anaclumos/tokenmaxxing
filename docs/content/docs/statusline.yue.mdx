title: statusline
description: "配額用顏色承載，一行，每個帳戶都睇得到"
---

tokenmaxxing 原生渲染 Claude Code 嘅 statusline（同時 tee 住個用量資訊來源）。設計原則：配額用顏色承載，唔係用數字。一行，例如：

```
tm-wt-demo Fable 5 (high) +156/-23  ◆ 𝒇 2h 1d  ◇ 19h  ◇ 𝒇 2d  ◇ full  ✗ ?
```

- 每個窗口 token 就係距離重設嘅時間，按已用百分比塗上一條連續嘅綠到黃到紅漸變（終端支援嘅話用真彩色，否則就退落 256 色立方體）。個漸變喺 0 錨定純綠，75 錨定黃，95 同以上錨定紅，所以舊嗰套嚴重程度分帶就以漸變錨點嘅形式保留咗落嚟。
- 模型名喺同一個漸變上面，按上下文窗口填充嚟塗色。
- 綠色 `◆` 排喺活躍帳戶嘅窗口前面；每個泊存帳戶都有自己嘅青色 `◇`（如果要重新認證就係紅色 `✗`）。帳戶按最快到嘅重設排序。
- 每模型喺每個區塊排最先，淨係一個塗色首字母：Fable 渲染做 `𝒇`；其他系列用轉大楷嘅首字母，永遠都按系列配對。
- 未掂過嘅泊存帳戶渲染做綠色 `full`。有量度到用量但係重設未知就渲染做個塗色嘅 `?`，而喺受閘模型上面，未量度嘅每模型上限就渲染做個未塗色嘅 `𝒇?`：未量度嘅永遠唔可以睇落好安全。
- 重設倒數淨係顯示最大嗰個單位，永遠唔會係「now」或者「0m」；冇即將重設嘅窗口就渲染做綠色 `0`（又空咗）。
- 連結咗嘅 git worktree 嘅 basename 排喺行首；主 checkout 喺嗰度就咩都唔渲染。個偵測會讀檔案系統嚟搵 `.git` 檔案，永遠都唔會開 git 子進程。
- 設定咗 `NO_COLOR` 嗰陣，嗰行就會退返去黐埋嘅數字格式（`2h5` 意思係 2 小時後重設，已用 5%；`ctx 42` 代表上下文填充）：冇顏色嘅話，耗盡咗嘅窗口永遠唔可以睇落好新鮮。

子 agent 任務會透過 claude 嘅 subagentStatusLine 介面攞到自己嘅面板行：每個活躍任務一行，系列名按嗰個任務嘅上下文填充嚟塗色。
