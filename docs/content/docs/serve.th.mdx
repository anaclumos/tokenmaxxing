---
title: "สะพานเชื่อม Slack: xx serve"
description: "xx serve รันเซสชัน Claude Code จากเธรด Slack ผ่าน Socket Mode"
---

`tokenmaxxing serve` รันเดมอน Slack ในเครื่องผ่าน Socket Mode โดยไม่ต้องใช้ URL สาธารณะ การตั้งค่า:

```sh
tokenmaxxing serve setup                    # พิมพ์ manifest ของแอป และถาม token ทั้งสองตัว
tokenmaxxing serve link <channel-id> <repo> # ผูกแชนเนลเข้ากับ checkout ของ repo
tokenmaxxing serve                          # รันเดมอน
```

กล่าวถึง (mention) บอทในแชนเนลที่ลิงก์ไว้ แล้วมันจะเปิดเซสชัน Claude Code สำหรับเธรดนั้นใน checkout ของ repo ที่ลิงก์ไว้ ทุกข้อความในเธรดจะรัน Agent SDK `query()` หนึ่งครั้งพร้อม `resume` ไม่ใช่ query แบบสตรีมมิงที่คงอยู่ถาวร ดังนั้น `ensureBestAccount()` จึงประเมินพูลใหม่ในทุกๆ เทิร์น และเดมอนสามารถรีสตาร์ทได้โดยไม่สูญเสียเธรด (บันทึกเธรดมีความคงทน เดมอนจะสมัครสมาชิก (re-subscribe) ให้ใหม่เมื่อเริ่มทำงาน)

พฤติกรรมที่น่าสังเกต:

- **สตรีมมิง**: การตอบกลับสตรีมเข้าสู่ Slack แบบเนทีฟ พร้อมการ์ดงานสำหรับการคิดและการรันเครื่องมือ โค้ดในบล็อกแบบ fenced เรนเดอร์พร้อมการไฮไลต์ การ์ด "Turn" ปิดท้ายพร้อมต้นทุนและระยะเวลา การ์ดทั้งหมดของหนึ่งเทิร์นยุบรวมเป็นบล็อกแผนเดียวที่ขยายได้ ดังนั้นหนึ่งเทิร์นโดยปกติจึงอ่านได้เป็นข้อความเดียว คือคำตอบพร้อมดรอปดาวน์หนึ่งอันของกิจกรรมของมัน (การลองใหม่กลางเทิร์นหรือการต่อท้ายที่ถูกปฏิเสธจะเปิดข้อความตามมา) การเรียก TodoWrite จะอัปเดตการ์ดเช็กลิสต์ที่เสถียรหนึ่งใบ ณ ที่เดิม Slack จะหมดอายุสตรีมแบบเนทีฟที่ฝั่งเซิร์ฟเวอร์หลังเงียบไปราว 30 วินาที หรือเมื่อข้อความมีอายุครบ 5 นาที แล้วแช่แข็งข้อความนั้นไว้เป็นป้าย "Something went wrong" ดังนั้นเดมอนจะปิดข้อความที่นิ่งหรือมีอายุยาวอย่างเรียบร้อยก่อนตัวจับเวลาใดตัวหนึ่งจะครบ แล้วไปต่อในข้อความใหม่
- **สิทธิ์**: `permissionMode` ต่อลิงก์มีค่าเริ่มต้นเป็น `acceptEdits` ส่วน `--yolo` (alias `--dangerous`) จะเลือกให้ลิงก์ใช้ `bypassPermissions` ไดอะล็อกแบบโต้ตอบไม่ได้รับอนุญาตในเทิร์นที่ถ่ายทอด (relayed) เพราะไม่มีใครตอบมันผ่าน Slack ได้ ดังนั้นโมเดลจะถามเป็นร้อยแก้วและการตอบกลับในเธรดของคุณคือเทิร์นถัดไป สกิลปลั๊กอินที่มาพร้อมกันจะสอนให้มันแท็กผู้ร้องขอและจบเทิร์นเมื่อต้องการการตัดสินใจ
- **รีแอ็กชันแสดงสถานะ**: ข้อความที่จุดเทิร์นจะพกสถานะของมันเป็นรีแอ็กชันอีโมจิ: นาฬิกาทรายขณะเทิร์นกำลังรัน จากนั้นเป็นเครื่องหมายถูก (เสร็จแล้ว) กากบาท (ล้มเหลว) หรือเครื่องหมายคำถาม (โมเดลต้องการการตัดสินใจของคุณ) ต้องการสโคป `reactions:write` จาก manifest ปัจจุบัน แอปที่มีอยู่แล้วต้องวาง manifest ใหม่และติดตั้งใหม่
- **การเรียกความสนใจและการสะกิด**: เมื่อโมเดลขอการตัดสินใจจากคุณ มันจะเรียกเครื่องมือ `need_attention` ภายในโปรเซส เพื่อให้เดมอนรู้ว่าเธรดกำลังรอคุณอยู่ หากคุณเงียบไป 10 นาที มันจะแท็กคุณหนึ่งครั้งในเธรด ขณะที่เธรดกำลังรอ การรีแอ็กต์ที่คำถามจะถูกส่งต่อเป็นคำตอบของคุณ (ยกนิ้วโป้งคือเลือกตัวเลือกที่แนะนำ) ส่วนรีแอ็กชันอื่นใดที่คุณเพิ่มในเธรดที่ติดตามอยู่จะถูกพับรวมเข้าเทิร์นถัดไปเป็นบริบท ต้องการ `reactions:read` และอีเวนต์ `reaction_added`
- **คำสั่งสแลช**: ข้อความในเธรดที่ข้อความหลังตัดคำนำหน้าเริ่มด้วย `/` จะรันเป็นคำสั่งสแลชของ claude ตัวเขียนข้อความ (composer) ของ Slack จะกลืนข้อความที่ขึ้นต้นด้วย `/` ดังนั้นให้ใช้รูปแบบกล่าวถึงก่อน (`@bot /usage`) หรือเว้นวรรคนำหน้า
- **การกลับมาทำงานต่ออัตโนมัติเมื่อหมดโควตา**: เมื่อทุกบัญชีในพูลหมดโควตาพร้อมกัน การขัดข้องช่วงสั้นจะ park ข้อความไว้แล้วลองใหม่ในที่เดิม ส่วนการขัดข้องที่นานกว่านั้นจะโพสต์ประกาศแจ้งรอไว้ และกลับมาทำงานต่อในเทิร์นนั้นโดยอัตโนมัติเมื่อพูลฟื้นตัว ทนต่อการรีสตาร์ทของเดมอนได้ มีเพียงลิมิตที่ไม่ทราบเวลาฟื้นตัวเท่านั้นที่จะขอให้คุณส่งข้อความใหม่
- **การลองใหม่เมื่อล้มเหลว**: เทิร์นที่ล้มเหลวโดยยังทำไม่จบ (โปรเซสลูก claude แครช หรือข้อผิดพลาดจาก API) จะลองใหม่เงียบๆ ได้อีกไม่เกิน 2 ครั้ง โดยกลับไปทำงานต่อในเซสชันเดิม เพื่อไม่ให้งานที่ทำเสร็จแล้วถูกรันซ้ำ หลังจากนั้นเท่านั้นเธรดจึงจะได้รับข้อผิดพลาดจริง เทิร์นที่ให้คำตอบจนจบแล้วจะไม่ถูกลองใหม่ และความล้มเหลวที่กลายเป็นว่าเกิดจากทุกบัญชีในพูลหมดโควตาจะถูกส่งต่อให้กลไกการกลับมาทำงานต่อเมื่อหมดโควตาข้างต้น
- **การแยกความผิดพลาด**: ความล้มเหลวของเธรดหนึ่งจะไม่ลากเธรดอื่นล้มตามไปด้วย งานแต่ละชิ้นในคิวเป็นเจ้าของข้อผิดพลาดของตัวเอง (ตัวจัดการที่แครชจะโพสต์ข้อมูลวินิจฉัยลงในเธรดของตัวเอง และเดมอนก็ให้บริการต่อไป) และเดมอนยังถือตัวกัน rejection ไว้เป็นด่านสุดท้าย เพราะไม่เช่นนั้นรันไทม์จะฆ่าทั้งโปรเซส รวมถึงเทิร์นของทุกเธรดที่กำลังทำงานพร้อมกัน เพียงเพราะ rejection หลงทางอันเดียว
- **การปิดอย่างนุ่มนวล**: SIGTERM/SIGINT จะระบาย (drain) เทิร์นใหม่จะถูกทิ้งอย่างมีเสียง เทิร์นที่กำลังทำงานได้เวลาสูงสุด 5 นาที และโปรเซสลูก claude รันแบบ detached ในกลุ่มโปรเซสของตัวเอง เพื่อให้การกด Ctrl-C ในเทอร์มินัลไม่สามารถฆ่ามันได้ก่อนที่การระบายจะรักษาเทิร์นไว้
- **การเคลียร์เธรด**: เมื่อคุณบอกว่างานเสร็จแล้ว โมเดลจะเรียกเครื่องมือ `finish_thread` ภายในโปรเซส หลังจากเทิร์นจบสมบูรณ์ เดมอนจะทิ้งบันทึกเธรด ยกเลิกการสมัครสมาชิก และโพสต์คำยืนยันหนึ่งครั้ง การกล่าวถึงใหม่จะเริ่มเซสชันใหม่
- **สุขอนามัยของข้อผิดพลาด**: ข้อผิดพลาดในเทิร์นจะโพสต์ข้อความที่ตัดให้เหลือเฉพาะข้อความ ไม่มีวันโพสต์เนื้อหาข้อผิดพลาดแบบดิบ
