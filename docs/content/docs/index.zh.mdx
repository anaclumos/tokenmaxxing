---

tokenmaxxing 是一款用于 Claude Code 账户自动切换的 CLI 工具。它把你拥有的多个订阅（Pro/Max）账户汇集在一起，当正在使用的账户接近用量限额时，把活动凭证热切换到更空闲的账户。你像往常一样运行 `claude`；切换发生在安全的回合边界，正在运行的会话会在新账户上继续同一段对话，无需重启。它同样支持多个会话并发运行。

唯一可见的行为出现在最坏情况：当整个账户池都触及限额时，会话会带着倒计时暂停，并在下一个重置的账户上自动恢复（按 Ctrl-C 可立即恢复）。

<Callout>
适用范围：macOS 和 Linux 上的 Claude Code，外加 OpenAI 的 Codex CLI 作为第二个并行的账户池。它汇集的是订阅账户，而非 API 密钥。这是一款供个人使用的工具，用于汇集你自己的账户，在你自己运行的会话与 agent 中使用 - 参见[个人使用与服务条款](/zh/terms)。
</Callout>

## 问题所在

Claude 订阅会同时计量三种限额（均已通过 `/usage` 确认）：

- **当前会话**：滚动的 5 小时窗口。
- **当前一周（所有模型）**：7 天的汇总额度。
- **当前一周，按模型**：针对各个模型家族的独立周上限。目前这类上限只存在于 Sonnet 和 Fable，且只有 Fable 的上限足够紧，才真正需要在意 - 它会远早于汇总额度就先触及上限。一台机器可能在周内所有模型仅用到 50% 时，就已经在周内 Fable 上用到 80%。

周配额是用不完就作废：账户到每周固定重置时仍未消耗的部分都会作废。如果你拥有多个账户，理性的策略是持续在最落后于自身周进度的账户上消耗配额，并在任一限额于会话中途触壁之前提前切走。

手动完成这件事意味着退出登录、重新登录，还会丢失对话。tokenmaxxing 将其自动化：正在运行的 `claude` 会在两次请求之间重新检查凭证存储，因此在底层换掉的凭证会就地生效（在 macOS 上约 30 秒内，在 Linux 上于下一次请求时）。普通切换从不重启会话。唯一仍需进程管理的情况是账户池彻底耗尽 - 会话无法让自己暂停 - 这正是轻量级监督进程存在的原因。

`claude` 的其他一切都保持不变：所有标志、MCP 服务器、hooks 和 skills 都会原样透传。
