tokenmaxxing خودکار Claude Code اکاؤنٹ بدلی لئی اک CLI اے۔ ایہہ تہاڈے اپنے کئی سبسکرپشن (Pro/Max) اکاؤنٹاں نوں اکٹھا کردا اے تے جدوں ورتوں وچلا اکاؤنٹ ورتوں دی حد نیڑے اپڑدا اے تاں چالو کریڈینشل نوں کسے تازہ اکاؤنٹ تے ہاٹ سویپ کر دیندا اے۔ تُسیں `claude` نوں بالکل اُنج ای چلاندے او جِنج ہمیشہ چلاندے او؛ بدلاؤ اک محفوظ ٹرن حد تے ہندا اے تے تہاڈا چلدا سیشن نویں اکاؤنٹ تے اوہو گل بات مُڑ چالو ہوئے بغیر جاری رکھدا اے۔ ایہہ اک ای ویلے کئی نال نال چلدے سیشناں تے کم کردا اے۔

اکو نظر آن والا رویہ سب توں مندے حال وچ اے: جدوں سارا پول اپنی حد تے اپڑ جاندا اے، تاں سیشن اک اُلٹی گنتی نال رُک جاندا اے تے اگلے ری سیٹ ہون والے اکاؤنٹ تے آپے مُڑ چالو ہو جاندا اے (Ctrl-C فوراً مُڑ چالو کر دیندا اے)۔

<Callout>
دائرہ: macOS تے Linux تے Claude Code، نال ای OpenAI دی Codex CLI اک دوجے، نال نال چلدے پول وانگوں۔ ایہہ سبسکرپشن اکاؤنٹ اکٹھے کردا اے، API کیز نئیں۔ ایہہ اک ذاتی ورتوں والا اوزار اے جیہڑا تہاڈے اپنے اکاؤنٹاں نوں، تہاڈے اپنے چلائے سیشناں تے ایجنٹاں وچ اکٹھا کرن لئی اے - ویکھو [ذاتی ورتوں تے سروسز دیاں شرطاں](#personal-use-and-terms-of-service)۔
</Callout>

## مسئلہ

اک Claude سبسکرپشن اک ای ویلے تِن حداں ماپدی اے (ساریاں `/usage` راہیں پُشٹی کیتیاں گئیاں):

- **موجودہ سیشن**: اک رولنگ 5 گھنٹے دی ونڈو۔
- **موجودہ ہفتہ (سارے ماڈل)**: اک 7 دن دا کُل جوڑ۔
- **موجودہ ہفتہ، فی ماڈل**: وکھ وکھ ماڈل خانداناں لئی الگ الگ ہفتہ وار حداں۔ ایہہ ہُنے صرف Sonnet تے Fable لئی موجود نیں، تے صرف Fable دی حد ایتھوں تیک تنگ اے جو معنی رکھدی اے - ایہہ کُل جوڑ توں کافی پہلاں لاگو ہو جاندی اے۔ اک مشین week-all وچ 50% تے بیٹھی ہو سکدی اے جدوں کہ اوہ پہلوں ای week-Fable وچ 80% تے ہووے۔

ہفتہ وار کوٹا ورتو یا گنوا دیو والا اے: اک اکاؤنٹ نے اپنے مقرر ہفتہ وار ری سیٹ تیک جیہڑا کوٹا نئیں ورتیا اوہ ضائع ہو جاندا اے۔ جے تہاڈے کول کئی اکاؤنٹ نیں، تاں سیانی چال ایہو اے کہ اوس اکاؤنٹ تے کوٹا ساڑدے رہو جیہڑا اپنی ہفتہ وار رفتار توں سب توں پِچھے ہووے، تے کسے وی اکلی حد دے سیشن دے وچالے کندھ نال ٹکران توں پہلاں بدل جاؤ۔

ایہہ کم ہتھیں کرن دا مطلب اے لاگ آؤٹ کرنا، لاگ اِن کرنا، تے اپنی گل بات گوانا۔ tokenmaxxing ایہنوں خودکار بنا دیندا اے: اک چلدا `claude` بینتیاں دے وچالے اپنے کریڈینشل سٹور نوں مُڑ جانچدا اے، سو ایہدے تھلے بدلیا گیا کریڈینشل اوتھے ای اپنا لیا جاندا اے (macOS تے تقریباً 30 سیکنڈ اندر، Linux تے اگلی بینتی تے)۔ اک سادہ بدلاؤ تہاڈا سیشن کدے مُڑ چالو نئیں کردا۔ اک صورت جیہدے وچ ہالی وی پروسیس بندوبست دی لوڑ پیندی اے اوہ اے پوری طرحاں مُک چُکیا پول - اک سیشن اپنے آپ نوں نئیں روک سکدا - تے بس ایسے واسطے پتلا سُپروائزر موجود اے۔

`claude` بارے باقی سب کجھ اونج ای رہندا اے: سارے فلیگ، MCP سرور، ہُک تے سکِلز جیویں دے تیویں لنگھ جاندے نیں۔

## چھیتی شروعات

macOS یا Linux تے [Bun](https://bun.sh) تے Claude Code دی لوڑ اے۔

```sh
bun add -g tokenmaxxing
tokenmaxxing init
```

`init` پنج کم کردا اے:

1. جیہڑے اکاؤنٹ نال تُسیں پہلوں لاگ اِن او اوہنوں اکاؤنٹ #1 وانگوں درآمد کردا اے (کوئی الگ `adopt` کمانڈ نئیں)۔
2. `claude` سُپروائزر شِم انسٹال کردا اے۔
3. Claude Code دی `settings.json` وچ تِن اِندراج انسٹال کردا اے: اک statusLine، اک Stop ہُک، تے اک SessionStart ہُک (نال اک subagentStatusLine اِندراج وی)۔
4. سُپروائزر دی bin ڈائریکٹری نوں تہاڈے شیل rc دے PATH نال جوڑدا اے (idempotent، اک `# tokenmaxxing PATH` تبصرے نال نشان زدہ)۔ اصل `claude` نوں روکن لئی ایہنوں PATH تے اوہدے توں اگے بیٹھنا پیندا اے۔
5. اک وقفے وار جانچ ٹائمر انسٹال کردا اے (macOS تے اک launchd ایجنٹ، Linux تے اک systemd یوزر ٹائمر) جیہڑا ہر 180 سیکنڈ بعد `tokenmaxxing check` چلاندا اے۔

اپنا شیل مُڑ چالو کرو، فیر ہور اکاؤنٹ شامل کرو تے چل پوو:

```sh
tokenmaxxing add        # اک ہور اکاؤنٹ نوں الگ تھلگ لاگ اِن کر کے پول وچ پا دیندا اے
claude                  # claude نوں ہمیشہ وانگوں ورتو
```

`tokenmaxxing` دا اک عرف `xx` وی اے۔ نِرا `tokenmaxxing` (یا `xx`) `status` چلاندا اے؛ `switch` ظاہر رہندا اے۔

## بناوٹ

tokenmaxxing اک ملٹی کال داخلہ نقطہ (`src/main.ts`) اے جیہڑا اوس ناں تھلے سدیا جان تے `claude` سُپروائزر وانگوں کم کردا اے، اندرونی سب کمانڈاں راہیں ہُک تے statusline شِم فراہم کردا اے، تے باقی حالتاں وچ CLI نوں چلاندا اے۔ ایہہ سِدھا Bun تھلے چلدا اے؛ npm پیکج TypeScript سورس بھیجدا اے، کوئی بلڈ نئیں۔

چلدے پُرزے:

### سُپروائزر شِم

`init` `claude` ناں والی اک 2 لائناں دی شیل شِم `~/.config/tokenmaxxing/bin/` وچ لکھدا اے تے اوس ڈائریکٹری نوں PATH تے پہلاں رکھدا اے۔ جدوں تُسیں `claude` ٹائپ کردے او، شِم سُپروائزر چلاندا اے، جیہڑا اصل claude بائنری نوں وراثتی stdio تے اک محفوظ کیتے `stty -g` ٹرمینل سنیپ شاٹ نال شروع کردا اے۔ ایہہ صرف اک پروسیس تے ٹرمینل منیجر اے: ایہہ کدے API ٹریفک نوں پراکسی نئیں کردا تے کدے راہ وچ ٹوکناں نوں نئیں چھیندا۔

پرنٹ موڈ سدے (`claude -p`، `--version`، `--help`)، غیر تعاملی سب کمانڈاں (`claude mcp`، `claude config`، تے ایویں ہور)، تے tokenmaxxing دیاں اپنیاں پروب سیشن بندوبست بغیر سِدھیاں لنگھ جاندیاں نیں۔ اک تعاملی سیشن لئی، سُپروائزر اک سیشن id پِن کردا اے (اک بناندا اے، یا اوہ جیہڑا تُسیں `--session-id` / `-r` / `-c` راہیں دِتا اوہنوں مُڑ ورتدا اے)، تہاڈے لانچ فلیگ محفوظ رکھدا اے تاں جو بعد وچ مُڑ لانچ اوہناں نوں دوبارہ چلا سکے، تے فیر اوس سیشن نال جُڑی اک respawn مارکر فائل تے نظر رکھدا اے۔

### statusline ٹی

Claude Code ہر ٹرن تے ریٹ لِمِٹ ڈیٹا (`rate_limits.five_hour` تے `rate_limits.seven_day`) statusline دے stdin وچ دھکدا اے۔ statusline سلاٹ tokenmaxxing دی ملکیت اے، سو ایہدا رینڈرر اک مفت، دھکے تے مبنی ورتوں فیڈ دا وی کم دیندا اے: ہر ٹِک تے ایہہ کُل جوڑ ونڈواں تے چالو ماڈل نوں `usage.json` وچ ٹی کر دیندا اے۔ فی ماڈل حداں statusline دے stdin وچ نئیں ہندیاں؛ ایہہ صرف `claude -p '/usage'` توں آندیاں نیں (مفت، صفر ٹوکن)، جیہنوں اک TTL نال پول کیتا جاندا اے تے جدوں چالو ماڈل گنجائش وچ تنگ ہووے تاں `model-usage.json` وچ کیش کیتا جاندا اے۔

ٹی بدلاؤ تے لکھن والا اے: جدوں اعداد نئیں بدلدے تاں ایہہ صرف فائل دا mtime ودھاندا اے، جیہڑا فیڈ دی زندگی دی دھڑکن دا کم کردا اے۔ تازگی ہمیشہ mtime نال پرکھی جاندی اے، کدے اندر رکھے ٹائم سٹیمپ نال نئیں۔

### Stop ہُک تے بدلاؤ

ہر ٹرن حد تے، Stop ہُک بدلاؤ دا فیصلہ چلاندا اے (ویکھو [بدلاؤ دا فیصلہ کیویں ہندا اے](#how-switching-decides))۔ جدوں کوئی بدلاؤ جائز ہووے، ایہہ اک `flock(2)` خصوصی لاک تھلے ہندا اے (`bun:ffi` راہیں لیا جاندا اے، کیوں جو macOS کوئی `flock(1)` بائنری نئیں بھیجدا)، تے کریڈینشل لکھت نال ای Claude Code دے اپنے refresh لاک نال جُڑ جاندی اے۔ اہم حصے دے اندر، اک بدلاؤ:

1. موجودہ لائیو کریڈینشل نوں اوہدے اصل مالک دی پارک کیتی بیک اپ وچ سمیٹدا اے۔
2. نشانہ اکاؤنٹ دے تازہ refresh کیتے کریڈینشل نوں لائیو والے وانگوں انسٹال کردا اے، موجودہ لائیو بلاب وچ رلا کے تاں جو نال دی حالت (جیویں فی MCP سرور OAuth ٹوکن) بچی رہوے۔
3. نشانہ دے گھمائے گئے ٹوکن نوں اوہدی اپنی بیک اپ وچ محفوظ رکھدا اے۔
4. `~/.claude.json` وچ `oauthAccount` فیلڈ نوں ایٹمی طور تے مُڑ لکھدا اے۔
5. نویں چالو لیبل نوں پکا کردا اے تے پرانے ورتوں سنیپ شاٹ صاف کردا اے، سب کجھ لاک کھلن توں پہلاں، تاں جو کوئی کریش کدے وی انسٹال کیتے کریڈینشل تے چالو لیبل نوں وکھو وکھ اکاؤنٹاں ول اشارہ کردے نہ چھڈ سکے۔

کیوں جو سارے طے شدہ پروفائل سیشن اکو لائیو کریڈینشل ساجھا کردے نیں، اک اکلا بدلاؤ اک ای ویلے ہر سیشن نوں منتقل کر دیندا اے، تے flock نال لاک تھلے مُڑ جانچ ریس لان والیاں ہُکاں نوں دو اکاؤنٹ ساڑن توں روکدی اے۔

### اوتھے ای اپنانا

اک چلدا claude سیشن بینتیاں دے وچالے اپنے کریڈینشل سٹور نوں پول کردا اے: macOS تے ایہہ اک نِکے کیش راہیں کی چین نوں مُڑ پڑھدا اے تے ایکسیس ٹوکناں دا موازنہ کردا اے؛ Linux تے ایہہ کریڈینشل فائل دا mtime ویکھدا اے تے بدلاؤ تے اپنے ٹوکن کیش خالی کر دیندا اے۔ نتیجہ ایہہ اے کہ اک بدلیا کریڈینشل macOS تے تقریباً 30 سیکنڈ اندر تے Linux تے بالکل اگلی بینتی تے، کسے مُڑ چالو کیتے بغیر، ہر چلدے سیشن ولوں اپنا لیا جاندا اے۔ ایسے لئی اک سادہ بدلاؤ کوئی مارکر نئیں لکھدا تے کوئی respawn شروع نئیں کردا - سیشن بس نویں اکاؤنٹ تے جاری رہندا اے۔ سیشن دے اندر `/usage` اوہو ٹوکن کیش ساجھا کردا اے، سو ایہدا اکاؤنٹ ڈسپلے اپنائے جان نال پلٹ جاندا اے۔

### مُکے پول دی اڈیک تے خودکار مُڑ چالو

صرف جدوں پول دا ہر اکاؤنٹ اپنیاں باراں توں اُتے ہووے تدے Stop ہُک اک respawn مارکر لکھدا اے (مارکر سکیما نوں اک `waitUntil` ٹائم سٹیمپ چاہیدا؛ اک سادہ بدلاؤ کدے وی اک نئیں بنا سکدا)۔ سُپروائزر مارکر ویکھدا اے، پہلوں ای پکی ہوئی ٹرن حد تے اپنے چائلڈ نوں SIGTERM کردا اے (Stop ہُک ٹرانسکرپٹ ڈسک تے آ جان تے تے claude وہلا ہون تے چلدا اے، سو کجھ وی نئیں گواچدا)، ٹرمینل بحال کردا اے، سب توں چھیتی ری سیٹ تیک اک اُلٹی گنتی ویکھاندا اے، تے فیر بحال کیتے اکاؤنٹ تے `claude --resume <session-id>` مُڑ لانچ کردا اے۔ اُلٹی گنتی دوران Ctrl-C فوراً مُڑ چالو کر دیندا اے۔ خودکار اڈیک `policy.maxWaitMs` (طے شدہ 1 گھنٹہ) نال محدود اے؛ اوہدے توں اگے فیصلہ اڈیک کرن دی بجائے پول نوں مُکیا ہویا دسدا اے۔

### وقفے وار جانچ ٹائمر

ہُک صرف ٹرن حداں تے چلدیاں نیں، تے اک لمی ایجنٹی ٹرن اک ونڈو نوں کسے اکلی حد بغیر تندرست توں مُکیا کر سکدی اے۔ ایسے لئی `init` اک وقفے وار ٹائمر وی انسٹال کردا اے - macOS تے اک launchd ایجنٹ، Linux تے اک systemd یوزر ٹائمر - جیہڑا ٹرن سرگرمی توں بے پرواہ ہر 180 سیکنڈ بعد `tokenmaxxing check` چلاندا اے۔

### اک SessionStart ہُک

جدوں کوئی سیشن شروع ہووے یا مُڑ چالو ہووے تاں اوہو پرکھ چلاندا اے، تاں جو اک تازہ سیشن ٹھیک اکاؤنٹ تے شروع ہووے۔ بدلاؤ توں بعد والا cooldown ایہنوں respawn توں بالکل بعد اک درست no-op بنا دیندا اے۔

## بدلاؤ دا فیصلہ کیویں ہندا اے [#how-switching-decides]

فیصلے دیاں دو تہاں نیں: اک اینگیجمنٹ گیٹ، تے فیر اک لالچی یا سخت راہ۔

### اینگیجمنٹ

`policy.greedySessionFloor` (طے شدہ 50، 5 گھنٹے دی سیشن ونڈو دے فیصد وچ) توں تھلے، فیصلہ چلدا ای نئیں - اک تازہ سیشن اپنے اکاؤنٹ تے سوار رہندا اے۔ جدوں چالو سیشن ونڈو 50% ورت لئی جاندی اے، یا کوئی سخت بار پار ہو جاندی اے، تاں فیصلہ چالو ہو جاندا اے۔

### چھانٹی باراں

ٹھریش ہولڈ چھانٹی باراں نیں، گھبراہٹ دا ٹریگر نئیں:

- `thresholds.session`: 95۔ اک 5 گھنٹے دا ری سیٹ اُڈیکنا سستا اے، سو سیشن ونڈو پہلاں ای بدل جاندی اے۔
- `thresholds.weekly`: 98۔ ایہہ اکلی بار 7 دن دے کُل جوڑ تے ہر فی ماڈل ہفتہ وار حد، دوواں نوں ڈھکدی اے۔ ہفتہ وار کوٹا ورتو یا گنوا دیو والا اے، سو ایہہ کندھ دے نیڑے تیک نکاسدا اے۔

دوویں جان بُجھ کے 100 توں تھلے نیں: گنجائش اوہ بجٹ اے جیہدے نال اکاؤنٹ دے اصل وچ اپنی حد نال ٹکران توں پہلاں اک صاف ٹرن حد تیک اپڑیا جا سکے (نال macOS تے اک ٹرن تیک اپنائے جان دی دیر وی)۔ اوہو باراں بدلاؤ دے اُمیدواراں نوں چھانٹدیاں نیں: اک اکاؤنٹ جیہڑا اپنی کسے وی بار توں اُتے ہووے اوہ درست نشانہ نئیں۔ ٹریگر تے چھانٹی ہمیشہ اوہو اثردار باراں ورتدے نیں (ٹھریش ہولڈ گھٹا کے `policy.projectionMargin`)، کیوں جو ٹریگر توں ڈھِلی چھانٹی بدلاؤاں نوں اوہناں اکاؤنٹاں تے لے جاوے گی جنہاں نوں ٹریگر فوراً مُڑ نشان لاندا اے، تے پول نوں پِنگ پونگ کراندی اے۔

### نشانہ: رفتار دباؤ

ورتن جوگے اکاؤنٹاں وچوں، نشانہ اوہ اے جیہڑا اپنی ہفتہ وار رفتار توں سب توں پِچھے ہووے: سب توں ودھ **رفتار دباؤ**، جیہدی تعریف اے باقی ہفتہ وار فیصد نوں اوس اکاؤنٹ دے ہفتہ وار ری سیٹ تیک دے ویلے تے تقسیم کرنا۔ اوہ اکاؤنٹ جِتدا اے جیہدا سب توں ودھ کوٹا ضائع ہون والا ہووے۔ برابری دی صورت وچ سب توں چھیتی ہفتہ وار میعاد پگن ول، فیر سب توں گھٹ 7 دن دی ورتوں ول ٹُٹدی اے۔

سب کجھ کیش کیتیاں ونڈواں تے چلدا اے جیہڑیاں مطلق UTC ایپاک وانگوں محفوظ ہندیاں نیں، سو اک باسی سنیپ شاٹ وی ٹھیک حل ہو جاندا اے: اک ہفتہ وار ری سیٹ جیہڑا لنگھ چُکیا ہووے اوہ ٹھیک 7 دن دیاں پُٹھاں وچ اگے کڈھیا جاندا اے، تے کوئی وی ونڈو جیہڑی اپنے کیش کیتے ری سیٹ توں لنگھ چُکی ہووے اوہ تازہ خالی گِنی جاندی اے (نہ کدے بدلن دی وجہ، نہ کدے کسے اکاؤنٹ نوں بینچ تے رکھن دی وجہ)۔

### لالچی بمقابلہ سخت راہ

- **لالچی راہ** (چالو، پر ہر بار توں تھلے): ہر اکاؤنٹ نوں درجہ دیو، موجودہ سمیت۔ جے موجودہ اکاؤنٹ پہلوں ای جِت جاندا اے یا برابر ہووے، تاں کجھ نہ کرو۔ نہیں تاں پکے طور تے بہتر اکاؤنٹ تے بدل جاؤ۔ ایہہ کدے اڈیک نئیں کردا تے کدے پہلوں پارک نئیں کردا - اک ورتن جوگا موجودہ اکاؤنٹ اک اڈیک دے بدلے وچ نئیں دِتا جاندا۔ کیوں جو موجودہ اکاؤنٹ نوں وی درجہ دِتا جاندا اے، خودکار راہ تے نِرا `tokenmaxxing switch` دوویں idempotent نیں: وقفے وار پرکھ ٹھیک اکاؤنٹ تے آ ٹِکدی اے تے فیر اوتھے ای رہندی اے۔
- **سخت راہ** (اک بار پار ہو گئی): بہترین ورتن جوگے اُمیدوار تے بدل جاؤ۔ جے کسے اُمیدوار دا refresh ٹوکن مریا ہویا نکلے، تاں اوہنوں مُڑ تصدیق دی لوڑ والا نشان لا دِتا جاندا اے تے اگلا اُمیدوار ازمایا جاندا اے۔ جے کوئی وی ورتن جوگا نہ ہووے، تاں مُکے پول دی اڈیک والی لاجک چلدی اے؛ صرف اوہ کال کرن والا جیہڑا سچ مُچ سیشن نوں روک سکدا اے (نگرانی ہیٹھلا Stop ہُک) نوں ہالی روکے پر سب توں چھیتی بحال ہون والے اکاؤنٹ تے پہلوں پارک کرن دی اجازت اے۔

### فی ماڈل حداں

`policy.switchModels` (طے شدہ `["fable"]`) اوہناں ماڈل خانداناں دے ناں دسدا اے جنہاں دی فی ماڈل ہفتہ وار حد اک بدلاؤ چھیڑ سکدی اے۔ ملان خاندان ٹوکن نال ہندا اے، کدے وی بالکل ٹھیک ڈسپلے سٹرنگ نال نئیں: ماڈل دے ڈسپلے ناں بدلدے رہندے نیں ("Fable" توں "Fable 5" بن گیا)، تے اک ٹھیک سٹرنگ والے گیٹ نے اک وار چُپ چاپ فی ماڈل بدلی نوں پوری طرحاں بند کر دِتا سی۔ دو نال جُڑے سلامتی اصول:

- اک انجان چالو ماڈل ہر ترتیب دِتے خاندان نوں گیٹ کردا اے۔ اک بدلاؤ سنیپ شاٹ صاف کرن توں فوراً بعد، اک ہیڈ لیس مشین ماڈل توں انی چل سکدی اے؛ انجان نوں بے قید سمجھن نے اک وار اک اکاؤنٹ نوں کئی گھنٹے اوہدی Fable حد تے بے دھیانی وچ بیٹھن دِتا۔
- اُمیدوار چھانٹی گیٹ کیتیاں فی ماڈل حداں نوں وی گِندی اے، سو اوہ پول جیہدے وچ ہر اکاؤنٹ اپنی Fable حد ساڑ چُکیا ہووے اوہ گول گول (round-robin) نئیں گھمدا۔

### کول ڈاؤن

اک 45 سیکنڈ دا بدلاؤ توں بعد والا کول ڈاؤن خودکار راہ نوں گیٹ کردا اے۔ statusline ٹی نوں بدلاؤ توں بعد اوہناں ای 45 سیکنڈاں لئی دبا دِتا جاندا اے (macOS تے اپنائے جان نوں 30 سیکنڈ تیک لگدے نیں)، سو اک پہلاں والی پرکھ اوس ڈیٹا تے چلدی جیہنوں بدلاؤ نے آپ ای غلط کر دِتا ہووے - اوہو صورتحال نے اک وار A توں B تے واپس والا respawn لوپ پیدا کر دِتا سی۔ ہتھیں `tokenmaxxing switch` کول ڈاؤن توں غیر متاثر اے۔

## ترتیب

Config `~/.config/tokenmaxxing/config.json` تے JSON اے۔ ہر فیلڈ اختیاری اے؛ طے شدہ قدراں فی فیلڈ لاگو ہندیاں نیں۔

```json
{
  "thresholds": { "session": 95, "weekly": 98 },
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 50,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000
  }
}
```

- `thresholds.session` / `thresholds.weekly`: اُتے دسیاں چھانٹی باراں۔
- `policy.projectionMargin`: اثردار باراں بنان لئی دوواں باراں وچوں گھٹایا جاندا اے۔
- `policy.greedySessionFloor`: سیشن ورتوں فیصد جِتھے لالچی اکٹھ چالو ہندا اے۔
- `policy.switchModels`: اوہ ماڈل خاندان جنہاں دی فی ماڈل ہفتہ وار حد اک بدلاؤ نوں گیٹ کردی اے (اِندراج لوڈ ویلے چھوٹے اکھراں وچ کر دِتے جاندے نیں)۔
- `policy.usagePollTtlMs`: اک `/usage` فی ماڈل پول کِنا چِر تازہ رہندا اے۔
- `policy.maxWaitMs`: مُکے پول دی خودکار اڈیک دی حد۔

`tokenmaxxing config` ذرائع نال اثردار config ویکھاندا اے؛ `config set`/`unset` نقطے والیاں کیز سودھدے نیں؛ `config tidy` انجان کیز چھانگدا اے۔

## حالت ڈائریکٹری خاکہ

سب کجھ `~/.config/tokenmaxxing/` تھلے رہندا اے (`TOKENMAXXING_HOME` نال بدلیا جا سکدا اے؛ ہر باہروں نظر آن والی راہ دا اک env اووَر رائیڈ اے تاں جو سارا اوزار ٹیسٹاں وچ الگ تھلگ چل سکے)۔

| راہ | ایہہ کیہ رکھدی اے |
|---|---|
| `config.json` | تہاڈی ترتیب (ٹکویں؛ طے شدہ قدراں فی فیلڈ لاگو ہندیاں نیں) |
| `accounts.json` | اکٹھے کیتے Claude اکاؤنٹاں دا غیر خفیہ اِنڈیکس: لیبل، آئی ڈی، کیش کیتیاں ورتوں ونڈواں۔ کدے ٹوکن نئیں |
| `usage.json` | statusline ٹی دا کُل جوڑ ونڈو سنیپ شاٹ؛ ایہدا mtime فیڈ دی زندگی دی دھڑکن اے |
| `model-usage.json` | `/usage` توں TTL کیش کیتیاں فی ماڈل ہفتہ وار حداں |
| `lastswap.json` | چھیکڑلے بدلاؤ دا ایپاک ٹائم سٹیمپ؛ 45 سیکنڈ دا کول ڈاؤن چلاندا اے |
| `lock` | `flock` فائل جیہڑی بدلاؤاں نوں وارو واری کردی اے |
| `tokenmaxxing.log` | صرف نال جوڑن والا ایونٹ لاگ |
| `bin/` | PATH شِم: `claude`، `codex`، تے `tokenmaxxing` / `xx` داخلہ نقطے |
| `respawn/<session-id>` | مُکن دی اڈیک دے respawn مارکر جنہاں نوں سُپروائزر ویکھدا اے |
| `creds/` | صرف Linux: پارک کیتیاں کریڈینشل فائلاں، اک 0700 ڈائریکٹری وچ 0600 (macOS اوہدی بجائے کریڈینشل نوں فی اکاؤنٹ کی چین آئٹماں وانگوں پارک کردا اے) |
| `onboard/`، `sample/` | `add`/`auth` لاگ اِناں تے پارک کیتے اکاؤنٹ دیاں `/usage` پروباں لئی سُٹن جوگے الگ تھلگ config ہوم؛ سادہ لکھت کریڈینشل رکھن والے onboard ہوم سمیٹن توں بعد مِٹا دِتے جاندے نیں |
| `slack.json` | `xx serve` ٹوکن تے چینل لنک (0600) |
| `slack-threads/` | `xx serve` لئی فی تھریڈ سیشن ریکارڈ |
| `codex-*` | نال نال چلدی Codex پول: `codex-accounts.json`، `codex-lastswap.json`، `codex-lock`، `codex-creds/`، `codex-onboard/`، `codex-respawn/`، تے `codex-live/` (ہر چلدے نگرانی ہیٹھلے codex سیشن لئی اک PID تصدیق شدہ موجودگی فائل، سو اک لائیو اکاؤنٹ کدے بدلاؤ دا نشانہ نئیں) |

اپنی ڈائریکٹری توں باہر، tokenmaxxing بالکل ایہو چیزاں نوں چھیندا اے: `~/.claude.json` (`oauthAccount` بدلاؤ)، Claude Code دی `settings.json` (ہُک تے statusline اِندراج)، لائیو کریڈینشل سٹور (macOS تے `Claude Code-credentials` کی چین آئٹم، Linux تے `.credentials.json`)، `~/.claude.lock` (claude دا refresh لاک، بدلاؤاں دوران لیا جاندا)، codex دیاں `auth.json` تے `hooks.json`، تے launchd یا systemd وچلا وقفے وار جانچ یونٹ۔

## کریڈینشل سٹوریج تے سلامتی ماڈل

ساری حالت `~/.config/tokenmaxxing/` وچ رہندی اے۔ کریڈینشل I/O اک اکلے پلیٹ فارم چُنے سٹور فیساڈ راہیں لنگھدی اے؛ کال تھاواں کدے پلیٹ فارم تے شاخ نئیں بناندیاں۔

**macOS**: کریڈینشل لاگ اِن کی چین وچ generic-password آئٹماں وانگوں رہندے نیں، اوہو تھاں مِلاندے جِتھے Claude Code آپ اوہناں نوں رکھدا اے۔ لائیو آئٹم اوہ اے جیہڑی claude پڑھدا اے؛ پول دے ہر اکاؤنٹ دی بیک اپ اوہدی اپنی `tokenmaxxing-cred-<uuid8>` کی چین آئٹم وانگوں پارک کیتی جاندی اے۔ ڈسک تے کجھ وی سادہ لکھت وچ نئیں۔ پڑھت `security find-generic-password -w` ورتدی اے (راز صرف stdout تے ای نظر آندا اے)؛ لکھت اک `add-generic-password` لائن نوں stdin راہیں `security -i` وچ پائپ کردی اے تاں جو راز کسے وی پروسیس دے argv وچ کدے نہ نظر آوے۔ تعاملی موڈ دا لگ بھگ 4 KB دا لائن بفر اے، سو ودھ وڈے بلاب اک argv لکھت تے واپس آ جاندے نیں - ایہو اک وجہ اے کہ پارک کیتیاں آئٹماں صرف گھٹو گھٹ OAuth آبجیکٹ رکھدیاں نیں۔

**Linux**: Claude Code کریڈینشل نوں اک 0600 سادہ لکھت فائل وانگوں رکھدا اے، تے tokenmaxxing اوہو ماڈل اپناندا اے: لائیو فائل claude دی اپنی `.credentials.json` اے، تے پارک کیتیاں بیک اپاں اک 0700 ڈائریکٹری وچ `~/.config/tokenmaxxing/creds/` تھلے ایٹمی 0600 فائلاں نیں۔ ایتھے ایٹمی دا مطلب اے temp وچ لکھو، fsync کرو، فیر مُڑ ناں دیو: اک نال نال چلدا پڑھن والا ہمیشہ اک پوری پرانی یا پوری نویں فائل ویکھدا اے، کدے ادھوری نئیں۔

بدلاؤ جیہڑے سلامتی اصول لاگو کردا اے:

- **اصل مالک ولوں سمیٹنا۔** اک بدلاؤ توں پہلاں، لائیو کریڈینشل دا اصل مالک API کولوں پُچھ کے پکا کیتا جاندا اے کہ ٹوکن کیہڑی تنظیم دا اے (OAuth roles اینڈ پوائنٹ خلاف `fetchTokenOrg`) - کدے وی محفوظ کیتے چالو لیبل تے بھروسہ کر کے نئیں، جیہڑا سرک سکدا اے۔ اک سرکے ہوئے لیبل نے اک وار اک اکاؤنٹ دی سمیٹ نوں دوجے اکاؤنٹ دی اکلی بیک اپ تے لکھوا دِتا سی۔ جے لائیو کریڈینشل پول توں باہرلے کسے اکاؤنٹ دا ہووے، تاں بدلاؤ اوہنوں مِٹان دی بجائے صاف انکار کر دیندا اے۔
- **اک اہم حصہ۔** سمیٹ، نویں کریڈینشل دی انسٹال، اوہدے گھمائے ٹوکن دی بیک اپ، `~/.claude.json` اکاؤنٹ بدلاؤ، تے چالو لیبل دی پکائی سب اکو لاک کیتے حصے دے اندر ہندے نیں۔
- **claude دے اپنے refresh نال جوڑ۔** میعاد نیڑے والا سیشن کسے وی پل اپنا ٹوکن گھما سکدا اے، سو کریڈینشل لکھت وی Claude Code دا refresh لاک لیندی اے (پوری کوشش، اک باسی لاک نوں مُڑ لین تے اک محدود ٹائم آؤٹ نال)۔
- **مرے گرانٹ صاف طرحاں ڈھلدے نیں۔** اک refresh جیہڑا `invalid_grant` نال واپس آوے اوس اکاؤنٹ نوں مُڑ تصدیق دی لوڑ والا نشان لاندا اے تے غلطی پھیلن توں پہلاں نشان محفوظ کر دیندا اے، سو مُڑ کوشش لوپ اُمیدواراں دا مجموعہ سُکیڑدے تے مُک جاندے نیں۔ `tokenmaxxing auth` اک نشان لگے اکاؤنٹ نوں اوتھے ای ٹھیک کردا اے، تے اوہ اک ایہو جیہے لاگ اِن توں انکار کر دیندا اے جیہڑا مرمت ہو رہے اکاؤنٹ توں وکھرے اکاؤنٹ تے اپڑے۔
- **کوئی ٹوکن لاگنگ نئیں۔** ٹوکن کدے وی لاگاں، غلطیاں، یا آؤٹ پُٹ وچ نظر نئیں آندے۔ ٹوکن تے ورتوں اینڈ پوائنٹاں توں غلطی باڈیاں کدے کچیاں نہیں دِسدیاں؛ صرف اک اجازت والیاں فیلڈاں دا مجموعہ بچدا اے، کیوں جو اک ٹوکن اینڈ پوائنٹ دی ناکامی باڈی بینتی دا مواد گونجا سکدی اے۔
- **پروب صفائی۔** کوئی وی شروع کیتی `claude` پروب اوہناں اٹھ ماحول متغیراں نوں صاف کردی اے جنہاں نوں claude اپنی کی چین کھوج توں پہلاں مندا اے (`ANTHROPIC_API_KEY`، `CLAUDE_CODE_OAUTH_TOKEN`، `CLAUDE_SECURESTORAGE_CONFIG_DIR`، تے ایویں ہور)، سو اک پروب کدے وی غلط اکاؤنٹ نال نئیں جوڑی جا سکدی۔

## پلیٹ فارم نوٹ: macOS بمقابلہ Linux

| | macOS | Linux |
|---|---|---|
| لائیو کریڈینشل | لاگ اِن کی چین generic-password آئٹم | 0600 `.credentials.json` فائل |
| پارک کیتے کریڈینشل | فی اکاؤنٹ کی چین آئٹماں | اک 0700 ڈائریکٹری وچ 0600 فائلاں |
| بدلاؤ توں بعد اپنانا | ~30 سیکنڈ اندر (کی چین پڑھت کیش) | اگلی بینتی (فائل mtime پول) |
| وقفے وار جانچ | launchd ایجنٹ، ہر 180s | systemd یوزر ٹائمر، ہر 180s |
| الگ تھلگ لاگ اِن سٹور | فی config dir ہیش نیم اسپیس والی کی چین سروس | الگ تھلگ config dir دے اندر اک فائل |

دو Linux لئی خاص گلاں جانن جوگیاں: claude اپنی کریڈینشل ڈائریکٹری نوں پہلاں `CLAUDE_SECURESTORAGE_CONFIG_DIR` توں حل کردا اے (فیر `CLAUDE_CONFIG_DIR`، فیر `~/.claude`)، تے tokenmaxxing اوس حل نوں بالکل اونج ای عکس بناندا اے تاں جو دوویں کدے بے میل نہ ہون۔ تے اوہو claude ورژن دے دو OS بلڈ `/usage` ری سیٹ گھڑیاں نوں وکھو وکھ طریقے نال بناندے نیں (اک " at " گلو ورتدا اے، دوجا اک کاما)؛ tokenmaxxing دا پارسر بالکل اوہو دو صورتاں مندا اے تے کسے تیجی تے اندازہ لان دی بجائے لاگ کردا اے۔

macOS تے، اک سچی حد: `init` تے `add` جان بُجھ کے کی چین نوں تعاملی طور تے چھیندے نیں، تاں جو پہلی `security` رسائی کسے ہیڈ لیس ہُک دے اندر ٹھنڈی نہ ہووے۔

## statusline

tokenmaxxing Claude Code دی statusline نوں مقامی طور تے رینڈر کردا اے (نال ورتوں فیڈ نوں ٹی کردے ہوئے)۔ ڈزائن دا اصول: کوٹا رنگ وچ چُکیا جاندا اے، نمبراں وچ نئیں۔ اک لائن، مثال ولوں:

```
tm-wt-demo Fable 5 (high) +156/-23  ◆ 𝒇 2h 1d  ◇ 19h  ◇ 𝒇 2d  ◇ full  ✗ ?
```

- ہر ونڈو ٹوکن اوہدے ری سیٹ تیک دا ویلہ اے، جیہڑا ورتوں فیصد مطابق اک متواتر ہرے توں پیلے توں لال ریمپ تے رنگیا جاندا اے (جدوں ٹرمینل سہار سکے تاں truecolor، نہیں تاں 256 رنگ کیوب تے پُٹھ نال)۔ ریمپ 0 لئی خالص ہرے، 75 تے پیلے، تے 95 تے اوہدوں اُتے لال تے لنگر پاندا اے، سو پرانے شدت دے بینڈ ریمپ لنگراں وانگوں بچے رہندے نیں۔
- ماڈل دا ناں اوہو ریمپ تے سیاق ونڈو دی بھرائی مطابق رنگیا جاندا اے۔
- اک ہرا `◆` چالو اکاؤنٹ دیاں ونڈواں دی اگوائی کردا اے؛ ہر پارک کیتے اکاؤنٹ نوں اوہدا اپنا سیان `◇` مِلدا اے (جے اوہنوں مُڑ تصدیق چاہیدی ہووے تاں لال `✗`)۔ اکاؤنٹ سب توں چھیتی آن والے ری سیٹ مطابق ترتیب پاندے نیں۔
- فی ماڈل ہر بلاک وچ پہلاں اک ننگے رنگے ابتدائی اکھر وانگوں آندا اے: Fable `𝒇` بناندا اے؛ ہور خاندان اپنا وڈے اکھر والا پہلا حرف ورتدے نیں، ہمیشہ خاندان نال مِلایا۔
- اک اَن چھوہیا پارک کیتا اکاؤنٹ اک ہرا `full` بناندا اے۔ اک انجان ری سیٹ نال ماپی گئی ورتوں اک رنگیا `?` بناندی اے، تے اک گیٹ کیتے ماڈل تے اک اَن ماپی فی ماڈل حد اک بے رنگ `𝒇?` بناندی اے - اَن ماپی کدے وی محفوظ نئیں دِسنی چاہیدی۔
- ری سیٹ اُلٹی گنتیاں صرف سب توں وڈی اکائی ویکھاندیاں نیں، کدے "now" یا "0m" نئیں؛ اک ونڈو جیہدا کوئی آن والا ری سیٹ نہ ہووے اوہ اک ہرا `0` بناندی اے (مُڑ خالی)۔
- اک جُڑی git worktree دا بیس ناں لائن دی اگوائی کردا اے؛ اک مین چیک آؤٹ اوتھے کجھ نئیں بناندا۔ کھوج اک `.git` فائل لئی فائل سسٹم پڑھدی اے تے کدے کوئی git سب پروسیس شروع نئیں کردی۔
- `NO_COLOR` سیٹ ہون تے، لائن اک چمبڑی عددی صورت تے واپس آ جاندی اے (`2h5` دا مطلب 2 گھنٹیاں وچ ری سیٹ، 5% ورتیا؛ سیاق بھرائی لئی `ctx 42`) - رنگ بغیر، اک نکاسیا ونڈو تازہ نئیں دِسنا چاہیدا۔

سب ایجنٹ کماں نوں claude دی subagentStatusLine سطح راہیں اپنیاں پینل قطاراں مِلدیاں نیں: ہر چالو کم لئی اک قطار، خاندان دا ناں اوس کم دی سیاق بھرائی مطابق رنگیا۔

## Codex سہارا

اوہو اکٹھ OpenAI دی Codex CLI لئی، تہاڈے اپنے ChatGPT سبسکرپشن اکاؤنٹاں خلاف کم کردا اے:

```sh
tokenmaxxing init --codex   # اپنا موجودہ codex لاگ اِن درآمد کرو + codex سُپروائزر تے Stop ہُک انسٹال کرو
tokenmaxxing add --codex    # اک ہور اکاؤنٹ الگ تھلگ لاگ اِن کرو - تہاڈا مُکھ لاگ اِن اَن چھوہیا رہندا اے
codex                       # codex نوں ہمیشہ وانگوں ورتو
```

Codex پول پوری طرحاں نال نال چلدی حالت اے: اپنا اکاؤنٹ اِنڈیکس، اپنیاں پارک کیتیاں کریڈینشل فائلاں (دوواں پلیٹ فارماں تے 0600 فائلاں، کیوں جو codex دا اپنا سٹور اک سادہ لکھت فائل اے)، اپنا لاک، اپنا چھیکڑلا بدلاؤ ٹائم سٹیمپ۔ فیصلہ پالیسی کوڈ توں بغیر Claude پول نال کجھ وی ساجھا نئیں۔

### Codex تے ہاٹ سویپ کیوں ناممکن اے

اک چلدا codex پروسیس اک اِن میموری auth منیجر رکھدا اے تے صاف صاف `auth.json` نوں مُڑ لوڈ کرن توں انکار کر دیندا اے جدوں اوہ ہُنے کسے وکھرے اکاؤنٹ دا ناں دسے۔ کوئی فائل واچر تے کوئی فی بینتی کریڈینشل پول نئیں، سو اک چلدے codex دے تھلے بدلیا کریڈینشل اِنفرینس لئی کدے اثر ای نئیں کردا۔ مُڑ چالو کرنا ای بدلاؤ اے: `codex resume <session-id>` اوس اکاؤنٹ تے مقامی ٹرانسکرپٹ نوں جاری رکھدا اے جیہڑا `auth.json` ہُنے رکھدا اے۔

tokenmaxxing ایہنوں اک codex سُپروائزر شِم نال سنبھالدا اے: Stop ہُک ہر ٹرن حد تے اوہو لالچی رفتار دباؤ فیصلہ چلاندا اے، تے جدوں اوہ بدلدا اے، اوہ اک مارکر لکھدا اے جیہڑا سُپروائزر نوں پکی حد تے سیشن نوں SIGTERM کرن تے تازہ اکاؤنٹ تے `codex resume <session-id>` مُڑ لانچ کرن لان دیندا اے، ٹرانسکرپٹ سلامت۔ کیوں جو ہر codex بدلاؤ اک نظر آن والا مُڑ چالو اے، codex لالچی راہ اک 1.2x بہتری مارجن رکھدی اے: اک چیلنجر نوں موجودہ اکاؤنٹ دے رفتار دباؤ نوں 20% نال ہرانا پیندا اے، وال جِنے نال نئیں۔ سخت راہ (اک پار کیتی بار) مارجن نوں نظر انداز کردی اے۔ codex لئی کوئی مُکے پول دی اُلٹی گنتی وی نئیں - کجھ وی codex سیشن نوں نئیں روک سکدا - سو اک پوری طرحاں مُکی codex پول اوتھے ای رہندی اے۔

ہور codex لئی خاص طریقہ کار:

- ورتوں codex دے اپنے ریٹ لِمِٹ اینڈ پوائنٹ خلاف اک مفت تصدیق شدہ GET توں پڑھی جاندی اے (اوہو کال جیہڑی CLI دا `/status` کردا اے): فیصد نال مطلق ایپاک ری سیٹ ویلے، کُل جوڑ ونڈواں تے فی ماڈل حداں دوویں۔ ونڈو دی درجہ بندی مدت مطابق ہندی اے، کدے تھاں مطابق نئیں، کیوں جو موجودہ پلاناں دی شاید کوئی 5 گھنٹے دی ونڈو ای نہ ہووے تے ہفتہ وار ونڈو مُکھ سلاٹ وچ بیٹھی ہوندی اے۔
- Codex refresh ٹوکن گھمدے نیں، تے اک بدلے گئے ٹوکن نوں مُڑ ورتنا سارے گرانٹ خاندان نوں مار دیندا اے۔ ہر گھماؤ اوہدے واپس آندے ای محفوظ کر لیا جاندا اے، چالو اکاؤنٹ دا نمونہ صرف لائیو بلاب راہیں ای لیا جاندا اے (کدے کوئی باسی پارک کیتی نقل نئیں)، تے فی سیشن موجودگی فائلاں یقینی بناندیاں نیں کہ اک اکاؤنٹ جیہڑا کسے لائیو نال دے سیشن وچ چل رہیا ہووے اوہ کدے بدلاؤ دا نشانہ نئیں تے اوہدا پارک کیتا ٹوکن کدے refresh نئیں ہندا۔
- Codex نوں فائل کریڈینشل سٹور چاہیدا: جے keyring سٹور پِن ہووے تاں `init --codex` چھیتی ناکام ہو جاندا اے، تے `add --codex` فائل موڈ سیٹنگ نوں الگ تھلگ آن بورڈنگ ہوم وچ لکھدا اے تاں جو لاگ اِن سمیٹن جوگا اپڑے۔
- اک ہتھیں قدم: codex اوہناں ہُکاں نوں چھڈ دیندا اے جنہاں تے بھروسہ کرن لئی اوہنوں نئیں کیہا گیا۔ `init --codex` توں بعد، codex اک وار کھولو تے `/hooks` راہیں tokenmaxxing Stop ہُک تے بھروسہ کرو، نہیں تاں خودکار بدلی چُپ چاپ بے حرکت رہندی اے۔ `init --codex` ایہہ یاد دہانی چھاپدا اے۔

## Slack پُل: xx serve

`tokenmaxxing serve` Socket Mode راہیں اک مقامی Slack ڈیمن چلاندا اے - کسے عوامی URL دی لوڑ نئیں۔ سیٹ اپ:

```sh
tokenmaxxing serve setup                    # ایپ مینی فیسٹ چھاپدا اے، دو ٹوکناں لئی پُچھدا اے
tokenmaxxing serve link <channel-id> <repo> # اک چینل نوں اک repo چیک آؤٹ نال جوڑو
tokenmaxxing serve                          # ڈیمن چلاؤ
```

کسے جُڑے چینل وچ بوٹ نوں مینشن کرو تے اوہ اوس تھریڈ لئی، جُڑے repo چیک آؤٹ وچ اک Claude Code سیشن کھولدا اے۔ ہر تھریڈ سنیہا اک Agent SDK `query()` نوں `resume` نال چلاندا اے - کدے کوئی مستقل سٹریمنگ کوئری نئیں - سو `ensureBestAccount()` ہر اکلے ٹرن تے پول نوں مُڑ پرکھدا اے تے ڈیمن تھریڈ گوائے بغیر مُڑ چالو ہو سکدا اے (تھریڈ ریکارڈ پائیدار نیں؛ ڈیمن شروعات تے اوہناں نوں مُڑ سبسکرائب کر لیندا اے)۔

غور طلب رویہ:

- **سٹریمنگ**: جواب مقامی طور تے Slack وچ سٹریم ہندے نیں، سوچ تے ٹول رنز لئی ٹاسک کارڈاں نال، واڑ والا کوڈ نمایانی نال رینڈر کیتا، لاگت تے مدت نال اک بند کرن والا "Turn" کارڈ، تے جدوں وی کوئی ٹول رن سٹریم کیتی لکھت نوں وچالے روکے تاں اک نواں Slack سنیہا کھلدا اے، سو اک ٹرن ٹول رنز دے آلے دوالے وکھو وکھ سنیہیاں وانگوں پڑھیا جاندا اے۔ TodoWrite کالاں اک ٹِکی چیک لسٹ کارڈ نوں اوتھے ای اپڈیٹ کردیاں نیں۔
- **اجازتاں**: فی لنک `permissionMode` طے شدہ طور تے `acceptEdits` اے؛ `--yolo` (عرف `--dangerous`) اک لنک نوں `bypassPermissions` وچ پا دیندا اے۔ ریلے کیتے ٹرناں وچ تعاملی ڈائیلاگ منع نیں - کوئی وی اوہناں دا جواب Slack راہیں نئیں دے سکدا - سو ماڈل عبارت وچ پُچھدا اے تے تہاڈا تھریڈ جواب اگلا ٹرن ہندا اے۔ اک نال آیا پلگ اِن سکِل اوہنوں سِکھاندی اے کہ جدوں اوہنوں کوئی فیصلہ چاہیدا ہووے تاں بینتی کرن والے نوں ٹیگ کرے تے ٹرن مکا دیوے۔
- **سلیش کمانڈاں**: اک تھریڈ سنیہا جیہدی چھِلی لکھت `/` نال شروع ہووے اوہ اک claude سلیش کمانڈ وانگوں چلدا اے۔ Slack دا کمپوزر `/` نال شروع ہون والے سنیہیاں نوں کھا جاندا اے، سو مینشن پہلاں والی صورت (`@bot /usage`) یا اگے اک خالی تھاں ورتو۔
- **سُچجی بندش**: SIGTERM/SIGINT خالی کردا اے - نویں ٹرن اُچی آواز نال چھڈے جاندے نیں، چلدے ٹرناں نوں 5 منٹ تیک مِلدے نیں، تے claude چائلڈ اپنے پروسیس گروپ وچ الگ ہو کے چلدا اے تاں جو اک ٹرمینل Ctrl-C ایہنوں خالی کرن ولوں ٹرن بچان توں پہلاں نہ مار سکے۔
- **تھریڈ صفائی**: جدوں تُسیں دسدے او کہ کم مُک گیا، ماڈل اک اِن پروسیس `finish_thread` ٹول سدّدا اے؛ ٹرن پوری طرحاں مُکن توں بعد، ڈیمن تھریڈ ریکارڈ چھڈ دیندا اے، اَن سبسکرائب کر دیندا اے، تے اک تصدیق چھاپدا اے۔ اک تازہ مینشن اک نواں سیشن شروع کردی اے۔
- **غلطی صفائی**: ٹرن غلطیاں چھانگی گئی صرف سنیہا لکھت چھاپدیاں نیں، کدے کچیاں غلطی باڈیاں نئیں۔

## Agent SDK سطح

پیکج دا پروگرامی داخلہ (`exports["."]` `src/sdk.ts` ول اشارہ کردا اے) tokenmaxxing نوں Claude Agent SDK نال جوڑدا اے اوہناں ایجنٹاں لئی جیہڑے تُسیں اپنے اکٹھے کیتے اکاؤنٹاں خلاف بناندے او۔ تہاڈی ایپ نوں Bun تھلے چلنا پیندا اے (tokenmaxxing TypeScript سورس بھیجدا اے تے `bun:ffi` ورتدا اے)۔

```ts
import { query } from "@anthropic-ai/claude-agent-sdk";
import { ensureBestAccount, pooledOptions, stopHookCheck } from "tokenmaxxing";

await ensureBestAccount(); // run the switch decision before the spawn

for await (const message of query({
  prompt: "...",
  options: {
    ...pooledOptions(), // pinned real claude + scrubbed env
    hooks: { Stop: [{ hooks: [stopHookCheck] }] }, // re-decide at every turn boundary
  },
})) {
  // capture the session id from the init message for `resume` across swaps
}
```

Agent SDK ہر `query()` لئی اک claude سب پروسیس شروع کردا اے تے شروعات تے اک وار کریڈینشل پڑھدا اے - کوئی statusline نئیں، کوئی کوئری دے وچالے ہاٹ سویپ نئیں - سو انضمام حد تے مبنی اے:

- `ensureBestAccount()` بالکل اوہو فیصلہ اے جیہڑا CLI ہُک تے ٹائمر چلاندے نیں (باراں، رفتار دباؤ، کول ڈاؤن، سارا ساجھا کوڈ)، کدے پیشگی نئیں: اک SDK سیشن نوں کدے وی مُکے پول دی اُلٹی گنتی لئی نئیں روکیا جا سکدا۔
- `pooledOptions()` `pathToClaudeCodeExecutable` نوں اصل claude بائنری تے پِن کردا اے (کدے سُپروائزر ریپر تے نئیں) تے اک پورا بدل `env` دیندا اے جیہدے وچ ہر ماحولی کریڈینشل اووَر رائیڈ صاف کیتا ہویا ہووے۔ جے تہاڈی ایپ دے ماحول وچ `CLAUDE_CONFIG_DIR` یا `CLAUDE_SECURESTORAGE_CONFIG_DIR` سیٹ ہووے تاں ایہہ چھیتی ناکام ہو جاندا اے: Linux تے اک بدلاؤ لائیو کریڈینشل اوتھے لکھوے گا جِتھے اوہ اشارہ کردے نیں جدوں کہ صاف کیتا سب پروسیس طے شدہ سٹور پڑھدا اے، اک چُپ چاپ غلط اکاؤنٹ بے میل۔
- `stopHookCheck` ٹرن حداں تے فیصلہ مُڑ چلاندا اے؛ جیہڑا بدلاؤ اوہ کردا اے اوہ اگلی شروعات تے لاگو ہندا اے۔ ایہہ اپنیاں غلطیاں آپ پھڑدا اے (stderr تے تے لاگ وچ لاگ کردے ہوئے) بجائے مُڑ سُٹن دے، کیوں جو اک اَن سنبھلیا ہُک استثنا ایجنٹ نوں وچالے روک سکدا اے، تے اک ٹُٹے بدلاؤ جانچ اُتے اک ٹرن روکنا موجودہ اکاؤنٹ تے چلدے رہن نالوں مہنگا پیندا اے۔

`sdk.ts` Agent SDK توں آپ کجھ وی درآمد نئیں کردا؛ ایہدیاں قدراں ڈھانچے وانگوں SDK دیاں آپشناں وچ پھیل جاندیاں نیں۔

## بلڈ تے ونڈ

npm پیکج TypeScript سورس بھیجدا اے، کوئی بلڈ نئیں: `tokenmaxxing` bin اک Bun shebang نال سِدھا `src/main.ts` ول اشارہ کردا اے، تے Bun 1.2.6 یا اوہدے توں نواں اوہنوں جیویں دا تیویں چلاندا اے۔ ایسے لئی Bun اک سخت لوڑ اے۔ ڈزائن ولوں کوئی کمپائل کیتیاں بائنریاں نئیں: اک پہلاں والی ریلیز نے ہر پلیٹ فارم نوں اک اکلی 61 MB دی macOS بائنری بھیجی سی تے اوہ Linux تے `exec format error` نال ناکام ہو گئی، تے فی پلیٹ فارم کمپائل کیتے پیکجاں نوں ہر اک نوں اپنی ریلیز پائپ لائن دی لوڑ ہندی، سو سورس نوں Bun ولوں چلانا ای ونڈ دا ماڈل بن گیا۔

پیکج دا `exports` نقشہ `src/sdk.ts` نوں اُتے دسے پروگرامی داخلے وانگوں سامنے لیاندا اے۔ ریلیزاں GitHub تے `v<version>` نال ٹیگ کیتیاں جاندیاں نیں؛ CI trusted publishing (OIDC، provenance نال) راہیں npm تے شائع کردا اے، تے شائع کرن والا گیٹ پہلاں typecheck تے پورا ٹیسٹ سویٹ چلاندا اے۔

## مسئلہ حل تے FAQ

**`claude` نگرانی ہیٹھ نئیں لگدا۔**
`tokenmaxxing doctor` چلاؤ۔ شِم نوں PATH حل جِتنا پیندا اے؛ ویکھو کہ تہاڈے شیل rc وچلی `# tokenmaxxing PATH` لائن موجودہ bin ڈائریکٹری ول اشارہ کردی اے تے اصل claude توں اگے بیٹھی اے۔ `doctor` `alias claude=...` یا اک `claude()` شیل فنکشن جیہڑا ریپر تے پرچھاواں پاندا ہووے، تے اوہناں عرفاں بارے وی خبردار کردا اے جیہڑے claude بائنری نوں مطلق راہ نال لانچ کردے نیں (اوہ سُپروائزر نوں پوری طرحاں بائی پاس کر دیندے نیں)۔

**Codex تے خودکار بدلی کدے نئیں چلدی۔**
Codex اوہناں ہُکاں نوں چھڈ دیندا اے جنہاں تے بھروسہ کرن لئی اوہنوں نئیں کیہا گیا۔ codex کھولو، `/hooks` چلاؤ، تے tokenmaxxing Stop ہُک تے بھروسہ کرو۔ بھروسہ ہُک دے ہیش خلاف درج ہندا اے، سو جے ہُک نوں کدے سودھیا جاوے تاں ایہہ مُڑ دینا پیندا اے۔

**اک اکاؤنٹ statusline وچ اک لال `✗` ویکھاندا اے۔**
اوہدا refresh ٹوکن مریا ہویا اے (منسوخ کیتا گیا یا اوہدی بیک اپ دے تھلوں گھمایا گیا)۔ اوہنوں اوتھے ای مُڑ تصدیق کرن لئی `tokenmaxxing auth <sel>` چلاؤ؛ کمانڈ تہانوں دسدی اے کیہڑی ای میل نال سائن اِن کرنا اے تے اک ایہو جیہے لاگ اِن توں انکار کردی اے جیہڑا کسے وکھرے اکاؤنٹ تے اپڑے۔

**ایہہ سب توں ودھ باقی کوٹے والے اکاؤنٹ تے کیوں نئیں بدلدا؟**
کیوں جو اوہ اکاؤنٹ کوٹا ضائع کرن دے سب توں ودھ خطرے وچ نئیں۔ نشانہ اوہ اکاؤنٹ اے جیہڑا اپنی ہفتہ وار رفتار توں سب توں پِچھے ہووے: باقی فیصد اوہدے ہفتہ وار ری سیٹ تیک دے ویلے تے تقسیم۔ برابر باقی مقدار نال ایہہ سب توں چھیتی میعاد پگن پہلاں ول گھٹ جاندا اے، تے برابر میعاد نال سب توں ودھ باقی پہلاں ول۔

**ایہہ ہُنے بدلیا اے تے statusline ہالی وی پرانا اکاؤنٹ ویکھا رہی اے۔**
macOS تے ~30 سیکنڈ تیک ایہہ توقع مطابق اے: چلدا سیشن اپنے اگلے کریڈینشل کیش refresh تے بدلیا کریڈینشل اپنا لیندا اے۔ ورتوں ٹی نوں بالکل ایسے وجہ کرکے اک بدلاؤ توں بعد 45 سیکنڈ لئی دبایا جاندا اے۔

**کیہ `status --force` دی کوئی لاگت اے؟**
ہاں، جان بُجھ کے: ایہہ فی اکاؤنٹ اک گھٹو گھٹ گِنی جان والی haiku بینتی بھیجدا اے تاں جو ہر 5 گھنٹے دی سیشن ونڈو سُتی رہن دی بجائے اوسے پل شروع ہو جاوے، فیر تازہ نمونہ لیندا اے۔ سادہ `status` تے `watch` کدے پِنگ نئیں کردے؛ `/usage` پڑھت مفت اے۔ دھیان رہوے کہ سرور ورتوں فیڈ اک تازہ کھلی ونڈو نوں سیکنڈاں توں منٹاں تیک دیر نال دسا سکدا اے، سو پِنگ توں فوراً بعد اک پروب ہالی وی پِنگ توں پہلاں والی حالت دسا سکدی اے - `status` پِنگ ناکام ہون دا ڈھونگ کرن دی بجائے اک نوٹ بناندی اے۔

**`/usage` پروب نے چالو اکاؤنٹ لئی کجھ وی واپس نئیں کیتا۔**
ایہہ اک جانیا پچھانیا claude رویہ اے: جدوں اوہدا اندرونی ورتوں فیچ ناکام ہووے یا ریٹ لِمِٹ ہووے، تاں `/usage` صرف مقامی سیشن اعداد وشمار بغیر کسے فیصد لائناں دے چھاپدا اے۔ tokenmaxxing چالو اکاؤنٹ دا نمونہ statusline دھکے توں لیندا اے تے صرف پارک کیتے اکاؤنٹاں نوں پروب کردا اے، ٹھیک ایسے توں بچن لئی۔

**پِچھوکڑ claude سیشن۔**
Claude دا پِچھوکڑ ڈیمن اصل ورژن والی بائنری نوں مطلق راہ نال شروع کردا اے، PATH شِماں نوں بائی پاس کردے ہوئے، سو پِچھوکڑ سیشن بے نگرانی ہندے نیں۔ ہُک ہالی وی `settings.json` راہیں چلدیاں نیں، تے کریڈینشل اپنائے جانا نال وقفے وار ٹائمر بدلی نوں ڈھکدے نیں، پر اوہناں لئی کوئی مارکر تے چلن والا respawn نئیں۔

**کسے شے نے اک وار بوہت سارے پروسیس شروع کر دِتے سن۔ کیہ ایہہ ہالی وی ہو سکدا اے؟**
سُپروائزر بالکل اوس تاریخی ناکامی خلاف پرتاں والے تکرار پہرے چُکدا اے (اک باسی ریپر جیہنوں "اصل" claude وانگوں پِن کیتا گیا سی): ماحول وچ اک ڈونگھائی نشان جیہڑا 5 پرتاں تے رُک جاندا اے، اک آن ڈسک شروعات دی رفتار محدود کرن والا، realpath شناخت جانچاں جیہڑیاں کسے وی ایہو جیہے اُمیدوار نوں رد کردیاں نیں جیہڑا مُڑ tokenmaxxing دی اپنی bin ڈائریکٹری وچ حل ہووے، تے اک سخت ناکامی (کدے کوئی چُپ چاپ PATH سکین نئیں) جدوں کوئی ترتیب دِتا claude راہ ہور موجود نہ رہوے۔ `init` تے `doctor` اک اُمیدوار نوں پِن کرن توں پہلاں `--version` چلا کے پکا کردے نیں کہ اوہ اصل وچ claude اے۔

**اَن انسٹال کرنا۔**
`tokenmaxxing uninstall` سُپروائزر شِماں، سیٹنگز اِندراج، تے وقفے وار ٹائمر ہٹا دیندا اے، تے تہاڈے اکاؤنٹ تے پارک کیتے کریڈینشل سلامت چھڈ دیندا اے۔ ایہہ صرف اوہو statusline اِندراج ہٹاندا اے جنہاں نوں اوہ اپنے وانگوں پچھاندا اے۔
