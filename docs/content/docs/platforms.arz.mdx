---
title: "ملاحظات المنصة: macOS مقابل Linux"
description: "الفرق بين macOS و Linux في التخزين، والتبني، والتايمرات"
---

| | macOS | Linux |
|---|---|---|
| الـ credential الحي | عنصر generic-password في الـ login keychain | ملف `.credentials.json` بصلاحية 0600 |
| الـ credentials المركونة | عناصر keychain لكل حساب | ملفات 0600 في مجلد 0700 |
| التبني بعد التبديل | خلال حوالي 30 ثانية (كاش قراءة الـ keychain) | الطلب اللي بعده (poll لـ mtime الملف) |
| الفحص الدوري | launchd agent، كل 180 ثانية | systemd user timer، كل 180 ثانية |
| مخزن تسجيل الدخول المعزول | خدمة keychain باسم مساحة مبني على hash لكل مجلد إعدادات | ملف جوّا مجلد الإعدادات المعزول |

تفصيلتين خاصين بـ Linux يستاهلوا تعرفهم: claude بيحدّد مجلد الـ credential بتاعه من `CLAUDE_SECURESTORAGE_CONFIG_DIR` الأول (وبعدين `CLAUDE_CONFIG_DIR`، وبعدين `~/.claude`)، و tokenmaxxing بيطابق التحديد ده بالظبط عشان الاتنين عمرهم ما يختلفوا. وبناءات الـ OS الاتنين لنفس نسخة claude بينسّقوا ساعات الـ reset بتاعت `/usage` بشكل مختلف (واحد بيستخدم رابط `" at "`، والتاني فاصلة)؛ الـ parser بتاع tokenmaxxing بيقبل الشكلين دول بالظبط وبيسجّل في اللوج، بدل ما يخمّن، لو لقى أي شكل تالت.

على macOS، قيد واحد بصراحة: `init` و `add` بيلمسوا الـ keychain بشكل تفاعلي عن قصد، عشان أول وصول لـ `security` مايكونش بارد جوّا hook من غير واجهة.
