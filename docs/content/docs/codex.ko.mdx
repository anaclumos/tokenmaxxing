동일한 풀링이 OpenAI의 Codex CLI에 대해서도, 직접 보유한 ChatGPT 구독 계정을 상대로 작동합니다:

```sh
tokenmaxxing init --codex   # 현재 codex 로그인을 가져오고 codex supervisor와 Stop 훅을 설치합니다
tokenmaxxing add --codex    # 다른 계정을 격리된 상태로 로그인합니다. 기본 로그인은 그대로 유지됩니다
codex                       # 늘 하던 대로 codex를 사용합니다
```

Codex 풀은 완전히 병렬 상태입니다. 자체 계정 인덱스, 자체 보관 자격 증명 파일(codex 자체 저장소가 평문 파일이므로 두 플랫폼 모두 0600 파일), 자체 잠금, 자체 마지막 교체 타임스탬프를 갖습니다. 결정 정책 코드를 제외하면 Claude 풀과 공유하는 것은 없습니다.

## Codex에서 hot-swap이 불가능한 이유

실행 중인 codex 프로세스는 하나의 인메모리 인증 관리자를 보유하며, `auth.json`이 이제 다른 계정을 가리키면 그것을 다시 로드하기를 명시적으로 거부합니다. 파일 워처도, 요청별 자격 증명 폴링도 없으므로, 실행 중인 codex 아래에서 교체된 자격 증명은 추론에 대해 그저 결코 적용되지 않습니다. 재시작이 곧 전환입니다. `codex resume <session-id>`는 `auth.json`이 이제 보유한 계정에서 로컬 트랜스크립트를 계속합니다.

tokenmaxxing은 이를 codex supervisor shim으로 처리합니다. Stop 훅은 매 턴 경계마다 동일한 그리디 진행 압력 결정을 실행하고, 교체할 때는 supervisor가 커밋된 경계에서 세션에 SIGTERM을 보내고 트랜스크립트를 그대로 둔 채 새 계정에서 `codex resume <session-id>`를 다시 실행하도록 만드는 마커를 기록합니다. 모든 codex 전환은 눈에 보이는 재시작이므로, codex 그리디 경로는 1.2배의 개선 여유를 둡니다. 도전 계정은 현재 계정의 진행 압력을 아슬아슬하게가 아니라 20% 앞서야 합니다. 하드 경로(기준선을 넘음)는 이 여유를 무시합니다. 또한 codex에는 풀 소진 카운트다운이 없습니다. codex 세션은 그 무엇도 일시 정지할 수 없기 때문입니다. 그래서 완전히 소진된 codex 풀은 그대로 머무릅니다.

그 밖의 codex 특유의 동작:

- 사용량은 codex 자체 rate-limit 엔드포인트에 대한 무료 인증 GET(CLI의 `/status`가 하는 것과 동일한 호출)에서 읽습니다. 백분율과 절대 epoch 초기화 시각, 합산 윈도우와 모델별 상한 모두를 얻습니다. 윈도우 분류는 위치 기반이 결코 아니라 기간 기반입니다. 현재 요금제에는 5시간 윈도우가 아예 없을 수 있고 주간 윈도우가 기본 슬롯에 놓이기 때문입니다.
- Codex 갱신 토큰은 회전하며, 대체된 토큰을 재사용하면 grant 계열 전체가 죽습니다. 모든 회전은 반환되는 즉시 저장되고, 활성 계정은 오직 라이브 blob을 통해서만 샘플링되며(오래된 보관 사본은 결코 사용하지 않음), 세션별 존재 파일은 라이브 형제 세션에서 실행 중인 계정이 결코 교체 대상이 되지 않고 그 보관 토큰이 결코 갱신되지 않도록 보장합니다.
- Codex는 파일 자격 증명 저장소를 요구합니다. keyring 저장소가 고정되어 있으면 `init --codex`는 즉시 실패하고, `add --codex`는 격리된 온보딩 홈에 파일 모드 설정을 기록하여 로그인이 수확 가능한 상태로 안착하도록 합니다.
- 수동 단계 하나: codex는 신뢰하라고 알려주지 않은 훅을 건너뜁니다. `init --codex` 이후 codex를 한 번 열어 `/hooks`를 통해 tokenmaxxing Stop 훅을 신뢰하세요. 그러지 않으면 자동 전환이 조용히 작동하지 않은 채로 남습니다. `init --codex`는 이 안내를 출력합니다.
