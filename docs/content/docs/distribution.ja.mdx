npm パッケージはビルド成果物ではなく TypeScript ソースを配布します。`tokenmaxxing` の bin は Bun のシバン付きで `src/main.ts` を直接指し、Bun 1.2.6 以降はそのまま実行します。これが Bun が必須要件である理由です。コンパイル済みバイナリは設計上存在しません。初期のリリースは単一の61 MB の macOS バイナリをすべてのプラットフォームに配布し、Linux では `exec format error` で失敗しました。プラットフォームごとのコンパイル済みパッケージはそれぞれ独自のリリースパイプラインを必要とするため、Bun によるソース実行が配布モデルになりました。

パッケージの `exports` マップは、[Agent SDK サーフェス](/ja/sdk)で説明したプログラム向けエントリポイントとして `src/sdk.ts` を公開します。リリースは GitHub 上で `v<version>` としてタグ付けされます。CI は trusted publishing (OIDC、来歴付き) で npm に公開し、公開ゲートはまず型チェックを実行します。

## Nix / nix-darwin

同じソースツリーは flake でもあります。Bun でソースをそのまま実行する方針はそのまま ([bun2nix](https://github.com/nix-community/bun2nix) の `writeBunApplication` 経由) で、次を公開しています。

| 出力 | 用途 |
|---|---|
| `packages.default` | PATH に `tokenmaxxing` と `xx` |
| `darwinModules.default` / `withOverlay` | nix-darwin: CLI を入れる (宣言的な check タイマーは任意) |
| `homeManagerModules.default` | macOS / Linux 向け Home Manager |
| `nixosModules.default` / `withOverlay` | NixOS へのシステム導入 |

プロファイルへ入れて (そうすることで `init` のスーパーバイザーシムが PATH 上の安定した `tokenmaxxing` を解決できます)、それから init します:

```sh
nix profile install github:anaclumos/tokenmaxxing
tokenmaxxing init
```

インストールせずに一度だけ動かす場合 (help / status のみ。この方法で `init` してはいけません):

```sh
nix run github:anaclumos/tokenmaxxing -- help
```

nix-darwin (`pkgs.tokenmaxxing` が解決されるよう overlay を足す):

```nix
{
  inputs.tokenmaxxing.url = "github:anaclumos/tokenmaxxing";
  modules = [
    inputs.tokenmaxxing.darwinModules.withOverlay
    { programs.tokenmaxxing.enable = true; }
  ];
}
```

Home Manager (パッケージを明示するか、Home Manager が使う pkgs にこの flake の overlay を適用します):

```nix
{
  imports = [ inputs.tokenmaxxing.homeManagerModules.default ];
  programs.tokenmaxxing.enable = true;
  programs.tokenmaxxing.package = inputs.tokenmaxxing.packages.${pkgs.system}.default;
}
```

Nix がやるのは CLI を PATH に載せるところまでです。アカウント取り込み、PATH 上の `claude` スーパーバイザーシム、`settings.json` のフック、(既定では) 定期チェックタイマーは、いままでどおり `tokenmaxxing init` 側です。これらは認証情報やユーザー所有の設定に触れるので、純粋なモジュールが書き換えるべきではありません。タイマーを init ではなく Nix に持たせたいときだけ `programs.tokenmaxxing.checkTimer.enable = true` にしてください (この設定は `TOKENMAXXING_SKIP_TIMER=1` もエクスポートするので、init が2つ目のユニットを書き込むことはありません)。宣言的なタイマーは init と同じくユーザーセッションのタイマーです。ヘッドレスな Linux では、ログインなしで発火させるために `loginctl enable-linger` が必要です。

`bun.lock` が変わったら、Nix の依存式を作り直します:

```sh
bun run nix:bun   # writes bun.nix via bun2nix@2.1.2
```
