---
title: Slack 橋接：xx serve
description: "xx serve 透過 Socket Mode 喺 Slack thread 行 Claude Code session"
---

`tokenmaxxing serve` 透過 Socket Mode 行一個本地 Slack 守護程序 - 唔需要公開 URL。設定：

```sh
tokenmaxxing serve setup                    # 列印 app manifest，提示輸入兩個 token
tokenmaxxing serve link <channel-id> <repo> # 將一個頻道綁去一個 repo checkout
tokenmaxxing serve                          # 行守護程序
```

喺連結咗嘅頻道提及個 bot，佢就會為嗰條 thread 喺連結嘅 repo checkout 入面開一個 Claude Code session。每一個新回合都會行一次帶 `resume` 嘅 Agent SDK `query()` - 所以 `ensureBestAccount()` 每一個回合都會重新評估帳戶池，而守護程序就算重新啟動都唔會失去 thread（thread 記錄係持久嘅;守護程序一啟動就會重新訂閱佢哋） - 不過一個回覆如果喺一次仲行緊嘅 query 期間到達，就會摺入嗰次 query 嘅串流輸入度，而唔係自己另外開一個 query；一個回覆如果錯過咗導向嘅窗口，就會當做下一個回合嚟行。

值得注意嘅行為：

- **導向**：一個回覆如果喺條 thread 嘅回合仲行緊嗰陣到達，就會摺入嗰個回合 - 同 Claude Code 互動用緊嘅回合中途注入一樣 - 所以個模型會喺佢下一個工具邊界度睇到，然後調整方向，而唔係第一時間做完錯嘅嘢先。一個回覆如果喺回合最後一次工具呼叫之後先到，就會即刻當做自己一個獨立回合嚟行；不論邊種情況都唔會有嘢俾漏低。畀導向咗嘅訊息會帶住沙漏反應，同個回合一齊完結，佢哋嘅文字仲會跟住個回合嘅持久標記，所以重新啟動同用量上限自動恢復都會重播佢。淨係排喺另一個等緊嘅訊息後面嘅訊息先會跳過呢個摺入（次序係保住嘅），而排走緊嘅守護程序仲係會大聲噉丟棄，唔會去導向。
- **串流**：回覆會原生串流入 Slack，有思考同工具運行嘅任務卡片、用高亮渲染嘅圍欄程式碼、一張寫住成本同持續時間嘅收尾「Turn」卡片；一個回合嘅卡片會摺埋成一個可展開嘅 plan block，所以一個回合通常睇落好似一條訊息：回覆，加埋一個顯示佢活動嘅落拉選單（回合中途重試，或者被拒嘅追加，會開一條跟進訊息）。TodoWrite 呼叫會就地更新同一張穩定嘅檢查清單卡片。Slack 喺伺服器嗰邊會令原生串流過期，靜咗大約 30 秒，或者活咗 5 分鐘，就過，將條訊息凍住，變成一個寫住「Something went wrong」嘅標籤，所以守護程序會趕喺兩個計時器夠鐘之前，乾淨俐落噉閂咗閒置或者活得太耐嘅訊息，再開一條新嘅繼續落去。
- **權限**：每個連結嘅 `permissionMode` 預設係 `acceptEdits`;`--yolo`（別名 `--dangerous`）就令連結轉用 `bypassPermissions`。轉發嘅回合入面唔准用互動式對話 - 冇人可以喺 Slack 度回答 - 所以個模型會用文字問，而你嘅 thread 回覆就係下一個回合。附帶嘅 plugin skill 會教佢，一需要做決定就標記請求者，然後結束個回合。
- **狀態反應**：觸發一個回合嘅訊息會用 emoji 反應帶住佢嘅狀態：回合行緊嘅時候係沙漏，之後係剔號（完成）、交叉（失敗），或者問號（個模型需要你做決定）。需要現時 manifest 入面嘅 `reactions:write` scope;現有嘅 app 要重新貼一次 manifest 再重新安裝。
- **注意同提醒**：當個模型要問你做決定，佢會呼叫進程內嘅 `need_attention` 工具，令守護程序知道條 thread 喺度等緊你。如果你 10 分鐘都冇出聲，佢會喺條 thread 度標記你一次。當一條 thread 喺等緊嘅時候，對條問題加反應就會當做你嘅答案轉發（一個讚會揀推薦嘅選項）;你喺追蹤緊嘅 thread 入面加嘅任何其他反應，都會摺入下一個回合做上下文。需要 `reactions:read` 同 `reaction_added` 事件。
- **斜線指令**：一條 thread 訊息，剝除後嘅文字以 `/` 開頭，就會當做 claude 斜線指令嚟行。Slack 嘅撰寫器會食咗以 `/` 開頭嘅訊息，所以要用提及優先嘅形式（`@bot /usage`），或者喺前面加個空格。
- **用量上限自動恢復**：帳戶池入面嘅帳戶全部撞晒上限嗰陣，一次好短嘅斷供會將條訊息泊住，原地重試;斷供耐啲嘅話就會貼一個等候通知，一等帳戶池復原就自動恢復嗰個回合，仲撐得過守護程序重新啟動。淨係嗰啲估唔到幾時先恢復嘅上限，先至會叫你重新發送。
- **失敗重試**：一個回合未答完就失敗（claude 仔進程崩咗、API 出錯），會靜靜雞再重試最多 2 次，用返同一個 session 恢復，所以做完咗嘅嘢永遠唔使重做;試晒之後，條 thread 先至會收到真正嘅錯誤。已經答完嘅回合永遠唔會重試;而如果個失敗查出嚟其實係帳戶池用晒額度，就會交返畀上面嗰套用量上限機制。
- **故障隔離**：一條 thread 出事，永遠唔會拖冧其他 thread。隊列入面每個任務都自己孭起自己嘅錯誤（handler 崩咗，就喺佢自己嗰條 thread 貼一段診斷，守護程序照舊服務），而守護程序仲留住一道最後防線嘅 rejection 守衛，因為冇咗佢，runtime 就會為咗一個走漏嘅 rejection 殺埋成個進程 - 連同每一條並發 thread 手上嘅回合。
- **優雅關閉**：SIGTERM/SIGINT 會排走 - 大聲噉丟棄新回合，畀行緊嘅回合最多 5 分鐘，而 claude 仔進程會喺自己嘅進程群組入面獨立噉行，所以終端嘅 Ctrl-C 喺排走保存個回合之前都殺佢唔死。
- **thread 清理**：當你話俾佢知件工作做完咗，個模型會呼叫進程內嘅 `finish_thread` 工具;喺回合完全結束之後，守護程序會丟棄個 thread 記錄、取消訂閱，再貼一個確認。一次新嘅提及就會開一個新 session。
- **錯誤衛生**：回合出錯時只會貼經修剪嘅淨訊息文字，永遠唔會係原始嘅錯誤內容。
