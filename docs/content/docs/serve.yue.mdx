---
title: Slack 橋接：xx serve
description: "xx serve 透過 Socket Mode 喺 Slack thread 行 Claude Code session"
---

`tokenmaxxing serve` 透過 Socket Mode 行一個本地 Slack 守護程序 - 唔需要公開 URL。設定：

```sh
tokenmaxxing serve setup                    # 列印 app manifest，提示輸入兩個 token
tokenmaxxing serve link <channel-id> <repo> # 將一個頻道綁去一個 repo checkout
tokenmaxxing serve                          # 行守護程序
```

喺連結咗嘅頻道提及個 bot，佢就會為嗰條 thread 喺連結嘅 repo checkout 入面開一個 Claude Code session。每條 thread 訊息都行一次帶 `resume` 嘅 Agent SDK `query()` - 永遠唔係持久嘅串流 query - 所以 `ensureBestAccount()` 每一個回合都會重新評估帳戶池，而守護程序就算重新啟動都唔會失去 thread（thread 記錄係持久嘅;守護程序一啟動就會重新訂閱佢哋）。

值得注意嘅行為：

- **串流**：回覆會原生串流入 Slack，有思考同工具運行嘅任務卡片、用高亮渲染嘅圍欄程式碼、一張寫住成本同持續時間嘅收尾「Turn」卡片，每當有工具運行打斷串流文字，就會開一條新 Slack 訊息，令一個回合睇落好似圍住工具運行嘅分開訊息。TodoWrite 呼叫會就地更新同一張穩定嘅檢查清單卡片。
- **權限**：每個連結嘅 `permissionMode` 預設係 `acceptEdits`;`--yolo`（別名 `--dangerous`）就令連結轉用 `bypassPermissions`。轉發嘅回合入面唔准用互動式對話 - 冇人可以喺 Slack 度回答 - 所以個模型會用文字問，而你嘅 thread 回覆就係下一個回合。附帶嘅 plugin skill 會教佢，一需要做決定就標記請求者，然後結束個回合。
- **狀態反應**：觸發一個回合嘅訊息會用 emoji 反應帶住佢嘅狀態：回合行緊嘅時候係沙漏，之後係剔號（完成）、交叉（失敗），或者問號（個模型需要你做決定）。需要現時 manifest 入面嘅 `reactions:write` scope;現有嘅 app 要重新貼一次 manifest 再重新安裝。
- **注意同提醒**：當個模型要問你做決定，佢會呼叫進程內嘅 `need_attention` 工具，令守護程序知道條 thread 喺度等緊你。如果你 10 分鐘都冇出聲，佢會喺條 thread 度標記你一次。當一條 thread 喺等緊嘅時候，對條問題加反應就會當做你嘅答案轉發（一個讚會揀推薦嘅選項）;你喺追蹤緊嘅 thread 入面加嘅任何其他反應，都會摺入下一個回合做上下文。需要 `reactions:read` 同 `reaction_added` 事件。
- **斜線指令**：一條 thread 訊息，剝除後嘅文字以 `/` 開頭，就會當做 claude 斜線指令嚟行。Slack 嘅撰寫器會食咗以 `/` 開頭嘅訊息，所以要用提及優先嘅形式（`@bot /usage`），或者喺前面加個空格。
- **優雅關閉**：SIGTERM/SIGINT 會排走 - 大聲噉丟棄新回合，畀行緊嘅回合最多 5 分鐘，而 claude 仔進程會喺自己嘅進程群組入面獨立噉行，所以終端嘅 Ctrl-C 喺排走保存個回合之前都殺佢唔死。
- **thread 清理**：當你話俾佢知件工作做完咗，個模型會呼叫進程內嘅 `finish_thread` 工具;喺回合完全結束之後，守護程序會丟棄個 thread 記錄、取消訂閱，再貼一個確認。一次新嘅提及就會開一個新 session。
- **錯誤衛生**：回合出錯時只會貼經修剪嘅淨訊息文字，永遠唔會係原始嘅錯誤內容。
