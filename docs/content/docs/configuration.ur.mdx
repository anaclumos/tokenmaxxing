---
title: کنفیگریشن
description: "config.json اسکیما، تھریشولڈز، اور پالیسی نوبز"
---

Config ایک JSON ہے `~/.config/tokenmaxxing/config.json` پر۔ ہر فیلڈ اختیاری ہے؛ ڈیفالٹس فی فیلڈ لاگو ہوتے ہیں۔

```json
{
  "thresholds": { "session": [50, 80, 95], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 50,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000
  }
}
```

- `thresholds.session`: 5 گھنٹے کی سیڑھی، یعنی اسکریننگ زینوں کی ایک صعودی فہرست۔ ہر جائزہ ایک فعال زینہ طے کرتا ہے، وہ سب سے نچلا زینہ جس سے پول کا کوئی نہ کوئی اکاؤنٹ اب بھی نیچے ہے، اور وہی زینہ محرک بھی ہے اور امیدواروں کی اسکریننگ بھی۔ Codex صرف سب سے اوپر والا زینہ پڑھتا ہے۔ دیکھیں [سوئچنگ کیسے فیصلہ کرتی ہے](/ur/switching)۔
- `thresholds.weekly`: ہفتہ وار اسکریننگ بار، جو 7 دن کے مجموعے اور ہر فی ماڈل ہفتہ وار حد دونوں کا احاطہ کرتی ہے۔
- `hardThresholds.session` / `hardThresholds.weekly`: دیوار بارز (پہلے سے طے شدہ 100، ہر اکاؤنٹ کی حقیقی سرور حد)۔ `hardThresholds.session` کا سب سے اوپر والے سیشن زینے کے برابر یا اس سے اوپر ہونا لازم ہے۔ جب ہر اکاؤنٹ اپنی اسکریننگ بار سے تجاوز کر جائے، تو خودکار Claude فیصلہ پارک کرنے سے پہلے ہر ایک کو اس کی دیوار تک نچوڑتا ہے - دیکھیں [دیوار](/ur/switching)۔ اسے غیر فعال کرنے کے لیے انہیں سب سے اوپر والے زینے اور ہفتہ وار بار کے برابر سیٹ کریں؛ Codex اس ترتیب کو نظر انداز کرتا ہے۔
- `claudeBin` / `codexBin`: ان اصل بائنریز پر پن کرتا ہے جنہیں سپروائزرز اسپان کرتے ہیں (`init` / `init --codex` کے ذریعے لکھا جاتا ہے؛ ری کرژن-گارڈ تشخیص آپ کو یہاں `claudeBin` ٹھیک کرنے کو کہتی ہے جب یہ اصل Claude بائنری کی طرف اشارہ کرنا چھوڑ دے)۔
- `policy.projectionMargin`: مؤثر بارز بنانے کے لیے ہر سیشن زینے، ہفتہ وار بار، اور دیوار بارز سے تفریق کیا جاتا ہے۔
- `policy.greedySessionFloor`: سیشن-استعمال فیصد جس پر لالچی یکجائی مصروف ہوتی ہے۔
- `policy.switchModels`: ماڈل فیملیز جن کی فی ماڈل ہفتہ وار حد ایک سوئچ کو گیٹ کرتی ہے (لوڈ ہونے پر اندراجات لوئر کیس کر دیے جاتے ہیں)۔
- `policy.usagePollTtlMs`: ایک `/usage` فی ماڈل پول کتنی دیر تازہ رہتا ہے۔
- `policy.maxWaitMs`: ختم شدہ پول کا خودکار انتظار حد۔

`tokenmaxxing config` ذرائع کے ساتھ مؤثر config دکھاتا ہے؛ `config set`/`unset` ڈوٹڈ کیز میں ترمیم کرتے ہیں؛ `config tidy` نامعلوم کیز کو صاف کرتا ہے۔
