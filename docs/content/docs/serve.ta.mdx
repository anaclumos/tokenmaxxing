---
title: "Slack பாலம்: xx serve"
description: "xx serve Socket Mode மீது Slack threads இலிருந்து Claude Code அமர்வுகளை இயக்குகிறது"
---

`tokenmaxxing serve` Socket Mode மீது ஒரு உள்ளூர் Slack டீமனை இயக்குகிறது - எந்த பொது URL உம் தேவையில்லை. அமைப்பு:

```sh
tokenmaxxing serve setup                    # ஆப் manifest ஐ அச்சிடுகிறது, இரண்டு டோக்கன்களைக் கேட்கிறது
tokenmaxxing serve link <channel-id> <repo> # ஒரு channel ஐ ஒரு repo checkout உடன் இணைக்கிறது
tokenmaxxing serve                          # டீமனை இயக்கு
```

இணைக்கப்பட்ட ஒரு channel இல் botஐ mention செய்யுங்கள், அது அந்த thread க்கு, இணைக்கப்பட்ட repo checkout இல் ஒரு Claude Code அமர்வைத் திறக்கிறது. ஒவ்வொரு thread செய்தியும் இன்னும் `resume` உடன் ஒரு Agent SDK `query()` ஐ இயக்குகிறது - எனவே `ensureBestAccount()` ஒவ்வொரு ஒற்றைத் திருப்பிலும் தொகுப்பை மறுமதிப்பீடு செய்கிறது மற்றும் threads ஐ இழக்காமல் டீமன் மறுதொடக்கம் செய்ய முடியும் (thread பதிவுகள் நீடித்தவை; டீமன் தொடக்கத்தில் அவற்றை மீண்டும் சந்தா செய்கிறது) - ஆனால் ஒவ்வொரு query உம் ஸ்ட்ரீமிங் input ஐ எடுத்துக்கொள்கிறது, இதுவே ஒரு பதில் ஏற்கனவே இயங்கிக்கொண்டிருக்கும் திருப்பை திசைப்படுத்த அனுமதிக்கிறது.

குறிப்பிடத்தக்க நடத்தை:

- **திசைப்படுத்துதல்**: thread இன் திருப்பு இன்னும் இயங்கிக்கொண்டிருக்கும்போது வரும் ஒரு பதில் அந்தத் திருப்பினுள் மடிந்துவிடுகிறது - Claude Code தொடர்பாடலில் பயன்படுத்தும் அதே திருப்பு-நடு injection - எனவே மாதிரி அதைத் தன் அடுத்த கருவி எல்லையில் பார்த்து, தவறானதை முதலில் முடிப்பதற்குப் பதிலாகத் திசையைச் சரிசெய்கிறது. திருப்பின் கடைசி கருவி அழைப்புக்குப் பிறகு வரும் ஒரு பதில் உடனடியாகத் தன் சொந்தத் திருப்பாக இயங்குகிறது; எந்த வகையிலும் எதுவும் கைவிடப்படுவதில்லை. திசைப்படுத்தப்பட்ட செய்திகள் மணல்கடிகார reaction ஐ அணிந்து திருப்புடன் சேர்ந்தே முடிவடைகின்றன, மேலும் அவற்றின் உரை திருப்பின் நீடித்த குறியீட்டின் மீது பயணிக்கிறது, எனவே மறுதொடக்கங்களும் பயன்பாட்டு-வரம்பு மீள்தொடக்கங்களும் அதை மீண்டும் இயக்குகின்றன. காத்திருக்கும் இன்னொரு செய்திக்குப் பின்னால் வரிசையில் உள்ள ஒரு செய்தி மட்டுமே மடிப்பைத் தவிர்க்கிறது (வரிசை பேணப்படுகிறது), மேலும் வடிகட்டிக்கொண்டிருக்கும் ஒரு டீமன் திசைப்படுத்துவதற்குப் பதிலாக இன்னும் சத்தமாகக் கைவிடுகிறது.
- **ஸ்ட்ரீமிங்**: பதில்கள் Slack இல் இயல்பாக ஸ்ட்ரீம் செய்கின்றன, சிந்தனை மற்றும் கருவி இயக்கங்களுக்கான பணி அட்டைகள், ஹைலைட்டிங்குடன் render செய்யப்பட்ட வேலிட்ட குறியீடு, செலவு மற்றும் கால அளவுடன் ஒரு நிறைவு "Turn" அட்டை; ஒரு திருப்பின் அனைத்து அட்டைகளும் விரிவாக்கக்கூடிய ஒரு திட்டத் தொகுதியாகச் சுருங்குகின்றன, எனவே ஒரு திருப்பு பொதுவாக ஒற்றைச் செய்தியாகப் படிக்கிறது: பதிலும் அதன் செயல்பாட்டின் ஒரு கீழ்விரிவும் (திருப்பின் நடுவே ஏற்படும் ஒரு retry அல்லது ஒரு நிராகரிக்கப்பட்ட append ஒரு பின்தொடர் செய்தியைத் திறக்கும்). TodoWrite அழைப்புகள் ஒரு நிலையான checklist அட்டையை இடத்திலேயே புதுப்பிக்கின்றன.
- **அனுமதிகள்**: ஒவ்வொரு-இணைப்பு `permissionMode` இயல்பாக `acceptEdits`; `--yolo` (புனைப்பெயர் `--dangerous`) ஒரு இணைப்பை `bypassPermissions` இல் தேர்ந்தெடுக்கிறது. தொடர்பாடல் உரையாடல்கள் திருப்பப்பட்ட திருப்புகளில் அனுமதிக்கப்படுவதில்லை - Slack வழியாக யாராலும் ஒன்றுக்கு பதிலளிக்க முடியாது - எனவே மாதிரி உரைநடையில் கேட்கிறது, உங்கள் thread பதிலே அடுத்த திருப்பாகும். ஒரு தொகுக்கப்பட்ட plugin skill, ஒரு முடிவு தேவைப்படும்போது கோரிக்கையாளரை tag செய்து திருப்பை முடிக்க அதற்குக் கற்பிக்கிறது.
- **நிலை reactions**: ஒரு திருப்பைத் தூண்டிய செய்தி அதன் நிலையை ஒரு emoji reaction ஆகச் சுமக்கிறது: திருப்பு இயங்கும்போது ஒரு மணல்கடிகாரம், பின்னர் ஒரு சரிக்குறி (முடிந்தது), ஒரு x (தோல்வி), அல்லது ஒரு கேள்விக்குறி (மாதிரிக்கு உங்கள் முடிவு தேவை). தற்போதைய manifest இலிருந்து `reactions:write` scope தேவை; ஏற்கனவே உள்ள apps manifest ஐ மீண்டும் ஒட்டி மறு நிறுவல் செய்ய வேண்டும்.
- **கவனம் மற்றும் நினைவூட்டல்கள்**: மாதிரி உங்களிடம் ஒரு முடிவைக் கேட்கும்போது அது ஒரு செயல்முறைக்குள்ளான `need_attention` கருவியை அழைக்கிறது, எனவே thread உங்களுக்காகக் காத்திருக்கிறது என்பதை டீமன் அறியும். நீங்கள் 10 நிமிடங்கள் அமைதியாக இருந்தால் அது thread இல் ஒரு முறை உங்களை tag செய்கிறது. ஒரு thread காத்திருக்கும்போது, கேள்விக்கு reaction செய்வது உங்கள் பதிலாகத் திருப்பப்படுகிறது (ஒரு thumbs up பரிந்துரைக்கப்பட்ட விருப்பத்தைத் தேர்ந்தெடுக்கிறது); கண்காணிக்கப்படும் ஒரு thread இல் நீங்கள் சேர்க்கும் வேறு எந்த reaction உம் அடுத்த திருப்பில் சூழலாக மடிக்கப்படுகிறது. `reactions:read` மற்றும் `reaction_added` நிகழ்வு தேவை.
- **Slash கட்டளைகள்**: ஒரு thread செய்தியின் துடைக்கப்பட்ட உரை `/` இல் தொடங்கினால் அது ஒரு claude slash கட்டளையாக இயங்குகிறது. Slack இன் composer `/` இல் தொடங்கும் செய்திகளை உண்கிறது, எனவே mention-முதல் வடிவத்தை (`@bot /usage`) அல்லது ஒரு முன்னணி இடைவெளியைப் பயன்படுத்துங்கள்.
- **பயன்பாட்டு வரம்பு தானியங்கி மீள்தொடக்கம்**: தொகுப்பில் உள்ள ஒவ்வொரு கணக்கும் அதன் வரம்பில் இருக்கும்போது, ஒரு குறுகிய தடங்கல் செய்தியை இடத்திலேயே நிறுத்தி வைத்து மீண்டும் முயற்சிக்கிறது; ஒரு நீண்ட தடங்கல் ஒரு காத்திருப்பு அறிவிப்பை இட்டு, தொகுப்பு மீளும்போது திருப்பை தானாகவே மீண்டும் தொடங்குகிறது - இது டீமன் மறுதொடக்கங்களையும் தாண்டி நீடிக்கும். அறியப்பட்ட மீட்பு நேரம் இல்லாத ஒரு வரம்பு மட்டுமே நீங்கள் மீண்டும் அனுப்புமாறு கேட்கிறது.
- **அழகான பணிநிறுத்தம்**: SIGTERM/SIGINT வடிகட்டுகிறது - புதிய திருப்புகள் சத்தமாக கைவிடப்படுகின்றன, ஓட்டத்தில் உள்ள திருப்புகள் 5 நிமிடங்கள் வரை பெறுகின்றன, மேலும் claude குழந்தை அதன் சொந்த செயல்முறை குழுவில் பிரிக்கப்பட்டு இயங்குகிறது, எனவே ஒரு முனைய Ctrl-C அது வடிகட்டல் திருப்பைப் பாதுகாக்கும் முன் அதைக் கொல்ல முடியாது.
- **Thread சுத்தம்**: வேலை முடிந்துவிட்டது என்று நீங்கள் அதற்குச் சொல்லும்போது, மாதிரி ஒரு செயல்முறைக்குள்ளான `finish_thread` கருவியை அழைக்கிறது; திருப்பு முழுமையாக முடிந்த பிறகு, டீமன் thread பதிவைக் கைவிட்டு, சந்தாவை நீக்கி, ஒரு உறுதிப்படுத்தலை இடுகிறது. ஒரு புதிய mention ஒரு புதிய அமர்வைத் தொடங்குகிறது.
- **பிழை சுகாதாரம்**: திருப்பு பிழைகள் ஒழுங்குபடுத்தப்பட்ட செய்தி-மட்டும் உரையை இடுகின்றன, ஒருபோதும் மூல பிழை உடல்களை அல்ல.
