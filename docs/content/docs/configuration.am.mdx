title: ውቅር
description: "የ config.json schema፣ thresholdዎች፣ እና የ policy መቆጣጠሪያዎች"
---

Config በ `~/.config/tokenmaxxing/config.json` JSON ነው። እያንዳንዱ field አማራጭ ነው፤ ነባሪዎች በ-field ይተገበራሉ።

```json
{
  "thresholds": { "session": [50, 80, 95], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 50,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000
  }
}
```

- `thresholds.session`፦ የ5-ሰዓቱ መሰላል፣ በዕርገት የተደረደረ የ screening ደረጃዎች ዝርዝር። እያንዳንዱ ግምገማ አንድ ንቁ ደረጃ ይፈታል፣ ማለትም አንዳች የተሰበሰበ መለያ ገና ከሱ በታች የሆነበትን ዝቅተኛውን ደረጃ፣ እና ያ ደረጃ ቀስቃሹም የእጩ ማጣሪያውም ነው። Codex የላይኛውን ደረጃ ብቻ ያነባል። [መቀያየር እንዴት እንደሚወሰን](/am/switching) ይመልከቱ።
- `thresholds.weekly`፦ ሳምንታዊው screening bar፣ የ7-ቀን ጥቅሉንም ሆነ እያንዳንዱን በ-ሞዴል ሳምንታዊ ገደብ ይሸፍናል።
- `hardThresholds.session` / `hardThresholds.weekly`፦ ግድግዳ barዎቹ (ነባሪ 100፣ የእያንዳንዱ መለያ እውነተኛ የ server ገደብ)። `hardThresholds.session` ከላይኛው session ደረጃ ጋር እኩል ወይም ከሱ በላይ መሆን አለበት። እያንዳንዱ መለያ ከ screening bar በላይ ሲሆን፣ automatic የ Claude ውሳኔው ከማቆሙ በፊት እያንዳንዱን እስከ ግድግዳው ድረስ ይጨምቃል - [ግድግዳው](/am/switching) ን ተመልከት። ለማሰናከል ከላይኛው ደረጃ እና ከሳምንታዊው bar ጋር እኩል አድርግ፤ Codex ይህን ቅንብር ችላ ይላል።
- `claudeBin` / `codexBin`፦ supervisorዎቹ የሚያስነሱትን ትክክለኛ binaryዎች ይሰካል (በ `init` / `init --codex` የተጻፈ፤ `claudeBin` እዚህ ወደ እውነተኛው Claude binary ማመልከቱን ሲያቆም recursion-guard ምርመራው እዚህ እንድታስተካክለው ይነግርሃል)።
- `policy.projectionMargin`፦ ተግባራዊ barዎችን ለመፍጠር ከእያንዳንዱ session ደረጃ፣ ከሳምንታዊው bar፣ እና ከግድግዳ barዎቹ ይቀነሳል።
- `policy.greedySessionFloor`፦ greedy convergence የሚሳተፍበት session-የተጠቀመ መቶኛ።
- `policy.switchModels`፦ በ-ሞዴል ሳምንታዊ ገደባቸው መቀያየርን የሚገድብ የሞዴል ቤተሰቦች (ግቤቶች በ load ጊዜ ወደ ትንንሽ ፊደላት ይቀየራሉ)።
- `policy.usagePollTtlMs`፦ የ `/usage` በ-ሞዴል poll ምን ያህል ጊዜ ትኩስ ሆኖ እንደሚቆይ።
- `policy.maxWaitMs`፦ የተሟጠጠ-pool በራስ-ሰር ጥበቃ ገደብ።

`tokenmaxxing config` ተግባራዊ config ን ከምንጮች ጋር ያሳያል፤ `config set`/`unset` በነጥብ የተለዩ keyዎችን ያርትዑ፤ `config tidy` የማይታወቁ keyዎችን ያስወግዳል።
