npm 패키지는 빌드 산출물이 아니라 TypeScript 소스를 배포합니다. `tokenmaxxing` bin은 Bun 셔뱅을 달고 곧바로 `src/main.ts`를 가리키며 Bun 1.2.6 이상이 그대로 실행합니다. 그래서 Bun이 필수 요건입니다. 컴파일된 바이너리는 설계상 없습니다. 초기 릴리스는 61 MB짜리 단일 macOS 바이너리를 모든 플랫폼에 배포했다가 Linux에서 `exec format error`로 실패했습니다. 플랫폼별 컴파일 패키지는 저마다 자체 릴리스 파이프라인이 필요했고 결국 Bun이 소스를 실행하는 방식이 배포 모델이 되었습니다.

패키지의 `exports` 맵은 [Agent SDK 인터페이스](/ko/sdk)에서 설명한 프로그래밍 진입점으로 `src/sdk.ts`를 노출합니다. 릴리스는 GitHub에서 `v<version>`으로 태그됩니다. CI는 신뢰할 수 있는 게시(trusted publishing, OIDC 및 provenance 포함)로 npm에 배포하며, 게시 게이트는 먼저 타입 체크를 실행합니다.

## Nix / nix-darwin

같은 소스 트리는 flake이기도 합니다. Bun이 소스를 그대로 실행하는 모델은 그대로 두고([bun2nix](https://github.com/nix-community/bun2nix)의 `writeBunApplication`), 다음을 노출합니다.

| 출력 | 용도 |
|---|---|
| `packages.default` | PATH에 `tokenmaxxing` + `xx` |
| `darwinModules.default` / `withOverlay` | nix-darwin: CLI 설치(선언적 점검 타이머는 선택) |
| `homeManagerModules.default` | macOS·Linux용 Home Manager |
| `nixosModules.default` / `withOverlay` | NixOS 시스템 설치 |

프로필에 설치한 다음(그래야 `init`이 만드는 supervisor shim이 PATH에서 안정적인 `tokenmaxxing`을 찾습니다) init을 실행하세요:

```sh
nix profile install github:anaclumos/tokenmaxxing
tokenmaxxing init
```

설치하지 않고 한 번만 실행하려면(help / status 전용입니다. 이 방식으로 `init`을 실행하면 안 됩니다):

```sh
nix run github:anaclumos/tokenmaxxing -- help
```

nix-darwin(`pkgs.tokenmaxxing`이 풀리도록 overlay 추가):

```nix
{
  inputs.tokenmaxxing.url = "github:anaclumos/tokenmaxxing";
  modules = [
    inputs.tokenmaxxing.darwinModules.withOverlay
    { programs.tokenmaxxing.enable = true; }
  ];
}
```

Home Manager(패키지를 직접 지정하거나, Home Manager가 쓰는 pkgs에 이 flake의 overlay를 적용하세요):

```nix
{
  imports = [ inputs.tokenmaxxing.homeManagerModules.default ];
  programs.tokenmaxxing.enable = true;
  programs.tokenmaxxing.package = inputs.tokenmaxxing.packages.${pkgs.system}.default;
}
```

Nix가 하는 일은 CLI를 PATH에 올리는 것뿐입니다. 계정 가져오기, PATH의 `claude` 슈퍼바이저 shim, `settings.json` 훅, (기본값으로는) 주기적 점검 타이머는 여전히 `tokenmaxxing init`에서 옵니다. 자격 증명과 사용자가 소유한 설정을 건드리는 부분이라 순수 모듈이 덮어쓰면 안 됩니다. 타이머를 init 대신 Nix가 맡게 하고 싶을 때만 `programs.tokenmaxxing.checkTimer.enable = true`를 켜세요(이 옵션은 `TOKENMAXXING_SKIP_TIMER=1`도 함께 내보내므로 init이 두 번째 유닛을 쓰지 않습니다). 선언적 타이머도 init과 마찬가지로 사용자 세션 타이머입니다. 헤드리스 Linux에서 로그인 없이 발동하게 하려면 `loginctl enable-linger`가 필요합니다. `checkTimer.intervalSeconds`는 `policy.checkIntervalMs`를 초로 환산한 값과 같게 유지하세요. 스스로 주기를 조절하는 일정은 설정 키를 읽는 반면 유닛은 Nix 값에 맞춰 발동하기 때문입니다.

`bun.lock`이 바뀌면 Nix 의존성 식을 다시 만듭니다:

```sh
bun run nix:bun   # writes bun.nix via bun2nix@2.1.2
```
