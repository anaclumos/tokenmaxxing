---
title: 상태 디렉터리 구조
description: "~/.config/tokenmaxxing 아래의 모든 파일과 디렉터리"
---

모든 것은 `~/.config/tokenmaxxing/` 아래에 있습니다(`TOKENMAXXING_HOME`으로 재정의 가능. 외부에서 관찰 가능한 모든 경로에 환경 변수 재정의가 있어 도구 전체가 테스트에서 격리된 상태로 실행될 수 있습니다).

| 경로 | 담는 내용 |
|---|---|
| `config.json` | 사용자 설정(희소하며 기본값이 필드별로 적용됩니다) |
| `accounts.json` | 풀에 등록된 Claude 계정의 비밀이 아닌 인덱스: 라벨, id, 캐시된 사용량 윈도우. 토큰은 결코 담지 않습니다 |
| `usage.json` | statusline tee의 합산 윈도우 스냅샷. mtime이 피드가 살아 있음을 알리는 하트비트입니다 |
| `model-usage.json` | `/usage`에서 얻은 TTL 캐시된 모델별 주간 상한 |
| `lastswap.json` | 마지막 교체의 epoch 타임스탬프. 45초 쿨다운을 구동합니다 |
| `depleted.json` | 기록된 풀 소진 대기. 리셋이 지나거나, 라이브 좌석이 옮겨가거나, 어떤 교체든 완료될 때까지 형제 훅들이 이를 재생합니다 |
| `lock` | 교체를 직렬화하는 `flock` 파일 |
| `sessions/<session-id>.json` | supervisor가 respawn을 위해 보존하는, 관리 대상 세션별 실행 플래그. 30일 동안 사용되지 않으면 정리됩니다(claude 자체의 트랜스크립트 보존 기간과 일치) |
| `tokenmaxxing.log` | 추가 전용 이벤트 로그 |
| `bin/` | PATH shim: `claude`, `codex`, `tokenmaxxing` / `xx` 진입점 |
| `respawn/<session-id>` | supervisor가 감시하는 소진 대기 respawn 마커 |
| `creds/` | Linux 전용: 보관된 자격 증명 파일, 0700 디렉터리 안의 0600(macOS는 대신 자격 증명을 계정별 키체인 항목으로 보관합니다) |
| `onboard/`, `sample/` | `add`/`auth` 로그인과 보관 계정 `/usage` 프로브를 위한 일회용 격리 설정 홈. 평문 자격 증명을 담은 onboard 홈은 수확 후 삭제됩니다 |
| `codex-*` | 병렬 Codex 풀: `codex-accounts.json`, `codex-lastswap.json`, `codex-lock`, `codex-creds/`, `codex-onboard/`, `codex-respawn/`, `codex-reconcile/`(형제 세션의 supervisor에게 라이브 계정으로 respawn하라고 요청하는 세션 간 신호), `codex-live/`(실행 중인 감독 대상 codex 세션마다 하나씩 PID로 검증되는 존재 파일. 그래서 라이브 계정은 결코 교체 대상이 되지 않습니다) |

자기 디렉터리 밖에서 tokenmaxxing이 건드리는 것은 정확히 다음뿐입니다: `~/.claude.json`(`oauthAccount` 교체), Claude Code의 `settings.json`(훅과 statusline 항목), 라이브 자격 증명 저장소(macOS에서는 `Claude Code-credentials` 키체인 항목, Linux에서는 `.credentials.json`), claude 자체의 갱신 잠금(교체 중에 획득하는 것으로, claude 설정 디렉터리 안의 기본 `.oauth_refresh.lock`과 레거시 `~/.claude.lock` 형제 잠금), codex의 `auth.json`과 `hooks.json`, 그리고 launchd 또는 systemd의 주기적 확인 유닛.
