---
title: 상태 디렉터리 구조
description: "~/.config/tokenmaxxing 아래의 모든 파일과 디렉터리"
---

모든 것은 `~/.config/tokenmaxxing/` 아래에 있습니다(`TOKENMAXXING_HOME`으로 재정의 가능. 외부에서 관찰 가능한 모든 경로에 환경 변수 재정의가 있어, 도구 전체가 테스트에서 격리된 상태로 실행될 수 있습니다).

| 경로 | 담는 내용 |
|---|---|
| `config.json` | 당신의 설정(희소하며, 기본값이 필드별로 적용됩니다) |
| `accounts.json` | 풀에 등록된 Claude 계정의 비밀이 아닌 인덱스: 라벨, id, 캐시된 사용량 윈도우. 토큰은 결코 담지 않습니다 |
| `usage.json` | statusline tee의 합산 윈도우 스냅샷. 그 mtime이 피드의 활성 상태 하트비트입니다 |
| `model-usage.json` | `/usage`에서 얻은 TTL 캐시된 모델별 주간 상한 |
| `lastswap.json` | 마지막 교체의 epoch 타임스탬프. 45초 쿨다운을 구동합니다 |
| `lock` | 교체를 직렬화하는 `flock` 파일 |
| `tokenmaxxing.log` | 추가 전용 이벤트 로그 |
| `bin/` | PATH shim: `claude`, `codex`, 그리고 `tokenmaxxing` / `xx` 진입점 |
| `respawn/<session-id>` | supervisor가 감시하는 소진 대기 respawn 마커 |
| `creds/` | Linux 전용: 보관된 자격 증명 파일, 0700 디렉터리 안의 0600(macOS는 대신 자격 증명을 계정별 키체인 항목으로 보관합니다) |
| `onboard/`, `sample/` | `add`/`auth` 로그인과 보관 계정 `/usage` 프로브를 위한 일회용 격리 설정 홈. 평문 자격 증명을 담은 onboard 홈은 수확 후 삭제됩니다 |
| `slack.json` | `xx serve` 토큰과 채널 링크(0600) |
| `slack-threads/` | `xx serve`의 스레드별 세션 기록 |
| `codex-*` | 병렬 Codex 풀: `codex-accounts.json`, `codex-lastswap.json`, `codex-lock`, `codex-creds/`, `codex-onboard/`, `codex-respawn/`, 그리고 `codex-live/`(실행 중인 감독 대상 codex 세션마다 하나씩 PID로 검증되는 존재 파일. 그래서 라이브 계정은 결코 교체 대상이 되지 않습니다) |

자기 디렉터리 밖에서 tokenmaxxing이 건드리는 것은 정확히 다음뿐입니다: `~/.claude.json`(`oauthAccount` 교체), Claude Code의 `settings.json`(훅과 statusline 항목), 라이브 자격 증명 저장소(macOS에서는 `Claude Code-credentials` 키체인 항목, Linux에서는 `.credentials.json`), `~/.claude.lock`(교체 중에 획득하는 claude의 갱신 잠금), codex의 `auth.json`과 `hooks.json`, 그리고 launchd 또는 systemd의 주기적 확인 유닛.
