---
title: statusline
description: "クォータは色で表現し、1行で、すべてのアカウントを表示"
---

tokenmaxxing は Claude Code の statusline をネイティブに描画します (使用量フィードを tee しながら)。設計原則は、クォータを数字ではなく色で表すことです。1行の例を示します。

```
tm-wt-demo Fable 5 (high) +156/-23  ◆ 𝒇 2h 1d  ◇ 19h  ◇ 𝒇 2d  ◇ full  ✗ ?
```

- 各ウィンドウのトークンはリセットまでの時間を表し、使用率に応じて緑から黄、赤へと変化する連続ランプで着色されます (端末が対応していれば truecolor、そうでなければ256色キューブへ段階化されます)。ランプは0で純緑、75で黄、95以上で赤にアンカーされるため、以前の重大度バンドがランプアンカーとして残ります。
- モデル名は、同じランプ上でコンテキストウィンドウの充填に応じて着色されます。
- 緑の `◆` がアクティブアカウントのウィンドウの先頭に付きます。パーク済みの各アカウントにはそれぞれシアンの `◇` が付きます (再認証が必要なら赤の `✗`)。アカウントは次に来るリセットが最も早い順にソートされます。
- モデルごとの情報は各ブロックの先頭に、着色された頭文字だけで現れます。Fable は `𝒇` を描画します。他のファミリーは大文字にした頭文字を使い、常にファミリー単位でマッチします。
- 手つかずのパーク済みアカウントは緑の `full` を描画します。リセットが不明な計測済み使用量は着色された `?` を、ゲートされたモデルの未計測のモデルごと上限は着色されない `𝒇?` を描画します。未計測は決して安全に見えてはなりません。
- リセットカウントダウンは最大の単位のみを表示し、"now" や "0m" は決して表示しません。次に来るリセットがないウィンドウは緑の `0` を描画します (再び空)。
- リンクされた git ワークツリーのベース名が行の先頭に付きます。メインチェックアウトではそこに何も描画しません。この検出はファイルシステムから `.git` ファイルを読み取り、git サブプロセスを決して起動しません。
- `NO_COLOR` が設定されている場合、行は数字を連結した形式にフォールバックします (`2h5` は2時間後にリセット、5%使用を意味し、`ctx 42` はコンテキスト充填を表す)。色がなければ、消費済みのウィンドウが未使用のように見えてはなりません。

サブエージェントのタスクには、claude の subagentStatusLine サーフェスによって専用のパネル行が用意されます。アクティブなタスクごとに1行で、ファミリー名はそのタスクのコンテキスト充填に応じて着色されます。
