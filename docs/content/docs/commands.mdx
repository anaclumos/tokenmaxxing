| Command | What it does |
|---|---|
| `tokenmaxxing init` | Import the current account, install the supervisor, hooks, and statusline |
| `tokenmaxxing init --codex` | Same for Codex: import the login, install the codex supervisor and Stop hook |
| `tokenmaxxing add` | Register an additional account (isolated login, harvested into the pool) |
| `tokenmaxxing add --codex` | Register an additional Codex account (isolated login) |
| `tokenmaxxing auth [sel \| --all]` | Reauthenticate a pooled account in place. Bare lists the pool and asks which; a selector targets one account and tells you which email to sign in with; `--all` walks every needs-reauth account one by one |
| `tokenmaxxing switch [sel]` | Switch to the best account (greedy, idempotent) or force a specific one |
| `tokenmaxxing switch --codex [sel]` | Switch the Codex pool (takes effect on the next codex start) |
| `tokenmaxxing ls` | List pooled accounts |
| `tokenmaxxing status` | Accounts with 5h / weekly / per-model usage bars, active and exhausted-until-reset |
| `tokenmaxxing status --force` | Additionally ping every account (one tiny haiku request each) so all 5h session timers start now, then sample fresh |
| `tokenmaxxing watch [seconds]` | Live status, re-rendered every N seconds (default 120, floor 30; never pings) |
| `tokenmaxxing config [get\|set\|unset\|tidy]` | Effective config with sources; edit dotted keys; `tidy` prunes unknown keys |
| `tokenmaxxing check [--if-due]` | Evaluate the switch decision once; `--if-due`, the form the periodic timer runs, skips it until the self-paced schedule says it is due |
| `tokenmaxxing doctor` | Verify the supervisor and settings entries survived |
| `tokenmaxxing rename [--codex] <sel> <label>` | Relabel a pooled account |
| `tokenmaxxing rm [--codex] <sel>` | Remove an account (and its parked credential) from the claude or codex pool |
| `tokenmaxxing uninstall` | Remove the supervisor and settings entries (accounts and credentials are kept) |
| `--json` | Print one JSON document on stdout instead of text (one per tick for `watch`). Works with `status`, `ls`, `config`, `doctor`, `check`, `switch`, `watch`, `rename`, `rm`, and `uninstall`; position-independent (`xx --json`, `xx status --json`). See [JSON output](#json-output) |

## JSON output

Add `--json` to any command in the table except the three login flows (`init`, `add`, `auth`) and it prints one JSON document on stdout instead of text (`help` ignores the flag). Progress notices such as `sampling live usage...` still go to stderr, so `xx status --json | jq` stays clean. Every document carries `ok`, which is `true` exactly when the exit code is 0; a failure keeps its non-zero exit code and adds `error` with the same message the text form prints.

```sh
xx status --json | jq '.claude.accounts[] | {label, active, exhausted, fiveHour: .usage.fiveHour.usedPercentage}'
xx check --json | jq '{swapped, account, reason, nextCheckAt}'
xx switch --json | jq '{switched, account, reason}'
```

What each command reports:

- `status` / bare `xx`: `now` (the reference time in epoch ms), `claude.thresholds`, the effective `claude.bars` and `claude.projectionMargin`, then one entry per account with `usage.fiveHour`, `usage.week`, `perModel`, `exhausted`, `needsReauth`, and `sample` (`{ok, source}` for a fresh read from the statusline tee or a probe, `{ok: false, reason}` when the live sample failed and `usage` is the cached value from `usageAt`). Windows are normalized the way the bars are drawn: a passed reset reads as 0 with the weekly reset rolled forward. Under `--force` each account also carries `pingError` (the ping's failure text, else null), `pingRejected` (true when that failure was the server refusing the ping at a limit, read from the structured error row of the ping's own transcript, so the text form says `ping rejected at the 5h limit` instead of guessing that no window opened), and `pinged` (true when the ping succeeded and the usage feed has not yet reported the 5h window it opened, the case the text form annotates). `codex` mirrors this with `aggregate` and `perLimit` windows that keep their `windowSeconds`. `watch --json` prints one such document per tick and never clears the screen.
- `ls`: both pools with `active`, `needsReauth`, `tier` or `planType`, and `addedAt`, no usage. `active` here is the pool's stored active label, while `status` computes `active` from the credential that is actually live, so the two disagree after a manual `/login` drifted the live account (`switch` reconciles that).
- `config`: `path`, `config` (the effective object), `sources` per dotted key (`env`, `file`, or `default`), `envOverrides` (the variable name behind each `env` source), and `unknownKeys`; `get` adds `value` and `source`, `set` reports `before`, `after`, and `envOverride` (the variable that still overrides the file value, else null), `unset` reports whether an override was removed (`unset`) and the resulting `value`, `tidy` reports `changed`, `droppedKeys`, and `casingNormalized`.
- `doctor`: `checks` (each `{ok, label, hint}`), `notes`, and `warnings`; `ok` is the overall verdict, so when any check fails the document also carries `error` and the exit code is 1.
- `check`: `due`, `swapped`, `account`, `reason`, `waitUntil`, and `nextCheckAt`; a `--if-due` run that is not due yet reports only `due: false` and `nextCheckAt`.
- `switch`: `switched`, `account`, and a short `reason` (`selected`, `best`, `already-on`, `current-wins`, `drift-reconciled`, `earliest-reset`, `no-target`, `all-at-limit`, `unknown-resets`), plus `weeklyResetsAt` on `current-wins`, `reauthNeeded` and `deadGrants` (the accounts whose refresh token died while the switch was trying them) when they apply. `availableAt` is Claude-only: the Codex pool has no earliest-reset fallback, so a Codex pick with no usable target fails with `reauthNeeded` instead.
- `rename` and `rm`: what changed (`from`/`to`, `removed`/`remaining`). `uninstall`: the steps it went through (`removed` always names the wrapper and settings entries, plus the timer and rc line when those steps reported success), `timerDeactivated`, and `pathLineRemoved`. It is destructive and the one `--json` command that writes outside the state root: `~/.claude/settings.json`, codex `hooks.json`, the shell rc, and the timer unit live under `HOME`, so `TOKENMAXXING_HOME` does not make it hermetic.

`init`, `add`, and `auth` run a login flow and refuse `--json` with exit code 2. Account identifiers (labels, emails, uuids) appear in the documents; credential material never does.
