| Command | What it does |
|---|---|
| `tokenmaxxing init` | Import the current account, install the supervisor, hooks, and statusline |
| `tokenmaxxing init --codex` | Same for Codex: import the login, install the codex supervisor and Stop hook |
| `tokenmaxxing add` | Register an additional account (isolated login, harvested into the pool) |
| `tokenmaxxing add --codex` | Register an additional Codex account (isolated login) |
| `tokenmaxxing auth [sel \| --all]` | Reauthenticate a pooled account in place. Bare lists the pool and asks which; a selector targets one account and tells you which email to sign in with; `--all` walks every needs-reauth account one by one |
| `tokenmaxxing switch [sel]` | Switch to the best account (idempotent) or force a specific one |
| `tokenmaxxing switch --codex [sel]` | Switch the Codex pool (takes effect on the next codex start) |
| `tokenmaxxing status [--cached]` | Accounts with 5h / weekly / per-model usage bars, active and exhausted-until-reset; `--cached` renders the stored figures without sampling |
| `tokenmaxxing config` | The config path and the effective values; edit the file in an editor |
| `tokenmaxxing check` | Evaluate the switch decision once and sample the stalest parked account; the periodic timer runs this every tick |
| `tokenmaxxing doctor` | Verify the supervisor and settings entries survived |
| `tokenmaxxing rename [--codex] <sel> <label>` | Relabel a pooled account |
| `tokenmaxxing rm [--codex] <sel>` | Remove an account (and its parked credential) from the claude or codex pool |
| `tokenmaxxing uninstall` | Remove the supervisor and settings entries (accounts and credentials are kept) |
| `tokenmaxxing setup-token [--print \| rm <label\|uuid>]` | Cursor Cloud only. Mint one `claude setup-token` per pooled account that has no stored token (a browser sign-in each), store them in `setup-tokens.json`, and print the `TOKENMAXXING_TOKENS` secret value; `--print` skips minting, `rm` drops a stored token (local only). See [Cursor Cloud](/cursor-cloud) |
| `tokenmaxxing cursor init [dir]` | Write the Claude relay subagent (`.cursor/agents/claude.md`) and `.cursor/environment.json` into a repo. Idempotent; an existing `environment.json` is left alone and the install line to add is printed |
| `tokenmaxxing cloud run [--session <id>] [--max-turns <n>] "<prompt>"` | On a Cursor Cloud VM: run `claude -p` on a setup token from `TOKENMAXXING_TOKENS`, keep a session on its token, and rotate to the next token when a run ends on a usage limit. The prompt is also read from stdin |
| `--json` | Print one JSON document on stdout instead of text. Works with `status`, `config`, `check`, and `switch`; position-independent (`xx --json`, `xx status --json`). See [JSON output](#json-output) |

## JSON output

Add `--json` to `status`, `config`, `check`, or `switch` and it prints one JSON document on stdout instead of text. Progress notices such as `sampling live usage...` still go to stderr, so `xx status --json | jq` stays clean. Every document carries `ok`, which is `true` exactly when the exit code is 0; a failure keeps its non-zero exit code and adds `error` with the same message the text form prints.

```sh
xx status --json | jq '.claude.accounts[] | {label, active, exhausted, fiveHour: .usage.fiveHour.usedPercentage}'
xx check --json | jq '{swapped, account, reason}'
xx switch --json | jq '{switched, account, reason}'
```

What each command reports:

- `status` / bare `xx`: `now` (the reference time in epoch ms), `claude.thresholds`, the effective `claude.bars` and `claude.projectionMargin`, then one entry per account with `usage.fiveHour`, `usage.week`, `perModel`, `exhausted`, `needsReauth`, and `sample` (`{ok, source}` for a fresh read from the statusline tee or a probe, `{ok: false, reason}` when the live sample failed and `usage` is the cached value from `usageAt`). Windows are normalized the way the bars are drawn: a passed reset reads as 0 with the weekly reset rolled forward. `codex` mirrors this with `aggregate` and `perLimit` windows that keep their `windowSeconds`. `status --cached` (also `xx --cached`) reads only the state files: every `sample` is `{ok: true, source: "cached"}`, `usage` is the stored value as of `usageAt` (null when the account was never sampled), `perModelAt` dates the per-model rows separately, and `active` is the pool's stored active label rather than the owner of the live credential, so it can lag a manual `/login` until `switch` reconciles it.
- `config`: `path` and `effective` (the config as loaded: file values over defaults, with `TOKENMAXXING_CLAUDE_BIN` and `TOKENMAXXING_CODEX_BIN` applied on top). A file that fails to load exits 1 with the zod message naming the field.
- `check`: `swapped`, `account`, `reason`, and `waitUntil`.
- `switch`: `switched`, `account`, and a short `reason` (`selected`, `best`, `already-on`, `current-wins`, `drift-reconciled`, `earliest-reset`, `no-target`, `all-at-limit`, `unknown-resets`), plus `weeklyResetsAt` on `current-wins`, `reauthNeeded` and `deadGrants` (the accounts whose refresh token died while the switch was trying them) when they apply. `availableAt` is Claude-only: the Codex pool has no earliest-reset fallback, so a Codex pick with no usable target fails with `reauthNeeded` instead.

Every other command refuses `--json` with exit code 2. Account identifiers (labels, emails, uuids) appear in the documents; credential material never does.
