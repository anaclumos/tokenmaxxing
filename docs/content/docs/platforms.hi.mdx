---
title: "प्लेटफ़ॉर्म नोट्स: macOS बनाम Linux"
description: "भंडारण, अपनाने, और टाइमर में macOS और Linux कैसे भिन्न हैं"
---

| | macOS | Linux |
|---|---|---|
| लाइव क्रेडेंशियल | लॉगिन keychain generic-password आइटम | 0600 `.credentials.json` फ़ाइल |
| पार्क किए गए क्रेडेंशियल | प्रति-खाता keychain आइटम | 0700 डायरेक्टरी में 0600 फ़ाइलें |
| स्वैप के बाद अपनाना | ~30 सेकंड के भीतर (keychain रीड कैश) | अगला अनुरोध (फ़ाइल mtime पोल) |
| आवधिक जांच | launchd एजेंट, हर 180s | systemd उपयोगकर्ता टाइमर, हर 180s |
| पृथक-लॉगिन स्टोर | प्रति config dir हैश-नेमस्पेस्ड keychain सेवा | पृथक config dir के अंदर एक फ़ाइल |

जानने योग्य दो Linux-विशिष्ट विवरण: claude अपनी क्रेडेंशियल डायरेक्टरी को पहले `CLAUDE_SECURESTORAGE_CONFIG_DIR` से हल करता है (फिर `CLAUDE_CONFIG_DIR`, फिर `~/.claude`), और tokenmaxxing उस समाधान को बिल्कुल प्रतिबिंबित करता है ताकि दोनों कभी desync न हों। और एक ही claude संस्करण के दो OS बिल्ड `/usage` रीसेट घड़ियों को अलग-अलग स्वरूपित करते हैं (एक " at " ग्लू का उपयोग करता है, दूसरा एक कॉमा); tokenmaxxing का पार्सर ठीक उन्हीं दो रूपों को स्वीकार करता है और किसी तीसरे पर अनुमान लगाने के बजाय लॉग करता है।

macOS पर, एक ईमानदार सीमा: `init` और `add` जानबूझकर keychain को इंटरैक्टिव रूप से छूते हैं, ताकि पहली `security` एक्सेस एक हेडलेस हुक के अंदर ठंडी न हो।
