---

การรวมพูลแบบเดียวกันนี้ใช้ได้กับ Codex CLI ของ OpenAI โดยใช้กับบัญชี ChatGPT-subscription ของคุณเอง:

```sh
tokenmaxxing init --codex   # นำเข้าล็อกอิน codex ปัจจุบันของคุณ + ติดตั้ง codex supervisor และ Stop hook
tokenmaxxing add --codex    # เข้าสู่ระบบอีกบัญชีแบบแยกส่วน ล็อกอินหลักของคุณจะไม่ถูกแตะต้อง
codex                       # ใช้ codex ได้เหมือนเดิม
```

พูลของ Codex เป็นสถานะที่คู่ขนานกันอย่างสมบูรณ์ มีดัชนีบัญชีของตัวเอง มีไฟล์ credential ที่ park ไว้ของตัวเอง (ไฟล์สิทธิ์ 0600 บนทั้งสองแพลตฟอร์ม เนื่องจากที่เก็บของ codex เองเป็นไฟล์ข้อความธรรมดา) มีล็อกของตัวเอง มี timestamp การสลับครั้งล่าสุดของตัวเอง ไม่มีอะไรถูกใช้ร่วมกับพูลของ Claude ยกเว้นโค้ดนโยบายการตัดสินใจ

## เหตุใด hot-swap จึงเป็นไปไม่ได้บน Codex

โปรเซส codex ที่กำลังทำงานถือ auth manager ในหน่วยความจำเพียงตัวเดียว และปฏิเสธอย่างชัดเจนที่จะโหลด `auth.json` ใหม่เมื่อมันระบุคนละบัญชี ไม่มีตัวเฝ้าดูไฟล์ (file watcher) และไม่มีการ poll credential ต่อคำขอ ดังนั้น credential ที่ถูกสลับอยู่ข้างใต้ codex ที่กำลังทำงานจึงไม่มีวันมีผลต่อการอนุมาน (inference) เลย การรีสตาร์ทคือการสลับ: `codex resume <session-id>` จะดำเนินทรานสคริปต์ภายในต่อบนบัญชีที่ `auth.json` ถืออยู่ในตอนนี้

tokenmaxxing จัดการเรื่องนี้ด้วย shim ของ codex supervisor คือ Stop hook จะรันการตัดสินใจแบบ greedy ตาม pace-pressure เดียวกันที่ขอบเขตของแต่ละเทิร์น และเมื่อมันสลับ มันจะเขียน marker ที่ทำให้ supervisor ส่ง SIGTERM ให้เซสชันที่ขอบเขตที่ยืนยันไปแล้วและเปิด `codex resume <session-id>` ใหม่บนบัญชีที่สด โดยทรานสคริปต์ยังคงอยู่ครบ เนื่องจากทุกการสลับของ codex เป็นการรีสตาร์ทที่มองเห็นได้ เส้นทาง greedy ของ codex จึงมีส่วนเผื่อการปรับปรุง 1.2 เท่า นั่นคือผู้ท้าชิงต้องเอาชนะ pace pressure ของบัญชีปัจจุบัน 20% ไม่ใช่แค่นิดเดียว ส่วนเส้นทาง hard (มีแถบถูกข้าม) จะไม่สนใจส่วนเผื่อนี้ นอกจากนี้ยังไม่มีการนับถอยหลังเมื่อพูลหมดสำหรับ codex เพราะไม่มีอะไรหยุดเซสชัน codex ได้ ดังนั้นพูล codex ที่หมดเกลี้ยงจึงอยู่นิ่งกับที่

กลไกเฉพาะของ codex อื่นๆ:

- การใช้งานถูกอ่านจาก GET แบบยืนยันตัวตนที่ฟรีต่อ rate-limit endpoint ของ codex เอง (คำเรียกเดียวกับที่ `/status` ของ CLI ใช้) ได้เปอร์เซ็นต์พร้อมเวลารีเซ็ตแบบ epoch สัมบูรณ์ ทั้งหน้าต่างยอดรวมและลิมิตแยกตามโมเดลเหมือนกัน การจำแนกหน้าต่างขับเคลื่อนด้วยระยะเวลา ไม่ใช่ด้วยตำแหน่ง เพราะแผนปัจจุบันอาจไม่มีหน้าต่าง 5 ชั่วโมงเลย และหน้าต่างรายสัปดาห์อยู่ในช่องหลัก (primary slot)
- refresh token ของ codex หมุนเวียน และการนำตัวที่ถูกแทนที่แล้วมาใช้ซ้ำจะทำลายทั้งตระกูล grant ทุกการหมุนเวียนจะถูกบันทึกทันทีที่ตอบกลับมา บัญชีที่ใช้งานอยู่จะถูกเก็บตัวอย่างผ่าน blob สดเท่านั้น (ไม่ใช่สำเนาที่ park ไว้ซึ่งเก่าค้าง) และไฟล์การมีอยู่ (presence file) ต่อเซสชันช่วยรับประกันว่าบัญชีที่กำลังทำงานในเซสชันข้างเคียงที่ยังทำงานอยู่จะไม่มีวันเป็นเป้าหมายการสลับ และไม่มีวันถูกรีเฟรช token ที่ park ไว้
- Codex ต้องใช้ที่เก็บ credential แบบไฟล์: `init --codex` จะล้มเหลวทันทีหากมีการปักหมุดที่เก็บแบบ keyring ไว้ และ `add --codex` จะเขียนการตั้งค่าโหมดไฟล์ลงในโฮมสำหรับ onboarding ที่แยกส่วน เพื่อให้ล็อกอินไปลงในที่ที่เก็บเกี่ยวได้
- มีขั้นตอนที่ต้องทำด้วยมือหนึ่งขั้น: codex จะข้ามฮุกที่ยังไม่ได้รับแจ้งให้เชื่อถือ หลังจาก `init --codex` ให้เปิด codex หนึ่งครั้งและเชื่อถือ Stop hook ของ tokenmaxxing ผ่าน `/hooks` มิฉะนั้นการสลับอัตโนมัติจะเงียบและไม่ทำงาน `init --codex` จะพิมพ์คำเตือนนี้ให้
