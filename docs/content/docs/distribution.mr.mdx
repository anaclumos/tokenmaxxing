npm पॅकेज TypeScript स्रोत पाठवते, बिल्ड नव्हे: `tokenmaxxing` bin थेट Bun shebang सह `src/main.ts` कडे इशारा करते, आणि Bun 1.2.6 किंवा नवीन ते जसेच्या तसे चालवते. म्हणूनच Bun ही एक कठोर आवश्यकता आहे. डिझाइनने कोणतीही संकलित बायनरी नाहीत: एका सुरुवातीच्या रिलीजने प्रत्येक प्लॅटफॉर्मवर एकच 61 MB macOS बायनरी पाठवली आणि Linux वर `exec format error` सह अपयशी झाली, आणि प्रति-प्लॅटफॉर्म संकलित पॅकेजेसना प्रत्येकी स्वतःची रिलीज पाइपलाइन लागली असती, त्यामुळे Bun द्वारे थेट स्रोत चालवणे हे वितरण मॉडेल बनले.

पॅकेजचा `exports` नकाशा [एजंट SDK पृष्ठभाग](/mr/sdk) मध्ये वर्णन केलेला प्रोग्रामॅटिक एंट्री म्हणून `src/sdk.ts` उघड करतो. रिलीज GitHub वर `v<version>` असे टॅग केले जातात; CI विश्वसनीय प्रकाशनाद्वारे (OIDC, provenance सह) npm वर प्रकाशित करते, आणि प्रकाशन गेट प्रथम typecheck चालवतो.

## Nix / nix-darwin

तोच स्रोत वृक्ष एक flake देखील आहे. Bun द्वारे स्रोत चालवण्याचे मॉडेल राखतो ([bun2nix](https://github.com/nix-community/bun2nix) च्या `writeBunApplication` मार्गे) आणि हे उघड करतो:

| आउटपुट | उद्देश |
|---|---|
| `packages.default` | PATH वर `tokenmaxxing` + `xx` |
| `darwinModules.default` / `withOverlay` | nix-darwin: CLI इंस्टॉल करा (पर्यायी घोषणात्मक तपासणी टाइमर) |
| `homeManagerModules.default` | macOS किंवा Linux वर Home Manager |
| `nixosModules.default` / `withOverlay` | NixOS सिस्टम इंस्टॉल |

प्रोफाइलमध्ये इंस्टॉल न करता एकदा चालवा:

```sh
nix run github:anaclumos/tokenmaxxing -- help
```

nix-darwin (`pkgs.tokenmaxxing` resolve व्हावे म्हणून overlay जोडतो):

```nix
{
  inputs.tokenmaxxing.url = "github:anaclumos/tokenmaxxing";
  modules = [
    inputs.tokenmaxxing.darwinModules.withOverlay
    { programs.tokenmaxxing.enable = true; }
  ];
}
```

किंवा पॅकेज स्पष्टपणे सेट करा (Home Manager सोबतही चालते):

```nix
{
  imports = [ inputs.tokenmaxxing.homeManagerModules.default ];
  programs.tokenmaxxing.enable = true;
  programs.tokenmaxxing.package = inputs.tokenmaxxing.packages.${pkgs.system}.default;
}
```

Nix फक्त CLI PATH वर ठेवतो. खाते आयात, PATH वरील `claude` सुपरवायझर shim, `settings.json` हुक, आणि (डीफॉल्टने) नियतकालिक तपासणी टाइमर अजूनही `tokenmaxxing init` कडून येतात — हे क्रेडेन्शियल्स आणि वापरकर्त्याच्या मालकीच्या सेटिंग्जना स्पर्श करतात जे शुद्ध मॉड्यूलने पुन्हा लिहू नयेत. `programs.tokenmaxxing.checkTimer.enable = true` फक्त तेव्हा सेट करा जेव्हा टाइमर init ऐवजी Nix कडे असावा असे वाटते.

`bun.lock` बदलल्यावर Nix अवलंबित्व अभिव्यक्ती पुन्हा तयार करा:

```sh
bun run nix:bun   # writes bun.nix via bun2nix
```
