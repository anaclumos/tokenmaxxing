---
title: پیکربندی
description: "شمای config.json، آستانه‌ها، و کلیدهای سیاست"
---

پیکربندی به‌صورت JSON در `~/.config/tokenmaxxing/config.json` است. هر فیلد اختیاری است؛ پیش‌فرض‌ها به‌ازای هر فیلد اعمال می‌شوند.

```json
{
  "thresholds": { "session": [90], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 80,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000
  }
}
```

- `thresholds.session`: نردبان ۵ ساعته، فهرستی صعودی از پله‌های غربالگری. هر ارزیابی یک پله فعال را تعیین می‌کند، پایین‌ترین پله‌ای که هنوز حسابی در استخر در آن قابل استفاده است، و همان پله هم ماشه است و هم غربال نامزدها. Codex فقط پله بالایی را می‌خواند. [نحوه تصمیم‌گیری جابه‌جایی](/fa/switching) را ببینید.
- `thresholds.weekly`: نوار غربالگری هفتگی، که هم مجموع ۷ روزه و هم هر سقف هفتگی به‌ازای هر مدل را پوشش می‌دهد.
- `hardThresholds.session` / `hardThresholds.weekly`: نوارهای دیوار (پیش‌فرض ۱۰۰، محدودیت واقعی سرور هر حساب). `hardThresholds.session` باید برابر یا بالاتر از بالاترین پله نشست باشد. وقتی هر حساب بالای نوار غربالگری خود است، تصمیم خودکار Claude پیش از پارک کردن، هر یک را تا دیوارش می‌فشارد - [دیوار](/fa/switching) را ببینید. برای غیرفعال کردن، آن را برابر با بالاترین پله و نوار هفتگی تنظیم کنید؛ Codex این تنظیم را نادیده می‌گیرد.
- `claudeBin` / `codexBin`: به باینری‌های واقعی که ناظرها اجرا می‌کنند سنجاق می‌شود (توسط `init` / `init --codex` نوشته می‌شود؛ تشخیص نگهبان بازگشتی به شما می‌گوید وقتی `claudeBin` دیگر به باینری واقعی Claude اشاره نمی‌کند، همین‌جا آن را اصلاح کنید).
- `policy.projectionMargin`: از هر پله نشست، از نوار هفتگی، و از نوارهای دیوار کم می‌شود تا نوارهای مؤثر شکل بگیرند.
- `policy.greedySessionFloor`: درصد استفاده نشست که در آن همگرایی حریصانه درگیر می‌شود.
- `policy.switchModels`: خانواده‌های مدلی که سقف هفتگی به‌ازای هر مدلشان یک جابه‌جایی را دروازه‌بندی می‌کند (ورودی‌ها هنگام بارگذاری کوچک‌حروف می‌شوند).
- `policy.usagePollTtlMs`: مدت زمانی که یک پیمایش `/usage` به‌ازای هر مدل تازه می‌ماند.
- `policy.maxWaitMs`: مرز انتظار خودکار استخر تهی.

`tokenmaxxing config` پیکربندی مؤثر را با منابع نشان می‌دهد؛ `config set`/`unset` کلیدهای نقطه‌ای را ویرایش می‌کنند؛ `config tidy` کلیدهای ناشناخته را هرس می‌کند.
