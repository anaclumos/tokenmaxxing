---
title: โครงสร้างไดเรกทอรีสถานะ
description: "ทุกไฟล์และไดเรกทอรีภายใต้ ~/.config/tokenmaxxing"
---

ทุกอย่างอยู่ใต้ `~/.config/tokenmaxxing/` (แทนที่ได้ด้วย `TOKENMAXXING_HOME` ทุกพาธที่สังเกตได้จากภายนอกมี env override เพื่อให้ทั้งเครื่องมือรันแบบแยกสมบูรณ์ (hermetic) ในการทดสอบได้)

| พาธ | เก็บอะไร |
|---|---|
| `config.json` | การตั้งค่าของคุณ (แบบเบาบาง ค่าเริ่มต้นมีผลรายฟิลด์) |
| `accounts.json` | ดัชนีที่ไม่เป็นความลับของบัญชี Claude ในพูล: ป้ายชื่อ, id, หน้าต่างการใช้งานที่แคชไว้ ไม่เคยเก็บ token |
| `usage.json` | สแนปช็อตหน้าต่างรวมจากการ tee ของ statusline; mtime ของมันคือสัญญาณชีพว่าฟีดยังมีชีวิตอยู่ |
| `model-usage.json` | ลิมิตรายสัปดาห์แยกตามโมเดลจาก `/usage` ที่แคชแบบมี TTL |
| `lastswap.json` | เวลา epoch ของการสลับครั้งล่าสุด ใช้ขับช่วงพัก 45 วินาที |
| `depleted.json` | การรอเมื่อพูลหมดเกลี้ยงที่บันทึกไว้ ถูกฮุกของเซสชันพี่น้องนำมาเล่นซ้ำจนกว่าจะถึงเวลารีเซ็ต ที่นั่งที่ใช้งานอยู่ย้าย หรือมีการสลับใดๆ เสร็จสิ้น |
| `lock` | ไฟล์ `flock` ที่ทำให้การสลับเป็นลำดับ |
| `serve-lock` | flock อินสแตนซ์เดียวของ `xx serve`: เดมอนรุ่นใหม่จะถูกกันไว้ตรงนี้จนกว่ารุ่นก่อนหน้าจะออกจนหมด |
| `sessions/<session-id>.json` | ธงการเปิดใช้งานของแต่ละเซสชันที่ถูกจัดการ ซึ่ง supervisor เก็บไว้สำหรับการ respawn; ถูกตัดทิ้งหลังไม่มีการใช้งาน 30 วัน (ตรงกับระยะเก็บ transcript ของ claude เอง) |
| `tokenmaxxing.log` | log เหตุการณ์แบบ append-only |
| `bin/` | shim ของ PATH: `claude`, `codex` และจุดเข้า `tokenmaxxing` / `xx` |
| `respawn/<session-id>` | มาร์กเกอร์ respawn เมื่อรอเพราะโควตาหมด ที่ supervisor คอยเฝ้าดู |
| `creds/` | เฉพาะ Linux: ไฟล์ credential ที่จอดไว้ สิทธิ์ 0600 ในไดเรกทอรี 0700 (บน macOS จะจอด credential เป็นรายการ keychain รายบัญชีแทน) |
| `onboard/`, `sample/` | config home แบบแยกส่วนที่ใช้แล้วทิ้ง สำหรับการล็อกอิน `add`/`auth` และการ probe `/usage` ของบัญชีที่จอดไว้ onboard home ที่มี credential แบบข้อความล้วนจะถูกลบหลังเก็บเกี่ยว |
| `slack.json` | token และลิงก์ช่องของ `xx serve` (0600) |
| `slack-threads/` | บันทึกเซสชันรายเธรดสำหรับ `xx serve` |
| `codex-*` | พูล Codex คู่ขนาน: `codex-accounts.json`, `codex-lastswap.json`, `codex-lock`, `codex-creds/`, `codex-onboard/`, `codex-respawn/`, `codex-reconcile/` (สัญญาณข้ามเซสชันที่ขอให้ supervisor ของเซสชันพี่น้องทำการ respawn ไปยังบัญชีที่ใช้งานอยู่) และ `codex-live/` (ไฟล์แสดงการมีอยู่หนึ่งไฟล์ที่ตรวจ PID ต่อเซสชัน codex ที่มี supervisor กำลังรัน เพื่อไม่ให้บัญชีที่กำลังทำงานถูกใช้เป็นเป้าหมายการสลับ) |

นอกไดเรกทอรีของตัวเอง tokenmaxxing แตะต้องเพียง: `~/.claude.json` (การสลับ `oauthAccount`), `settings.json` ของ Claude Code (รายการฮุกและ statusline), ที่เก็บ credential ที่ใช้งานจริง (รายการ keychain `Claude Code-credentials` บน macOS, `.credentials.json` บน Linux), ล็อกรีเฟรชของ claude เองที่จับระหว่างการสลับ (ล็อกหลัก `.oauth_refresh.lock` ภายในไดเรกทอรี config ของ claude บวกกับล็อกพี่น้องรุ่นเก่า `~/.claude.lock`), `auth.json` และ `hooks.json` ของ codex และยูนิตตรวจสอบเป็นระยะใน launchd หรือ systemd
