---
title: statusline
description: "โควตาสื่อสารผ่านสี หนึ่งบรรทัด แสดงทุกบัญชี"
---

tokenmaxxing เรนเดอร์ statusline ของ Claude Code แบบเนทีฟ (พร้อมกับ tee ฟีดการใช้งาน) หลักการออกแบบคือ: โควตาสื่อสารผ่านสี ไม่ใช่ตัวเลข หนึ่งบรรทัด ตัวอย่างเช่น:

```
tm-wt-demo Fable 5 (high) +156/-23  ◆ 𝒇 2h 1d  ◇ 19h  ◇ 𝒇 2d  ◇ full  ✗ ?
```

- โทเคนของแต่ละหน้าต่างคือเวลาจนถึงการรีเซ็ตของมัน ทาสีบนแรมป์ (ramp) สีเขียวไปเหลืองไปแดงแบบต่อเนื่องตามเปอร์เซ็นต์การใช้ (truecolor เมื่อเทอร์มินัลรองรับ มิฉะนั้นจะไล่ลงบนคิวบ์สี 256 สี) แรมป์ยึดที่สีเขียวล้วนสำหรับค่า 0 สีเหลืองที่ 75 และสีแดงที่ 95 ขึ้นไป ดังนั้นแถบระดับความรุนแรงแบบเดิมจึงยังคงอยู่ในฐานะจุดยึดของแรมป์
- ชื่อโมเดลถูกทาสีตามปริมาณการเติมของหน้าต่างบริบท (context window) บนแรมป์เดียวกัน
- สัญลักษณ์ `◆` สีเขียวนำหน้าหน้าต่างของบัญชีที่ใช้งานอยู่ ทุกบัญชีที่ park ไว้จะได้ `◇` สีฟ้าคราม (cyan) ของตัวเอง (เป็น `✗` สีแดงหากต้องยืนยันตัวตนใหม่) บัญชีเรียงตามการรีเซ็ตที่กำลังจะมาถึงเร็วที่สุด
- ข้อมูลแยกตามโมเดลมาก่อนในแต่ละบล็อกในรูปอักษรตัวแรกที่ทาสีล้วนๆ: Fable แสดงเป็น `𝒇` ตระกูลอื่นใช้อักษรตัวแรกแบบพิมพ์ใหญ่ จับคู่ตามตระกูลเสมอ
- บัญชีที่ park ไว้และยังไม่ถูกแตะจะแสดงเป็น `full` สีเขียว การใช้งานที่วัดได้แต่ไม่ทราบเวลารีเซ็ตจะแสดงเป็น `?` ที่ทาสี และลิมิตแยกตามโมเดลที่ยังไม่ได้วัดบนโมเดลที่ถูกเปิดประตูจะแสดงเป็น `𝒇?` ที่ไม่ทาสี ค่าที่ยังไม่ได้วัดต้องไม่มีวันดูปลอดภัย
- การนับถอยหลังการรีเซ็ตจะแสดงเฉพาะหน่วยที่ใหญ่ที่สุดเท่านั้น ไม่มีวันแสดง "now" หรือ "0m" หน้าต่างที่ไม่มีการรีเซ็ตที่กำลังจะมาถึงจะแสดงเป็น `0` สีเขียว (ว่างอีกครั้ง)
- basename ของ git worktree ที่ลิงก์ไว้จะนำหน้าบรรทัด ส่วน checkout หลักจะไม่แสดงอะไรตรงนั้น การตรวจจับจะอ่านไฟล์ระบบเพื่อหาไฟล์ `.git` และไม่เคย spawn โปรเซสย่อยของ git
- เมื่อตั้งค่า `NO_COLOR` บรรทัดจะย้อนกลับไปใช้รูปแบบตัวเลขที่ติดกัน (`2h5` หมายถึงรีเซ็ตในอีก 2 ชั่วโมง ใช้ไป 5% ส่วน `ctx 42` คือปริมาณการเติมบริบท) เมื่อไม่มีสี หน้าต่างที่หมดแล้วต้องไม่ดูเหมือนยังสดใหม่

งานของ subagent จะได้แถวในแผงของตัวเองผ่านพื้นผิว subagentStatusLine ของ claude คือหนึ่งแถวต่อหนึ่งงานที่ทำงานอยู่ ชื่อตระกูลทาสีตามปริมาณการเติมบริบทของงานนั้น
