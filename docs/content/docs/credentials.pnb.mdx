---
title: کریڈینشل سٹوریج تے سلامتی ماڈل
description: "کریڈینشل ہر پلیٹ فارم تے کِتھے رہندے نیں تے اوہ اصول جیہڑے ہر بدلاؤ لاگو کردا اے"
---

ساری حالت `~/.config/tokenmaxxing/` وچ رہندی اے۔ کریڈینشل I/O اک اکلے پلیٹ فارم چُنے سٹور فیساڈ راہیں لنگھدی اے؛ کال تھاواں کدے پلیٹ فارم تے شاخ نئیں بناندیاں۔

**macOS**: کریڈینشل لاگ اِن کی چین وچ generic-password آئٹماں وانگوں رہندے نیں، اوہو تھاں مِلاندے جِتھے Claude Code آپ اوہناں نوں رکھدا اے۔ لائیو آئٹم اوہ اے جیہڑی claude پڑھدا اے؛ پول دے ہر اکاؤنٹ دی بیک اپ اوہدی اپنی `tokenmaxxing-cred-<uuid8>` کی چین آئٹم وانگوں پارک کیتی جاندی اے۔ ڈسک تے کجھ وی سادہ لکھت وچ نئیں۔ پڑھت `security find-generic-password -w` ورتدی اے (راز صرف stdout تے ای نظر آندا اے)؛ لکھت اک `add-generic-password` لائن نوں stdin راہیں `security -i` وچ پائپ کردی اے تاں جو راز کسے وی پروسیس دے argv وچ کدے نہ نظر آوے۔ تعاملی موڈ دا لگ بھگ 4 KB دا لائن بفر اے، سو ودھ وڈے بلاب اک argv لکھت تے واپس آ جاندے نیں - ایہو اک وجہ اے کہ پارک کیتیاں آئٹماں صرف گھٹو گھٹ OAuth آبجیکٹ رکھدیاں نیں۔

**Linux**: Claude Code کریڈینشل نوں اک 0600 سادہ لکھت فائل وانگوں رکھدا اے، تے tokenmaxxing اوہو ماڈل اپناندا اے: لائیو فائل claude دی اپنی `.credentials.json` اے، تے پارک کیتیاں بیک اپاں اک 0700 ڈائریکٹری وچ `~/.config/tokenmaxxing/creds/` تھلے ایٹمی 0600 فائلاں نیں۔ ایتھے ایٹمی دا مطلب اے temp وچ لکھو، fsync کرو، فیر مُڑ ناں دیو: اک نال نال چلدا پڑھن والا ہمیشہ اک پوری پرانی یا پوری نویں فائل ویکھدا اے، کدے ادھوری نئیں۔

بدلاؤ جیہڑے سلامتی اصول لاگو کردا اے:

- **اصل مالک ولوں سمیٹنا۔** اک بدلاؤ توں پہلاں، لائیو کریڈینشل دا اصل مالک API کولوں پُچھ کے پکا کیتا جاندا اے کہ ٹوکن کیہڑی تنظیم دا اے (OAuth roles اینڈ پوائنٹ خلاف `fetchTokenOrg`) - کدے وی محفوظ کیتے چالو لیبل تے بھروسہ کر کے نئیں، جیہڑا سرک سکدا اے۔ اک سرکے ہوئے لیبل نے اک وار اک اکاؤنٹ دی سمیٹ نوں دوجے اکاؤنٹ دی اکلی بیک اپ تے لکھوا دِتا سی۔ جے لائیو کریڈینشل پول توں باہرلے کسے اکاؤنٹ دا ہووے، تاں بدلاؤ اوہنوں مِٹان دی بجائے صاف انکار کر دیندا اے۔
- **اک اہم حصہ۔** سمیٹ، نویں کریڈینشل دی انسٹال، اوہدے گھمائے ٹوکن دی بیک اپ، `~/.claude.json` اکاؤنٹ بدلاؤ، تے چالو لیبل دی پکائی سب اکو لاک کیتے حصے دے اندر ہندے نیں۔
- **claude دے اپنے refresh نال جوڑ۔** میعاد نیڑے والا سیشن کسے وی پل اپنا ٹوکن گھما سکدا اے، سو کریڈینشل لکھت وی Claude Code دا refresh لاک لیندی اے (پوری کوشش، اک باسی لاک نوں مُڑ لین تے اک محدود ٹائم آؤٹ نال)۔
- **مرے گرانٹ صاف طرحاں ڈھلدے نیں۔** اک refresh جیہڑا `invalid_grant` نال واپس آوے اوس اکاؤنٹ نوں مُڑ تصدیق دی لوڑ والا نشان لاندا اے تے غلطی پھیلن توں پہلاں نشان محفوظ کر دیندا اے، سو مُڑ کوشش لوپ اُمیدواراں دا مجموعہ سُکیڑدے تے مُک جاندے نیں۔ `tokenmaxxing auth` اک نشان لگے اکاؤنٹ نوں اوتھے ای ٹھیک کردا اے، تے اوہ اک ایہو جیہے لاگ اِن توں انکار کر دیندا اے جیہڑا مرمت ہو رہے اکاؤنٹ توں وکھرے اکاؤنٹ تے اپڑے۔
- **کوئی ٹوکن لاگنگ نئیں۔** ٹوکن کدے وی لاگاں، غلطیاں، یا آؤٹ پُٹ وچ نظر نئیں آندے۔ ٹوکن تے ورتوں اینڈ پوائنٹاں توں غلطی باڈیاں کدے کچیاں نہیں دِسدیاں؛ صرف اک اجازت والیاں فیلڈاں دا مجموعہ بچدا اے، کیوں جو اک ٹوکن اینڈ پوائنٹ دی ناکامی باڈی بینتی دا مواد گونجا سکدی اے۔
- **پروب صفائی۔** کوئی وی شروع کیتی `claude` پروب اوہناں اٹھ ماحول متغیراں نوں صاف کردی اے جنہاں نوں claude اپنی کی چین کھوج توں پہلاں مندا اے (`ANTHROPIC_API_KEY`، `CLAUDE_CODE_OAUTH_TOKEN`، `CLAUDE_SECURESTORAGE_CONFIG_DIR`، تے ایویں ہور)، سو اک پروب کدے وی غلط اکاؤنٹ نال نئیں جوڑی جا سکدی۔
