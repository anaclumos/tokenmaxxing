কনফিগ হলো `~/.config/tokenmaxxing/config.json`-এ JSON। প্রতিটি ফিল্ড ঐচ্ছিক; ডিফল্টগুলো প্রতি-ফিল্ডে প্রযোজ্য।

```json
{
  "thresholds": { "session": [50, 80, 95], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 50,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000
  }
}
```

- `thresholds.session`: 5-ঘণ্টার ল্যাডার, ঊর্ধ্বক্রমে সাজানো স্ক্রিনিং ধাপের একটি তালিকা। প্রতিটি মূল্যায়ন একটিমাত্র সক্রিয় ধাপ ঠিক করে, অর্থাৎ সবচেয়ে নিচের যে ধাপটি পুলের কোনো অ্যাকাউন্ট এখনো পার করে, আর সেই ধাপটিই একই সঙ্গে ট্রিগার এবং প্রার্থী বাছাইয়ের স্ক্রিন। Codex কেবল সবচেয়ে ওপরের ধাপটি পড়ে। দেখুন [সুইচিং কীভাবে সিদ্ধান্ত নেয়](/bn/switching)।
- `thresholds.weekly`: সাপ্তাহিক স্ক্রিনিং বার, যা 7-দিনের সমষ্টি এবং প্রতিটি প্রতি-মডেল সাপ্তাহিক সীমা আওতাভুক্ত করে।
- `hardThresholds.session` / `hardThresholds.weekly`: দেয়াল বার (ডিফল্ট 100, প্রতিটি অ্যাকাউন্টের আসল সার্ভার সীমা)। `hardThresholds.session` অবশ্যই সেশন ল্যাডারের সবচেয়ে ওপরের ধাপে বা তার ওপরে থাকতে হবে। যখন প্রতিটি অ্যাকাউন্ট তার স্ক্রিনিং বারের ওপরে থাকে, স্বয়ংক্রিয় Claude সিদ্ধান্ত পার্ক করার আগে প্রতিটিকে তার দেয়াল পর্যন্ত নিংড়ে নেয়: দেখুন [দেয়াল](/bn/switching)। নিষ্ক্রিয় করতে সবচেয়ে ওপরের ধাপ ও সাপ্তাহিক বারের সমান সেট করুন; Codex এই সেটিং উপেক্ষা করে।
- `claudeBin` / `codexBin`: সুপারভাইজরগুলো যে আসল বাইনারি স্পন করে তার সঙ্গে পিন করে (`init` / `init --codex` দিয়ে লেখা; recursion-guard ডায়াগনস্টিক আপনাকে বলে এখানে `claudeBin` ঠিক করতে যখন এটি আর আসল Claude বাইনারির দিকে নির্দেশ করে না)।
- `policy.projectionMargin`: কার্যকর বার তৈরি করতে প্রতিটি সেশন ধাপ, সাপ্তাহিক বার ও দেয়াল বার থেকে বিয়োগ করা হয়।
- `policy.greedySessionFloor`: সেশন-ব্যবহৃত শতাংশ যেখানে greedy অভিসরণ সক্রিয় হয়।
- `policy.switchModels`: সেই মডেল ফ্যামিলি যাদের প্রতি-মডেল সাপ্তাহিক সীমা একটি বদলকে গেট করে (এন্ট্রিগুলো লোড করার সময় ছোট হাতের অক্ষরে রূপান্তরিত হয়)।
- `policy.usagePollTtlMs`: একটি `/usage` প্রতি-মডেল পোল কতক্ষণ তাজা থাকে।
- `policy.maxWaitMs`: নিঃশেষিত-পুল স্বয়ংক্রিয়-অপেক্ষার সীমা।

`tokenmaxxing config` উৎসসহ কার্যকর কনফিগ দেখায়; `config set`/`unset` ডটেড কী সম্পাদনা করে; `config tidy` অজানা কী ছেঁটে ফেলে।
