---
title: "플랫폼 참고 사항: macOS 대 Linux"
description: "저장, 채택, 타이머에서 macOS와 Linux가 다른 점"
---

| | macOS | Linux |
|---|---|---|
| 라이브 자격 증명 | 로그인 키체인 generic-password 항목 | 0600 `.credentials.json` 파일 |
| 보관 자격 증명 | 계정별 키체인 항목 | 0700 디렉터리 안의 0600 파일 |
| 교체 후 채택 | 약 30초 이내(키체인 읽기 캐시) | 다음 요청(파일 mtime 폴링) |
| 주기적 확인 | launchd 에이전트, 180초마다 | systemd 사용자 타이머, 180초마다 |
| 격리 로그인 저장소 | 설정 디렉터리별 해시 네임스페이스 키체인 서비스 | 격리된 설정 디렉터리 안의 파일 |

Linux 특유의 세부 사항 두 가지는 알아둘 만합니다. claude는 자격 증명 디렉터리를 `CLAUDE_SECURESTORAGE_CONFIG_DIR`에서 먼저 해석하고(그다음 `CLAUDE_CONFIG_DIR`, 그다음 `~/.claude`), tokenmaxxing은 그 해석을 정확히 그대로 따라 하므로 둘이 어긋나는 일이 없습니다. 같은 claude 버전의 두 OS 빌드는 `/usage` 초기화 시각을 서로 다르게 포맷합니다(하나는 " at " 연결자를, 다른 하나는 쉼표를 사용합니다). tokenmaxxing의 파서는 정확히 그 두 형식만 받아들이며 제3의 형식이 오면 추측하는 대신 로그를 남깁니다.

macOS에는 솔직히 말해 제약이 하나 있습니다. `init`과 `add`는 의도적으로 키체인을 대화형으로 건드립니다. 그래야 첫 `security` 접근이 헤드리스 훅 안에서 콜드 상태가 아니게 됩니다.
