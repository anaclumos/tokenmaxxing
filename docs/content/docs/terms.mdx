title: Personal use and terms of service
description: Pool accounts you own, in sessions and agents you run yourself
---

tokenmaxxing pools accounts you own, in sessions and agents you run yourself. That wording is deliberate: Anthropic does not allow third-party products to offer claude.ai login or claude.ai rate limits, and that includes agents built on the Agent SDK. Do not ship anything built on tokenmaxxing to third parties. tokenmaxxing is not a proxy: it never handles API traffic, and it holds no OAuth refresh grant of its own for Claude. The only Anthropic endpoints it calls are a read-only identity check at onboarding and in `doctor` (`GET /api/oauth/profile`, to verify which account a token actually belongs to) and the no-spend usage read every sampler makes (`GET /api/oauth/usage?at_wall=1&skip_spend=1`, the same read Claude Code's own `/usage` makes); every other quota figure comes from Claude Code's statusline feed. tokenmaxxing holds no refresh grant, so an expired stored access token stays unmeasured until a session on that store refreshes it. For Codex it calls OpenAI's usage endpoint and, for an idle account whose token is expiring, the standard refresh grant.

A setup token stored as a Cursor Runtime Secret for the [Cursor Cloud](/cursor-cloud) path follows Anthropic's own GitHub Actions pattern, a `claude setup-token` value kept as a CI secret and billed to the subscription of the person who minted it, and stays personal use of your own accounts in agents you run yourself.
