npm 包发布的是 TypeScript 源码，而非构建产物：`tokenmaxxing` bin 直接指向带 Bun shebang 的 `src/main.ts`，Bun 1.2.6 或更新版本会原样运行。Bun 因此成为硬性要求。刻意不提供任何编译好的二进制：早期曾有一个版本向每个平台都发布了单个 61 MB 的 macOS 二进制，在 Linux 上以 `exec format error` 失败，而按平台编译的包又各自需要一套发布流水线，因此由 Bun 运行源码成了分发模式。

该包的 `exports` 映射把 `src/sdk.ts` 暴露为 [Agent SDK 接口](/zh/sdk) 中所述的编程入口。发布版本在 GitHub 上以 `v<version>` 打标签；CI 通过可信发布（OIDC，带有来源证明）发布到 npm，且发布关卡会先运行类型检查。

## Nix／nix-darwin

同一份源码树也是一个 flake。它仍采用由 Bun 直接跑源码的模式（经 [bun2nix](https://github.com/nix-community/bun2nix) 的 `writeBunApplication`），并暴露：

| 输出 | 用途 |
|---|---|
| `packages.default` | 把 `tokenmaxxing` 与 `xx` 放进 PATH |
| `darwinModules.default` / `withOverlay` | nix-darwin：安装 CLI（可选声明式检查定时器） |
| `homeManagerModules.default` | macOS 或 Linux 上的 Home Manager |
| `nixosModules.default` / `withOverlay` | NixOS 系统级安装 |

装进 profile（这样 `init` 写出的监督进程 shim 才能在 PATH 上稳定解析到 `tokenmaxxing`），然后再 init：

```sh
nix profile install github:anaclumos/tokenmaxxing
tokenmaxxing init
```

不安装、临时跑一次（只适合 help / status，不要用这种方式跑 `init`）：

```sh
nix run github:anaclumos/tokenmaxxing -- help
```

nix-darwin（加上 overlay，让 `pkgs.tokenmaxxing` 能解析到）：

```nix
{
  inputs.tokenmaxxing.url = "github:anaclumos/tokenmaxxing";
  modules = [
    inputs.tokenmaxxing.darwinModules.withOverlay
    { programs.tokenmaxxing.enable = true; }
  ];
}
```

Home Manager（显式指定 package，或者把这个 flake 的 overlay 应用到 Home Manager 所用的 pkgs 上）：

```nix
{
  imports = [ inputs.tokenmaxxing.homeManagerModules.default ];
  programs.tokenmaxxing.enable = true;
  programs.tokenmaxxing.package = inputs.tokenmaxxing.packages.${pkgs.system}.default;
}
```

Nix 只负责把 CLI 放进 PATH。账户导入、PATH 上的 `claude` 监督进程 shim、`settings.json` 里的 hook，以及（默认情况下）周期性检查定时器，仍由 `tokenmaxxing init` 负责，这些会碰到凭证和用户自己的配置，纯模块不该去改写。只有当你希望定时器由 Nix 接管、而不是由 init 接管时，才设置 `programs.tokenmaxxing.checkTimer.enable = true`（它同时会导出 `TOKENMAXXING_SKIP_TIMER=1`，这样 init 就不会再写第二个单元）。声明式定时器和 init 一样，都是用户会话级的定时器，无头 Linux 需要 `loginctl enable-linger`，它才能在没有登录的情况下触发。请让 `checkTimer.intervalSeconds` 与换算成秒的 `policy.checkIntervalMs` 保持一致，因为自调节的排期读的是配置键，而单元触发用的是 Nix 里的那个值。

`bun.lock` 有变动时，重新生成 Nix 依赖表达式：

```sh
bun run nix:bun   # writes bun.nix via bun2nix@2.1.2
```
