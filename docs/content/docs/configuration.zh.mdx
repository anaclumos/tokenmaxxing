---
title: 配置
description: "config.json 的结构、阈值与策略旋钮"
---

配置文件是位于 `~/.config/tokenmaxxing/config.json` 的 JSON。每个字段都是可选的；默认值按字段分别应用。

```json
{
  "thresholds": { "session": [50, 80, 95], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 50,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000
  }
}
```

- `thresholds.session`：5 小时窗口的阶梯，一份自低到高排列的筛选档位列表。每次评估都会解析出一个生效档位，也就是池中仍有账户在其之下可用的最低一档，这一档既是触发线，也是候选账户的筛选线。Codex 只读取最高的一档。参见[切换如何决策](/zh/switching)。
- `thresholds.weekly`：周筛选阈值条，同时覆盖 7 天汇总额度和每个按模型的周上限。
- `hardThresholds.session` / `hardThresholds.weekly`：上限墙阈值条（默认 100，即每个账户真实的服务端限额）。`hardThresholds.session` 必须不低于最高的那一档会话档位。当每个账户都超过其筛选阈值条时，Claude 的自动决策会在停放之前把每个账户都压榨到它的上限墙，参见[上限墙](/zh/switching)。把它设为与最高会话档位和周阈值条相等即可禁用；Codex 会忽略此设置。
- `claudeBin` / `codexBin`：钉定监督进程实际生成的真实二进制文件（由 `init` / `init --codex` 写入；当递归防护诊断提示 `claudeBin` 不再指向真实的 Claude 二进制文件时，就在这里修正它）。
- `policy.projectionMargin`：从每一档会话档位、周阈值条和上限墙阈值条中减去，得到有效阈值条。
- `policy.greedySessionFloor`：贪心收敛开始介入时的会话已用百分比。
- `policy.switchModels`：单模型周上限会为切换设定门槛的模型家族（加载时条目转为小写）。
- `policy.usagePollTtlMs`：`/usage` 按模型轮询保持新鲜的时长。
- `policy.maxWaitMs`：账户池耗尽后自动等待的上限。

`tokenmaxxing config` 显示有效配置及其来源；`config set`/`unset` 编辑点分键；`config tidy` 清除未知键。
