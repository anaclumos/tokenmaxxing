---
title: நேர்மையான வரம்புகள்
description: "ஒன்றிணைந்த உடனுக்குடன் மாற்றத்துடன் வரும் சமரசங்கள்"
---

- **ஒரு குளிர்ச்சியான திருப்பு.** Prompt cache நிறுவனம்-வரம்பிடப்பட்டது, எனவே ஒரு புதிய கணக்கில் முதல் திருப்பு சூழலை ஒருமுறை மீண்டும் பதிவேற்றுகிறது.
- **தீர்ந்துபோன-இடைநிறுத்த இடையூறு.** முழுமையாக தீர்ந்துபோன ஒரு தொகுப்பு மட்டுமே எண்ணிக்கைக்காக அமர்வை நிறுத்துகிறது; அந்த பிளவு நொடியில் தட்டச்சு செய்யப்பட்ட எதுவும் இழக்கப்படுகிறது.
- **ஏற்றுக்கொள்ளல் தாமதம்.** macOS இல் ஒரு மாற்றத்தின் ~30 வினாடிகளுக்குள் முதல் திருப்பு இன்னும் பழைய கணக்கை அளவிடக்கூடும்; பட்டைகளின் இடம் அதை உள்வாங்குகிறது.
- **பகிரப்பட்ட வெடிப்பு ஆரம்.** அனைத்து இயல்பு-சுயவிவர அமர்வுகளும் ஒரு நேரடி சான்றுதலைப் பகிர்ந்து கொள்கின்றன, எனவே ஒரு மாற்றம் அவை அனைத்தையும் ஒன்றாக நகர்த்துகிறது (ஒவ்வொன்றும் இடத்திலேயே ஏற்றுக்கொள்கிறது).
- **Linux இல் plaintext சான்றுதல்கள்.** Claude Code தானே Linux சான்றுதல்களை ஒரு 0600 plaintext கோப்பாக சேமிக்கிறது; tokenmaxxing இன் நிறுத்தப்பட்ட நகல்கள் அதே மாதிரியைப் பின்பற்றுகின்றன.
- **ஒரு ஹோஸ்டுக்கு ஒரு தொகுப்பு.** ஒரே கணக்குகளை பல இயந்திரங்களில் ஒன்றிணைப்பது வேலை செய்கிறது, ஆனால் ஒவ்வொரு ஹோஸ்டும் டோக்கன்களை தனித்தனியாக நிறுத்தி சுழற்றுகிறது, குறுக்கு-ஹோஸ்ட் lock ஏதுமின்றி: ஒரே கணக்கின் டோக்கனை ஒரே நேரத்தில் புதுப்பிக்கும் இரண்டு ஹோஸ்டுகள் ஒன்றோடொன்று போட்டியிடுகின்றன. Claude இல், ஒரு புதுப்பிப்பு சுழற்சி முந்தைய access token ஐ உடனடியாக ரத்துசெய்கிறது, எனவே மற்ற ஹோஸ்டில் உள்ள அமர்வுகள் 401 உடன் தோல்வியடைகின்றன, மேலும் அதன் பழைய refresh token `invalid_grant` (மீள்-அங்கீகாரம் தேவை) என்று திரும்புகிறது. மேலும் Codex க்கு, ஒரு பழைய நிறுத்தப்பட்ட நகலிலிருந்து ஒரு புதுப்பிப்பு அந்த உள்நுழைவுக்கு ஆபத்தானது (refresh-token மறு பயன்பாட்டில் OpenAI முழு grant family யையும் செல்லாததாக்குகிறது, ஒவ்வொரு ஹோஸ்டிலும் `auth` ஐ கட்டாயப்படுத்துகிறது). நீங்கள் ஒரு கணக்கை ஒன்றுக்கு மேற்பட்ட இயந்திரங்களில் ஒன்றிணைத்தால், Claude இல் re-auth சலசலப்பை எதிர்பாருங்கள், மேலும் Codex க்கு அதை முற்றிலும் தவிருங்கள்.
