---
title: Структура каталога состояния
description: "Каждый файл и каталог в ~/.config/tokenmaxxing"
---

Всё находится в `~/.config/tokenmaxxing/` (переопределяется через `TOKENMAXXING_HOME`; у каждого внешне наблюдаемого пути есть переопределение через переменную окружения, так что весь инструмент может герметично работать в тестах).

| Путь | Что содержит |
|---|---|
| `config.json` | Ваша конфигурация (разреженная; значения по умолчанию применяются к каждому полю) |
| `accounts.json` | Несекретный индекс объединённых аккаунтов Claude: метки, id, кэшированные окна использования. Никогда токены |
| `usage.json` | Снимок агрегированных окон от ответвления statusline; его mtime - сигнал жизнеспособности канала |
| `model-usage.json` | Недельные лимиты по моделям из `/usage`, кэшированные с TTL |
| `lastswap.json` | Метка времени в эпохах последнего переключения; управляет 45-секундной паузой |
| `depleted.json` | Записанное ожидание при исчерпанном пуле, воспроизводимое соседними хуками, пока не пройдёт сброс, не сменится активный аккаунт или не завершится любое переключение |
| `lock` | Файл `flock`, сериализующий переключения |
| `serve-lock` | Единственная блокировка экземпляра `xx serve`: новое поколение демона блокируется здесь, пока предыдущее полностью не завершится |
| `sessions/<session-id>.json` | Флаги запуска для каждой управляемой сессии, сохраняемые супервизором для перезапусков; удаляются после 30 дней бездействия (в соответствии с собственным сроком хранения транскриптов claude) |
| `tokenmaxxing.log` | Журнал событий только для добавления |
| `bin/` | Shim-ы PATH: `claude`, `codex` и точки входа `tokenmaxxing` / `xx` |
| `respawn/<session-id>` | Маркеры перезапуска для ожидания при исчерпании, за которыми следит супервизор |
| `creds/` | Только Linux: файлы припаркованных учётных данных, 0600 в каталоге 0700 (на macOS учётные данные паркуются как элементы keychain для каждого аккаунта) |
| `onboard/`, `sample/` | Одноразовые изолированные конфигурационные домашние каталоги для входов `add`/`auth` и проверок `/usage` припаркованных аккаунтов; домашние каталоги онбординга, содержащие учётные данные в открытом виде, удаляются после сбора |
| `slack.json` | Токены и привязки каналов `xx serve` (0600) |
| `slack-threads/` | Записи сессий для каждого треда для `xx serve` |
| `codex-*` | Параллельный пул Codex: `codex-accounts.json`, `codex-lastswap.json`, `codex-lock`, `codex-creds/`, `codex-onboard/`, `codex-respawn/`, `codex-reconcile/` (межсессионные сигналы, просящие супервизор соседней сессии перезапуститься на активный аккаунт) и `codex-live/` (по одному PID-проверенному файлу присутствия на каждую работающую контролируемую сессию codex, так что живой аккаунт никогда не становится целью переключения) |

Вне своего собственного каталога tokenmaxxing затрагивает ровно: `~/.claude.json` (замена `oauthAccount`), `settings.json` Claude Code (записи хука и statusline), активное хранилище учётных данных (элемент keychain `Claude Code-credentials` на macOS, `.credentials.json` в Linux), собственные блокировки обновления claude, берущиеся во время переключений (основная `.oauth_refresh.lock` внутри конфигурационного каталога claude, плюс устаревшая соседняя `~/.claude.lock`), `auth.json` и `hooks.json` codex, а также юнит периодической проверки в launchd или systemd.
