tokenmaxxing 係一個自動切換 Claude Code 帳戶嘅 CLI。佢會將你擁有嘅多個訂閱（Pro/Max）帳戶集合埋一齊，當使用緊嗰個帳戶快到用量上限，就將活躍憑證熱切換去另一個新鮮啲嘅帳戶。你照舊咁行 `claude`；切換會喺安全嘅回合邊界發生，而你行緊嘅 session 會喺新帳戶上面繼續同一段對話，唔使重新啟動。就算同時開好多個 session，佢一樣運作到。

唯一睇得到嘅行為就係最壞嘅情況：成個帳戶池都去到上限嗰陣，session 會暫停，顯示緊倒數，然後喺下一個會重設嘅帳戶上面自動繼續（撳 Ctrl-C 即刻繼續）。

<Callout>
範圍：macOS 同 Linux 上面嘅 Claude Code，加上 OpenAI 嘅 Codex CLI 作為第二個並行帳戶池。佢集合嘅係訂閱帳戶，唔係 API key。呢個係個人用途嘅工具，用嚟集合你自己擁有嘅帳戶，喺你自己行嘅 session 同 agent 入面用 - 睇[個人用途同服務條款](/yue/terms)。
</Callout>

## 問題所在

一個 Claude 訂閱會同時計量三個上限（全部都用 `/usage` 確認到）：

- **目前 session**：滾動嘅 5 小時窗口。
- **本週（所有模型）**：7 日嘅總量。
- **本週，每個模型**：個別模型系列各自嘅每週上限。呢啲目前淨係 Sonnet 同 Fable 先有，而且淨係 Fable 嘅上限緊到有影響 - 佢會遠遠早過總量就綁死。一部機可以週總量得 50%，但週 Fable 已經去到 80%。

每週配額係用剩即棄：一個帳戶喺固定嘅每週重設之前用唔晒嘅份額就會作廢。如果你有幾個帳戶，理性嘅策略就係一路揀最落後於自己每週步伐嗰個帳戶嚟燒配額，同埋趁任何一個上限喺 session 中途撞牆之前就切走。

自己用手做，就要登出、登入，仲會冇埋你段對話。tokenmaxxing 將佢自動化：一個行緊嘅 `claude` 會喺兩次請求之間重新檢查憑證儲存，所以喺佢底下換咗嘅憑證會就地採用（喺 macOS 大約 30 秒之內，喺 Linux 就下一次請求）。普通嘅切換永遠都唔會重新啟動你個 session。唯一仲需要進程管理嘅情況，就係成個帳戶池完全耗盡 - session 冇辦法自己叫停自己 - 而呢個就係嗰個輕量監督者存在嘅原因。

關於 `claude` 嘅所有其他嘢都冇變：所有旗標、MCP 伺服器、hook 同 skill 都會照樣通過。
