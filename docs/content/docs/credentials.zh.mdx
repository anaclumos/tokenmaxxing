---
title: 凭证存储与安全模型
description: "凭证在各平台的存放位置，以及每次切换强制执行的规则"
---

所有状态都存放在 `~/.config/tokenmaxxing/`。凭证 I/O 都经过单一的、按平台选择的存储门面；调用点从不按平台分支。

**macOS**：凭证以 generic-password 条目存放在登录钥匙串中，与 Claude Code 自身存放它们的位置一致。活动条目是 claude 读取的那个；每个池内账户的备份以它自己的 `tokenmaxxing-cred-<uuid8>` 钥匙串条目停放。磁盘上没有任何明文。读取使用 `security find-generic-password -w`（密文只会出现在 stdout 上）；写入把一行 `add-generic-password` 通过 stdin 管道输入 `security -i`，因此密文绝不会出现在任何进程的 argv 中。交互模式有大约 4 KB 的行缓冲，因此过大的数据块会退回到 argv 写入 - 这也是停放条目只存储最小 OAuth 对象的原因之一。

**Linux**：Claude Code 把凭证存储为一个 0600 明文文件，tokenmaxxing 沿用同样的模型：活动文件是 claude 自己的 `.credentials.json`，停放备份则是位于一个 0700 目录下的 `~/.config/tokenmaxxing/creds/` 中的原子 0600 文件。这里的原子意味着写入临时文件、fsync，然后重命名：并发读取者始终看到的要么是完整的旧文件，要么是完整的新文件，绝不会是部分文件。

切换所强制执行的安全规则：

- **按真正所有者收集。** 在切换之前，活动凭证的实际所有者是通过询问 API 该 token 属于哪个组织来解析的（针对 OAuth roles 端点的 `fetchTokenOrg`）- 绝不通过信任可能漂移的已存活动标签。一个漂移的标签曾经导致一个账户的收集覆盖了另一个账户唯一的备份。如果活动凭证属于池外的某个账户，切换会直接拒绝，而不是把它覆盖掉。
- **单一临界区。** 收集、新凭证的安装、其轮换 token 的备份、`~/.claude.json` 账户切换，以及活动标签提交，全都发生在同一个加锁区段内。
- **与 claude 自身刷新互锁。** 一个临近过期的会话可能在任何时刻轮换它自己的 token，因此凭证写入也会取用 Claude Code 的刷新锁（尽力而为，带过期锁回收和有界超时）。
- **失效授权优雅降级。** 一次返回 `invalid_grant` 的刷新会把该账户标记为需重新认证，并在错误传播之前持久化该标记，从而让重试循环缩小候选集并终止。`tokenmaxxing auth` 会就地修复一个被标记的账户，并拒绝一个落在与待修复账户不同账户上的登录。
- **不记录 token。** Token 绝不出现在日志、错误或输出中。来自 token 和 usage 端点的错误正文绝不原样呈现；只有一组允许列表内的字段得以保留，因为一个 token 端点的失败正文可能回显请求材料。
- **探测卫生。** 任何被 spawn 的 `claude` 探测都会清除 claude 在其钥匙串查找之前所遵循的八个环境变量（`ANTHROPIC_API_KEY`、`CLAUDE_CODE_OAUTH_TOKEN`、`CLAUDE_SECURESTORAGE_CONFIG_DIR` 等等），因此一次探测绝不会被归属到错误的账户上。
