---
title: Configuración
description: "El esquema de config.json, los umbrales y los ajustes de política"
---

La configuración es JSON en `~/.config/tokenmaxxing/config.json`. Cada campo es opcional; los valores por defecto se aplican por campo.

```json
{
  "thresholds": { "session": [50, 80, 95], "weekly": 98 },
  "hardThresholds": { "session": 100, "weekly": 100 },
  "claudeBin": "/path/to/real/claude",
  "codexBin": "/path/to/real/codex",
  "policy": {
    "projectionMargin": 0,
    "greedySessionFloor": 50,
    "switchModels": ["fable"],
    "usagePollTtlMs": 90000,
    "maxWaitMs": 3600000
  }
}
```

- `thresholds.session`: la escalera de 5 horas, una lista ascendente de peldaños de cribado. Cada evaluación resuelve un peldaño activo, el peldaño más bajo en el que alguna cuenta del grupo sigue siendo utilizable, y ese peldaño es a la vez el disparador y el cribado de candidatas. Codex solo lee el peldaño superior. Ver [Cómo decide el cambio](/es/switching).
- `thresholds.weekly`: la barra de cribado semanal, que cubre el agregado de 7 días y cada tope semanal por modelo.
- `hardThresholds.session` / `hardThresholds.weekly`: las barras de muro (por defecto 100, el límite real del servidor de cada cuenta). `hardThresholds.session` tiene que estar en el peldaño de sesión superior o por encima de él. Cuando cada cuenta está por encima de su barra de cribado, la decisión automática de Claude exprime cada una hasta su muro antes de estacionar - ver [El muro](/es/switching). Fija igual al peldaño superior y a la barra semanal para deshabilitarlo; Codex ignora este ajuste.
- `claudeBin` / `codexBin`: fija los binarios REALES que generan los supervisores (escritos por `init` / `init --codex`; el diagnóstico de la protección contra recursión te indica que corrijas `claudeBin` aquí cuando deje de apuntar al binario real de Claude).
- `policy.projectionMargin`: se resta de cada peldaño de sesión, de la barra semanal y de las barras de muro para formar las barras efectivas.
- `policy.greedySessionFloor`: porcentaje de sesión usado al cual entra en juego la convergencia voraz.
- `policy.switchModels`: familias de modelos cuyo tope semanal por modelo pone compuerta a un cambio (las entradas se pasan a minúsculas al cargarse).
- `policy.usagePollTtlMs`: cuánto tiempo permanece fresco un sondeo por modelo de `/usage`.
- `policy.maxWaitMs`: el límite de la espera automática por grupo agotado.

`tokenmaxxing config` muestra la configuración efectiva con sus fuentes; `config set`/`unset` editan claves con puntos; `config tidy` poda claves desconocidas.
