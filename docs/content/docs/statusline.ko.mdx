---
title: statusline
description: "색으로 전달되는 할당량, 한 줄, 모든 계정 표시"
---

tokenmaxxing은 Claude Code의 statusline을 네이티브로 렌더링합니다(사용량 피드를 tee하면서). 설계 원칙은 간단합니다. 할당량을 숫자가 아니라 색으로 나타내며 전체를 한 줄에 담습니다. 예를 들면 다음과 같습니다.

```
tm-wt-demo Fable 5 (high) +156/-23  ◆ 𝒇 2h 1d  ◇ 19h  ◇ 𝒇 2d  ◇ full  ✗ ?
```

- 각 윈도우 토큰은 초기화까지 남은 시간이며 사용 백분율에 따라 초록에서 노랑을 거쳐 빨강으로 이어지는 연속 그러데이션(ramp)으로 채색됩니다(터미널이 지원하면 트루컬러, 아니면 256색 큐브에 단계적으로 매핑). 그러데이션은 0에서 순수 초록, 75에서 노랑, 95 이상에서 빨강으로 고정되므로 기존 심각도 구간이 그러데이션 앵커로 그대로 남습니다.
- 모델 이름은 같은 그러데이션 위에서 컨텍스트 윈도우 채움 정도로 채색됩니다.
- 초록 `◆`가 활성 계정의 윈도우 앞에 옵니다. 보관된 계정마다 시안색 `◇`가 붙습니다(재인증이 필요하면 빨간 `✗`). 계정은 가장 가까운 초기화 순으로 정렬됩니다.
- 각 블록에서 모델별 정보가 채색된 이니셜 하나로 맨 앞에 옵니다. Fable은 `𝒇`로 렌더링되고, 다른 계열은 대문자로 바꾼 첫 글자를 쓰며 항상 계열 단위로 매칭합니다.
- 손대지 않은 보관 계정은 초록 `full`로 렌더링됩니다. 초기화 시각을 알 수 없는 측정된 사용량은 채색된 `?`로, 게이트된 모델의 측정되지 않은 모델별 상한은 채색되지 않은 `𝒇?`로 렌더링됩니다. 측정되지 않은 값이 안전해 보여서는 안 됩니다.
- 초기화 카운트다운은 가장 큰 단위 하나만 표시하고 "now"나 "0m"은 절대 표시하지 않습니다. 예정된 초기화가 없는 윈도우는 초록 `0`으로 렌더링됩니다(다시 비었음).
- 연결된 git worktree의 basename이 줄 맨 앞에 옵니다. 메인 체크아웃은 그 자리에 아무것도 렌더링하지 않습니다. 감지할 때는 파일 시스템에서 `.git` 파일을 읽을 뿐, git 서브프로세스는 생성하지 않습니다.
- `NO_COLOR`가 설정되면 줄은 붙여 쓴 숫자 형식으로 대체됩니다(`2h5`는 2시간 후 초기화와 5% 사용을 뜻하고 `ctx 42`는 컨텍스트 채움을 나타냅니다). 색이 없으면 소진된 윈도우가 여유 있어 보여서는 안 됩니다.

서브에이전트 작업에는 claude의 subagentStatusLine을 통해 별도의 패널 행이 생깁니다. 활성 작업 하나에 행 하나씩이며, 계열 이름은 그 작업의 컨텍스트 채움으로 채색됩니다.
