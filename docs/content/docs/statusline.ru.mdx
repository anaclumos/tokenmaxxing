title: Statusline
description: "Квота передаётся цветом, одна строка, виден каждый аккаунт"
---

tokenmaxxing отрисовывает statusline Claude Code нативно (одновременно ответвляя канал данных об использовании). Принцип дизайна: квота передаётся цветом, а не числами. Одна строка, например:

```
tm-wt-demo Fable 5 (high) +156/-23  ◆ 𝒇 2h 1d  ◇ 19h  ◇ 𝒇 2d  ◇ full  ✗ ?
```

- Каждый токен окна - это его время до сброса, окрашенное по непрерывному градиенту от зелёного через жёлтый к красному по проценту использования (truecolor, когда терминал это поддерживает, иначе с шагом по 256-цветному кубу). Градиент закрепляется на чистом зелёном для 0, жёлтом на 75 и красном на 95 и выше, поэтому старые полосы серьёзности сохраняются как опорные точки градиента.
- Имя модели окрашивается по заполнению контекстного окна на том же градиенте.
- Зелёный `◆` возглавляет окна активного аккаунта; каждый припаркованный аккаунт получает свой голубой `◇` (красный `✗`, если требуется повторная аутентификация). Аккаунты сортируются по ближайшему предстоящему сбросу.
- Показатель по модели идёт первым в каждом блоке как одиночная окрашенная буква: Fable отображается как `𝒇`; другие семейства используют свою первую букву в верхнем регистре, всегда с сопоставлением по семейству.
- Нетронутый припаркованный аккаунт отображается зелёным `full`. Измеренное использование с неизвестным сбросом отображается окрашенным `?`, а неизмеренный лимит по модели на заблокированной модели отображается неокрашенным `𝒇?` - неизмеренное никогда не должно выглядеть безопасным.
- Обратный отсчёт до сброса показывает только наибольшую единицу, никогда «now» или «0m»; окно без предстоящего сброса отображается зелёным `0` (снова пустое).
- Имя связанного git-worktree возглавляет строку; основной checkout там ничего не отображает. Определение читает из файловой системы файл `.git` и никогда не порождает подпроцесс git.
- При установленном `NO_COLOR` строка откатывается к склеенному числовому формату (`2h5` означает сброс через 2 часа, 5% использовано; `ctx 42` для заполнения контекста) - без цвета исчерпанное окно не должно выглядеть свежим.

Задачи субагентов получают свои строки на панели через surface subagentStatusLine claude: по одной строке на активную задачу, имя семейства окрашивается по заполнению контекста этой задачи.
