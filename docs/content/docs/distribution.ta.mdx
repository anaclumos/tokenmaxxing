---

npm தொகுப்பு ஒரு பில்டை அல்ல, TypeScript மூலத்தை அனுப்புகிறது: `tokenmaxxing` bin ஒரு Bun shebang உடன் நேராக `src/main.ts` ஐ சுட்டுகிறது, மேலும் Bun 1.2.6 அல்லது புதியது அதை அப்படியே இயக்குகிறது. அதனால்தான் Bun ஒரு கடினமான தேவை. வடிவமைப்பின்படி எந்த தொகுக்கப்பட்ட binaries உம் இல்லை: ஒரு ஆரம்ப வெளியீடு ஒவ்வொரு தளத்திற்கும் ஒரு ஒற்றை 61 MB macOS binary ஐ அனுப்பியது, மேலும் Linux இல் `exec format error` உடன் தோல்வியடைந்தது, மேலும் ஒவ்வொரு-தளத்திற்கும் தொகுக்கப்பட்ட தொகுப்புகள் ஒவ்வொன்றும் அதற்கே சொந்தமான வெளியீட்டு pipeline தேவைப்படும், எனவே Bun-ஆல்-இயக்கப்படும்-மூலம் விநியோக மாதிரியாக மாறியது.

தொகுப்பின் `exports` வரைபடம் [ஏஜென்ட் SDK அணுகுமுறை](/ta/sdk) என்பதில் விவரிக்கப்பட்ட நிரல்முறை நுழைவாக `src/sdk.ts` ஐ வெளிப்படுத்துகிறது. வெளியீடுகள் GitHub இல் `v<version>` என குறியிடப்படுகின்றன; CI நம்பகமான வெளியீடு வழியாக npm க்கு வெளியிடுகிறது (OIDC, provenance உடன்), மேலும் வெளியீட்டு வாயில் முதலில் typecheck ஐ இயக்குகிறது.

## Nix / nix-darwin

அதே மூல மரம் ஒரு flake ஆகவும் உள்ளது. Bun-ஆல்-இயக்கப்படும்-மூல மாதிரியை வைத்திருக்கிறது ([bun2nix](https://github.com/nix-community/bun2nix) இன் `writeBunApplication` வழியாக) மற்றும் இவற்றை வெளிப்படுத்துகிறது:

| வெளியீடு | நோக்கம் |
|---|---|
| `packages.default` | PATH இல் `tokenmaxxing` + `xx` |
| `darwinModules.default` / `withOverlay` | nix-darwin: CLI ஐ நிறுவு (விருப்பத் தேர்வாக அறிவிப்பு முறை சரிபார்ப்பு டைமர்) |
| `homeManagerModules.default` | macOS அல்லது Linux இல் Home Manager |
| `nixosModules.default` / `withOverlay` | NixOS கணினி நிறுவல் |

சுயவிவரத்தில் நிறுவுங்கள் (`init` இன் மேற்பார்வையாளர் shims நிலையான ஒரு `tokenmaxxing` ஐ PATH இல் கண்டுபிடிக்க), பிறகு init செய்யுங்கள்:

```sh
nix profile install github:anaclumos/tokenmaxxing
tokenmaxxing init
```

நிறுவாமல் ஒருமுறை இயக்குதல் (help / status க்கு மட்டும். இப்படி `init` செய்யாதீர்கள்):

```sh
nix run github:anaclumos/tokenmaxxing -- help
```

nix-darwin (`pkgs.tokenmaxxing` தீர்க்கப்பட overlay சேர்க்கிறது):

```nix
{
  inputs.tokenmaxxing.url = "github:anaclumos/tokenmaxxing";
  modules = [
    inputs.tokenmaxxing.darwinModules.withOverlay
    { programs.tokenmaxxing.enable = true; }
  ];
}
```

Home Manager (தொகுப்பை வெளிப்படையாக அமைக்கவும், அல்லது Home Manager பயன்படுத்தும் pkgs க்கு இந்த flake இன் overlay ஐப் பொருத்தவும்):

```nix
{
  imports = [ inputs.tokenmaxxing.homeManagerModules.default ];
  programs.tokenmaxxing.enable = true;
  programs.tokenmaxxing.package = inputs.tokenmaxxing.packages.${pkgs.system}.default;
}
```

Nix CLI ஐ PATH இல் மட்டும் வைக்கிறது. கணக்கு இறக்குமதி, PATH இல் உள்ள `claude` மேற்பார்வையாளர் shim, `settings.json` hooks, மற்றும் (இயல்பாக) காலமுறை சரிபார்ப்பு டைமர் இன்னும் `tokenmaxxing init` இலிருந்தே வருகின்றன. இவை அங்கீகாரத் தகவல்களையும் பயனர் உரிமையான அமைப்புகளையும் தொடுகின்றன, தூய தொகுதி ஒன்று அவற்றை மீண்டும் எழுதக்கூடாது. init க்குப் பதிலாக டைமரை Nix வைத்திருக்க வேண்டும் என்றால் மட்டும் `programs.tokenmaxxing.checkTimer.enable = true` அமைக்கவும் (அது `TOKENMAXXING_SKIP_TIMER=1` ஐயும் ஏற்றுமதி செய்கிறது, எனவே init இரண்டாவது ஒரு unit ஐ எழுதாது). அறிவிப்பு முறை டைமர் init ஐப் போலவே ஒரு பயனர்-அமர்வு டைமர். தலையில்லா Linux இல் உள்நுழைவு இல்லாமல் அது இயங்க `loginctl enable-linger` தேவை.

`bun.lock` மாறும்போது, Nix சார்பு வெளிப்பாட்டை மீண்டும் உருவாக்கவும்:

```sh
bun run nix:bun   # writes bun.nix via bun2nix@2.1.2
```
