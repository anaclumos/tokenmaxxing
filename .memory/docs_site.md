# Docs site

Traps in the Next.js and Fumadocs app under `docs/`. It has its own `bun.lock`, and the Vercel Preview deployment on the pull request head is its content check (`shipping`).

- The docs site pins `fumadocs-core` 16.11.5, behind the live fumadocs.dev docs (`llms(source, { renderPage })` exists only from 16.15.9): verify a Fumadocs or Next API in `docs/node_modules` after `bun install` inside `docs/`, never from the live docs, and keep the `fumadocs-ui` alias `npm:@fumadocs/base-ui@<version>` that `create-fumadocs-app` writes. `llms(source)` there exposes only `index(lang?)` and `indexNode(node, lang?)`, so `docs/app/llms-full.txt/route.ts` joins `getLLMText` over `source.getPages()` by hand; that route is not custom code to replace with a library call.
- A `##` heading in `docs/content/docs/*.mdx` is a link target for other pages (`/switching#the-bars`, `/architecture#the-sessionstart-hook`, `/distribution#automatic-updates`), so a rename breaks links silently; grep `](/<page>#<anchor>)` across `docs/content` before renaming a heading or restructuring a page.
- Nothing checks `docs/bun.lock` against `docs/package.json` before a merge: CI runs `bun install --frozen-lockfile` for the root package only and Vercel runs a plain `bun install` in `docs/`, so run `bun install` in `docs/` and commit both files together on any docs dependency change.
- `docs/next.config.mjs` sets only `turbopack.root: import.meta.dirname`, because the repository root and `docs/` each carry a `bun.lock` and `next build` otherwise infers the repository root as the workspace root and warns on every build; Next copies it into `outputFileTracingRoot` and warns when both are set with different values, and fumadocs-mdx `createMDX` spreads the existing `turbopack` object so `root` survives. Keep both lockfiles.
- `docs/lib/source.ts` has no `lucideIconsPlugin()` and `docs/package.json` has no `lucide-react`, because no page frontmatter or `meta.json` sets `icon`; a page that adds an `icon` key brings both back.
- `docs/proxy.ts` tries `rewriteRoot` (`/{index}.md`, which also catches the `/.md` a client builds from a bare `/`) before `rewriteSuffix` (`{/*path}.md`): the suffix rule alone sends `/index.md` to `/llms.mdx/docs/index/content.md`, which no page has because the root page's slug is empty.
- `docs/package.json` runs plain `next dev`, which binds `0.0.0.0` (Next 16.2.10 default) and exposes the preview to the network; start it with `next dev -H localhost`, link `http://localhost:PORT`, and check for a running server on the checkout with `pgrep -f` first, remembering the pattern also matches the checking shell.
- A remark plugin for the docs goes in the default export `defineConfig({ mdxOptions: { remarkPlugins: [...] } })` of `docs/source.config.ts`, which appends to the Fumadocs preset; a collection-level `mdxOptions` inside `defineDocs` removes the default options and plugins.
- Diagrams are ` ```mermaid ` fences that `docs/lib/remark-mermaid.ts` hands to `docs/components/mermaid.tsx`; keep the local plugin and component, because `fumadocs-mermaid` is third-party with extra UI chrome and fumadocs-core's `remarkMdxMermaid` exports `<Mermaid chart="...">` with quotes escaped as `&#x22;` in the Markdown export (`useTheme` comes from `fumadocs-ui/provider/base`, so no `next-themes` dependency). A wide diagram scales its text down, so draw wide graphs as `flowchart TD`, and mermaid wraps a label at a hyphen or mid-phrase, so break labels with explicit `<br/>`. Keep every node and edge to a claim the page already makes.
- Fumadocs' Markdown stringifier serializes an unknown JSX element children-only, so an element whose content lives in an attribute (`Mermaid` `chart`) becomes `<></>` in `llms-full.txt`, each page's `content.md`, and the Copy Markdown button; set `node.data._stringify = { text: <original fence> }` as `remark-mermaid.ts` does, never `{ node: <code node> }`, and after adding a custom remark plugin check `curl http://localhost:<port>/llms-full.txt | grep -c '<></>'` and count fences against the source.
- Mermaid renders client-side and `docs/components/mermaid.tsx` falls back to a `pre` on a parse error, so the Vercel Preview build never fails on a broken diagram; render new or edited diagrams with `agent-browser` on a static `file://` page that loads `docs/node_modules/mermaid/dist/mermaid.min.js`, in light and dark themes.
