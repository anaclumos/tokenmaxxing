# Platform

Traps in Bun, zod, ky, and es-toolkit that the code depends on. Bun and zod move monthly: re-verify a line on a bump.

- `os.homedir()` and `os.userInfo().homedir` follow `HOME`, verbatim with a trailing slash, and Bun fixes `homedir()` at process start: assigning `process.env.HOME` inside a script changes `Bun.env.HOME` but not `homedir()`, so a mutating call such as `uninstallSupervisor` still edits the live `~/.claude/settings.json`, `~/.codex/hooks.json`, and shell rc. Set `HOME=<throwaway>` on the spawning command line and assert `homedir()` before a mutating call. `loginHome` in `src/lib/install.ts` reads `id -P` (macOS) or `getent passwd <uid>` (Linux), and `onLoginHome` compares both sides through `path.resolve`; never replace it with `userInfo().homedir`.
- `JSON.stringify` is not shell quoting: inside double quotes `$(...)` and backticks still expand (`/tmp/$(printf x)` became `/tmp/x`). The shims in `src/lib/install.ts` and the hook commands in `src/lib/settings.ts` quote with it; a change to that quoting uses `$.escape` from `bun` and changes `isOurHookCommand` in the same diff, because it parses the generated quoting.
- `Bun.spawnSync` has no `input` option (that is `node:child_process`): an `input` key is ignored and the child reads an empty stdin, so a hook or CLI run sees no payload. Feed hook stdin from a file with a shell redirect (`< stdin.json`).
- `Bun.semver.satisfies(v, "*")` is no version validator: it rejects a prerelease such as `0.88.0-beta.1` and accepts `""` and `v0.87.1`. To accept any bare version and reject other text, call `Bun.semver.order(v, "0.0.0")` inside try/catch and read a throw as "not a version", as `isBareVersion` in `src/lib/claudebin.ts` does.
- `engines.bun` is `>=1.4.0` because Bun 1.3.x `Bun.TOML.parse` accepts malformed TOML (`a = b`, `x = 9007199254740993`) that the codex preflight and the `doctor` hook-trust check rely on throwing; 1.4.0 and later throw `SyntaxError`. `nix/package.nix` asserts `lib.versionAtLeast bun.version "1.4.0"` and `flake.lock` pins a nixpkgs with Bun 1.4 or newer, because the `withOverlay` modules build with the consumer's nixpkgs `bun`; raise all three together, and probe a new floor with a downloaded release binary in a scratch directory.
- `@types/bun` is pinned to 1.3.14 while `engines.bun` is `>=1.4.0`, so a Bun 1.4 API or global missing from those types (`Bun.TOML.stringify`, `Temporal`) fails the CI typecheck: bump the pin in the change that needs it instead of casting. The typecheck proves nothing about the Bun floor an API needs.
- `Bun.secrets` cannot replace the `/usr/bin/security` spawn in `src/lib/keychain.ts`: each login-keychain item trusts only the program that created it, so `bun` and `security` each prompt on the other's items, the call has no timeout (an unanswered prompt leaves the promise pending), and it rejects with `ERR_SECRETS_INTERACTION_NOT_ALLOWED` where no dialog can show (read from Bun and Apple source, untested on a Mac). On Linux it uses libsecret while Claude Code keeps a 0600 `.credentials.json`, and Bun has no native `flock`, so `bun:ffi` in `src/lib/lock.ts` stays.
- `Bun.serve` with `routes` and a `fetch` fallback sends a wrong-method request for a registered route to `fetch`, sends a throwing route handler to `error`, and answers `HEAD` on a `GET` route 200 with no body; the hub's 401 and 404 ordering in `src/cli/serve.ts` depends on this (Bun 1.4.2).
- Bun's `JSON.parse` `SyntaxError` message echoes an unquoted fragment of its input, so a bare parse of a credential file or an error body can put token text into an error and the log: read state and credential files through `readJsonFile(path, schema)` in `src/lib/state.ts`, whose errors name only the path and the failing fields, and keep the status checks and `safeErrorDetail` in the ky fetch helpers instead of `.json(schema)`, because with `throwHttpErrors: false` an error body reaches the schema without its status.
- `statSync(p, { throwIfNoEntry: false })` returns `undefined` only for `ENOENT`; `ENOTDIR` and `EACCES` still throw, so the PATH scan in `src/lib/claudebin.ts` keeps `existsSync` in front of it, and the pair survives a candidate deleted between the two calls.
- `new TextDecoder().decode(bytes)` strips a leading UTF-8 BOM and `Buffer.toString("utf8")` keeps it, so a file reader built on `TextDecoder` (`readPiJson`) needs no manual strip.
- zod 4 reports a failed `z.union` as one root `Invalid input` issue with no path, which drops the field names `readJsonFile` prints; accept an optional or null section with a loose probe object, a `.transform` to `null`, and a `.pipe` into the real schema, as `CodexAuthFileSchema` in `src/lib/codexauth.ts` does.
- In zod 4.4, `.default({})` on an object whose fields carry their own defaults returns `{}` unparsed, while `.prefault({})` parses it and fills the nested defaults; a config section with leaf `.default()` values takes `.prefault({})`, as in `src/lib/types.ts`.
- The shared ky client in `src/lib/http.ts` keeps `retry: 0` beside `throwHttpErrors: false`: ky retries a status only through the `HTTPError` it throws, and ky 2.0.2 does not classify Bun 1.4 fetch failures as network errors, so no retry ever ran and the one-attempt-per-sample rule would rest on that mismatch. A ky bump that learns Bun's errors would retry every GET twice without the explicit `0`; probe with `http.extend({ hooks: { beforeRetry: [...] } })` against a local `Bun.serve` that answers 503, and never document a 429 as retried by ky.
- Spreading `process.env` with named keys drops its string index signature, so es-toolkit `omit` on the spread result fails the typecheck with `Type '"OTHER"' is not assignable`: annotate the env as `Record<string, string | undefined>`, call `omit` first, and spread the extra keys after it (`{ ...omit(env, keys), TOKENMAXXING_PROBE: "1" }`).
- es-toolkit `once` marks the function called before invoking it, so a first call that throws caches `undefined` and every later call returns it silently; never wrap a throwing resolver in `once` (the `claude --version` lookup behind `claudeUserAgent` would drop the `User-Agent` and hide every reset grant), and memoize in a module variable set only after the value validates.
