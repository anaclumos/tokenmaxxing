# Pool state

Traps in the state files, the pool lock, and the presence records that supervisors of different releases share.

- A presence record's `startedAt` is the exact `ps -o lstart=` string read under `LC_ALL=C` (`pidStartTimes` in `src/lib/proc.ts`, one `ps -p <pid,pid,...> -o pid= -o lstart=` for every record, because one `ps` per record costs seconds under the pool lock at about 70 records). Keep the format: `live/` and `codex-live/` are shared with supervisors still on the previous release during a self-update, and a release that reads another format deletes every older record as dead and frees accounts live sessions hold. Never switch to `/proc/<pid>/stat`, which macOS lacks.
- The pool lock is a non-blocking `flock` polled every `RETRY_MS` (75 ms, `src/lib/lock.ts`), not a fair queue: every contender races each release, so work inside a critical section multiplies, and a `__supervise` launch or its SIGTERM path can wait minutes behind a burst of `seat <pid>` borrows. Keep process spawns and network reads out of a `withLock` callback, because an await on network I/O there starves every hook and supervisor; when a hook or a CLI command hangs with no output (`timeout 20` exits 124 under about 100 supervisors), look for such an await first, then find the holder as in [[host]].
- `collect` in `src/cli/status.ts` copies a fresh sample onto the stored record field by field (`hasCredits`, `email`, `tier`, `usageRetryAt`, `lastProbeAt`, then `landWindows` and `landGrant`), so a new `Account` field that a sampler writes is lost on every `status` run until it is added to that merge.
- Every state-root directory that receives a `writeFileAtomic` target belongs in `tmpSweepDirs` (`src/lib/sessions.ts`), or a `.tmp.` file stranded by a hard kill, possibly a 0600 credential, is never collected. The sweep enters a store child only when its dirent `isDirectory()` (a symlinked child leads out of the root), removes regular files only, and lists through `listDir`, because the supervisor prunes before the spawn and one throw blocks every session.
- A reader that lists a directory `writeFileAtomic` writes into skips names `isStagingFile` (`src/lib/atomic.ts`) matches or filters to its own suffix, because a writer killed between the `wx` open and the rename leaves its staging file there for up to the sweep's hour. `livingPresences` throws on any other name it cannot parse, so an unskipped staging file in `live/` fails `status`, every `seat` grant, and every move until it is removed.
