tokenmaxxing (repo `~/Developer/tokenmaxxing`, greenfield as of 2026-07-08) is the owner's CLI for managing usage quota across many agent-CLI accounts: pick the account with the most headroom, swap to a fresh account when the active one hits its 5-hour/weekly limit, and keep sessions continuable across swaps. (User's Claim, 2026-07-08.)

**Why:** This is the product goal the user stated when starting the repo; every design decision here serves it.

**How to apply:** Full design lives in the repo's `DESIGN.md`; the architecture section of `AGENTS.md` is the current authoritative summary. Key decisions (2026-07-08, after the user twice narrowed scope): **v1 is Claude Code ONLY, macOS first** (Linux landed 2026-07-09; Codex dropped for now, verified mechanics preserved in [[cc-codex-auth-mechanics]]). **Model = THIN SUPERVISOR + HOOK (supervised-respawn):** the user types `claude` as always, but PATH resolves to a thin supervisor shim (`~/.config/tokenmaxxing/bin/claude`) that runs the real claude with inherited stdio + saved termios and, on a swap marker, kills + relaunches `claude --resume <session-id>`. The supervisor exists because a hook CANNOT respawn into the terminal (shell reclaims it when claude exits). NOTE (corrected 2026-07-10, see [[usage-after-switch-live-observation]]): a running claude DOES adopt an externally swapped credential (within ~30s on macOS, next request on Linux), so the supervisor is NOT needed for credential adoption; its remaining value is UX (depleted-pool countdown + auto `--resume`). The supervisor is process/PTY-only, NOT an API proxy. Mechanism: statusLine shim tees `usage.json`; **Stop hook** at the threshold (default 98 since 2026-07-14, was 95) takes a `flock`, swaps the credential (harvest-A → refresh-B → keychain write → atomically swap `oauthAccount` in `~/.claude.json`, under claude's `~/.claude.lock`), writes a `respawn/<session_id>` marker, and `kill -TERM $PPID`; the supervisor relaunches `--resume`. Kill happens ONLY at a salvageable state (post-Stop, turn committed to transcript, claude idle) - that's WHY the threshold sits below 100% (default 98): headroom to reach a clean boundary before the wall. Works for N concurrent sessions: per-terminal supervisor, per-session id, each respawns independently under one shared swap. NO `adopt` command - `tokenmaxxing init` auto-registers the existing login as account #1. All config+state in **`~/.config/tokenmaxxing/`**. `CLAUDE_CONFIG_DIR` used ONLY during `add` onboarding. Stack: TS on Bun, shipped as SOURCE (compiled-binary distribution deleted in v0.2.1, see below). Note: npm name `tokenmaxxing` owned by the user (anaclumos). (User's Claim, 2026-07-08.)

**v0.2.1 + npm trusted publishing (2026-07-09):** the npm package now ships TypeScript SOURCE with a bun-shebang bin (`bin: ./src/main.ts`, exec bit committed to git); compiled-binary distribution is deleted. Why: 0.2.0 (published manually from the mac) shipped a 61MB darwin-arm64 Mach-O to every platform, so `bun add -g tokenmaxxing` on [[linux-arm-host]] died with `exec format error`; per-platform compiled npm packaging would need N packages each with its own trusted publisher. `installSupervisor` now always writes the 2-line `exec <bun> run <realpathSync(Bun.main)>` shim (realpath resolves the `~/.bun/bin/tokenmaxxing` symlink into the installed package tree so imports resolve; the self-copy + codesign path is gone). Release flow: bump `package.json` version → commit/push → `gh release create v<version>` → `.github/workflows/ci.yml` publishes via npm trusted publishing (OIDC; publisher registered by the user = anaclumos/tokenmaxxing + `ci.yml`, filename must match exactly). Hard-won CI facts (verified via official docs 2026-07-09): trusted publishing needs npm >= 11.5.1 → node 24 via setup-node@v6 (ubuntu-latest default node 22 bundles npm 10.9.8, silently too old), `id-token: write`, GitHub-hosted runners only, provenance automatic; `bun publish` has NO OIDC support as of bun 1.3.14 (oven-sh/bun#15601, PR #30522 unmerged) so the publish step must be `npm publish`. ci.yml guards that the release tag equals `v<package.json version>`. Gotcha: `bun add -g <local .tgz>` over an existing same-name global errors `DependencyLoop`; `bun remove -g` first. Verified on the ARM box: tarball global install, `init` (repair path), all-green `doctor`, 47-pass test suite.
