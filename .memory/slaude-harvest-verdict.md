Slaude (~/Developer/slaude, multi-tenant Next.js/Vercel Slack+Claude product) is being shut down; the owner asked which good parts move into `xx serve`. A 25-agent workflow read both codebases, synthesized 17 candidates, and adversarially verified each against serve's source and recorded owner decisions. Survivors (not yet implemented; owner picks):

1. **External-author / Slack Connect guard** (small): serve's only sender filter is `relayable = !isMe && !isBot` (serve.ts ~293); any human in a linked channel, incl. Slack Connect externals/guests, can drive a session - bypassPermissions autonomy on `--yolo` links. Port slaude `src/lib/slack/bot.ts:78-103` `isOutsideAuthor` (zod-parse team/team_id/user_team/source_team from `Message.raw`, fail-closed on mismatch/absence vs the workspace team id captured at setup, persisted in slack.json). Matches the owner's recorded 2026-07-16 rule "outsiders must not work".
2. **Rate-limit park-and-retry around the turn** (medium): slackbridge.ts ~114 discards `ensureBestAccount()`'s SwapDecision; a depleted-pool turn spawns anyway, fails, posts "trying again may help", and nothing retries at reset. Port slaude's loop shape (thread-session.ts:100-138, steps 159-187): pool-swap first -> silent ~10s retry; whole pool depleted -> park until reset epoch with a Slack `<t:epoch:R>` countdown post, re-run the SAME prompt into the SAME session, bounded park budget, then an explicit dropped-message notice. Serve can park BEFORE the failed spawn since it owns the decision. Design details: surface waitUntil on non-anticipatory all-depleted returns (decide.ts ~261-280 currently omits it), and make parks sane vs the 300s SIGTERM drain. Carry slaude's invariant: only an ERRORED result counts as a rate limit (never re-run a successful answer that mentions limits).
3. **Drain-drop notice in-thread** (small, ~3 lines): serve.ts ~247-252 drops turns during SIGTERM drain with log-only `serve.drain_dropped`; the Slack user sees nothing. Post a best-effort fire-and-forget notice ("dropped, re-send after restart") in the draining branch; never await it.
4. **AGENTS.md safeguard bullet** (doc-only): live linked Slack channels are production surfaces - unsolicited test/probe sends need in-the-moment approval (slaude .memory/prod-safety-rules.md, incident the day serve went live). Owner-instructed decision pings stay the exception.

Verified skips worth remembering: chat 4.34.0 dedupes unconditionally at a 10min default TTL (explicit dedupeTtlMs is a no-op); @chat-adapter/slack never slices streamed markdown (slaude's 4000-char truncation bug was its own hand-rolled relay, cannot occur in serve); queue-TTL expiry has no app callback in chat 4.34.0 (only onQueueFull). Two surfaced-not-ported items needing owner decisions: same-repo cross-thread turns run concurrent claude subprocesses in one cwd (real, but a serve mutex conflicts with the normal-mode/agent-cuts-worktree decision); relayThread/runDaemon have zero automated coverage (needs a from-scratch hermetic harness + runDaemon injectability refactor, not a Slaude port).
