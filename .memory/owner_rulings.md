# Owner rulings

Standing decisions that no code or doc shows.

- A destructive instruction covers exactly the nouns it names: "delete the stale worktrees" covers worktrees, not their branches. Before a deletion pass, list the targets grouped by artifact kind, record every tip SHA, touch only the named kind, and offer the adjacent kinds as a question.
- A surfaced design fork holds until the owner picks, and silence never authorizes the stated lean. Only in-plan actions continue meanwhile: retrying the same named mechanism, cancelling dead tasks, watching state.
- A retry budget or a try/catch around an unexplained failure is monkeypatching: identify the mechanism that produces the symptom, fix that layer, and only then decide whether a bounded retry is warranted for transient residue. One structural error boundary beats per-site catches.
- An open design or scoping question is decided by a Codex consult when the owner names one ("codex:rescue"): a headless `codex exec --skip-git-repo-check -s read-only -c model_reasoning_effort=high -C <dir> -o <file> "<prompt>"` from the repo, or a tmux question-and-answer session. It meters the owner's Codex quota, so run one consult per question, treat the owner naming it as the spend mandate, and put the verdict in the PR body.
- Research and verification subagents run on Opus or Sonnet in small fan-outs; Fable is for one small hardest-judgment stage, and a wide Fable fan-out is asked about first, because the dev hosts are logged in with the pooled accounts.
- Every `status` chart label is lowercase: `5h`, `week`, and short family names such as `fable`, `spark`, `rsrv`; titlecase is barred.
- The defaults are `thresholds.session` 90, `thresholds.weekly` 98, and `policy.projectionMargin` 0: the owner set the session bar back to 90 after a release shipped 98 on both windows, so never "restore" 98 on the session window.
- `status` keeps its multi-column card grid (`renderGrid` in `src/cli/status.ts`, columns from the terminal width) for pools with many accounts; a simplification or audit pass does not propose removing it.
- The Claude usage GET and profile GET keep `Content-Type: application/json` (`src/lib/usage.ts`, `src/lib/oauth.ts`), because Claude Code sends it on both and no live read has tested either without it; never drop it as a bodiless-GET cleanup.
- `readJsonFile` errors in `src/lib/state.ts` stay one line (`<path> is corrupt (unparsable JSON) - repair or remove the file`, `<path> does not match its schema (<path>: <message>, ...) - repair or remove the file`), never `z.prettifyError`, because the text reaches the terminal, `--json` output, and the stream-json notice that T3 Code cuts at 120 characters; `z.prettifyError` stays limited to log fields until a consumer needs the multi-line form.
- The grok and opencode-go auth-file readers are strict file, tolerant entries: a missing file (`ENOENT`) means no login, a file that fails to read or parse throws and names the file, and an entry that fails its schema is skipped. One corrupt grok store failing `status` for every pool is accepted; add no per-account catch in `samplePool`, and verify such a change with a plain `status`, because `status --cached` never reads the store.
- A tee `usage/<uuid8>.json` that exists but fails to open, read, or parse makes `loadUsageSnapshot` throw, so one corrupt tee fails `check`, the Stop hook decision, `status`, and supervised launches; only `ENOENT` or a tee naming another account reads as null. `writeUsage` treats an unreadable previous tee as changed and rewrites it, so the next turn repairs it. An idle account's corrupt tee stays until it is removed by hand; do not make the reader tolerant.
- The owner's order to update the host after a release is the mandate to install the published version by hand with the self-update's own argv, once the `publish` job passed and `npm view tokenmaxxing version` lists it (the tick's self-update runs at most once per 24 hours): `bun add -g --registry https://registry.npmjs.org/ tokenmaxxing@<version>` with the state directory as cwd and `BUN_INSTALL_GLOBAL_DIR` set to the detected global root (`src/lib/update.ts`), then the hub restart in [[host]]. Without `--registry` the install can fail `No version matching "<version>"`, and an unversioned add keeps the old version. Check the shim's `--version` and `diff -rq` the global package's `src` against the merged `src`; never kill running supervisors and run no `init`, `add`, `auth`, or `uninstall`.
