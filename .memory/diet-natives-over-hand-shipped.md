# Diet pass: natives over hand-shipped code

Dated 2026-09-07 (branch t3code/audit-native-capabilities). Decisions that a future pass would otherwise re-litigate.

- Every JSON state file loads through `readJson` / `parseJson` in `src/lib/json.ts`: absent is `null`, corrupt or off-schema throws with the path and the zod issue. The one lenient file is `nextcheck.json` (`tryReadJson`), because `docs/state-directory.mdx` promises that a corrupt pace file means "due now" and a check running is the safe direction. Hook stdin, statusline stdin, and CLI stdout from `claude -p` go through `tryParseJson`, because a malformed external payload is an expected state there, never a state-file corruption. The respawn and reconcile markers are owned state and read through `readJson`: a corrupt codex marker read as absent would resume the session on stale in-memory credentials while `auth.json` points at another account, so the supervisor kills the child, restores the terminal, and exits with the path instead. The onboard `identityReady` poll keeps `tryReadJson` because it reads claude's own `.claude.json` while the login is still writing it.
- `.catch(undefined)` survives only on external per-turn payload fields (`StatusLineStdinSchema`, `SubagentStatusLineStdinSchema`, the Stop and StopFailure stdin schemas). The statusline must render every turn and the StopFailure hook is the Fable backstop, so one drifted field must not disable the whole payload. `session_id` keeps `z.uuid()` because the value names a file under `respawn/`. Every `TOKENMAXXING_*` env override throws when set but empty (`envOverride` in `src/lib/paths.ts`); `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, and `USER` mirror the vendor semantics where an empty value is unset.
- The config file schema carries its defaults (`.default()` on leaves, `.prefault({})` on sections) so `ConfigSchema.parse(raw)` yields a full `Config`; `config tidy` rebuilds the file from `KNOWN_KEYS` rather than running it through the schema, or defaults would be written into the file.
- Temporal was not adopted for `parseResetClock`: Bun 1.4.2 ships `Temporal` at runtime, but neither bun-types 1.3.14 nor TypeScript 5.9 declares it, so the swap would need a hand-written ambient declaration. Re-check when bun-types declares it.
- `Bun.secrets` (Keychain Services on macOS, libsecret on Linux) addresses items by the same service and account pair `security add-generic-password` uses, so it could replace `src/lib/keychain.ts` including the 4000-byte `security -i` workaround. Not adopted: items created by the `security` binary carry an ACL trusting that binary, so reads from the bun binary raise a Keychain access dialog per item, which the headless launchd check cannot answer, and items written by Bun.secrets would in turn prompt when Claude Code reads them through `security`. Needs a live Mac test before anyone proposes it again; see [[bun-tcc-appdata-prompts]].
- es-toolkit `retry` was not used for the usage probe: it needs a throwing function and sleeps after the final failure, so the null-returning probe would gain a sentinel error and a trailing delay.
- `makeUsagePaint` takes its escape code from `Bun.color`; the 256-color index now follows Bun's quantization (rgb(255,128,0) is index 208, the old hand cube gave 214). Truecolor output is byte-identical.
- ky runs with `throwHttpErrors` on. Callers classify `HTTPError` by `response.status` and the pre-parsed `error.data`, and `NetworkError` or `TimeoutError` as unreachable; response bodies are never echoed into messages. Codex dead grants classify on the structured codes (`error` string, `error.code`, `error.type`), never on body text.
- The `docs/lib/cn.ts` re-export has no importers; deleting it and the `cnfast` dependency is the owner's call (hook ruling on deletions, 2026-09-07).
