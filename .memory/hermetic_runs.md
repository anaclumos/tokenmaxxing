# Hermetic runs

Traps in running the supervisor, hooks, `check`, `status`, and `seat` against a throwaway state. The rules (no mutating command on a live host, a full isolated `HOME`, `TOKENMAXXING_SKIP_TIMER=1`) are in `AGENTS.md` "Verification".

- A fresh worktree has no `node_modules`, so a dependency's source is not there to read; run `bun install --frozen-lockfile` once in the worktree, and once more under `docs/` for the docs app.
- Resolve `BUN=$(command -v bun)` before exporting a throwaway `HOME`, because `~/.bun/bin/bun` then expands under the fake home and exits 127; run `env -i PATH=<dirs> HOME=<tmp> TOKENMAXXING_HOME=<tmp> TOKENMAXXING_SKIP_TIMER=1 TOKENMAXXING_CLAUDE_BIN=<stub> "$BUN" run src/main.ts <args>`.
- A hermetic `check`, `status`, hook, or supervisor run from an agent shell inherits the session's seat and supervisor stamps; run it under `env -i`, or unset `CLAUDE_SECURESTORAGE_CONFIG_DIR`, `TOKENMAXXING_SUPERVISED`, `TOKENMAXXING_SESSION_ID`, `TOKENMAXXING_LAUNCHED_AT`, `TOKENMAXXING_MODEL`, `TOKENMAXXING_REFUSED`, and `TOKENMAXXING_WRAP_DEPTH` with `env -u`, or the run reads the agent's seat (`seatFromEnv`), counts as supervised, and can trip the wrap depth guard.
- A hermetic supervisor case is `timeout -k 5 90 env -i PATH=<bun dir>:/usr/bin:/bin HOME=<scratch>/home TOKENMAXXING_HOME=<scratch>/tm TOKENMAXXING_SKIP_TIMER=1 bun <tree>/src/main.ts __supervise <claude args> < /dev/null` with `claudeBin` in `$TOKENMAXXING_HOME/config.json` naming a bash stub (`resolveRealBin` needs only an existing file that is not the wrapper) and no `accounts.json` (seat null, no usage read). A stub `claude` that emits stream-json lines ends with `exec sleep`, because a forked sleep is an orphan that holds the supervisor's stdout pipe open and stalls its drain.
- A worktree-isolated subagent refuses a Bash command it cannot prove stays in its worktree ("too complex to verify"): an inline `HOME=`, `BUN_INSTALL=`, or `TOKENMAXXING_HOME=` prefix, or `git` inside `$(...)`, a pipe, or a chain. Write each hermetic scenario to a script with the Write tool and run it as one plain `sh /tmp/<dir>/run.sh <arg>`; the same assignments inside the script pass.
- Deny the network with `unshare -rn sh -c 'ip link set lo up && <run>'` (a loopback-only user and network namespace) and start the stub usage endpoint as its own `bun` process inside it, because an in-process server stalls behind `Bun.spawnSync`. Where `kernel.apparmor_restrict_unprivileged_userns=1`, `unshare -rn` fails with `write failed /proc/self/uid_map: Operation not permitted`, and `unshare -Un` leaves loopback down; use `bwrap --unshare-net --ro-bind / / --dev-bind /dev /dev --bind <scratch> <scratch>` under `env -i` (stray writes fail with `EROFS`, loopback stays up for the stub). Pointing `HTTPS_PROXY` or a `TOKENMAXXING_*_URL` at a dead port proves nothing about egress.
- Never pipe a hermetic script into `head -1` or another early reader: the early close kills the script before it stops the stub server, and the stub survives; stop each by PID and confirm the PIDs are gone.
- A hermetic `seat <pid>` or presence run needs stand-in pids that stay alive, because `writePresence` throws `could not read pid N's start time (ps lstart)` for a dead pid; start each with a backgrounded `tail -f /dev/null &` (never inside a command substitution, which hangs on the inherited stdout), record each PID, and stop each by PID at the end.
- `source env.sh && tokenmaxxing seat ... &` backgrounds the whole chain, so the throwaway `HOME` and `TOKENMAXXING_HOME` load only in the background subshell and the foreground commands write the live pool; source the hermetic env in the foreground, put `&` only on the sleeper, and print `$TOKENMAXXING_HOME` or the store path `seat` returns before any command that writes state.
- Probe real `claude` argv and stream behavior without quota through the real versioned binary, never the wrapper: `--bare`, an invalid `ANTHROPIC_API_KEY`, `TOKENMAXXING_PROBE=1 TOKENMAXXING_UNMANAGED=1`, the seat and supervisor variables unset, and a throwaway `CLAUDE_CONFIG_DIR` whose `.claude.json` holds `{"hasCompletedOnboarding":true}`; a pty probe of the interactive form stalls at the trust dialog and proves nothing.
- A test of the wrapper recursion guard with a shim that strips `TOKENMAXXING_WRAP_DEPTH` can fork-bomb the host: Bun aborts near nesting level 56 under the thread limit, and a detaching shim (`setsid -f`) is unbounded. Run each loop case in `systemd-run --user --scope --quiet --unit=<name> -p TasksMax=500 -p MemoryMax=4G`, stop the scope by name, and confirm `systemctl --user list-units --all '<name>*'` is empty.
- Verify a refactor of `src/lib/install.ts` by running install and uninstall before and after under a throwaway `HOME` and `TOKENMAXXING_HOME` with `TOKENMAXXING_SKIP_TIMER=1`, `Object.defineProperty(process, "platform", { value: "darwin" })` for the macOS branch, and `Bun.spawnSync` replaced by a recorder, then `diff` the written unit files and the recorded `launchctl` and `systemctl` lines.
