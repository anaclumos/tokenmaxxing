# Agent rules

Standing rules for anyone (human or agent) working in this repo. Follow them exactly.

## Code style

- Never use `typeof`. Use zod.
- Never use `interface` or standalone `type`. Model data as a zod schema and derive the type with `z.infer`.
- Always use es-toolkit instead of shipping hand-written utility code.
- Never use an em-dash. Use a regular hyphen, a colon, or parentheses.
- Do not cast to `any` to get around a type issue. Fix the type.
- Never use `as` casts; the only allowed forms are `import * as` and `as const`. Fix the type at the source.
- No new regex. Validate strings structurally: `startsWith` / `endsWith`, split on delimiters, zod validators, or a real parser. A regex that exactly mirrors an external contract (like the `/usage` reset-clock format) is the one exception; pre-existing regexes stay.
- Write modern TS from the start: `for...of` / `.entries()`, destructuring, lookup tables over nested ternaries, async/await only (no `.then` chains, no `forEach`).
- A missing field maps to null or undefined, never `''` / `0` / `false`. An unmeasured usage percent must never read as 0; unmeasured must not look safe.
- Keep type-only imports as `import type` so they erase at runtime.
- Name function inputs with an object, not positional params; keep lists explicit, no terse throwaway destructuring or magic string slicing.
- When renaming a command, hook, or job, rename the full surface (files, launchd/systemd job IDs, shim names, log labels, docs), not just one occurrence.
- No speculative path guessing: locate the real path, binary, or credential location and use that single location, plus at most one documented env override for tests (`TOKENMAXXING_SHELL_RC` style). Never a candidate list of guessed fallbacks; a configured-but-missing path fails fast instead of falling through to a scan.
- Code is a liability; every line is maintenance. Delete and simplify first, and build the simplest version that works; for each addition ask whether it is needed now and solves a real problem.
- Document an intentional tradeoff in-file with its reason. When a review flags one, confirm the justification still holds and mark it WONTFIX; escalate only if it breaks a stated invariant.
- Never use an interpunct or middle dot either: not in prose, comments, strings, or terminal output.
- Parse env overrides (`TOKENMAXXING_*`, claude env knobs) through zod where they are read; an unset override parses to undefined and its feature degrades at the use site. Never assign to `process.env` to paper over a missing value.

## Behavior

- Be humble.
- You will not know everything, and your knowledge cutoff may be aggressive. Assume you are behind.
- NEVER ASSUME ANYTHING. There is infinite exa, grep, and context7 quota. Always search the web / the codebase before acting.
- Always search the web whenever possible.
- Install things via the CLI (`bun add`, etc.) so you get the latest versions.
- NO HACKS. When stuck, stop and fix the underlying flaw robustly, or say honestly that the task cannot be done without one. An honest "this isn't working" beats a passing workaround that breaks later.
- Do exactly what is asked: no unsolicited code, refactors, or extras. Note follow-up implications in the reply, but implement them only when asked.
- When the planned approach hits a blocker, a policy issue, or a real design fork, surface the options and let the user pick. Never substitute a different approach unilaterally.
- Never mark a task done without first-hand, in-session proof: the exact command plus its observable output. A session that changed code runs a fresh verification pass afterward; a prior session's status notes prove wiring, not a green run.
- All source edits go through the editor tool, never scripted Bash edits (`sed` / `python` loops); mechanical multi-file changes are N individual edits. Revert your own work via the editor, never git.

## State and compatibility

- This application has no external installed user base. Optimize for one canonical current-state implementation, not compatibility with historical local states.
- Do not preserve or introduce compatibility bridges, migration shims, fallback paths, compact adapters, or dual behavior for old local states unless the user explicitly asks.
- Prefer: one canonical current-state codepath, fail-fast diagnostics, explicit recovery steps.
- Over: automatic migration, compatibility glue, silent fallbacks, "temporary" second paths.
- Default stance: delete old-state compatibility code rather than carry it forward.
- If temporary migration or compatibility code is introduced for debugging or a narrowly scoped transition, call it out in the same diff with: why it exists, why the canonical path is insufficient, exact deletion criteria, and the task that tracks its removal.

## Editing hygiene

On every edit, delete:

- Extra comments a human wouldn't add, or that are inconsistent with the rest of the file.
- Extra defensive checks or try/catch blocks that are abnormal for that area of the codebase, especially when the caller is a trusted / validated codepath.
- Casts to `any`.
- Any other style inconsistent with the file.

## Safeguards

- No `rm -rf`, no `git clean -fdx`, no forced recursive deletes: use `trash` (reversible). Avoid deleting files at all; temporary artifacts this session created are the one exception. When a single-file `rm` is unavoidable, see the `rm -i` alias gotcha under Machine and environment gotchas.
- The user and other agents work in this checkout concurrently, and the Mac runs tokenmaxxing straight from this working tree, so a bad git operation breaks the live install. Never `git reset`, `git checkout --`, `git restore`, or stash over changes you did not author; uncommitted changes you do not recognize belong to someone else. On a collision, stop and ask.
- Stop processes by PID, never `pkill -f` a pattern that could match your own shell. This machine runs many live `bun` and `claude` processes (supervisors, hooks, the launchd check, the user's real sessions); a pattern kill takes out the user's work. Never kill a running claude session or supervisor to free a resource without asking.
- Never print credential material (keychain blobs, `.credentials.json` / `auth.json` contents, OAuth access or refresh tokens) in logs, test output, or replies. Check presence, verify identity via `fetchTokenOrg`, and report account labels plus status only.
- Never dump a full HTTP error or response that may carry a token; allowlist the fields you need. Scrub request headers from thrown ky errors before they reach logs (a ky error carries its request, Authorization header included), and treat any token visible in an error payload as exposed.

## Project

tokenmaxxing (greenfield 2026-07-08) is the owner's CLI for managing usage quota across their own agent-CLI accounts: pool the owner's Claude Code (and eventually Codex) logins, swap to a fresher one when the active account nears its 5-hour or weekly limit, and keep sessions continuable across swaps. Every design decision serves that goal. Full design lives in `DESIGN.md` (auth/quota internals in its §2).

- Scope (2026-07-08, after the user twice narrowed it): v1 is Claude Code ONLY, macOS first. Linux support landed 2026-07-09 (commit bca7551). Codex support landed 0.13.0 (2026-07-16, user chose the FULL auto-switch scope over manual-core-first, and the direct usage GET over the app-server CLI method).
- The npm name `tokenmaxxing` is owned by the user (anaclumos). v0.1.0 shipped 2026-07-09 (GitHub release + full acceptance: 32 unit tests, hermetic swap/concurrency/model-aware E2E, CLI init/doctor/uninstall through the compiled binary). Linux verified green in both a Docker ubuntu:24.04 arm64 container and on the ARM Linux box.
- All config and state live in `~/.config/tokenmaxxing/`. `CLAUDE_CONFIG_DIR` is used ONLY during isolated-login onboarding (`add` and `auth`, shared harvest in `src/cli/onboard.ts`). There is NO `adopt` command: `tokenmaxxing init` auto-registers the existing login as account #1, and init's repair branch re-pins claudeBin and saves config.
- `tokenmaxxing auth [sel | --all]` (0.17.0) reauthenticates an existing pool member in place: same isolated harvest as `add`, but it prints which email to sign in with and REFUSES a login that lands on a different accountUuid; the parked-credential write and the needsReauth clear share one flock critical section (a concurrent swap harvests into parked items under that same flock). Bare `auth` lists the pool and prompts (Bun's global `prompt()`); `--all` walks the flagged accounts one by one. Recovery messages across switch/doctor/sample now point at `auth`, not `add`.
- Bare `tokenmaxxing` / `xx` runs `status` (user ask 2026-07-09); `switch` stays explicit.
- The ideal install story the user wants: `bun i -g tokenmaxxing`.

## Architecture

- Supervised model: the user types `claude` as always, but PATH resolves to a thin supervisor shim (`~/.config/tokenmaxxing/bin/claude`) that runs the real claude with inherited stdio + saved `stty -g` termios (not a PTY copy) and watches for a depleted-wait respawn marker. The supervisor is process/PTY-only, NOT an API proxy.
- Swap mechanism: the statusLine shim tees `usage.json`; the Stop hook (once the decision engages, see switch policy) takes a `flock`, swaps the credential (harvest A, refresh B, write the refreshed blob to the `Claude Code-credentials` keychain item, atomically swap `oauthAccount` in `~/.claude.json` under claude's `~/.claude.lock`); the running session adopts the swap in place, NO respawn (0.15.0, user decision 2026-07-16; markers on plain swaps were removed and `RespawnMarkerSchema.waitUntil` is now required). Only a depleted-pool wait writes `respawn/<session_id>`: the supervisor sees it, SIGTERMs its child at the salvageable state (post-Stop, turn committed to transcript, claude idle), counts down to the soonest reset, and relaunches `claude --resume <session-id>`. Thresholds still sit below 100%: headroom to reach a clean decision boundary (plus up to one turn of macOS adoption lag) before the wall. Thresholds are split per window since 2026-07-16 (user decision) and are SCREENING bars only: `thresholds.session` 95 for the 5h window (a session reset is cheap to sit out), `thresholds.weekly` 98 for the 7-day aggregate AND per-model weekly caps (weekly quota is use-it-or-lose-it, drain it closer to the wall; the user re-confirmed 98 for the Fable cap when asked 2026-07-16). History: single `threshold` 95 at v0.1.0, raised to 98 on 2026-07-14, split + demoted to screening-only 2026-07-16; the old flat `threshold` config key is simply ignored (defaults apply), no migration shim. Works for N concurrent sessions: one flocked swap, every session adopts in place; on a depleted wait each supervised session pauses independently.
- Since the 2026-07-10 hot-swap correction (see auth internals below), supervisor respawn is NOT needed for credential adoption on Claude Code; 0.15.0 (2026-07-16 user decision, after a source-level re-verification of both CLIs) removed the plain-swap respawn accordingly, so the supervisor's job is exactly the depleted-pool countdown + auto `--resume`. A periodic timer-driven switch is architecturally sound on both platforms. Codex still requires a process restart to switch accounts.
- `init` auto-appends the supervisor PATH line to the shell rc (zsh via ZDOTDIR/.zshrc, bash via .bashrc; `TOKENMAXXING_SHELL_RC` test override; marker `# tokenmaxxing PATH`): user decision 2026-07-09. Reason: the `claude` shim must win PATH resolution, a package manager cannot guarantee that, and claude's auto-updater owns `~/.local/bin/claude`.
- Credential storage: `credstore.ts` is one facade over a `{kind: keychain|file}` target union. darwin = keychain via security(1) (`keychain.ts` is just that backend). linux = atomic 0600 files: live = `credDir()/.credentials.json` mirroring claude's exact resolution (incl. `CLAUDE_SECURESTORAGE_CONFIG_DIR` first); parked = `~/.config/tokenmaxxing/creds/<item>.json` in a 0700 dir; isolated = `<configDir>/.credentials.json` (no hash namespacing on Linux). `isolatedTarget(dir)` is first-class; add/sample use it.

## Release and CI

- Shipping is PR-BASED (user decision 2026-07-18, supersedes the direct-push-to-main flow used through 0.18.0): completed work reaches main only through a pull request. Flow: work on a branch, commit there, push the branch, open a PR (`gh pr create`), make CI pass, handle every review comment, merge when all clear. Never push work directly to main.
- The npm package ships TypeScript SOURCE with a bun-shebang bin (`bin: ./src/main.ts`, exec bit committed to git). Compiled-binary distribution is deleted: 0.2.0 shipped a 61MB darwin-arm64 Mach-O to every platform and died on Linux with `exec format error`, and per-platform compiled packages would each need their own trusted publisher.
- `installSupervisor` always writes the 2-line `exec <bun> run <realpathSync(Bun.main)>` shim (realpath resolves the `~/.bun/bin/tokenmaxxing` symlink into the installed package tree so imports resolve). The self-copy + codesign path is gone.
- Release flow: bump `package.json` version, land it on main via the PR flow above, `gh release create v<version>`; `.github/workflows/ci.yml` publishes via npm trusted publishing (OIDC; the registered publisher is anaclumos/tokenmaxxing + `ci.yml`, and the workflow filename must match exactly). ci.yml guards that the release tag equals `v<package.json version>`.
- Hard-won CI facts (verified against official docs 2026-07-09): trusted publishing needs npm >= 11.5.1, so node 24 via setup-node@v6 (ubuntu-latest's default node 22 bundles npm 10.9.8, silently too old); `id-token: write`; GitHub-hosted runners only; provenance automatic. `bun publish` has NO OIDC support as of bun 1.3.14 (oven-sh/bun#15601, PR #30522 unmerged), so the publish step must be `npm publish`.
- `bun add -g <local .tgz>` over an existing same-name global errors `DependencyLoop`; `bun remove -g` first.
- Commit often: small commits for small changes, conventional-commits style with a detailed body, no Co-Authored-By trailer. Commit after each verified milestone and push the work branch; do not sit on a finished diff. Merging to main goes through the PR flow, never a direct push.
- Stage only your own hunks: on a co-edited file extract your hunk with `git apply --cached`, never stage the whole file (whole-file add is fine only for files this session created). Inspect `git status` and `git diff --cached` untruncated immediately before committing.
- Never force-push and never amend a pushed commit. On any concurrent-commit signal (rejected push, unexpected remote sha, staged hunks you did not write), stop and ask.
- Never commit temporary artifacts (captured statusline output, logs, scratch dumps); write them to the session scratchpad with absolute paths, and `trash` any that land in the worktree.
- Run `bun run typecheck` and `bun test` before committing, and run every script or check you add or change once before committing; an unexecuted script is unverified. After a decision-path change, also re-run the standalone swap-concurrency E2E (see Outstanding test debt).
- When a change alters CI or operational semantics (release flow, hooks, timers, install paths), update this file and DESIGN.md in the same commit.

## Claude Code auth and quota internals (verified)

Verified against Claude Code 2.1.204-2.1.207 and Codex CLI 0.143.0 (rust-v0.143.0 source). Both CLIs change monthly: re-verify before trusting in a later month.

- macOS: creds live in the Keychain, generic-password, service `Claude Code-credentials`, account `$USER`. There is no `~/.claude/.credentials.json` on macOS.
- Linux (binary-verified 2.1.205 native ELF + strace): the build is compile-time specialized; the credential-storage selector returns the plaintext-file store unconditionally and the keychain prefetch is a stub (no keyring/libsecret path). Creds file = `<credDir>/.credentials.json` (mkdir + write + chmod 0600), where credDir = `CLAUDE_SECURESTORAGE_CONFIG_DIR ?? CLAUDE_CONFIG_DIR ?? ~/.claude` (SECURESTORAGE checked FIRST, empty string falls through, `.normalize("NFC")` applied). No hash-namespacing on Linux: `CLAUDE_CONFIG_DIR` isolation is just the file inside that dir. `.claude.json` = `$CLAUDE_CONFIG_DIR/.claude.json` else `~/.claude.json` on both platforms.
- Setting `CLAUDE_CONFIG_DIR` on macOS namespaces the Keychain service to `Claude Code-credentials-<first 8 hex of sha256(NFC(raw env string))>`. The hash is over the RAW string, so the path must be byte-stable (trailing slash or `~` vs absolute yields a different entry). A missing namespaced keychain item does NOT fall back to the un-suffixed live item: it falls back to `<CLAUDE_CONFIG_DIR>/.credentials.json` then `{}` (binary-verified), so isolation is sound once the env is clean.
- Account identity sits in `.claude.json` `oauthAccount`; quota is metered server-side per `organizationUuid`.
- HOT-SWAP ADOPTION (corrected 2026-07-10 after the user's live observation exposed a wrong recorded verification; mechanism confirmed in 2.1.204/205/206 alike): a running claude session DOES adopt an externally swapped credential on both platforms, without restart. Every ensure-fresh call starts with a freshness poll: Linux mtime-stats `.credentials.json` and hard-flushes all token caches on change (no throttle); macOS clears the token memos and re-reads the keychain through a raw 30s cache, comparing accessToken. That poll runs at every inference-client creation (the query loop creates the client on the first attempt of EVERY request and recreates it on 401/407/connection-reset) and on every firstPartyApi call with refreshOAuth (including in-session `/usage`). Net adoption: the first request >= 30s after the last raw keychain read on macOS; the next request on Linux. Near-expiry refresh margin is 300s (not 120s), and the refresh path resolves races by adopting a mid-flight external write. A 401 (or 403 "OAuth token has been revoked") force-flushes the 30s cache and adopts immediately. A 429 never invalidates the token, but only the currently-retrying request keeps its snapshotted old token (429 retries reuse the same client); the session's next request adopts the swap. In-session `/usage` shares the exact token caches inference uses, so its account display flips with adoption, and within any 30s window `/usage` and inference necessarily hold the same token.
- Swaps must still run under claude's refresh lock, and a near-expiry session can refresh-write its own account's rotated token into the live store at any time, so harvest-by-true-owner stays mandatory.
- The default keychain item (`Claude Code-credentials`, unnamespaced) is shared by ALL default-profile sessions, so one swap migrates every session.
- There is NO `CLAUDE_CODE_DISABLE_HOOKS` env/flag. `--bare` disables hooks but also kills keychain reads; use `--settings '{"disableAllHooks":true}'` to disable hooks for a nested call.
- statusLine stdin carries `rate_limits`; Stop hook stdin does not. Feed usage via the statusLine shim writing a state file.
- Primary quota source (canonical, user-decided 2026-07-09): `claude -p '/usage'` (free, `num_turns:0`, 0 tokens), run in a throwaway `CLAUDE_CONFIG_DIR` for parked accounts. The direct `GET api.anthropic.com/api/oauth/usage` (Bearer, no beta header; response `limits[]` with `kind` in session|weekly_all|weekly_scoped, `percent`, ISO `resets_at`, per-model rows named by `scope.model.display_name`) was tried and REJECTED by the user: it 429s when the account being sampled is the token running the current session, and it is "the web one"; the user's steer is to fix the CLI method, not bypass it. `/usage` is just a renderer over that same endpoint (verified in the 2.1.205 bundle).
- Two real gotchas of the `/usage` CLI method: (1) it is fail-silent: when claude's internal usage fetch errors/429s, `/usage` prints only local session stats with NO percentage lines, so the ACTIVE/busy token yields nothing; sample the active account from the statusLine `usage.json` push, never by probing its own token. (2) Reset times are human-formatted (`resets Jul 13 at 11:59pm (Asia/Seoul)`); parse them to epoch via `parseResetClock` in usage.ts (month/day + h[:mm]am/pm + IANA tz, year inferred nearest-to-now, zoned-wall-to-epoch via Intl offset).
- `status --force` ping mechanics (built + live-verified 2026-07-16): `/usage` is free and starts NO window; one minimal metered request (`claude -p "Reply with exactly: ok" --model haiku`, ~27k input tokens of system prompt, `--tools ""` does not shrink it) opens the account's 5h session window at that instant - verified live, windows later showed `resets in 4h50m` anchored at the ping. The `haiku` model alias works on 2.1.207 even though `--help` lists only fable/opus/sonnet; haiku is the cheapest tier and has no per-model weekly cap, so a ping never nudges a switch-gating window. GOTCHA: the server usage feed reflects a freshly opened window with a lag (somewhere between ~10s and a few minutes), so a `/usage` probe seconds after the ping still shows the dormant pre-ping session row; status renders a "usage feed lags" note instead of pretending the ping failed. There is NO `--max-turns` flag on 2.1.207.
- Probe env MUST scrub these (claude reads them BEFORE the keychain, so an inherited value would attribute the probe to the wrong account): `CLAUDE_CODE_OAUTH_TOKEN` (checked first, memoized per process), `CLAUDE_SECURESTORAGE_CONFIG_DIR`, `CLAUDE_CODE_SUBSCRIPTION_TYPE`, `CLAUDE_CODE_RATE_LIMIT_TIER`, `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`.
- Token identity ground truth: `GET api.anthropic.com/api/oauth/claude_cli/roles` (plain Bearer) returns `{organization_uuid, organization_name, organization_role, ...}` = the org the token ACTUALLY belongs to. This is tokenmaxxing's identity guard (`fetchTokenOrg`) after the 2026-07-09 contamination incident. Labels drift; only the token API is authoritative.
- OAuth refresh: token endpoint `https://platform.claude.com/v1/oauth/token` (migrated from console.anthropic.com), client_id `9d1c250a-e61b-44d9-88ed-5944d1962f5e`, JSON body, no auth/beta headers.
- ToS note: consumer-OAuth server enforcement (2026-01) restricts some raw-token endpoints (e.g. `/api/claude_cli_profile` 403s "OAuth authentication is currently not allowed"). The tool relies on the CLI `/usage` method described above rather than direct API calls.
- `claude setup-token` / `CLAUDE_CODE_OAUTH_TOKEN` was investigated and ABANDONED 2026-07-09; do not revisit without solving usage. The setup-token (`sk-ant-oat01-`, 1yr, non-rotating, precedence above keychain, meters against the subscription) would kill reauth churn BUT is inference-only scoped and verified (real token, 2.1.205) to break monitoring: `claude -p '/usage'` returns the headless cost footer with NO rate-limit percentages. Verified-good under the token: precedence over keychain, no keychain mutation, no rotation collision (5/5 parallel probes). Stay on keychain-swap.
- Claude's background daemon bypasses PATH shims (observed on the ARM Linux box 2026-07-10): `claude daemon` / `bg-pty-host` sessions spawn the REAL versioned binary by absolute path (`~/.local/share/claude/versions/<v>`), so they never pass through the supervisor; bg sessions are unsupervised (hooks still fire via settings.json; on Linux adoption + the periodic timer cover switching, but there is no marker-driven respawn). Long-lived bg processes keep running an OLD version after an auto-update. A supervisor auto-`--resume` can collide with a bg fork of the same transcript and exit immediately; the `supervisor.exit` log (added 2026-07-10) records child exit code/signal for diagnosis.

## Codex internals (verified for 0.13.0)

Verified 2026-07-16 against openai/codex tag rust-v0.144.5 source (auth moved to a `login/` crate, config to a `config/` crate), the local 0.144.4 binary's embedded wire schemas, the official hooks docs (developers.openai.com/codex redirects to learn.chatgpt.com/docs), and one live read of the usage endpoint. Codex changes monthly: re-verify before trusting in a later month.

- Creds in `$CODEX_HOME/auth.json` (0600; default `~/.codex`). Store mode config key is now `cli_auth_credentials_store_mode` (file/keyring/auto/ephemeral, default auto = keyring-if-available); the keyring entry is service "Codex Auth", per-home hash-namespaced. tokenmaxxing REQUIRES file mode (`init --codex` fails fast on a keyring pin; `add --codex` writes `cli_auth_credentials_store_mode = "file"` into the onboard home's config.toml so the isolated login lands harvestable). auth.json shape: `tokens {id_token, access_token, refresh_token, account_id?}`, `last_refresh`, plus siblings (auth_mode, OPENAI_API_KEY possibly null) preserved verbatim on round-trip. Identity claims live in the id_token payload under the `https://api.openai.com/auth` claim (chatgpt_account_id, chatgpt_plan_type); `tokens.account_id` is the explicit copy.
- HOT-SWAP IS STILL IMPOSSIBLE: `AuthManager.reload_if_account_id_matches` skips a reload when auth.json now names a different account ("you have since logged out or signed in to another account"). RESTART IS THE SWITCH; `codex resume <session-id>` / `resume --last` / `codex exec resume` continue the local transcript on whatever account auth.json now holds. Re-verified in depth at rust-v0.144.5 (2026-07-16, 6-agent source sweep incl. two adversarial passes): ONE AuthManager per process (`app-server/src/in_process.rs` bootstrap, shared by tui/exec; `/new` reuses it), NO file watcher or reload timer anywhere in codex-rs, per-request tokens come from the in-memory cache, and the near-expiry refresh runs the guarded reload FIRST - on cross-account mismatch it errors permanently WITHOUT refreshing (error swallowed to logs; the session limps on its stale token until a server 401 surfaces "Please sign in again"), so a post-swap session cannot rotate the harvested account's token via the refresh path. CAVEAT from the adversarial pass: the ChatGPT Apps/connectors surface (Feature::Apps, default-enabled) builds THROWAWAY AuthManagers that fresh-read auth.json on every `/new` and `/apps`, sends backend GETs under the swapped-in account's Bearer, and can proactively refresh-and-persist that account's rotated refresh token outside tokenmaxxing's codex flock. Inference identity still never flips, but "idle tui touches no tokens" is FALSE: read the live blob fresh at the last moment, persist rotations instantly, and treat harvest-vs-inflight-rotation as a real (narrow) race.
- Refresh: POST `https://auth.openai.com/oauth/token`, client_id `app_EMoamEEZ73f0CkXaXp7hrann`, JSON body, no auth headers. Proactive margin 5 minutes to JWT exp OR last_refresh older than 8 days. The refresh_token ROTATES and reuse of a superseded one is punished (`refresh_token_reused/expired/invalidated` all = dead grant), so harvest-by-true-owner is mandatory and every rotation must be persisted immediately. There is NO cross-process lock on auth.json (in-process semaphore only): tokenmaxxing's codex flock serializes only tokenmaxxing actors, and swaps happen at idle turn boundaries where the running codex has just finished with (and if needed refreshed) its token.

## Codex architecture (0.13.0)

## Codex decision invariants (0.13.0 adversarial review, 2026-07-16)

Each guards a confirmed pre-ship finding. Preserve all of them.

- The current account is ALWAYS the live auth.json's own identity (`liveCodexAccountId`), never the stored `activeAccountId` label. Trusting the label once let the decision target the RUNNING account: performCodexSwap would refresh its superseded parked token (reuse punishment kills the grant family) and rotate the live token out from under the session. `performCodexSwap` also backstops this: it refuses a target equal to the live identity.
- `performCodexSwap` resolves and validates the live owner BEFORE the network refresh, and persists the target's rotation to its parked file the INSTANT the refresh returns. A refusal (or crash) after a rotation but before persistence strands a reuse-punished token.
- PRESENCE FILES (`codex-live/<supervisorId>` = {accountId, pid, ts}; PID-validated, dead entries auto-cleaned): each supervisor declares its session's account at every (re)spawn. A present account is NEVER a swap target (picker paths filter through `targetableCodexAccounts`) and its parked blob is NEVER refreshed by the sampler: under concurrency, "parked" does not imply "not running" (a swap respawns only the deciding session; siblings keep their account and keep rotating its token).
- The codex greedy path carries a RESPAWN-COST margin (`CODEX_SWAP_IMPROVEMENT` 1.2 in codexpick.ts): engagement is chronic on weekly-only plans, and every greedy swap visibly restarts a live session, so a challenger must beat the seat's pace pressure by 20%, not by a hair. The hard path (crossed bar) ignores the margin.
- No depleted pre-park, 45s cooldown, dead-grant re-rank loops terminate via persisted needsReauth: all mirrored from the claude invariants.
- Error-shape rule (repo-wide since 0.13.0): HTTP error bodies from token/usage endpoints are NEVER surfaced raw. `safeErrorDetail` (http.ts) allowlists error/error_description/detail/message; a token endpoint's failure body can echo request material.

## Switch policy and per-model limits

- Switch targets the account FURTHEST BEHIND ITS OWN WEEKLY PACE (user decision 2026-07-13, superseding the 2026-07-10/12 soonest-expiry policy). The user asked for a pace ratio (actual used % over expected % for elapsed window time) and delegated improving the equation; the shipped metric is the forward-looking equivalent, `pacePressure` = remaining% / time-to-weekly-reset, highest first. Same use-it-or-lose-it rationale (weekly allowance is forfeited at a fixed per-account reset, support.claude.com article 11049741): the highest-pressure account is the one most quota is about to be wasted on. The raw backward ratio was rejected because it blows up right after a reset (expected ~0) and ignores how much quota is at risk; pressure strictly refines the old policy (equal remaining = soonest expiry first, equal expiry = most remaining first). Still NOT most-remaining-first in general.
- Bare `xx switch` is GREEDY and IDEMPOTENT: rank every account (current included) by pace pressure among those with every window under its screening bar (session 95 / weekly 98); if the current account already wins, do nothing. It can therefore run periodically and converge. It decides entirely off cached per-account windows: cached resetsAt values are absolute UTC epoch ms, weekly resets extrapolate forward in exact 7-day steps on the fixed anchor, and a session window past its cached reset counts as empty.
- The hooks/timer path (`evaluateAndMaybeSwap`) shares those greedy semantics since 2026-07-16 (user decision: "if there is a more greedily available underused account, we should switch often"). It ENGAGES once the active session window reaches `policy.greedySessionFloor` (default 50) or the active account crosses any screening bar. Engaged-but-under-every-bar = the greedy path: `currentWins` (picker.ts, shared with bare switch) keeps the seat on best-or-tie, otherwise `chooseAndSwap` onto the strictly better account; it NEVER depleted-waits or pre-parks (a usable current account must not be traded for a wait). Over a bar = the hard path, unchanged (swap away or depleted-wait). Below the floor the decision does not run at all: a fresh session rides its account.
- `pickBest` in `src/lib/picker.ts` filters usable accounts (no reauth, not exhausted) and sorts by `pacePressure` descending (a rolled-over cached week counts as fresh 100% remaining; never-sampled or no reset anchor = pressure 0, ranks last), tiebreak soonest `weeklyExpiry` then lowest 7-day usage. `ctx.currentAccountUuid: null` ranks everyone (bare `xx switch` and decide's `currentWins` seat check); non-null excludes the active account (`chooseAndSwap`), which MUST keep excluding it because a per-model-cap trigger leaves the active account aggregate-usable (in the greedy seat check the same protection comes from `currentWins` requiring the active account to pass `isExhausted`, whose gated families cover the burnt cap). Every PickCtx and trigger floor is built from `effectiveBars(cfg)` (thresholds minus projectionMargin): ONE bar per window for trigger and screening alike, otherwise a margin-triggered swap lands on an account inside the margin band and ping-pongs on the cooldown beat.
- Claude subscription quota has THREE limits (confirmed via `/usage` 2026-07-09): current session (5h rolling; statusLine `rate_limits.five_hour`), current week all models (7-day aggregate; `rate_limits.seven_day`), and current week per-model. The per-model cap is NOT in statusLine stdin; it comes only from `claude -p '/usage'`, polled TTL-cached when the active model is capacity-constrained. The hard path fires if session >= thresholds.session (95) OR week-all >= thresholds.weekly (98) OR week-(active model) >= thresholds.weekly; candidate screening (isExhausted/usableAt) applies the same per-window bars (both sides through `effectiveBars`), and the greedy path usually swaps long before any bar via `policy.greedySessionFloor`.
- Per-model weekly caps currently exist ONLY for Sonnet and Fable; there is NO Opus-only quota, and only Fable's cap matters for switching (user's claim 2026-07-12: "we only care about Fable"; "fable = need to switch, sonnet = ok"). `policy.switchModels` defaults to `["fable"]` (state.ts DEFAULT_CONFIG, changed 2026-07-12). The per-model cap bites well before the aggregate: this machine sat at 50% week-all while at 80% week-Fable.
- MODEL-NAME MATCHING TRAP: statusLine `model.display_name` is VERSIONED for Opus (`"Opus 4.8"`, id `claude-opus-4-8`) but BARE for Fable (`"Fable"`). Any exact-match gate on lowercased display names silently excludes Opus; that was the root cause of the 2026-07-09 ARM-box depletion (Opus weekly drained to 100%, 14x "You've hit your weekly limit" over Jul 8-9, zero auto-switch, model-usage.json never created). Match by family substring/prefix, never exact display string.
- `/usage` per-model rows may not list Opus at all: every captured output shows only `Current week (Fable)`, even while an Opus weekly cap was the binding drained limit. All captured probes were of accounts at 0% Opus, so it is UNVERIFIED whether the Opus row appears once real Opus consumption exists; probe an account with known Opus usage before trusting `/usage` as an Opus-cap source.

## Decision-path invariants (v0.6.1, 2026-07-12)

Each guards a verified live failure. Preserve all of them.

- `loadFreshSnapshots` (decide.ts) is the ONLY snapshot loader for decisions: one `/usage` probe refreshes BOTH usage.json and model-usage.json when the tee is absent, org-drifted, or older than `usagePollTtlMs`. The original bug: cold-start discarded perModel and stamped model:null, so `needsPerModel` gated off and the ARM box ignored Fable 95/95 for 9+ hours of checks.
- Unknown model (`model: null`) gates EVERY `switchModels` family; a known-unconstrained model gates none ("fable=switch, sonnet=ok" survives). Never "restore" the old matchedFamily-only gate.
- usage.json freshness = file MTIME, not the embedded ts: `writeUsage`'s write-on-change suppression bumps mtime (utimesSync) as the tee's liveness heartbeat. Judging by ts made a live Sonnet session look headless for up to 8.5 of every 10 minutes.
- Per-model caps of gated families count in `isExhausted`/`usableAt` (PickCtx.switchFamilies). Without this an all-Fable-burnt pool round-robin swaps; with it, live-verified: the cascade across the four accounts correctly skipped the fable-burnt one.
- 45s POST_SWAP_COOLDOWN in `evaluateAndMaybeSwap`: a model-blind evaluation right after a model-aware swap otherwise undoes it (A/B respawn loop).
- Depleted-path pre-parking (swapping onto a still-blocked soonest-recovering account) happens only when `anticipatory` (the supervised Stop hook with a session id, the only caller whose respawn marker pauses until reset). Timer/SessionStart stay put; the normal pick path adopts the target once its reset passes.
- The greedy path (engaged, under every bar) never reaches the depleted logic: `currentWins` keeps the seat, else swap onto the strictly better account, else `no-usable-target` and stay put. Only the hard path (a screening bar crossed) may depleted-wait; anything else trades a working session for a wait.
- The greedy path does NOT use `chooseAndSwap`: its dead-token fallback lands on the next usable candidate unconditionally, which is right when over a bar but wrong when the current account is healthy - a dead grant on the winner would bounce the session onto a pace-worse account and back (adversarial review catch, 2026-07-16). The greedy loop re-checks `currentWins` after every `InvalidGrantError` (performSwap persists needs-reauth before throwing, so each reload shrinks the candidate set and the loop terminates). E2E test 9 pins this.
- Unknown-reset blocked windows self-bound at sampledAt + window duration (5h/7d); no permanent bench, no waitUntil=now churn.

## Supervisor recursion guards (v0.6.2)

- Incident (2026-07-13 user report, on 0.6.1): unbounded wrapper recursion. A v0.4.0-era install had pinned a shim as config.json claudeBin; the supervisor spawned it, the shim resolved `claude` from PATH back onto the wrapper, forever (~1800 bun processes, ~10/sec). Reproduced on HEAD via a bounded shim harness. Most plausible poisoning: tokenmaxxing's own stale wrapper; `ensurePathInRc` marker-idempotency keeps an OLD binDir on PATH after a `TOKENMAXXING_HOME` relocation, and init's PATH scan (exact-string binDir skip) pinned that stale wrapper. `TOKENMAXXING_PROBE` never prevented spawning, only session management. The 60s probe killer was defeated because descendants inherit the stdout pipe and `new Response(p.stdout).text()` waits for ALL holders.
- Root lesson: every guard was existence-based; nothing validated that "the real claude" actually was claude, and no spawn path was depth-bounded.
- The 0.6.2 layered guards: (a) `TOKENMAXXING_WRAP_DEPTH` env sentinel, supervisor aborts at 5, both spawn arms tag depth+1; (b) `resolveRealClaude` rejects candidates whose realpath parent is realpath(binDir); (c) `probeUsage` presets depth to the cap (a probe must never re-enter the wrapper); (d) `verifyRealClaude` (`--version`, 15s timeout, must print /claude/i) gates init pinning (`resolveVerifiedClaude` walks ALL PATH candidates) and doctor; (e) probe pipe reads race child-exit + 2s grace.
- User aliases like `cc`/`cco` with plain-`claude` bodies are supervised via PATH and fine; doctor warns on `alias claude=` / `claude()` shadowing and absolute-path bypass aliases.
- When adding ANY new spawn of "the real claude": spawn `resolveRealClaude()` output, and preset the depth cap if that path must never re-enter the wrapper.

To update a box: `bun remove -g tokenmaxxing && bun add -g tokenmaxxing@<ver>`. Shim paths survive the reinstall; running supervisors pick up new code on next spawn (hooks/statusline spawn fresh per invocation).

## Machine and environment gotchas

- On the user's Mac, `rm` is aliased to `rm -i` (zsh profile). In a non-TTY shell the confirmation prompt gets EOF, `rm` deletes nothing, and it still exits 0, so `rm file && echo ok` lies (this broke the claude-hud removal on 2026-07-11). Always pass `-f` (or use `command rm`) when deleting files in Bash tool calls on this machine, and verify the path is gone afterward.
- macOS has no `/bin/true` (only `/usr/bin/true`); use `/usr/bin/true` in tests (it exists on macOS and usr-merged Linux). Incident 2026-07-12: a swap e2e seeded `claudeBin: "/bin/true"`, `resolveRealClaude` fell through to its PATH scan (whose recursion guard only skipped the relocated test binDir), resolved the user's real installed wrapper, and spawned a forever-hung `/usage` probe that wedged the e2e for 15+ minutes. Fixes: `resolveRealClaude` now throws on a configured-but-missing claudeBin instead of PATH-scanning, and `probeUsageOnce` kills the child after 60s (PROBE_KILL_MS). Caveat learned 2026-07-13: the 60s kill alone was NOT sufficient (descendants inherit the stdout pipe and the read blocked past the kill); see the v0.6.2 recursion guards above.
- Piping macOS tar into a Linux container creates AppleDouble `._*.test.ts` files that `bun test` executes; use `COPYFILE_DISABLE=1`.
- macOS 26 recurring TCC dialogs "bun would like to access data from other apps" (first reported 2026-07-12) come from the tokenmaxxing periodic check: the `com.tokenmaxxing.check` launchd agent fires every 180s and runs the check via the dev shim, whose root executable is plain `bun`, so macOS attributes every TCC request from the job (including children) to "bun". The check spawns `claude -p /usage --output-format json` nearly every run (`usagePollTtlMs` 90s < 180s interval), and the claude CLI is known upstream to touch other apps' protected data (anthropics/claude-code issues #63130, #36832, #36675: unstable per-version binary identity, no app bundle). The system TCC db has bun listed in Full Disk Access but toggled OFF, so App Data prompts keep re-firing (the user-level `kTCCServiceSystemPolicyAppData` row, auth_value 5, does not stop them). Fix: toggle `bun` ON in System Settings > Privacy & Security > Full Disk Access. Scoped alternative: install a compiled tokenmaxxing binary signed with a stable (non-ad-hoc) identity + Info.plist and grant that FDA instead. Clicking Allow on the dialog does not durably persist for path-identified CLI clients.
- Shell commands: atomic, small, readable; no long chained one-liners. On zsh, quote args and use `command <tool>` when an interactive alias could interfere (see the `rm -i` bullet above).
- Run long steps (10+ minutes) in the background from the start with a hard time bound in the command itself (`gtimeout N ...`); keep quick probes in the foreground. Verification commands must surface real exit codes: never pipe through `| tail` or append `; true`.
- Drive interactive CLIs (claude included) from non-TTY shells inside tmux (capture-pane / send-keys), never by piping newlines.
- Watcher and poll loops you start surface errors as events (never swallowed with `2>/dev/null ... || true`), abort visibly after ~3 consecutive failures, cover every terminal state, and are never trusted as armed until confirmed to be a live process.
- When uninstalling or relocating tooling, check the shell rcs for stale init and PATH blocks; they do not auto-remove, and a stale `# tokenmaxxing PATH` line pointing at an old binDir is exactly how the supervisor recursion incident started.

## Mistakes I have made

When the user is unhappy with a mistake, record it here in this same bullet style so it is not repeated.

- Re-ran a live interactive PTY test after the user had already declined it. Respect a rejection the first time.
- `installSupervisor` copied the running binary onto itself (`copyFileSync(self, target)` with `self === target`), truncating and destroying the installed binary. Guard self-referential file operations.
- `init` re-imported the "current account" from `~/.claude.json` `oauthAccount` and parked the live credential under it, assuming `oauthAccount` matches the live keychain credential. After swaps they diverge, so this clobbered a parked backup. Do not assume identity files agree with credential stores; make destructive commands idempotent and fail-fast on drift.
- Shipped the keychain write over `security -i` without verifying its line-buffer limit, then a real 4.3KB blob truncated silently. Verify external tool limits with a real-sized payload before relying on them.
- Installed the compiled binary by `copyFileSync` alone. macOS AMFI SIGKILLs (exit 137) a copied ad-hoc-signed Mach-O because the copy gets a `com.apple.provenance` xattr and the signature stops validating. After copying a Mach-O on macOS, `xattr -c` + `codesign --force --sign -` it. A byte-identical copy is not a runnable copy on macOS.
- Declared "no contamination" after seeing distinct parked-credential hashes and ~1-minute-different `/usage` reset clocks. Distinct blobs do not prove distinct accounts: two rotations of the SAME account's token differ byte-for-byte. Verify a credential's true owner via the roles endpoint (`fetchTokenOrg`), never by comparing blobs.
- `performSwap` harvested the live credential into whatever account `accounts.json` labeled active. Labels drift from the live blob (kill mid-swap before `saveAccounts`, manual `/login`), and one drifted harvest overwrote another account's backup, destroying its only credential. Park a credential under its token's API-reported identity, and commit the active label inside the same critical section as the credential writes.
- Wrote an em-dash in a ci.yml comment and in package.json's description. The em-dash ban covers every file (comments, YAML, JSON strings) AND chat replies, not just repo prose; grep changes for `—` before finishing.
- Told the user "a running macOS claude does NOT hot-swap on a credential swap" from a recorded verification that was wrong (the per-request ensure-fresh poll existed in every version checked). The user's live observation contradicted it and the user was right. When an observation contradicts a recorded verification, re-verify against the current binary instead of explaining the observation away.
- Ran `status --force` against the live Mac pool as "verification" without asking, pinging all 8 real accounts and starting their 5h session timers. A feature request is not permission to spend real quota or mutate live account state; verify with hermetic tests, and ask before any live run that meters an account or starts a window.
- Kept shipping through repeated concurrent-work signals during the 0.19.0/0.20.0 release: a foreign commit appeared on my branch and foreign edits kept landing in my worktree, and I still committed, pushed, and worked the PR on the strength of an earlier "proceed". A prior go-ahead does not cover collision evidence that arrived after it: every NEW signal of concurrent work freezes all git actions (commit, push, merge, release) until the user rules; file edits wait uncommitted.
- Staged whole co-edited files (test assertions and a MEMORY.md correction someone else wrote into the shipping worktree mid-task) and committed + pushed them before asking. A foreign edit appearing in the working tree DURING a task is a concurrent-work signal like any other: stop and ask at that moment, and stage only your own hunks; "the content looks like it was meant for my PR" is a judgment the author makes, not me.
- Wrote "0.19.0 RELEASED" into the memory index inside the version-bump commit, before the release existed, and pushed it. Never write a completion claim (RELEASED, done, verified) into memory or docs ahead of the command output that proves it; record in-flight states as in-flight and flip them only after first-hand proof.
- During the same ship, two sessions edited this thread's worktree concurrently and a commit on the branch bundled the other session's pending hunks whole. On the FIRST foreign edit or unexpected commit inside your own session's worktree or branch, freeze all git actions (no staging, no commits, no pushes) and ask; do not keep preparing a commit around the collision.
