# Agent rules

Repo-specific rules only. The owner's global rules load alongside this file in every session, so nothing here repeats them; where this file is silent, the global rule applies. Long-form detail lives in `DESIGN.md` and `docs/content/docs/`. New lessons belong in `.cursor/rules/` under the owner's 2026-09-10 instruction. Existing `.memory/` links are historical references, not an active write surface.

## The project

tokenmaxxing pools the owner's own Claude Code and Codex logins, starts each session on its own pooled account, moves a session to a fresher account as its account nears the 5-hour or weekly limit, and keeps sessions continuable across moves. Design: `DESIGN.md`. User docs: `docs/content/docs/`.

No external installed user base, so this is pre-production code: delete old-state compatibility rather than carry it forward.

## Safeguards and machine gotchas

- Resolve the installed entry point before assuming a checkout is the active runtime.
- This machine runs live supervisors, hooks, the periodic check, and the owner's real claude sessions. Stop processes by PID, and never kill a running session or supervisor to free a resource without asking.
- The owner's hosts are managed environments: never run `init`, `add`, `auth`, `uninstall`, or anything that writes settings.json, launchd/systemd units, shell rc, or the global package on a live host (owner, 2026-08-30). Ship code; activation is the owner's step.
- This working tree is a shared checkout (the owner and other agents work in it live). Stage commits by explicit path, never `git add -A`/`-u` (hook correction, 2026-08-30).
- No dynamic workflows on this repo: never orchestrate through the Workflow tool or any scripted fan-out. Spawn every subagent by hand, one deliberate Agent call per subagent with a prompt crafted for that task (owner, 2026-09-10).
- Never print credential material: keychain blobs, `.credentials.json`, `auth.json`, OAuth access or refresh tokens. Report account labels and status only. A ky error carries its request, Authorization header included.
- Ask before any run that meters real quota or opens a session window (live-pool runs). Free `/usage` reads are fine.
- This repo is PUBLIC. The no-Slack-info and no-device-info rule covers PR bodies, commit messages, review replies, release notes, and docs, not just `.memory`.
- Pool account labels are personal data, the same as emails and organization names: the owner names seats after people. Never paste `status`, `doctor`, or log output that carries labels, emails, or org names into a PR body, commit, review reply, doc, memory, or subagent prompt. Mask or count them ("six team seats", "15 accounts") the way emails are masked (owner correction 2026-09-06).
- `rm` is aliased to `rm -i` on the owner's Mac. In a non-TTY shell the prompt gets EOF, nothing is deleted, and it still exits 0, so `rm f && echo ok` lies. Deletion is the owner's call except for artifacts this session created; when you must, pass `-f` and verify the path is gone.
- macOS has no `/bin/true`. Use `/usr/bin/true` in tests.
- Env overrides parse through zod at the read site rather than a central `env.ts`, because the CLI's knobs are all optional. Unset parses to undefined and the feature degrades there.
- State files that exist but fail to parse THROW. A truncated `accounts.json` read as an empty pool once let `init` overwrite it.
- A configured-but-missing path (`claudeBin`, `codexBin`, credential locations) fails fast. Never fall through to a PATH scan: seeding `/bin/true` as claudeBin made the scan resolve the real installed wrapper and wedge an E2E for 15 minutes, the same shape that fed the runaway-recursion incident.
- For platform-specific behavior differences, compare the installed package versions before attributing the difference to the platform.
- Core deps are zod, es-toolkit, and ky. The global default stack does not apply (there is no date-fns here, date math goes through `Intl` in `parseResetClock`).
- Keep `node:fs`, which is Bun-native. `Bun.file`/`Bun.write` are async-only, non-atomic, and have no create-mode, so they cannot serve the 0600 credential store or the flock fd. When asked to simplify this, that is the answer.

## Credentials and identity

- One Claude Code credential store per pooled account, `stores/<uuid8>/`, never one per session (#79, 2026-09-12). A session runs on an account because the supervisor set `CLAUDE_SECURESTORAGE_CONFIG_DIR` to that store at spawn; the seat is fixed for the life of the process, and hooks, the statusline, and the CLI read it from the inherited variable (`seatFromEnv`), never from `~/.claude.json`, which Claude Code rewrites after whichever session refreshed last. `activeId` stays `null` for both pools.
- One Codex credential store per pooled account, `codex-stores/<uuid8>/`, never one per session. A session runs on an account because the supervisor set `CODEX_HOME` to that store at spawn; the seat is fixed for the life of the process, and the hook reads it from the inherited variable (`codexSeatFromEnv`). The store holds only `auth.json`: everything else is a symlink to the matching entry in the shared `~/.codex`, so sessions, history, and config stay shared and `codex resume` works across stores.
- tokenmaxxing writes a store once, at onboarding (`init`, `add`, `auth`: isolated login, owner verified through `fetchTokenIdentity`, harvested into the store), and never again. Claude Code's own refresh is the only writer afterwards, under the refresh lock it roots at the store, with its compare-and-swap on the refresh token. There is no tokenmaxxing refresh grant, no harvest, no park, no install, and no `withClaudeRefreshLock` outside the onboarding reread. Never copy a credential between stores or between hosts: a refresh rotation revokes the previous access token of that grant (verified 2026-09-06), so the other copy 401s, force-refreshes a superseded refresh token, gets `invalid_grant`, and Claude Code dead-clears it. Separate logins are separate grants and do not interfere, which is why the same accounts can be pooled on several hosts by logging in on each (`docs/limitations.mdx`).
- Identity is the `accountUuid` that `fetchTokenIdentity` reports for a token (`GET /api/oauth/profile`), never the organization, never a stored label, and never a blob comparison. Team seats share one `organizationUuid`, so an org-keyed lookup collapses every seat onto the first one in the array (2026-09-06). The check runs at onboarding (a login whose token belongs to another account than its identity file names changes nothing) and in `doctor`; a probe under a store needs no check, because only Claude Code writes the store.
- `isDeadCredential` (empty `accessToken` or `refreshToken`) is the one dead-grant signal: a dead store stamps `needsReauth` and the decision tries the next candidate (`InvalidGrantError` classifies as `dead-grant`); a missing or unreadable store is `StoreUnusableError`, skipped for the evaluation only (the `rejected` set in `decide.ts`). The set narrows only the candidate list, so one bad store never aborts an evaluation (the 2026-09-06 livelock).
- Claude Code hashes the NFC-normalized `CLAUDE_SECURESTORAGE_CONFIG_DIR` into the macOS keychain item name whenever that variable is set, even with `CLAUDE_CONFIG_DIR` also set (2.1.269 binary, `xSe`); `isolatedTarget(storeDir)` names the same item. A missing namespaced item never falls back to the default one, so isolation is sound once the probe env is scrubbed and the intended store is set.

## Switching

One rule (#81, 2026-09-12; per-session seats since #79): under both bars the seat holds; at or over a bar, `pickBest` ranks the usable candidates and the session moves by respawn under the winner's store; with nothing usable, the depleted-wait path resumes on the soonest reset within `policy.maxWaitMs`. The same ranking places a session at launch (`pickSeat`). Claude ranking (consult verdict for #79): `seatHeadroom`, `(session bar - session used) / (live sessions + 1)`, highest first, then `pacePressure` (remaining percent of the binding gated window, or the weekly aggregate when the account has no gated row, over time to its reset, highest first), then soonest reset, then lowest weekly use; unknown usage last. Codex ranks by `pacePressure` alone, excludes accounts present in another codex session, and has no manual switch either; neither pool has one. Policy lives in `docs/content/docs/switching.mdx`, with review lessons in `.cursor/rules/switch-verification.md` and `.cursor/rules/per-account-stores.md`.

- One engine, two providers (#93): `decide.ts`, `picker.ts`, `status`, and the account commands take a `Provider` (`src/lib/provider.ts`) and never branch on its name. What differs per product lives in `src/lib/claude.ts` and `src/lib/codex.ts` (identity, credential store, usage source, presence, login and install flows, the swap) and in the codex entries (restart on swap). A product-only rule is a provider capability (`seats`: `shared` for Claude, `live` for Codex, which decides whether present accounts stay candidates, whether `PickCtx.seats` carries the session counts, and whether a move needs the caller's respawn; `waitsWhenDepleted`; `presence`; `gatedFamilies` returning `null` for "every named limit gates"), not an `if` in the engine. Every cached window carries its own duration and sample time, so `isSessionWindow` is one duration test for both providers.
- A Claude move is `swap` = verify the target's store, then the caller's respawn marker (`writeRespawnMarker` in `sessions.ts`, one shared site for the Stop, StopFailure, and SessionStart hooks). The engine returns `needs-respawn` for a shared-seat provider when the caller cannot respawn (an unsupervised session, a subagent failure, the check tick), after the enforced stamp and before any pick. The Stop hook writes the marker on `swapped` too, because every Claude move is a respawn; the supervisor honors the marker's `accountId` on relaunch and re-picks only when that account left the pool. The marker's `compact` flag (`true` from Stop and SessionStart, `false` from StopFailure) makes the supervisor run `claude -p --resume <sid> /compact` under the old seat's store between the kill and the relaunch (`src/lib/compact.ts`; `/compact` is `supportsNonInteractive` in the 2.1.269 binary, and `--resume` honors the `compact_boundary` row). Codex compacts hook-side instead, before the decision, through `codex app-server` (`thread/resume` then `thread/compact/start`, JSONL over stdio, verified against 0.153.4), because after the respawn the old account's store is no longer the session's home. Both steps are bounded and best-effort: a failure logs and the move proceeds with the full context. The relaunch submits a first prompt that names the move (and the compaction, when it landed) and asks Claude to continue, so the conversation goes on without a keystroke: a positional prompt after the session id in a terminal session, or the first `user` line through the supervisor's stdin relay in a stream-json session, because the 2.1.270 binary ignores a positional prompt under `--input-format stream-json`. Every value-taking root flag has to be in `VALUE_TAKING_ROOT_FLAGS`, or a respawn drops its value as a positional: `--permission-prompt-tool stdio` lost `stdio` that way and the relaunched harness session could not answer permission prompts. Audit the table on each binary bump against `claude --help` and against the flags the Claude Agent SDK's argument builder pushes (`grep -o 'push("--[a-z-]*",' sdk.mjs` in the cached `@anthropic-ai/claude-agent-sdk`), because `--help` hides the SDK-only ones (`--max-turns`, `--thinking`, `--task-budget`, and the like on 0.3.257). The relay decision reads the effective flag set after the persisted flags load, because a bare `claude --resume <sid>` replays a harness session's stream-json flags from `sessions/<sid>.json`.
- The supervisor watches its own seat every ten seconds while the child runs (`moveExhaustedSeat`: the account record plus the seat's tee through `teeObservation`, `usableAt` against `thresholdBars(cfg)`); at or over a bar it runs `evaluateAndMaybeSwap` with the seat passed explicitly (the supervisor's env names no store) and writes the respawn marker itself with `compact: true`, under the same `launchedAt` gate. This is the move that waits for no hook: a harness session (T3 Code, the Agent SDK) has no statusline tee and no turn boundary while a Workflow or background agents burn the window between prompts (observed 2026-09-17: a seat ran from 60 to 102 percent between turns, the workflow agents stalled silently for seven minutes, and the first main-loop StopFailure fired before its row was flushed), and a subagent StopFailure stamps the wall but returns `needs-respawn`. A turn in flight is cut at the bar. A deadline at or before `overriddenUntil` (Ctrl-C on the depleted countdown) suppresses the watch, the same gate `consumableMarker` applies. A decision that moves nothing is retried after a minute, a quiet check after ten seconds.
- The supervisor forwards SIGTERM to the real claude child and exits after it. The Agent SDK stops a session with SIGTERM on the process it spawned, which is the wrapper; without the forward the child survived as an orphan on the old seat while the harness relaunched the same session through a new supervisor, and the orphan's hooks wrote markers with the old launch stamp that the stale gate discarded (`supervisor.marker_stale`, 2026-09-17).
- `sampleOldest` probes accounts with a live session first, then the oldest, so a seat's cached figure is about one `usagePollTtlMs` old instead of a full round of the pool.
- The StopFailure hook waits up to three seconds for the transcript's error row before classifying (`awaitEnforcedRow`): Claude Code can fire the hook before the row is flushed, and an unclassified failure stamps nothing. `stopfailure.unclassified` logs `subagent`.
- Build EVERY Claude PickCtx and trigger from `thresholdBars(cfg)`: `thresholds.session` minus `policy.projectionMargin`, and `thresholds.weekly` as configured (the margin guards only the session window against single-turn overshoot; a weekly margin would strand use-it-or-lose-it headroom). Trigger and screening share the bars, or a move lands on an account the trigger re-flags and ping-pongs. Codex reads the same bars. The session ladder, `hardThresholds`, the engagement floor, organization affinity, incumbent hysteresis, and the Layer 2 wall squeeze were deleted in #81; do not reintroduce a second bar per window.
- `isExhausted` is the one screen: session, weekly aggregate, gated per-model caps, and `enforcedUntil`, each against its bar. The depleted pause happens at the bar, not at 100.
- Selection reads cached figures only, after folding every account's tee under the lock (`teeObservation`/`foldTee` in `sample.ts`; ordering between a tee and the record uses the sample time inside the tee, never the file mtime, because Linux stamps mtime from the coarse clock and it can lag `Date.now()` by a tick). Freshness comes from the check tick: `sampleOldest` probes up to three accounts per tick, the ones whose last attempt (`lastUsageAt` or `lastProbeAt`) is oldest, skipping any attempted within `policy.usagePollTtlMs`, under each account's store with the `-tick` probe home so it never collides with a `status` probe of the same account. A failed attempt is recorded too, so a broken account does not starve the rest of the round-robin, and its cached figure stays as stale as it was. Five consecutive store-read failures stamp `needsReauth` (a missing credential never recovers on its own); a successful read resets the counter. The pool lock covers only the reservation (`prepareProbe`: a store read, no network) and the result write; the `/usage` child (`runProbe`) runs outside the lock so the StopFailure stamp and move never wait on it. Do not move the child back under the lock. The child gets one attempt (`retries: 0`, the round-robin is the retry loop) and the result is stored only when it is newer than `lastUsageAt`. There is no post-swap cooldown on either pool (both `lastSwapJson` are `null`); Codex kept 45 seconds while it rewrote one live `auth.json`, which per-session stores no longer invalidate.
- Codex has no depleted pause: each session moves by its own respawn, so there is nothing to pause, and a fully depleted pool rides each account until the server refuses it.
- The periodic timer runs a plain `check` every `policy.checkIntervalMs` tick, the tick `init` writes into the timer unit; the self-paced cadence (`--if-due`, `nextcheck.json`, headroom bands) was deleted in #82 and is not to return. A tick has no seat, so it never moves anything; it folds tees and samples.
- Match model names by family substring or prefix, never by exact display string. Display names drift per release in BOTH directions ("Opus 4.8", and "Fable" became "Fable 5" in 2.1.206), so any exact-match gate silently stops matching. One did, and an account's Opus weekly drained to 100% with no auto-switch.
- Unmeasured must never look safe: an unmeasured usage percent renders as unknown, never 0, and ranks last, never first.
- Per-model weekly caps exist only for Sonnet and Fable, and only Fable gates a switch (owner, 2026-07-12).

## Claude internals

Verified auth and quota mechanics live in `.memory/cc-codex-auth-mechanics.md`; the credential store and swap sequence are in `DESIGN.md` §2-3. Both CLIs change monthly, so re-verify before trusting a recorded fact.

- Quota comes from `claude -p '/usage'` (free, 0 tokens), probed under the account's store (`CLAUDE_SECURESTORAGE_CONFIG_DIR`) with a throwaway `CLAUDE_CONFIG_DIR` probe home (`sample/<uuid8>`, a seeded `.claude.json`, no credential) so no hooks load; Claude Code refreshes a near-expiry token inside the probe itself. The direct `GET /api/oauth/usage` 429s for an account currently serving a session, so it is used only for an account with no live session and a still-fresh stored token, and the CLI probe is the source for a session-serving account, a stale token, and onboarding (#95, 2026-09-13). The read is `?at_wall=1&skip_spend=1`; `skip_spend=1` is the no-spend read Claude Code itself uses (2.1.269 binary), so it opens no window and spends nothing. tokenmaxxing has no refresh grant, so a stale-token account cannot be read this way and falls back to the CLI probe, which refreshes; the direct GET never refreshes. The response is `rate_limits.{five_hour,seven_day}.{utilization (0..1), resets_at (epoch seconds)}`; per-model rows still come from the CLI probe and the StopFailure backstop. Codex reads its own usage GET (separately approved), not this endpoint.
- `/usage` on a token that is busy serving sessions is fail-silent whenever Claude's internal usage fetch errors or 429s (2026-08-30 diagnosis: 10,198 failed probes), but it is not a dead path: on 2026-09-05 (2.1.261) every live probe of the day succeeded. So the per-account statusLine tee (`usage/<uuid8>.json`) stays the primary source for an account with sessions, the decision engine falls back to the store probe when the seat's tee is older than `usagePollTtlMs` (one attempt, doubling the per-seat interval per consecutive silent failure up to 30 minutes, reset on success), and `status` probes an account only when its tee is missing or older than the stored sample. A silent result is unmeasured, never zero, and a sample never overwrites a newer one (`status` and the decision engine both keep the newest of tee and stored record). The tee carries no per-model rows, so a seat's Fable cap still comes from that probe and goes blind for hours under load; the StopFailure hook is the backstop, not a better probe.
- StopFailure (verified 2.1.251) fires INSTEAD of Stop when a turn ends on an API error, for subagents too (`agent_id` set), with `error` (`rate_limit`, ...) and `last_assistant_message` on stdin. `quotaLimits` (rateLimitType, resetsAt in epoch seconds) lives only on the transcript row. The Fable cap failure is the credits branch: no quotaLimits, no reset, text `You've reached your Fable 5 limit.` or `Fable 5 requires usage credits.`. The statusline payload no longer carries `organizationUuid`.
- `claude setup-token` was investigated and abandoned for the local pool: it is inference-only scoped and returns no rate-limit percentages, which breaks monitoring. Do not revisit without solving usage. The Cursor Cloud relay (1.29.0) uses setup tokens on the cloud VM only, where rotation is reactive on a limit error; that is not a precedent for the local path, and the local switching engine never reads one.
- Every new spawn of the real claude goes through `resolveRealClaude()`. Preset the depth cap for probe subtrees that must never re-enter the wrapper; set `TOKENMAXXING_UNMANAGED` where nested invocations are legitimate. The layered guards live in `src/lib/claudebin.ts`; read them there before adding a spawn. A spawn that must read a pooled account sets `CLAUDE_SECURESTORAGE_CONFIG_DIR` to that store after the `CRED_ENV_OVERRIDES` scrub (`probeEnv` in `usage.ts`, the supervisor's launch env); a spawn that must not (the onboarding login) leaves it scrubbed.

## Cursor Cloud relay

Setup tokens are Cursor Cloud only. The page is `docs/content/docs/cursor-cloud.mdx`; the code is `src/cli/setuptoken.ts`, `src/cli/cursorinit.ts`, `src/cli/cloudrun.ts`, and `src/lib/cloud.ts`.

- `tokenmaxxing setup-token` prints credential material by design. No agent runs it, in any session, hermetic or not. `setup-token --print` and `setup-token rm` under a throwaway `TOKENMAXXING_HOME` with a synthetic store, and a mint against a stub binary that prints a fake token, are the only allowed exercises, and the fake token stays out of the transcript.
- `cloud run` is the one place `CLAUDE_CODE_OAUTH_TOKEN` is set on purpose, on the child's env after the scrub. The probe scrub list (`CRED_ENV_OVERRIDES`) is unchanged, and the mint child runs scrubbed in a throwaway `CLAUDE_CONFIG_DIR` under `setup-token/`, because Claude Code reads that variable first and an ambient token hijacks the flow.
- The relay lives only under `.cursor/agents/`, never `.claude/agents/`: Claude Code loads its own `agents/` folders, and a Claude subagent that spawns claude through the runner is the recursion the wrap-depth guards exist for.
- The mint capture reads the lines between the `Your OAuth token (valid for` and `Store this token securely` markers the 2.1.268 binary renders (the token is its own line between them), joined so a wrapped token survives, with a paste prompt as the fallback. Whether the flow prints to a piped stdout is undocumented and owner-verified in #104.
- On the VM the runner relies on `--dangerously-skip-permissions`, which Claude Code refuses under root; Cursor's environment `user` must stay non-root.

## Codex

Source-verified against rust-v0.144.5 (2026-07-16); the installed CLI is 0.145.0 and codex changes monthly, so re-verify before trusting any line here. Detail: `docs/codex.mdx` and `.memory/cc-codex-auth-mechanics.md`.

- No hot-swap: restart IS the switch (`codex resume <sid>`).
- Refresh-token reuse is punished, and a superseded token kills the whole grant family. Harvest by true owner and persist every rotation into the account's own store the instant it returns; never refresh an account running in another session from outside.
- An idle codex still touches tokens: the Apps surface builds throwaway auth managers that fresh-read the session's own store home `auth.json` mid-run. Sample from the store file at the last moment.
- An account running in another supervised session is never a placement or move target and never gets its store refreshed from outside. Unmeasured does not imply not running.
- Classify windows by DURATION, never by position. Current plans may have no 5h window at all.
- Codex silently skips untrusted hooks until the user runs `/hooks`, so auto-switching never engages until they do. Never clobber the user's `notify` key in `config.toml`; nothing in code guards it.
- `~/.codex/hooks.json` is not the only hook config source: a plugin manifest can point at its own via a `hooks` path key (verified in the 0.145.0 binary). tokenmaxxing only ever writes hooks.json, so check for other sources before assuming precedence.
- Codex Stop stdin carries `session_id`, `turn_id`, `transcript_path`, `stop_hook_active`, and `last_assistant_message` (all verified in the 0.145.0 binary), but no error signal, so the reverted text-sniffing failsafe below applies here too. `CodexStopStdinSchema` is a loose object declaring only `session_id` and `hook_event_name`, so it silently swallows the rest.

## Release and CI

Ship = work on a branch, bump `package.json` in the same PR, open the PR, make CI pass, wait out the review window, handle every review (fix, or refute with reasons), merge, `gh release create v<version>`, verify the npm publish landed, then tear down. A merge without a publish is not shipped. This repo merges its own PRs, which overrides the global "open the PR and stop". Detail: `.memory/shipping-pr-based.md`.

- A PR that changes no packed file skips the bump and the release (owner, 2026-09-08). The packed set is whatever `npm pack --dry-run` lists, NOT the `files` array: `src`, `README.md`, `DESIGN.md`, plus `LICENSE` and `package.json`, which npm always includes even though `files` never names them. A change confined to `docs/`, `.memory/`, or AGENTS.md would publish a tarball identical to the last one but for its version, so merge it and stop; the docs site deploys from main on its own. Everything else about the ship still applies, the review window included. Touch one packed file and the full ship is back.

- Never push work directly to main.
- The review window is 10 minutes of reviewer silence, babysat every minute: poll the PR each minute for new reviews, comments, check results, and merge state, handle whatever appears (fix or refute, resolve conflicts, fix CI), and merge only after 10 consecutive quiet minutes. Every new item restarts the clock. Green checks never shorten it, because reviewers post findings after their checks pass.
- The PR review bots are the adversarial pass. Do not run a separate local adversarial-review workflow before opening the PR (owner, 2026-09-06); spend the effort on hermetic verification instead.
- npm trusted publishing is bound to the literal workflow filename `ci.yml`. Renaming it silently breaks publishing.
- `bun add -g <local .tgz>` over an existing global errors `DependencyLoop`. Run `bun remove -g` first.

## Statusline

Short pointers.

- Statusline: `src/entries/statusline.ts` renders natively and tees `usage/<uuid8>.json` for the session's seat (from the inherited store variable; no seat, no tee); subagent rows in `src/entries/subagentstatusline.ts`. Format spec in `docs/statusline.mdx`. statusLine stdin sends top-level sub-objects as JSON `null`, so their schemas need `.nullable().optional()`, not `.optional()`. The main payload can never reflect the focused subagent; the subagent rows are the only such surface. This runs every turn, so keep it O(ms) and off flock and oauth: read the HEAD file, never spawn a git subprocess.

## CLI output

`status`, `config`, and `check` have a text form and a `--json` form (`ok` mirrors exit 0, failures add `error`, progress on stderr only; contract in `docs/commands.mdx`); every other command is text only and `main.ts` refuses the flag for it before dispatch (decided 2026-09-12, issue #88: the CI smoke step parses `config --json`, the docs give `jq` recipes for the other two, and nothing consumes the rest). On those three, route every new success line through `emitJson` behind the `json` flag and every error through `emitError` (`notes` are text-only hints, `extra` is structured data). A bare `console.log` on a `--json`-capable command breaks the contract for scripts, and the text form must stay byte-identical: `status` renders from the same report the JSON prints, so change the collect step, not the renderer, when a number is wrong. Do not add `--json` to another command without a consumer.

## Do not reintroduce

- A Stop-hook text-sniffing limit failsafe. Stop stdin carries no `is_error`, so it fired on turns that merely discussed limits and stamped healthy accounts as walled. The real errored-turn signal is the StopFailure hook (`src/entries/stopfailurehook.ts`): it classifies only the transcript row Claude Code itself marked `isApiErrorMessage`, never prose, attributes it to the seat the process runs under (fixed for the life of the process, so no swap clock or cooldown is needed; #79), writes only `enforcedUntil` on the account, inside the decision's own critical section so the stamp and the candidate selection cannot interleave with another hook's stamp (no usage-window rewrite, no per-model stamp, no second enforcement field; #90 and #118, 2026-09-12). Keep it that way.
- A shared live credential for Claude, or anything that served it: harvest, park, install, a tokenmaxxing refresh grant, a `~/.claude.json` rewrite, a post-swap cooldown, a pool-wide depleted record, an ambient store-variable refusal, a manual Claude `switch`, or a copy of one grant in two stores (#79, 2026-09-12). The Codex equivalents are gone too: the shared live `auth.json`, the parked `codex-creds/` copies, the pool-wide active label, the post-swap cooldown, the manual `switch --codex`, and the cross-session reconcile.
- Statusline formats already rejected: meter glyphs, Unicode fractions, dim or faint ANSI anywhere, account names, S/W window labels, percent signs, remaining-instead-of-used, usage numbers in color mode, and the counted parked collapse.
- Compatibility bridges, migration shims, or dual behavior for old local states.

## Lessons that cost something

- Verify an external tool's limits with a real-sized payload before relying on it. A 4.3KB credential blob truncated silently through `security -i`.
- A prior go-ahead does not cover collision evidence that arrives after it. Every new signal of concurrent work freezes git actions until the owner rules.
- Never write a completion claim into docs or memory ahead of the output that proves it.
- `status --ping` (removed 2026-09-12) opened a real 5h window on every account it pinged. A feature request is not permission to spend.
- `TOKENMAXXING_HOME` isolates state files only. `init`, `uninstall`, and the codex hook install write settings.json, codex `hooks.json`, the shell rc, and the timer unit under `HOME` regardless, so a throwaway root does not make them hermetic: a review subagent ran `uninstall --json` under one and stripped a live install (2026-09-05). Subagent prompts must forbid those commands by name; "hermetic" is not enough. A minting `setup-token` joins that list: it opens a browser sign-in and prints credential material.

## Cursor Cloud specific instructions

The cloud VM is a throwaway Linux clone, not the owner's Mac, so its git-safety and live-process cautions do not apply here; the machine-gotchas above still describe real runtime behavior.

- Runtime is Bun, which is not on the base image. The startup update script installs it to `~/.bun/bin` (added to `~/.bashrc`). A fresh non-login shell may not have it on PATH: run `export PATH="$HOME/.bun/bin:$PATH"` or call `~/.bun/bin/bun` directly.
- No Claude/Codex subscription logins exist here and none should be created, so the live swap loop, `init`, `add`, `auth`, and `status` cannot run end to end. Exercise the decision engine hermetically instead, under a throwaway `TOKENMAXXING_HOME` (see `## Testing`).
- For manual CLI pokes that must not touch real state, point `TOKENMAXXING_HOME` at a throwaway dir (e.g. `TOKENMAXXING_HOME=/tmp/xx bun run src/main.ts config`); it overrides the whole `~/.config/tokenmaxxing` state root. Commands that only read/write local state (`help`, `config`, `status --cached`, `doctor`) work with no accounts; `doctor` exits 1 on a fresh dir because nothing is installed, which is correct.
- The docs site under `docs/` is a separate Next.js app with its own `bun.lock`; the root update script does not install it. Run `cd docs && bun install` then `bun run dev` (serves http://localhost:3000). First page load compiles via Turbopack and can take ~20s.
