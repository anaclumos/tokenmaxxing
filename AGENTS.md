# Agent rules

Repo-specific rules only. The owner's global rules load alongside this file in every session, so nothing here repeats them; where this file is silent, the global rule applies. Long-form detail lives in `DESIGN.md` and `docs/content/docs/`. New lessons belong in `.cursor/rules/` under the owner's 2026-09-10 instruction. Existing `.memory/` links are historical references, not an active write surface.

## The project

tokenmaxxing pools the owner's own Claude Code and Codex logins, starts each session on its own pooled account, moves a session to a fresher account as its account nears the 5-hour or weekly limit, and keeps sessions continuable across moves. Design: `DESIGN.md`. User docs: `docs/content/docs/`.

No external installed user base, so this is pre-production code: delete old-state compatibility rather than carry it forward.

## Safeguards and machine gotchas

- Resolve the installed entry point before assuming a checkout is the active runtime.
- This machine runs live supervisors, hooks, the periodic check, and the owner's real claude sessions. Stop processes by PID, and never kill a running session or supervisor to free a resource without asking.
- The owner's hosts are managed environments: never run `init`, `add`, `auth`, `uninstall`, or anything that writes settings.json, launchd/systemd units, shell rc, or the global package on a live host (owner, 2026-08-30). Ship code; activation is the owner's step.
- This working tree is a shared checkout (the owner and other agents work in it live). Stage commits by explicit path, never `git add -A`/`-u` (hook correction, 2026-08-30).
- No dynamic workflows on this repo: never orchestrate through the Workflow tool or any scripted fan-out. Spawn every subagent by hand, one deliberate Agent call per subagent with a prompt crafted for that task (owner, 2026-09-10).
- Never print credential material: keychain blobs, `.credentials.json`, `auth.json`, OAuth access or refresh tokens. Report account labels and status only. A ky error carries its request, Authorization header included.
- Ask before any run that meters real quota or opens a session window (live-pool runs). Free `/usage` reads are fine.
- This repo is PUBLIC. The no-Slack-info and no-device-info rule covers PR bodies, commit messages, review replies, release notes, and docs, not just `.memory`.
- Pool account labels are personal data, the same as emails and organization names: the owner names seats after people. Never paste `status`, `doctor`, or log output that carries labels, emails, or org names into a PR body, commit, review reply, doc, memory, or subagent prompt. Mask or count them ("six team seats", "15 accounts") the way emails are masked (owner correction 2026-09-06).
- `rm` is aliased to `rm -i` on the owner's Mac. In a non-TTY shell the prompt gets EOF, nothing is deleted, and it still exits 0, so `rm f && echo ok` lies. Deletion is the owner's call except for artifacts this session created; when you must, pass `-f` and verify the path is gone.
- macOS has no `/bin/true`. Use `/usr/bin/true` in tests.
- Env overrides parse through zod at the read site rather than a central `env.ts`, because the CLI's knobs are all optional. Unset parses to undefined and the feature degrades there.
- State files that exist but fail to parse THROW. A truncated `accounts.json` read as an empty pool once let `init` overwrite it.
- A configured-but-missing path (`claudeBin`, `codexBin`, credential locations) fails fast. Never fall through to a PATH scan: seeding `/bin/true` as claudeBin made the scan resolve the real installed wrapper and wedge an E2E for 15 minutes, the same shape that fed the runaway-recursion incident.
- For platform-specific behavior differences, compare the installed package versions before attributing the difference to the platform.
- Core deps are zod, es-toolkit, and ky. The global default stack does not apply (there is no date-fns here and no date helper: a reset time parses through zod at the read site, as ISO 8601 with an offset from the direct usage read and as epoch seconds through `EpochSecondsSchema` from the transcript row and the statusline stdin).
- Keep `node:fs`, which is Bun-native. `Bun.file`/`Bun.write` are async-only, non-atomic, and have no create-mode, so they cannot serve the 0600 credential store or the flock fd. When asked to simplify this, that is the answer.

## Credentials and identity

- One Claude Code credential store per pooled account, `stores/<uuid8>/`, never one per session (#79, 2026-09-12). A session runs on an account because the supervisor set `CLAUDE_SECURESTORAGE_CONFIG_DIR` to that store at spawn; the seat is fixed for the life of the process, and hooks, the statusline, and the CLI read it from the inherited variable (`seatFromEnv`), never from `~/.claude.json`, which Claude Code rewrites after whichever session refreshed last. Neither pool index carries an active account: `AccountsIndexSchema` is `{version: 2, accounts}`, and an older file that still holds `activeId` loads and drops the key on the next save.
- One Codex credential store per pooled account, `codex-stores/<uuid8>/`, never one per session. A session runs on an account because the supervisor set `CODEX_HOME` to that store at spawn; the seat is fixed for the life of the process, and the hook reads it from the inherited variable (`codexSeatFromEnv`). The store holds only `auth.json`: everything else is a symlink to the matching entry in the shared `~/.codex`, so sessions, history, and config stay shared and `codex resume` works across stores.
- tokenmaxxing writes a store once, at onboarding (`init`, `add`, `auth`: isolated login, owner verified through `fetchTokenIdentity`, harvested into the store), and never again. Claude Code's own refresh is the only writer afterwards, under the refresh lock it roots at the store, with its compare-and-swap on the refresh token. There is no tokenmaxxing refresh grant, no harvest, no park, no install, and no `withClaudeRefreshLock` outside the onboarding reread. Never copy a credential between stores or between hosts: a refresh rotation revokes the previous access token of that grant (verified 2026-09-06), so the other copy 401s, force-refreshes a superseded refresh token, gets `invalid_grant`, and Claude Code dead-clears it. Separate logins are separate grants and do not interfere, which is why the same accounts can be pooled on several hosts by logging in on each (`docs/limitations.mdx`).
- Identity is the `accountUuid` that `fetchTokenIdentity` reports for a token (`GET /api/oauth/profile`), never the organization, never a stored label, and never a blob comparison. Team seats share one `organizationUuid`, so an org-keyed lookup collapses every seat onto the first one in the array (2026-09-06). The check runs at onboarding (a login whose token belongs to another account than its identity file names changes nothing) and in `doctor`; a probe under a store needs no check, because only Claude Code writes the store.
- `isDeadCredential` (empty `accessToken` or `refreshToken`) is the one dead-grant signal: a dead store stamps `needsReauth` and the decision tries the next candidate (`InvalidGrantError` classifies as `dead-grant`); a missing or unreadable store is `StoreUnusableError`, skipped for the evaluation only (the `rejected` set in `decide.ts`). The set narrows only the candidate list, so one bad store never aborts an evaluation (the 2026-09-06 livelock).
- Claude Code hashes the NFC-normalized `CLAUDE_SECURESTORAGE_CONFIG_DIR` into the macOS keychain item name whenever that variable is set, even with `CLAUDE_CONFIG_DIR` also set (2.1.269 binary, `xSe`); `isolatedTarget(storeDir)` names the same item. A missing namespaced item never falls back to the default one, so isolation is sound once the probe env is scrubbed and the intended store is set.
- Grok quota is the weekly `creditUsagePercent` from `GET https://cli-chat-proxy.grok.com/v1/billing?format=credits` (`TOKENMAXXING_GROK_USAGE_URL` overrides). The dollar billing GET without `format=credits` is not quota: subscription accounts report `monthlyLimit` 0 there while credits remain. tokenmaxxing does not refresh grok tokens; an expired stored access token is retried against the live `GROK_HOME` login when that login is the same account. A failed grok sample does not write the dollar body: an account with no stored window stays unmeasured, and one with a stored credits window keeps that figure as stale as it was.

## Switching

One rule (#81, 2026-09-12; per-session seats since #79): under both bars the seat holds; at or over a bar, `pickBest` ranks the usable candidates and the session moves by respawn under the winner's store; with nothing usable, the depleted-wait path resumes on the soonest reset within `policy.maxWaitMs`. The same ranking places a session at launch (`pickSeat`). Claude ranking (consult verdict for #79): `seatHeadroom`, `(session bar - session used) / (live sessions + 1)`, highest first, then `pacePressure` (remaining percent of the binding gated window, or the weekly aggregate when the account has no gated row, over time to its reset, highest first), then soonest reset, then lowest weekly use; unknown usage last. Codex ranks by `pacePressure` alone, excludes accounts present in another codex session, and has no manual switch either; neither pool has one. Policy lives in `docs/content/docs/switching.mdx`, with review lessons in `.cursor/rules/switch-verification.md` and `.cursor/rules/per-account-stores.md`.

- One engine, two providers (#93): `decide.ts`, `picker.ts`, `status`, and the account commands take a `Provider` (`src/lib/provider.ts`) and never branch on its name. What differs per product lives in `src/lib/claude.ts` and `src/lib/codex.ts` (identity, credential store, usage source, presence, login and install flows, the swap) and in the codex entries (restart on swap). A product-only rule is a provider capability (`seats`: `shared` for Claude, `live` for Codex, which decides whether present accounts stay candidates, whether `PickCtx.seats` carries the session counts, and whether a move needs the caller's respawn; `waitsWhenDepleted`; `presence`; `gatedFamilies` returning `null` for "every named limit gates"), not an `if` in the engine. Every cached window carries its own duration and sample time, so `isSessionWindow` is one duration test for both providers.
- A Claude move is `swap` = verify the target's store, then the caller's respawn marker (`writeRespawnMarker` in `sessions.ts`, one shared site for the Stop, StopFailure, and SessionStart hooks). The engine returns `needs-respawn` for a shared-seat provider when the caller cannot respawn (an unsupervised session, a subagent failure, the check tick), after the enforced stamp and before any pick. The Stop hook writes the marker on `swapped` too, because every Claude move is a respawn; the supervisor honors the marker's `accountId` on relaunch and re-picks only when that account left the pool. The Stop, StopFailure, and SessionStart hooks write the marker only when stdin `session_id` is absent or equals the session's live id (`liveSessionId`): `TOKENMAXXING_SESSION_ID`, or the `current` id in `sessions/<sid>.json`. A hook whose stdin id differs adopts it as the live id (`adoptLiveSession`) only when the hook's own process descends, through shell processes alone, from the pid in the session's presence record, which is the claude the supervisor spawned: `/clear` and an in-session `/resume` give that process a new session id. `source` cannot prove the emitter, because `/clear` is `supportsNonInteractive` in the 2.1.278 binary and a nested `claude -p /clear` reports `source: "clear"` too. Any other differing id belongs to a nested process that inherits the supervised environment and runs its own session; it does not move the parent. The marker file stays named after the launch id; the marker carries the live id, and a relaunch whose live id has no transcript in the cwd yet (a `/clear` with no turn since) starts it with `--session-id` instead of `--resume`, because `claude --resume` on an id without a transcript exits with `No conversation found`. The marker's `compact` flag (`true` from Stop and SessionStart, `false` from StopFailure) makes the supervisor run `claude -p --resume <live id> /compact` under the old seat's store between the kill and the relaunch (`src/lib/compact.ts`; `/compact` is `supportsNonInteractive` in the 2.1.269 binary, and `--resume` honors the `compact_boundary` row). Codex compacts hook-side instead, before the decision, through `codex app-server` (`thread/resume` then `thread/compact/start`, JSONL over stdio, verified against 0.153.4), because after the respawn the old account's store is no longer the session's home. Both steps are bounded and best-effort: a failure logs and the move proceeds with the full context. The relaunch submits a first prompt that names the move (and the compaction, when it landed) and asks Claude to continue, so the conversation goes on without a keystroke: a positional prompt after the session id in a terminal session, or the first `user` line through the supervisor's stdin relay in a stream-json session, because the 2.1.270 binary ignores a positional prompt under `--input-format stream-json`. Every value-taking root flag has to be in `VALUE_TAKING_ROOT_FLAGS`, or a respawn drops its value as a positional: `--permission-prompt-tool stdio` lost `stdio` that way and the relaunched harness session could not answer permission prompts. Audit the table on each binary bump against `claude --help` and against the flags the Claude Agent SDK's argument builder pushes (`grep -o 'push("--[a-z-]*",' sdk.mjs` in the cached `@anthropic-ai/claude-agent-sdk`), because `--help` hides the SDK-only ones (`--max-turns`, `--thinking`, `--task-budget`, and the like on 0.3.257). The relay decision reads the effective flag set after the persisted flags load, because a bare `claude --resume <sid>` replays a harness session's stream-json flags from `sessions/<sid>.json`.
- The supervisor watches its own seat every ten seconds while the child runs (`moveExhaustedSeat`: the account record plus the seat's tee through `teeObservation`, `usableAt` against `thresholdBars(cfg)`); at or over a bar it runs `evaluateAndMaybeSwap` with the seat passed explicitly (the supervisor's env names no store) and writes the respawn marker itself with `compact: true`, under the same `launchedAt` gate. This is the move that waits for no hook: a harness session (T3 Code, the Agent SDK) has no statusline tee and no turn boundary while a Workflow or background agents burn the window between prompts (observed 2026-09-17: a seat ran from 60 to 102 percent between turns, the workflow agents stalled silently for seven minutes, and the first main-loop StopFailure fired before its row was flushed), and a subagent StopFailure stamps the wall but returns `needs-respawn`. A turn in flight is cut at the bar. A deadline at or before `overriddenUntil` (Ctrl-C on the depleted countdown) suppresses the watch, the same gate `consumableMarker` applies. A decision that moves nothing is retried after a minute, a quiet check after ten seconds.
- The supervisor forwards SIGTERM to the real claude child and exits after it. The Agent SDK stops a session with SIGTERM on the process it spawned, which is the wrapper; without the forward the child survived as an orphan on the old seat while the harness relaunched the same session through a new supervisor, and the orphan's hooks wrote markers with the old launch stamp that the stale gate discarded (`supervisor.marker_stale`, 2026-09-17).
- `sampleOldest` probes accounts with a live session first, then the oldest, so a seat's cached figure is about one `usagePollTtlMs` old instead of a full round of the pool.
- The StopFailure hook waits up to three seconds for the transcript's error row before classifying (`awaitEnforcedRow`): Claude Code can fire the hook before the row is flushed, and an unclassified failure stamps nothing. `stopfailure.unclassified` logs `subagent`.
- Build EVERY Claude PickCtx and trigger from `thresholdBars(cfg)`: `thresholds.session` minus `policy.projectionMargin`, and `thresholds.weekly` as configured (the margin guards only the session window against single-turn overshoot; a weekly margin would strand use-it-or-lose-it headroom). Trigger and screening share the bars, or a move lands on an account the trigger re-flags and ping-pongs. Codex reads the same bars. The session ladder, `hardThresholds`, the engagement floor, organization affinity, incumbent hysteresis, and the Layer 2 wall squeeze were deleted in #81; do not reintroduce a second bar per window.
- `isExhausted` is the one screen: session, weekly aggregate, gated per-model caps, and `enforcedUntil`, each against its bar. The depleted pause happens at the bar, not at 100.
- Selection reads cached figures only, after folding every account's tee under the lock (`teeObservation`/`foldTee` in `sample.ts`; ordering between a tee and the record uses the sample time inside the tee, never the file mtime, because Linux stamps mtime from the coarse clock and it can lag `Date.now()` by a tick). Freshness comes from the check tick: `sampleOldest` samples up to three accounts per tick, accounts with a live session first and then the ones whose last attempt (`lastUsageAt` or `lastProbeAt`) is oldest, skipping any attempted within `policy.usagePollTtlMs`, over the direct usage read with each account's stored token. A failed attempt is recorded too, so a broken account does not starve the rest of the round-robin, and its cached figure stays as stale as it was. Five consecutive store-read failures stamp `needsReauth` (a missing credential never recovers on its own); a successful read resets the counter. The pool lock covers only the reservation (`prepareSample`: a store read, no network) and the result write; the usage GET (`runSample`) runs outside the lock so the StopFailure stamp and move never wait on it. Do not move it back under the lock. The read gets one attempt per sample on every path (the round-robin is the retry loop), a failed read yields no figure for that attempt and leaves the cached figure as stale as it was, and the result is stored only when it is newer than `lastUsageAt`. tokenmaxxing holds no refresh grant: an expired stored access token stays unmeasured until a session on that store refreshes it. There is no post-swap cooldown on either pool; Codex kept 45 seconds while it rewrote one live `auth.json`, which per-session stores no longer invalidate.
- Codex has no depleted pause: each session moves by its own respawn, so there is nothing to pause, and a fully depleted pool rides each account until the server refuses it.
- The periodic timer runs a plain `check` every `policy.checkIntervalMs` tick, the tick `init` writes into the timer unit; the self-paced cadence (`--if-due`, `nextcheck.json`, headroom bands) was deleted in #82 and is not to return. A tick has no seat, so it never moves anything; it folds tees and samples.
- Match model names by family substring or prefix, never by exact display string. Display names drift per release in BOTH directions ("Opus 4.8", and "Fable" became "Fable 5" in 2.1.206), so any exact-match gate silently stops matching. One did, and an account's Opus weekly drained to 100% with no auto-switch.
- Unmeasured must never look safe: an unmeasured usage percent renders as unknown, never 0, and ranks last, never first. Unmeasured must never look exhausted either: a failed grok credits read never writes the dollar billing body. An account with no stored sample stays `exhausted` false with `usage` null; one with a stored credits sample keeps that stale figure.
- Per-model weekly caps exist only for Sonnet and Fable, and only Fable gates a switch (owner, 2026-07-12).
- A session's model is a fact of its process, the same as its seat: the `--model` value in the supervisor's effective flag set (`modelFromFlag` in `usage.ts`, which drops a `[1m]` suffix and returns a model only when the value names a family in `MODEL_FAMILIES`, the binary's alias families). The supervisor builds the `families` of `pickSeat`, the seat watch, and its own `evaluateAndMaybeSwap` call from it and never from a tee, and it sets `TOKENMAXXING_MODEL` on the child so the hooks' `claude.gatedFamilies` reads it ahead of the per-account tee, which reports whichever session on the seat rendered last and does not exist for a harness session. The engine derives `observeLive`'s `perModel` from the same families, so the in-decision per-model sample follows the session's model and never the tee's. A session spawned as Opus gates no family, so a spent Fable cap neither moves it nor screens a candidate for it (owner, 2026-09-19). `best`, `opusplan`, an unlisted family, and a launch without `--model` are unknown and gate every configured family. The StopFailure classification and the blind screen still read `policy.switchModels`: they are the backstop for a `/model` change and for a subagent on another model. Audit `MODEL_FAMILIES` on each binary bump.
- A stream-json session (`--output-format stream-json`: the Agent SDK, T3 Code) has no TUI, so the statusLine command never runs (no tee for that seat) and its stderr is a log nobody reads. The supervisor's notices (compaction, move, depleted wait with its resume time, resume, and a fatal exit) therefore go to stdout there as `{"type":"system","subtype":"informational","level":"warning",...}` lines, the shape the 2.1.270 binary emits for its own print-mode notices; the SDK (0.3.263) passes unknown system subtypes through, and T3 Code renders `informational` only at level `warning` and `notification` only at priority `high` or `immediate`, dropping `notice`. Every stdout line is a permanent chat row, so the per-second countdown stays terminal-only, and the supervisor writes only between the kill and the relaunch, except a fatal that ends the session. The mode is read from the effective flag set like the relay, never from the parent process (#150). Detail: `.cursor/rules/harness-notices.md`.

## Claude internals

Verified auth and quota mechanics live in `.memory/cc-codex-auth-mechanics.md`; the credential store and swap sequence are in `DESIGN.md` §2-3. Both CLIs change monthly, so re-verify before trusting a recorded fact.

- Quota comes from the direct `GET /api/oauth/usage?at_wall=1&skip_spend=1` with the account's stored access token, from every sampler (the check tick, `status`, the seat's in-decision read, and onboarding); `skip_spend=1` is the no-spend read Claude Code itself uses (2.1.269 binary), so it opens no window and spends nothing. The body is top-level `five_hour` and `seven_day` (`utilization` already a percent, `resets_at` validated as ISO 8601 with an offset) plus `limits[]`, whose `kind: weekly_scoped` rows carry the per-model caps keyed by `scope.model.display_name`, the same rows `/usage` renders (verified live 2026-09-17 against the 2.1.270 binary). The 1.41.0 schema (`rate_limits.*`, a 0..1 ratio, epoch seconds) matched no real body, so the read failed on every tick until 1.53.0 (#148). The read answers 200 for a seat with live sessions (verified 2026-09-17 on a seat serving 14), so there is no live-seat gate; the 2026-07 finding that it 429s for a serving account predates `skip_spend=1`. Nothing parses `/usage` text, and there is no second usage source and no `/usage` spawn: a failed read yields no figure for that attempt. The endpoint rate limits per account, not per host: a limited account answers 429 with `retry-after` in seconds (3227 observed) while other accounts answer 200 from the same host in the same second, and a read during the penalty fails too (one account stayed limited for over 97 minutes while the tick and a 10-minute `status` job kept reading it; verified live 2026-09-21). `fetchUsageDirect` returns that deadline, every sampler stores it as `usageRetryAt` (onboarding through `Harvest.usageRetryAt`), and `usageBlockedUntil` in `sample.ts` is the one gate: `sampleOldest` still checks a blocked account's store on its turn and sends it no read, `observeLive` skips the probe without counting a failure, and `sampleAccountUsage` answers `status` with the wait. A new sampler goes through `sampleAccountUsage` or checks the gate itself. tokenmaxxing holds no refresh grant, so an expired stored access token stays unmeasured until a session on that store refreshes it. Codex reads its own usage GET (separately approved), not this endpoint.
- The per-account statusLine tee (`usage/<uuid8>.json`) stays the primary source for an account with sessions. The decision engine samples the seat with the direct read when the seat's tee is older than `usagePollTtlMs` or its active model is a gated family (one attempt, doubling the per-seat interval per consecutive failure up to 30 minutes, reset on success), and `status` samples an account only when its tee is missing or older than the stored sample. A failed sample is unmeasured, never zero, and a sample never overwrites a newer one (`status` and the decision engine both keep the newest of tee and stored record). The tee carries no per-model rows, so a seat's Fable cap comes from that in-decision sample (the direct read carries the scoped rows); the StopFailure hook is the backstop.
- StopFailure (verified 2.1.251) fires INSTEAD of Stop when a turn ends on an API error, for subagents too (`agent_id` set), with `error` (`rate_limit`, ...) and `last_assistant_message` on stdin. `quotaLimits` (rateLimitType, resetsAt in epoch seconds) lives only on the transcript row. The Fable cap failure is the credits branch: no quotaLimits, no reset, text `You've reached your Fable 5 limit.` or `Fable 5 requires usage credits.`. The statusline payload no longer carries `organizationUuid`.
- `claude setup-token` was investigated and abandoned for the local pool: it is inference-only scoped and returns no rate-limit percentages, which breaks monitoring. Do not revisit without solving usage.
- Every new spawn of the real claude goes through `resolveRealClaude()`. Preset the depth cap for subtrees that must never re-enter the wrapper; set `TOKENMAXXING_UNMANAGED` where nested invocations are legitimate. The layered guards live in `src/lib/claudebin.ts`; read them there before adding a spawn. A spawn that must read a pooled account sets `CLAUDE_SECURESTORAGE_CONFIG_DIR` to that store after the `CRED_ENV_OVERRIDES` scrub (the supervisor's launch env); a spawn that must not (the onboarding login) leaves it scrubbed.

## Codex

Source-verified against rust-v0.144.5 (2026-07-16); the installed CLI is 0.145.0 and codex changes monthly, so re-verify before trusting any line here. Detail: `docs/codex.mdx` and `.memory/cc-codex-auth-mechanics.md`.

- No hot-swap: restart IS the switch (`codex resume <sid>`).
- Refresh-token reuse is punished, and a superseded token kills the whole grant family. Harvest by true owner and persist every rotation into the account's own store the instant it returns; never refresh an account running in another session from outside.
- An idle codex still touches tokens: the Apps surface builds throwaway auth managers that fresh-read the session's own store home `auth.json` mid-run. Sample from the store file at the last moment.
- An account running in another supervised session is never a placement or move target and never gets its store refreshed from outside. Unmeasured does not imply not running.
- Classify windows by DURATION, never by position. Current plans may have no 5h window at all.
- Codex silently skips untrusted hooks until the user runs `/hooks`, so auto-switching never engages until they do. Never clobber the user's `notify` key in `config.toml`; nothing in code guards it.
- `~/.codex/hooks.json` is not the only hook config source: a plugin manifest can point at its own via a `hooks` path key (verified in the 0.145.0 binary). tokenmaxxing only ever writes hooks.json, so check for other sources before assuming precedence.
- `tokenmaxxing seat --codex <pid>` is the one supported borrow for unattended consumers (plugins, SDK scripts): it refreshes every candidate older than `usagePollTtlMs` through `observeCodex` with `refresh: false` outside the lock (a borrower drains quota with no Stop hook and no `status`, so the cached figure is the only thing that would otherwise screen; the read never rotates a token, because two borrows run concurrently from parallel hooks and a double refresh kills the grant family, so an expiring token keeps its cached figure), then under the pool lock it picks a usable non-present account whose store holds a readable credential (`codexStoreUsable`, the one predicate for that, shared with `pickCodexSeat` and `validWanted`), writes `codex-live/seat-<pid>`, and prints the store for the consumer to pass as `CODEX_HOME`. Presence keyed to the consumer's pid self-reaps when it exits. Pointing a consumer at `codex-stores/` directly skips the lock and presence and can kill a grant family; never do it and never recommend it.
- The Codex Stop hook moves nothing unless the presence record of its supervisor id exists and names the seat in its `CODEX_HOME` (`codexstop.foreign_seat`): a borrowed child spawned inside a supervised session inherits `TOKENMAXXING_CODEX_SUPERVISOR_ID`, and without the guard its move wrote a marker that restarted the parent on the child's thread; the record is absent between the supervisor's `clearPresence` and its rewrite during a respawn, when only such a child can be running. A seatless supervised session has no record and no move to lose (`evaluateAndMaybeSwap` returns before the lock with no seat). The Claude hooks guard the same case by session id.
- Codex Stop stdin carries `session_id`, `turn_id`, `transcript_path`, `stop_hook_active`, and `last_assistant_message` (all verified in the 0.145.0 binary), but no error signal, so the reverted text-sniffing failsafe below applies here too. `CodexStopStdinSchema` is a loose object declaring only `session_id` and `hook_event_name`, so it silently swallows the rest.

## Release and CI

Ship = work on a branch, open the PR, make CI pass, wait out the review window, handle every review (fix, or refute with reasons), merge, verify the release CI made, then tear down. Never bump `package.json` in a PR: CI assigns the version at merge time, so sibling PRs cannot collide on it (#151). A merge without a publish is not shipped. This repo merges its own PRs, which overrides the global "open the PR and stop". Detail: `.memory/shipping-pr-based.md`.

- The `publish` job in `ci.yml` runs on every push to main and nowhere else (a `workflow_dispatch` on another ref does nothing). When a packed file changed since the tag of the current version, it bumps the minor version, commits `chore: release <version>` to main, creates the GitHub release at that commit, and publishes; otherwise it publishes nothing. The packed set is read from the merge commit's tree, so a PR that only deletes `README.md`, `DESIGN.md`, or `LICENSE` is outside the diff; touch `package.json` in that PR to release it. The packed set is whatever `npm pack --dry-run` lists, NOT the `files` array: `src`, `README.md`, `DESIGN.md`, plus `LICENSE` and `package.json`, which npm always includes even though `files` never names them. A change confined to `docs/`, `.memory/`, `.github/`, or AGENTS.md publishes nothing; the docs site deploys from main on its own. The review window applies to every PR either way. A version set by hand in a PR is published as it is when the registry lacks it, which is how a major release happens.
- Verify a release by watching the `publish` job on the merge commit's CI run (`gh run watch`), then `npm view tokenmaxxing version`. A green merge is not a publish.
- The release commit is the one push to main outside a PR; it comes from `GITHUB_TOKEN`, so it triggers no CI run. Publish jobs serialize on the `publish` concurrency group: a job whose release commit loses the push race fails without publishing, and the job queued behind it releases both merges as one version. A job that pushed its release commit and then failed to publish leaves main and the tag one version ahead of the registry; the next push to main, or `gh workflow run ci.yml --ref main`, publishes that version.
- Never push work directly to main.
- The review window is 10 minutes of reviewer silence, babysat every minute: poll the PR each minute for new reviews, comments, check results, and merge state, handle whatever appears (fix or refute, resolve conflicts, fix CI), and merge only after 10 consecutive quiet minutes. Every new item restarts the clock. Green checks never shorten it, because reviewers post findings after their checks pass.
- The PR review bots are the adversarial pass. Do not run a separate local adversarial-review workflow before opening the PR (owner, 2026-09-06); spend the effort on hermetic verification instead.
- npm trusted publishing is bound to the literal workflow filename `ci.yml`. Renaming it silently breaks publishing.
- `gh release create --target` takes a branch name or a full commit SHA; a short SHA fails with HTTP 422.
- `bun add -g <local .tgz>` over an existing global errors `DependencyLoop`. Run `bun remove -g` first.

## Statusline

Short pointers.

- Statusline: `src/entries/statusline.ts` renders natively and tees `usage/<uuid8>.json` for the session's seat (from the inherited store variable; no seat, no tee); subagent rows in `src/entries/subagentstatusline.ts`. Format spec in `docs/statusline.mdx`. statusLine stdin sends top-level sub-objects as JSON `null`, so their schemas need `.nullable().optional()`, not `.optional()`. The main payload can never reflect the focused subagent; the subagent rows are the only such surface. This runs every turn, so keep it O(ms) and off flock and oauth: read the HEAD file, never spawn a git subprocess.

## CLI output

`status`, `config`, and `check` have a text form and a `--json` form (`ok` mirrors exit 0, failures add `error`, progress on stderr only; contract in `docs/commands.mdx`); every other command is text only and `main.ts` refuses the flag for it before dispatch (decided 2026-09-12, issue #88: the CI smoke step parses `config --json`, the docs give `jq` recipes for the other two, and nothing consumes the rest). On those three, route every new success line through `emitJson` behind the `json` flag and every error through `emitError` (`notes` are text-only hints, `extra` is structured data). A bare `console.log` on a `--json`-capable command breaks the contract for scripts, and the text form must stay byte-identical: `status` renders from the same report the JSON prints, so change the collect step, not the renderer, when a number is wrong. Do not add `--json` to another command without a consumer.

## Usage hub

`serve` (`src/cli/serve.ts`) answers the CLIProxyAPI management subset a dashboard reads, `GET /v0/management/auth-files` and `POST /v0/management/api-call`, on the hostname `localhost` at `hub.port` (the loopback address the host's own resolver names, so a same-host consumer's `http://localhost:<port>` lands on it), with the key in `hub-key` (0600, minted on the first run, never printed; an existing key file readable by others is refused at boot). The contract is verified against router-for-me/CLIProxyAPI v7.3.11 and against what T3 Code's server decodes; user page in `docs/content/docs/hub.mdx`. The hub is a view over the cached figures and never a proxy: `api-call` matches the Claude and Codex usage URLs only, ignores the client's `header`, and never forwards a request. A Claude account is never read live from the hub, because the usage endpoint rate limits each Claude account on its own (#170) and the check tick already samples every account as often as that allows: `auth-files` and `api-call` both answer from the index with the tee folded in memory (`foldTee`, never saved), so `unavailable` and the served windows agree. A Codex account goes through `observeCodex` with `probe: true` and `refresh: false`, because no tick samples that pool: a cached figure older than `policy.usagePollTtlMs` costs one usage GET with the stored access token, stored under the pool lock the way a `status` sample is, and never a token refresh. The two-hour cutoff is per window, on each window's own `sampledAt` (a fresh tee advances the aggregate windows while `mergeWindows` keeps the per-model rows at the time of the last direct read): a window older than that is left out, and an account whose session and weekly windows are both that old is a 502, because the protocol carries no sample age and a passed reset would otherwise read as 0. The Codex body places the cached windows in `primary_window` and `secondary_window` by ascending duration (a weekly-only plan keeps the primary slot) and carries the named limits as `additional_rate_limits`. `reset-quota`, the Codex credit reads, and every other route are 404 or 400; keep it that way until a consumer needs one. The Claude `init` runs the hub as a background service beside the check timer (`com.tokenmaxxing.hub` launchd agent on macOS, `tokenmaxxing-hub.service` systemd user service on Linux, both running `serve`; `TOKENMAXXING_SKIP_HUB=1` skips the imperative unit the way `TOKENMAXXING_SKIP_TIMER=1` skips the timer, `doctor` checks it, `uninstall` removes it, and the Nix `hub.enable` option owns it instead).

## Lessons that cost something

- Verify an external tool's limits with a real-sized payload before relying on it. A 4.3KB credential blob truncated silently through `security -i`.
- A prior go-ahead does not cover collision evidence that arrives after it. Every new signal of concurrent work freezes git actions until the owner rules.
- Never write a completion claim into docs or memory ahead of the output that proves it.
- `status --ping` (removed 2026-09-12) opened a real 5h window on every account it pinged. A feature request is not permission to spend.
- `TOKENMAXXING_HOME` isolates state files only. `init`, `uninstall`, and the codex hook install write settings.json, codex `hooks.json`, the shell rc, and the timer unit under `HOME` regardless, so a throwaway root does not make them hermetic: a review subagent ran `uninstall --json` under one and stripped a live install (2026-09-05, issue #149). A run of a mutating command (`init`, `add`, `auth`, `uninstall`, the codex hook install) builds a full isolated `HOME` with `TOKENMAXXING_SKIP_TIMER=1` set, or runs in a container; a single app variable is never the isolation. `HOME` alone does not cover the timer: `systemctl --user` and `launchctl` address the login user's instance under any `HOME`. `uninstall` guards this in code (`onLoginHome` in `install.ts`): it prints its targets first, refuses without `--yes` when `HOME` is the login home (`getent passwd` on Linux, `id -P` on macOS, compared after `path.resolve`), and under an isolated `HOME` removes only the unit files under that `HOME` without addressing the instance. `init` has no such guard, so a hermetic `init` needs `TOKENMAXXING_SKIP_TIMER=1`. Every subagent brief names the verbs the seat may not run (`init`, `add`, `auth`, `uninstall`); "hermetic" is not enough.
